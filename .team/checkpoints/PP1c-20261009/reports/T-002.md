### 2. Concrete minimal lease API and persistent schema proposal

Keep current v1 `acquire`, `assertQuiesced`, `bindBackend`, `finish` exports/signatures for existing FRESH_INIT. Do not delete/recreate v1 metadata or reinterpret its COMPLETE/UNKNOWN statuses. Extract only shared reserve/load/durable-update/release mechanics into a private module, with v1 behavior regression tests.

Proposed public host-only exports in `scripts/local/maintenance-workflow.mjs`:

```js
beginWorkflow(inspection, {operationId, purpose, completionPolicy}, deps)
assertWorkflow(token, {side, stage}, deps)
reserveRestoreTarget(token, {runId}, deps)
runOwnedHelper(token, {side, kind}, deps)
verifyRecoveryProof(token, deps)
attachRecovery(token, accountOptions, deps)
finishWorkflow(token, outcome, deps)
```

`purpose` is one of BACKUP_LOCAL, RESTORE_VERIFY_LOCAL, RECOVER_ADMIN. These strings are host workflow labels; no Java Operation expansion. `completionPolicy` is RESTORE_ORIGINAL or KEEP_STOPPED and is sealed by the chosen workflow, not an arbitrary injected adapter. RESTORE_VERIFY_LOCAL can capture a new bundle before restoring it when producing a recovery prerequisite. Adapters/deps are test-only injection, never CLI fields.

Keep the authoritative paths `sourceRoot/maintenance/operation.lock`, `target.json`, `lease.json`, `operations/<operationId>.json`. Existing source `target.json` remains exact TargetV1. Add strict LeaseV2 as a version-discriminated alternative for host workflows:

```text
LeaseV2 = {
 version:2, operationId, purpose, releaseId, phase, createdAt,
 source:TargetV1, sourceConnection:{jdbcUrl,dataGateway},
 originalApiState:running|stopped, completionPolicy:RESTORE_ORIGINAL|KEEP_STOPPED,
 target:null|RestoreTargetV1,
 helper:null|HelperV1,
 proof:null|ProofV1,
 account:null|{operation:RECOVER_ADMIN,phase:PRE_CONNECTION|BOUND|COMMITTED,
              boundBackend:null|BackendV1}
}
RestoreTargetV1 = {
 version:1, runId, targetId, project, sourceOperationId,

}

}

```

All keys mandatory; null is explicit; unknown keys rejected; each enum/ID/hash/time inherits existing canonical constraints. TargetV1 in the child is the identity tuple shape, not permission to treat its RESTORE_* receipt as PP1a PREPARED. Volume refs bind name, driver, labels and inspected mountpoint through created-resource evidence; Docker named volumes have names, not container-style immutable full IDs. Record that distinction rather than inventing a 64-hex volume ID. The live identity must also bind PG database OID and immutable container/network IDs.

JournalV2 is exactly `{version:2,operationId,purpose,sourceTargetId,releaseId,phase,at,failureCode,leaseSha256,proofSha256}`; nullable proof/failure fields mandatory. Durable transitions write private BEGIN and END phase evidence bound to operation and old/new lease hashes; incomplete/mismatched updates fail closed. This is one registry, not a second journal mutex. Files mode0600/nlink1/current owner; dirs0700; nofollow; exclusive operation reservation; fsync file and parent; immutable terminal evidence.

Phases: RESERVED → SOURCE_QUIESCED → CAPTURED → LOCAL_VERIFIED → TARGET_RESERVED → TARGET_BLANK → DB_RESTORED → MEDIA_RESTORED → RAW_VERIFIED → SESSIONS_REVOKED → MATCHED_STARTED → RESTORE_VERIFIED → COMPLETE. BACKUP_LOCAL may terminate after LOCAL_VERIFIED and required completion policy; RECOVER_ADMIN instead goes SOURCE_QUIESCED → PROOF_BOUND → ACCOUNT_BOUND → COMMITTED → COMPLETE. Failure is FAILED_OR_UNKNOWN; commit-known recovery failure remains COMMITTED with the fixed restart failure code. Every action has a durable begin/end; no transitions inferred from exit zero alone.

`token` is an opaque frozen capability backed by a private WeakMap and operation/lock inode+device identity. It authorizes only the currently recorded source and child target. New process attachment derives paths from runId, reads exact private schema, and reruns live inspection; serializing/reconstructing a token object is not authority. `reserveRestoreTarget` exclusive-creates its root and an immutable `{sourceRunId,operationId}` ownership marker, reserves its run/project before any container/volume creation, and never acquires another lock. Child root remains explicitly RESTORE_*; ordinary account, prepare, forward and verification entrypoints reject this marker/receipt. It is never silently promoted into an independent writable source. This closes cross-entrypoint adoption without a second mutex/deadlock.

Compatibility: a unified strict lease loader recognizes exactly v1 or v2. Before replacing the latest lease, verify the preceding lease/journal/terminal evidence is COMPLETE and the lock absent; preserve every prior operation reservation. Prior v1 COMPLETE can precede v2, and v2 COMPLETE can precede v1 FRESH_INIT only if all existing fresh raw/media proofs independently pass. COMMITTED/FAILED_OR_UNKNOWN, malformed/missing registry, incomplete BEGIN, unknown version, missing child ownership, or lock present refuse all writers. No migration of an active lease. Duplicate operations always reject, including COMPLETE. New v1/v2 behavior is available only after G06/G07 freeze and regressions pass.

FinishWorkflow uses purpose-specific receipts. BACKUP_LOCAL requires complete bundle plus exact source pre/post proof and the chosen service state. RESTORE_VERIFY_LOCAL requires all raw/revoke/smoke evidence, child stopped after drill, and exact unchanged source. RECOVER_ADMIN keeps the unchanged six-field principal Result; backupId is bound in lease/proof and the existing success audit, not an extra Result field. Only owning code releases its empty identity-checked lock after its terminal evidence and live state agree. No generic `success:true` or nested `finish` call.

### 5. Local RECOVER_ADMIN proof handoff without new loose flag

Choose a fixed private lookup pointer under source maintenance, e.g. `recovery-candidate.json` containing only `{version:1,backupId,restoreOperationId,proofSha256}`. Releasing a completed lock is allowed; it does not itself restart a stopped source. Persist terminal source inventory/identity hashes and child evidence; child remains non-adoptable. A normal backup that resumes source is still useful, but its snapshot will usually become stale for immediate admin recovery after session/audit/startup changes.

Compute a new source inventory with trusted readonly helper and require exact equality to the backup's full pre-revoke source state. Any session/audit/content/file change rejects as stale; no age window or ignored tables. No helper remains before opening the account connection.

Before commit, live quiescence and bundle/proof file identity/hash still match. `Result` stays six fields; recordCommitted/close and host finish preserve commit-known failure semantics.
