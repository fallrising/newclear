### Review decision

The v0.2 reviews are a sound design input, but they are not yet a normative implementation contract. P0-A may proceed to document adoption only after the clauses below are made normative and owner-accepted. ### Remaining contradictions and overdesign

| Finding | Required disposition for P0-A |
|---|---|
| The augmented SDD sometimes says P0-A is Fake-only, while its broader “P0” table retains Fake plus one Codex profile and G3 discusses P0-A/B together. | Define separate exits: P0-A/G1 excludes AC-54 and all real-provider evidence; P0-B/G2 adds one real adapter; product/release acceptance is a later aggregate gate. |
| `WaitingHuman` is described both as a Run state and as a WorkItem condition. | A `Question`/`Blocker` is the durable WorkItem-level fact. `Run.WaitingHuman` is legal only for an adapter that declares durable checkpoint/resume. Otherwise the Run becomes `Interrupted(NeedsInput)` and an answer creates a new Run. |
| “Transactional projections” can be read as making views another writable truth, despite the state-first authority decision. | Normalized domain rows are canonical operational state. Domain mutation, audit event, outbox intent, and stored command result commit together. Board/Inbox/dependency indexes are rebuildable read models and never command targets. Audit is not a complete event-sourcing log. |
| Restore introduces a restore/service generation, but SSE resume is defined by sequence alone. A client can present an old cursor after an older backup is restored. | Define every stream cursor as `(stream_epoch, event_seq)`. Restore rotates `stream_epoch`; an epoch mismatch returns reset-required and a fresh snapshot. Callback authority separately requires the current restore generation and per-Run lease epoch. |
| Lease expiry, timeout, cancellation, process observation, and side-effect outcome remain easy to collapse into one terminal status. | Keep them orthogonal. Expiry removes authority, not the process; cancel/deadline are requests until stop is observed; `OutcomeUnknown` survives terminalization and blocks automatic retry/publication. |
| Driver/engine, idempotency retention, backup behavior, and restore fencing remain open while the plan blocks production code on them. | ADR-0004 must select these before persistence implementation. Retain a command tombstone or reject expired keys; never allow an old retry to become a new command silently. |
| Proposed timeouts, limits, generic external-mutation machinery, connector rules, and real credential isolation exceed what Fake-only P0-A can prove. | Keep limits as configurable initial policy, not product guarantees. Implement only Fake sink/adapter boundaries and denial behavior. Defer real connector/runtime mechanics and their acceptance to P0-B/P1. |
| The object inventory risks becoming a service-per-noun design. | Treat ACRevision as part of TaskSpec and CandidateSubmission/CompletionRecord as immutable WorkItem records for P0-A. Review/Evidence/Blocker/Question remain records; do not create generic services solely to mirror the glossary. |

### SQLite driver decision criteria

No driver is selected and no engine, race, backup, restore, disk-full, or benchmark command was run by this review. ADR-0004 may choose CGO or pure-Go only after recording:

1. The actual linked/embedded SQLite engine version and evidence that it contains the WAL-reset correction identified by the v0.2 review (3.51.3+ or a verified backport), independent of the Go module version.
2. Supported online-backup/snapshot API, WAL/checkpoint controls, `synchronous=FULL`, foreign-key and busy-timeout setup on every connection, and usable SQLite error-code classification.
3. Cancellation/interrupt behavior, connection-pool behavior, bounded busy retry, migration transaction semantics, and deterministic fault-injection seams.
4. CGO/static-link/cross-build consequences for the release target versus the separate supported `go test -race` image and C toolchain requirements.
5. Maintainer/security cadence, license, pinned module and image digests, reproducible build path, extension loading disabled by default, and supported target architectures.
6. Successful contract evidence for restart, concurrent writer, checkpoint pressure, backup/restore, migration interruption, `SQLITE_BUSY`, disk-full, and the declared benchmark dataset. Performance alone cannot override a failed correctness or recovery criterion.

Until those checks exist, the correct traceability status is `Proposed/NotRun`, not Passed and not an implicit preference for a familiar driver.
