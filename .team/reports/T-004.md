### Recommended P0-A startup and connection contract

Use the selected module at the exact pin above and construct the controlled absolute file URI with `net/url`; the tested semantic DSN is:

```text
file:/absolute/state/taskboard.db?_pragma=foreign_keys(1)&_pragma=journal_mode(WAL)&_pragma=synchronous(FULL)&_pragma=busy_timeout(5000)
```

Required policy:

1. The database and artifact roots are local, same-host filesystems under operator-owned mode-`0700` directories. Do not support NFS/network filesystems for WAL mode.
2. Open through the exact DSN so `foreign_keys=ON`, `synchronous=FULL` and the bounded 5,000 ms busy timeout apply to every pooled connection; initialize `journal_mode=WAL` and fail startup unless reading back all four PRAGMAs returns `1`, `wal`, `2`, and `5000` respectively.
3. At startup record the selected Go module version, `sqlite_version()` and `sqlite_source_id()`; CI and startup must reject an engine below `3.51.3`. An upgrade is a fresh selection event and must rerun this matrix.
4. Use one serialized application write path and explicit `BEGIN IMMEDIATE` for kernel command transactions; do not retry `SQLITE_BUSY` indefinitely. Preserve the typed primary/extended SQLite result code. Reads may use a bounded pool; the spike proved four separately configured connections.
5. Run schema migrations before dispatch on one startup connection, inside an explicit transaction where SQLite permits. A failed migration keeps dispatch disabled.
6. Do not enable extension loading or accept arbitrary PRAGMA/DSN fragments from requests.

### Recommended backup and restore contract

Use a **writer-quiesced `VACUUM INTO` snapshot**, not a live copy of `taskboard.db`, `-wal`, and `-shm`:

1. Enter backup mode, reject/queue new mutation commands, and wait for the current application writer to finish. Reads may remain available. Create a unique, non-existing temporary target inside a mode-`0700` backup directory on the same filesystem.
2. On a dedicated connection execute parameter-bound `VACUUM INTO ?`. On success set the snapshot mode to `0600`, fsync it, reopen it, and require `PRAGMA integrity_check='ok'`, zero `PRAGMA foreign_key_check` rows, the supported schema version, and all manifest-required rows/material references.
3. Hash the snapshot, write a manifest binding the SHA-256, byte size, schema version, engine/source ID, accepted graph/spec IDs, artifact inventory, restore generation and durable event watermark; fsync snapshot, manifest and parent directory, then atomically rename both into immutable digest-addressed names. Resume writes only after publication completes or is abandoned cleanly.
4. Restore begins dispatch-disabled with all old database handles closed. Verify snapshot/manifest digests and required external artifact bytes, install the database through same-filesystem atomic rename into an empty restore location, remove no historical backup, reopen with the startup DSN, and repeat integrity/FK/schema/material checks.
5. After successful restore, rotate restore generation and SSE stream epoch, reconcile pending/unknown actions without replay, and only then allow dispatch. Missing material remains Missing and cannot satisfy Done.

The spike directly proves the engine's `VACUUM INTO` snapshot can be copied, synced and reopened consistently after the source advances. Manifest atomicity, crash injection, disk-full behavior and generation rotation remain product implementation acceptance work; this report does not convert them to Passed.

## Risks and Follow-ups

- Product-level disk-full, kill-during-migration/backup, corrupt-manifest, concurrent-write-during-backup, restore-generation and SSE-epoch cases are **NotRun** in this selection spike. They remain mandatory implementation/acceptance evidence; the proposed writer-quiesced protocol deliberately avoids claiming fully online concurrent-write backup.
- Only Linux/amd64 was tested. The pure-Go choice reduces portability risk but does not prove other target architectures; each release target needs its own build and functional evidence.
- The five-second busy timeout is a bound, not a retry policy or availability guarantee. Application writes should be serialized, report typed busy failures, and never hide indefinite retry behind the driver.
- `VACUUM INTO` creates a logical snapshot, not a byte-identical copy of the live WAL set. The implementation must preserve the manifest, fsync, atomic-publication and restore-fencing steps above.
- `govulncheck` is point-in-time and Go-call-graph scoped. Pin updates require renewed module provenance, license, engine/source-ID, vulnerability and full contract/race evidence.
