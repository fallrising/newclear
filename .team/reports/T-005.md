## Summary

### Decision

P0-A should expose versioned JSON under /api/v1: read-only projection queries, a single typed application-command ingress, command-result lookup, resumable SSE, and Project-bound immutable artifact reads. OpenAPI describes wire shapes only. Go authenticates the session, injects the actor, canonicalizes and authorizes the command, checks idempotency/version, enforces every lifecycle and Done guard, and writes state/audit/outbox/result atomically. Neither the client nor OpenAPI is a business-invariant authority.

The HTTP body has no authoritative actor_id. The session supplies it before the Go service constructs the domain command; it may appear only as read-only audit/result data.

### Endpoints and authority

| Endpoint | Purpose | Authority / permission | Idempotency and version |
| --- | --- | --- | --- |
| GET /api/v1/projects | List Project projections. | project.read; projection only. | Read-only; includes cursor. |
| POST /api/v1/projects | CreateProject. | project.create; Go validates new identity/binding. | Required key; supplied project_id has expected_version 0. Scope: principal + proposed project + operation + key. |
| GET /api/v1/projects/{project_id} | Project summary. | project.read before resource disclosure. | Read-only; returns Project version/cursor. |
| GET /api/v1/projects/{project_id}/board | Board/Attention snapshot. | project.read; never command authority. | Read-only; consistent snapshot cursor. |
| GET /api/v1/projects/{project_id}/work-items | List WorkItem projections. | project.read. | Read-only; each result has aggregate version. |
| GET /api/v1/projects/{project_id}/work-items/{work_item_id} | Detail with AC coverage, Runs, Candidate/Review/Evidence references and audit summary. | project.read; Go checks Project ownership. | Read-only; immutable records are references. |
| POST /api/v1/projects/{project_id}/commands | Typed application command ingress. | Go checks operation permission before sensitive body/resource resolution. | Every mutation needs a key and target aggregate expected_version. |
| GET /api/v1/projects/{project_id}/commands/{command_id} | Recover result after response loss. | Original actor or audit.read, after project authorization. | Read-only; returns stored result and never re-executes. |
| GET /api/v1/projects/{project_id}/events?cursor={epoch}:{sequence} | Resumable SSE projection. | project.read at connect and while streaming. | Read-only; cursor is stream epoch + event sequence. |
| GET /api/v1/projects/{project_id}/artifacts/{sha256} | Read a bound immutable object. | artifact.read/project.read; Go checks Project binding, digest and Present availability. | Read-only; ETag/integrity equal SHA-256. No filesystem path/upload endpoint. |

The V1 command operation discriminator permits: CreateWorkItem, UpdateWorkItemMetadata, MarkReady, DispatchRun, SubmitCandidate, RequestQA, RequestRework, CompleteWorkItem, ReopenWorkItem, RequestCancellation, FinalizeCancellation, AddBlocker, ResolveBlocker, AcceptSpecificationRevision, PreviewImpactPlan, ActivateImpactPlan, ReconcileRun, PublishFixtureObservation, PublishFixtureReview, PublishFixtureEvidence, and ApproveSubject.

CreateWorkItem, accepted-revision, and ImpactPlan commands use the Project version. WorkItem transitions/blockers use its WorkItem version. Run/fake-observation operations additionally carry the Run lease epoch and restore generation whenever Go requires fencing. Dispatch, cancellation, reconciliation, approval, and completion require the human/operator capability. PublishFixture operations additionally require a local Fake fixture/admin capability and reject any adapter other than fake/v1. Every listed mutation has an idempotency key, including rejected commands.

### Snapshot, cursor, and reset

```json
{
  "api_version": "v1",
  "projection": { "kind": "project_board/v1", "project_id": "prj_01J8R3", "lanes": [] },
  "cursor": { "stream_epoch": 7, "event_sequence": 441 }
}
```

The client connects from this exact cursor. Last-Event-ID and cursor use epoch:sequence; if both occur, they must match. Committed projection events are ordered only within their epoch:

```text
id: 7:442
event: work_item.changed
data: {"api_version":"v1","cursor":{"stream_epoch":7,"event_sequence":442},"projection":{"kind":"work_item/v1","id":"wi_01J8R4","version":13}}
```

Duplicates are safe by cursor/resource version. For an expired/wrong-epoch cursor, emit the following then close; the client fetches snapshot_url before reconnecting. Queue overflow or authorization revocation also closes without blocking a Go transaction.

```text
event: projection_reset_required
data: {"api_version":"v1","reason":"epoch_mismatch","current_epoch":8,"minimum_sequence":1,"snapshot_url":"/api/v1/projects/prj_01J8R3/board"}
```

### Validation and compatibility

- Go accepts bounded UTF-8 application/json with one JSON value, no duplicate keys, no unknown V1 request fields, strict discriminator payloads, validated IDs/timestamps/versions/digests/enums, and route/body Project identity equality. Identity fields contain no floats.
- Canonical request digest is calculated in Go after route binding and session actor injection: sorted keys, normalized RFC3339-nanosecond times, stable AC ordering, and semantic fields only. It includes API version, Project, actor, operation, expected version and payload; it excludes command_id, idempotency_key and issued_at. Same key/different digest is idempotency_conflict; expired retention yields tombstone/expired-key handling, never a new command.
- Unknown V1 request fields/operations reject because excluding them could weaken signed/subject semantics. Servers may add optional response fields/event types; clients ignore unknown response fields, preserve unknown events for display only, and treat unknown state/enum as non-actionable attention, never success. Breaking request semantics require /api/v2.
- OpenAPI may generate edge types/shape validation. It must not own transition guards, permissions, canonicalization, digest calculation, transaction boundaries, or the Done predicate; named Go commands recheck them transactionally.
