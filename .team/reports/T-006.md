- `backend/go.mod` and `backend/go.sum` for one Go module. Commit both; use `go mod download` and
  `go mod verify` in the pinned Go environment. Do not introduce a `go.work` file for a single
  module.
- `web/package.json` and `web/pnpm-lock.yaml` for one private frontend package. Commit both, set
  `packageManager` to pnpm `11.25.0`, constrain `engines.node` to the Node 24 line, and make CI use
  `pnpm install --frozen-lockfile`. Do not introduce `pnpm-workspace.yaml` until there is a real
  second JS package.
- Direct dependencies and devDependencies use exact versions (no `^`, `~`, `*`, `latest`, or Git
  branches); the lockfile freezes transitives and integrity hashes. A `.node-version` of `24.20.0`
  may mirror the manifest for local tooling, but the manifest/lockfile pair remains authoritative.
- Commit shadcn-generated source instead of regenerating it in CI. The bootstrap review must retain
  the generation command and generated-file hashes so a future refresh is auditable even if the
  upstream registry changes.
- Put stable gate entry points in component-owned scripts (for example `scripts/ci/backend.sh`,
  `scripts/ci/web.sh`, and `scripts/ci/e2e.sh`). Local and root CI call the same scripts. Image
  references and package/tool versions must be mechanically checked against their authoritative
  manifests to prevent duplicated pins from silently drifting.

### Root workflow contract

Create exactly one canonical root workflow, `.github/workflows/hai-taskboard-ci.yml`, during the CI
bootstrap task. Its contract is:

- Name `hai-taskboard-ci`; trigger on `pull_request`, pushes to `main`, and `workflow_dispatch`.
  Both push/PR path filters contain only `products/hai-taskboard/**` and
  `.github/workflows/hai-taskboard-ci.yml`.
- Set top-level `permissions: { contents: read }` and concurrency key
  `hai-taskboard-ci-${{ github.workflow }}-${{ github.ref }}` with `cancel-in-progress: true`.
- Define `backend`, `frontend`, and `e2e` jobs in this one workflow, on `ubuntu-latest`, with explicit
  least-privilege job permissions and timeouts (20, 20, and 30 minutes respectively). E2E depends on
  successful backend and frontend gates.
- Each job checks out with the monorepo's established immutable
  `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (`v7.0.1`) and
  `persist-credentials: false`, then invokes only its component-owned gate script. Those scripts run
  the digest-pinned containers above from the repository root and mount only the component/work
  directories they need.
- Do not use secrets, write tokens, publish, deploy, mutate external systems, or depend on services
  outside the checked-out repository and pulled pinned images. Upload only bounded test artifacts;
  any artifact action must also be pinned to an immutable full commit SHA.
- Before adoption, validate the workflow's YAML/action pins/path filters with the repository policy
  checks and confirm an unrelated component-only change does not select it. The moving
  `ubuntu-latest` host is not evidence of a fixed userland; log the resolved runner image and image
  platform while keeping actual build/test tools inside the digest-pinned containers.

This follows [the monorepo CI contract](../../docs/specs/monorepo-ci.md) and the root workflow
precedents reviewed in `.github/workflows/*.yml`: root ownership, product-plus-workflow path filters,
read-only permissions, cancellation, explicit timeouts, immutable action SHAs, and component-owned
commands. It deliberately adds no component-local workflow.
