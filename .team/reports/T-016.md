## Delivered behavior

- Typed Admin clients and guarded routes now cover `/admin/access`, `/admin/navigation`, `/admin/catalog`, `/admin/cmdb-models` and `/admin/audit`; the Admin overview links to every implemented workflow, so no empty M2 Admin page remains.
- Access UI lists users and fixed role assignments, creates/revokes scoped grants and enables/disables another user. Self-change and last/recovery constraints surface the handler's explicit refusal.
- A transport correction accepts only the exact receipt of a policy-changing command that already advanced the subscribed session: same actor/session/generation, non-GET, increased identity/policy epoch and response policy equal to current policy. Produced reads, cross-principal responses and older receipts remain stale and fail closed; a regression test fixes this boundary.
- Navigation UI edits only registered label/group/order/enabled metadata. AppShell projects the current center's persisted navigation without deriving routes or permissions from data, keeps static route guards, and falls back to the registry if the navigation read fails. Required Admin/recovery entries cannot be disabled.
- Catalog UI creates a new draft revision, edits its name/description, publishes it and disables new requests. Existing immutable request snapshots remain domain-owned.
- CMDB model UI creates optional-only typed metadata, renames/hides it and displays core-key validation failures. It does not expose identity/type/required mutation.
- Audit UI filters safe governance history by actor and entity type without rendering raw command payloads, credentials or arbitrary logs.
