## Summary

Audited the V08/ERU-015 requirements and the existing controller, inventory,
manual reimage, worker-generation, desired-app, and provenance contracts. The
narrowest safe first slice is one local-only, review-only plan for one complete
Profile A rebuild of the exact four reviewed hosts. It must not execute,
quiesce, reimage, bootstrap, restore, or update generation. Three-run V08
acceptance is a series of three separately reviewed fresh-generation plans and
evidence sets, never one replayable destructive bundle.

### V08 requirements mapped to reusable contracts

- V08 requires three fresh rebuilds using the same pinned version and desired
  manifests; every accepted run must re-establish V01-V04, prove no old node,
  workload, or plugin-capacity residue, and record candidate RTO
  (`labs/eru-vps-mvp/docs/SDD.md:178-192`). ERU-015 independently requires a
  new generation and externally available versions/secrets; worker component
  reinstall 3/3 is explicitly not a substitute
  (`labs/eru-vps-mvp/docs/TASKS.md:37-42`).
- Desired state comes from Git app specs/image digests, host identity comes
  from private inventory, cold rebuild discards etcd/runtime state, and
  evidence stays outside the four hosts (`docs/SDD.md:106-120`). Reuse that
  ownership model directly.
- `controller_preflight.assess()` already produces a secret-free readiness
  object containing controller/package versions, source commit/cleanliness,
  artifact/upstream/patch digests, private-input presence, fixed SSH aliases,
  blockers, and `ready_for_review`
  (`scripts/controller_preflight.py:51-156`). Reuse its result as one bound
  input; do not interpret it as bootstrap or live-health proof

- Reuse `labctl.identifier()`, `digest`, `atomic_json`, and the envelope shape
  `{"plan": plan, "sha256": digest(plan)}` for immutable IDs and storage

### Minimal private input schema

Use one JSON object under a dedicated private directory, rejecting duplicate,
unknown, and missing fields. The first slice should accept exactly:

```text
schema_version: 1
mode: "fresh"
topology_profile: "profile-a-four-host-basic"
series:
  id: bounded identifier
  required_successes: 3
  iteration: 1..3
  previous_accepted_run: null for 1, otherwise {id, plan_sha256, generation}
expected_cluster: {cluster_id: "eru-vps-mvp", generation: integer >= 1}
controller_report: {path, sha256}
inventory: {path: "private/deployment-plan.json", sha256}
host_intents: exactly four {alias, node, path, sha256}
fresh_etcd:
  mode: "new-empty"
  restore_source: null
  prior_token_sha256: 64 lowercase hex
  target_token_sha256: different 64 lowercase hex
desired_apps: nonempty list of ERU-012 v1 app objects
writer_quiescence_review: {confirmed: true, reviewed_at, evidence_sha256}
data_disposition_review: {confirmed_discardable: true, reviewed_at,
                          evidence_sha256}
```

`host_intents` must cover `<disposable-01>` through `04` exactly once, bind
the inventory's exact alias/node and currently reviewed machine identity, and
enumerate every erased volume. The core may use its inventory node identity for
binding, but it is not passed through worker-only payload/registration code.
`desired_apps` is normalized through `validate_spec()` and must have unique
logical names; the plan stores normalized specs plus `spec_sha256` and
deterministic `appname`. No secret, credential, raw host key, or token value is
copied into the plan—only reviewed private paths, redacted identity, and
digests.

The two attestations are review evidence, not proof that quiescence or backup
is still true at execution time. A later executor must recheck them and live
state. Unknown local data, non-project Docker/runtime ownership, an unlisted
volume, a wildcard provider reference, missing external secrets, or any
non-stateless desired app blocks the plan.

### Immutable review plan fields

The plan should contain:

- `schema_version`, `id`, `created_at`, `operation` set to
  `full-cluster-fresh-rebuild-review-plan`, `mode: fresh`, `decision`,
  `blockers`, `executable: false`, and `execution_implemented: false`.
- `series` and `topology_profile`, with one plan representing exactly one
  iteration and one proposed generation.
- `generation_before` copied from a strict read-only existing cluster record
  and `generation_after = generation_before + 1`; `cluster_id` is unchanged.
- `scope.hosts`: the four normalized intent records with alias/node/current
  machine ID/provider resource/OS image/exact erase scope and source path/hash.
- `bindings`: source Git commit, clean-source result, `code_inputs_sha256`,
  controller-report hash and selected readiness summary, artifact/upstream/core
  provenance hashes, full private inventory file hash plus the redacted
  `load_inventory()` projection, cluster-record hash, fresh-etcd token digests,
  and the two review-evidence hashes.
- `desired_apps`: normalized ERU-012 specs with logical name, spec digest, and
  appname; plus one digest over the sorted complete set.
- `fresh_policy`: `restore_allowed: false`, `existing_etcd_allowed: false`,
  `existing_runtime_authoritative: false`, `old_metadata_import_allowed: false`,
  and `app_source: versioned_desired_specs_only`.
- `stages`, `acceptance`, `checks_not_performed`, and `plan_sha256`.

The builder must reread and hash every referenced regular private file without
following an out-of-scope symlink, call the existing validators, and then seal
the complete plan. A self-digest alone is not authority: every later stage must
reload the immutable saved plan and compare the caller-provided expected hash.

### Stage and evidence contract

Each stage is descriptive in this slice and has
`implemented: false`, `executable: false`, an exact `host_scope`, a destructive
flag, prerequisites, and required evidence. Recommended ordered stages are:

| Stage | Review boundary and required future evidence |
| --- | --- |
| `controller-ready` | Fresh secret-free controller assessment; exact Git/artifact/upstream/patch/inventory hashes; external keys/secrets available. `ready_for_review` is not bootstrap proof. |
| `scope-reviewed` | Four exact provider resources and all erased volumes; data disposition accepted; no wildcard/all scope; current machine identities still match. |
| `writers-quiesced` | Deploy writers and scheduled mutations stopped; in-flight operations resolved; evidence timestamp and owner review. |
| `generation-started` | Durable external journal records plan hash and consumed `generation_after` before the first destructive action. No remote action exists in this slice. |
| `hosts-reimaged` | Per-host owner receipt; new machine and boot IDs; freshly authenticated host keys; intended OS image and volume result; no provider-API claim. |
| `network-and-access-ready` | Exact four aliases, private addresses, firewall/SSH trust, controller reachability; secrets remain external/redacted. |
| `empty-control-plane` | Empty etcd data roots, new unequal cluster token, no snapshot restore, expected new member set, and no old core/resource-plugin keyspace. |
| `cluster-bootstrapped` | Pinned artifacts/source; V01 node/pod/core/etcd evidence with command exit codes and duration. |
| `apps-replayed` | Fresh ERU-012 plans from the normalized specs; exact replicas/owner/spec labels plus per-worker lifecycle and HTTP evidence for V02/V03. |
| `resources-accepted` | V04 over-capacity rejection, successful remove, zero residual quota, and per-node capacity/usage evidence. |
| `residue-audited` | No old machine/node/workload IDs, no old etcd/plugin capacity records, no unexpected attached data roots; full keyspace/prefix evidence rather than `/eru` only. |
| `generation-accepted` | All prior gates passed, RTO components recorded, private generation state committed exactly once, immutable evidence index sealed. |

Evidence for every stage should include `stage`, `started_at`, `finished_at`,
`status`, `plan_id`, `plan_sha256`, `cluster_id`, `generation`, `host_scope`,
`command_exit_codes` or explicit manual receipt references, artifact hashes,
private evidence paths/hashes, blockers, and `remote_mutation_performed`. Raw
credentials, host keys, inventory contents, and workload IDs stay private;
public output reports only counts, decisions, plan IDs/hashes, generation, and
private relative paths.

The future state machine should retain the SDD vocabulary
`planned -> preflighted -> quiesced -> rebuilding -> registered -> verified -> complete`
and record `failed_at` without continuing to another host
(`docs/SDD.md:131-148`). Review-only delivery stops at `planned`.

### Fresh/restore separation and generation semantics

- `mode` is exactly `fresh`; any snapshot path/hash, restore revision,
  preserved etcd data directory, old membership import, or workload metadata
  import is a hard blocker. Restore belongs to V10/ERU-016. The runbook also
  requires empty etcd and forbids mixing snapshot restore into a fresh
  operation (`docs/RUNBOOK.md:145-153,177-185`).
- Versioned stateless desired specs are replayed; old container/workload IDs are
  evidence of residue, not identities to restore. External business-data
  restore is out of scope and must have separate reviewed evidence.
- Planning never calls `Operator.cluster()`, because that helper creates a
  default cluster record when absent (`scripts/labctl.py:220-228`). Add a strict
  read-only loader that requires an existing regular record and binds its raw
  hash.
- One plan binds `generation_before = G` and `generation_after = G+1` and makes
  no writes. Before any future destructive action, a durable external journal
  must mark `G+1` consumed by this exact plan. A started destructive generation
  is never reused after failure; recovery gets a new source-bound plan and a
  later generation. Only a fully accepted run becomes the current successful
  cluster generation.
- V08's three successes are three separately sealed plans/evidence sets with
  monotonically increasing generations. `previous_accepted_run` must match the
  immediately preceding accepted plan. Any failed attempt resets the
  consecutive-success count; it never gets relabeled as one of the three.
- ERU-014's generation commit assumes one resumed worker and atomically updates
  one inventory render plus `cluster.json`
  (`scripts/reimage_worker_generation.py:111-179,297-399`). ERU-015 needs its
  own external generation-start/accept journal over all four incarnations and
  must not call that executor.

### Unsafe reuse and correctness/security risks

- `Operator.plan(rebuild-node)` explicitly rejects core/etcd and scopes one
  worker (`scripts/labctl.py:240-270,322-413`). Expanding its target list would
  bypass distinct core/empty-etcd semantics; create a separate review builder.
- `Operator.__init__()` and `Operator.cluster()` create private directories or
  state (`scripts/labctl.py:127-137,220-228`). Keep the review builder's reads
  explicit; only its final private plan write is allowed.
- `Operator.snapshot()` proves the current cluster matches the current
  inventory (`scripts/labctl.py:188-218`); it cannot prove future blank-host or
  empty-etcd state and must not be copied as the target baseline.
- `reimage_worker_plan` deliberately installs only agent/CNI and preserves OS,
  SSH/Tailscale, Docker/containerd (`scripts/reimage_worker_plan.py:139-160,190-229`).
  It is neither a core bootstrap nor a full fresh-host payload.
- `controller_preflight.ready_for_review` checks availability/shape of old
  inputs and aliases; old preflight evidence is only required to exist and is
  not current remote health (`scripts/controller_preflight.py:118-155`).
- The broad operation can irreversibly erase all four machines. Exact provider
  and volume references, current machine IDs, per-host freshness rechecks, and
  an explicit non-project-data disposition are mandatory. Never accept `all`,
  `*`, alias inference, or an implicit default host set.
- Reimaging the core removes the only control plane. Controller assets,
  inventory, secrets, artifact bytes, host trust bootstrap, plans, locks, and
  journals must be external before mutation (`docs/SDD.md:34-60,106-120`).
- A reused disk/token or accidental restore can resurrect stale etcd/plugin
  capacity. Prove empty data roots, a new token, complete prefix/keyspace state,
  and no old node/workload IDs; checking only `/eru` is insufficient
  (`docs/SDD.md:161-170`).
- ERU-012 v1 accepts only stateless, digest-pinned apps and excludes secret/
  volume fields (`scripts/app_desired.py:108-169`). Stateful data restore or
  host-network apps require separate review and must block this first slice.
- RTO evidence must distinguish provider queue time from installation time and
  also record total wall time; the 30-minute value remains a candidate, not an
  implementation guarantee (`docs/SDD.md:178-192`).

## Risks and Follow-ups

- Highest risk: adapting the single-worker ERU-014 executor or generation
  commit into a four-host destructive path. Reuse validation patterns only.
- Highest risk: treating `ready_for_review`, a self-hash, or old preflight
  presence as proof that remote hosts are safe to erase or ready to bootstrap.
- High risk: ambiguous provider/volume scope or undiscovered local/stateful
  data can cause irreversible loss; any uncertainty blocks the plan.
- High risk: mixing fresh and restore semantics can resurrect stale core/plugin
  metadata while appearing to be a clean V08 run.
- High risk: generation reuse after a destructive failure destroys provenance.
  A future executor needs an external durable generation-start record before
  any host mutation and must consume failed generations.
- Follow-up: independently review the eventual executor design, locking,
  cross-controller recovery, exact empty-etcd proof, and manual-console receipt
  chain before authorizing any remote implementation. They are intentionally
  outside this review-only slice.
