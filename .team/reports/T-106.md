# T-106 ERU-015 fresh-rebuild planner audit

## Summary

The repository has useful building blocks for an ERU-015 V08 planner, but no fresh-cluster planner or CLI route. `labctl plan` accepts only `reapply`, `smoke`, `cleanup`, `rebuild-node`, and `canary-start` (`scripts/labctl.py:760-763`); no parser or implementation path represents `rebuild-cluster --mode fresh`. Existing code can validate the reviewed four-host shape (`labctl.py:70-76`), bind source/lock/private-input digests and current generation (`labctl.py:57-67`, `:220-228`, `:271-283`), and reject later binding drift in executable operations (`labctl.py:600-618`), but those guarantees are not yet assembled into an immutable, review-only, whole-cluster destructive-scope contract.

The first ERU-015 slice should therefore be a local-only planner: it may read approved private inputs and local controller facts, but it must never contact a VPS, mutate private inputs, authorize execution, reimage a host, initialize etcd, or claim V01-V04/V08 passed. Its private plan should bind exact destructive scope and sources; its public CLI summary should expose only safe counts, modes, generations, decisions, blockers, digests, and a private record reference—not aliases, IPs, provider/volume identities, host keys, tokens, app commands, or raw specs.

## Risks and Follow-ups

- A useful private review plan necessarily needs exact provider/volume/topology scope, but the public CLI must not serialize that private plan wholesale. Treat private-record contents and public summary as separate contracts.
- `controller_preflight.assess` is an availability/readiness audit, not an authorization artifact: it follows symlinked files, records the current dirty/clean state at one time, and does not validate provider resources, disks, OS image, fresh-vs-restore, or a complete desired manifest.
- Existing `code_inputs` includes broad script/patch/private hashes (`labctl.py:57-67`) but does not by itself express why each destructive input is trusted or whether external secrets are recoverable. The new plan should use explicit named bindings and availability attestations.
- Hash determinism must not erase meaningful scope order/identity. Normalize only fields defined as semantically unordered or observational; exact host/provider/volume ownership and current→next generation must remain hash-relevant.
- Do not add an executor, provider call, SSH probe, or destructive shell command in the review-planner slice. Those require a separately reviewed task, explicit authorization, new failure/recovery contracts, and real V08 evidence.
