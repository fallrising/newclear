Official etcd v3.6 recovery semantics set the restore contract: capture with `etcdctl snapshot save`; derive hash/revision/key count/size with `etcdutl snapshot status`; restore with `etcdutl snapshot restore`; use the same snapshot for all restored members; create a new logical cluster with new member/cluster identities and a token that excludes old members; and explicitly review revision bump/compaction for watch or cache consumers. A copied `member/snap/db` can omit WAL-resident data and requires `--skip-hash-check`, so the first ERU-016 slice should reject that source type and any skip-hash request. Source: [official etcd v3.6 disaster recovery guide](https://etcd.io/docs/v3.6/op-guide/recovery/).

## Risks and Follow-ups

- Highest risk is false provenance: a self-consistent snapshot plus self-authored status JSON is not proof of the intended cluster. Require a separately anchored capture receipt/catalog and locally derive status from the exact bytes with the pinned tool.
- A whole etcd snapshot is full-keyspace by format, but the plan still needs an intended-cluster/full-control-metadata capture receipt and post-restore class reconciliation; a `/eru`-only export or hand-built database must never satisfy V10.
- Old-control isolation cannot be proven by an offline review planner. Represent it as a mandatory future gate with exact private scope and `checks_not_performed`, never as an achieved boolean based only on operator prose.
- Revision bump size is an operational policy derived from snapshot age/write rate and known watch/cache consumers. The planner must bind the reviewed choice and reject invalid combinations; it must not invent a universal number.
- Current Profile A is a single etcd member. The V10 planner must not silently claim Profile B/three-member HA; ERU-017 remains a separate task.
- Passing local fake tests will prove only planner validation, immutable storage, serialization, and stage modeling. V10 remains open until an isolated real restore demonstrates old-control fencing, metadata/runtime/plugin/API/HTTP reconciliation, writer resume, and measured RPO/RTO, without claiming application-volume recovery.
