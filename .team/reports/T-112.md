## Summary

Reviewed the fixed ERU-016 candidate from base `6ff7455`, including the changed durable documentation/CLI wiring and the untracked control-restore implementation and focused tests. The local-only, non-executable boundary is real: the public CLI exposes only `plan-control-restore`, the restore planner does not construct `Operator`, its only subprocesses are local Git provenance checks, generic `execute` reads a different record area, and the documentation does not claim V10 acceptance.

The candidate is not ready for acceptance. No separate BLOCKING-severity finding was identified, but one HIGH and four MEDIUM findings remain open.

### HIGH

1. **Snapshot/tool/catalog provenance is self-forgeable and can still produce `decision: reviewable`.** `labs/eru-vps-mvp/scripts/control_restore_ops.py:223-258` reads status and catalog records from the same locally supplied `private/` trust domain and supplies them directly to the planner. `labs/eru-vps-mvp/scripts/control_restore.py:176-224` accepts caller-provided binary digests, a Boolean `verified`, a syntactically valid status hash, and a mutually consistent catalog record; none is authenticated by a separately trusted receipt/signature/catalog anchor. Consequently, `capture_method: etcdctl-snapshot-save` and `full_keyspace: true` are assertions rather than established provenance. The positive fixture demonstrates the gap: arbitrary non-etcd bytes, fabricated `deadbeef` status, invented tool digests, and a locally generated catalog receipt at `labs/eru-vps-mvp/tests/test_control_restore.py:99-129` and `labs/eru-vps-mvp/tests/test_control_restore.py:146-166` are accepted as reviewable. An actor able to rewrite the intent/evidence set can bless a stale, partial, or non-snapshot payload while preserving every current digest relationship.

### MEDIUM

1. **Retained-worker and restored-control reconciliation is aggregate-only and conflates Eru membership with etcd membership.** The source contract at `labs/eru-vps-mvp/scripts/control_restore.py:282-301` contains only opaque hashes and counts, not exact member/node/workload/plugin identities. The retained baseline merely copies those hashes at `labs/eru-vps-mvp/scripts/control_restore.py:381-392`, and `expected_membership_sha256` is required to equal the *target etcd initial-cluster* digest at `labs/eru-vps-mvp/scripts/control_restore.py:394-404`. The positive fixture encodes that conflation at `labs/eru-vps-mvp/tests/test_control_restore.py:193-206`. This cannot prove that three retained Eru workers, their workloads, runtime, and plugin accounting agree with the restored metadata, nor can it identify a missing/extra/stale object.

2. **Revision rollback and core-key readiness are not substantively validated.** `labs/eru-vps-mvp/scripts/control_restore.py:369-379` accepts any positive revision bump below `2**63` plus arbitrary `basis_sha256` and `client_restart_set_sha256` values. It does not bind an explicit complete watcher/client set, demonstrate that the bump is adequate for the reviewed revision/history, or block on an unknown watcher. Likewise, `labs/eru-vps-mvp/scripts/control_restore.py:394-409` accepts one of two core-key mode strings and any SHA-256-shaped evidence value, with no availability/rotation/revocation state from which an unavailable key could become a blocker.

3. **The new logical-cluster target is missing host identity and contains an unbound data-directory aggregate.** The target member schema at `labs/eru-vps-mvp/scripts/control_restore.py:346-367` binds name, peer URL, client URL, and one data-dir digest, but no host identity. `target_data_dirs_sha256` is only checked for syntax and inequality with the source aggregate; it is never derived from or compared with the member data-dir set. A plan can therefore contain contradictory target data-dir identities and cannot prove the member is assigned to the reviewed Profile A host.

4. **Private-path safety has validation/use races below the trusted top-level symlink.** `_private_file` performs path-based symlink/regular-file checks and returns a pathname at `labs/eru-vps-mvp/scripts/control_restore_ops.py:37-66`; JSON is then reopened by pathname at `labs/eru-vps-mvp/scripts/control_restore_ops.py:69-82`. Snapshot `O_NOFOLLOW` protects only the final component after the same path walk, not an ancestor exchanged between validation and open (`labs/eru-vps-mvp/scripts/control_restore_ops.py:93-117`). Record directories are likewise walked and later used by pathname (`labs/eru-vps-mvp/scripts/control_restore_ops.py:120-145`). The tests cover pre-existing final-component symlinks and same-ID concurrency (`labs/eru-vps-mvp/tests/test_control_restore.py:391-433`), not ancestor replacement during validation/use. A local concurrent writer can redirect a read or record operation after the checks; descriptor-relative traversal/revalidation is required for the promised fail-closed boundary.
