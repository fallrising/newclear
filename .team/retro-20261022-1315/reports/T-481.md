## Documentation

Tool module/CLI help documents flags: `--seeds` (default `7 19 41`), `--scenarios` (default `complementary same_profession unaffordable`), `--max-steps` (default 400; accepted range 1–10000). CLI requires launcher-provided `AGENT_BUILD_DIR`. Output is deterministic JSON, including full trace, ledger, per-character rounds/balances, waits/rejections, final and reopened worlds. It contains no bearer tokens. Full trace goes to `AGENT_EVIDENCE_DIR/simulation.json` by default, or an explicit `--output PATH`; existing evidence is never overwritten. Stdout contains only a compact JSON summary and evidence path. The process exits 0 only when every requested scenario has its expected completion/stall outcome and round counts. It exits 1 on invariant failure, unexpected scenario outcome, or budget exhaustion; truthful evidence is retained for budget exhaustion. The CLI test verifies exit 1 and saved evidence with `--max-steps 4`. Final compact stdout is saved beside the full evidence as `summary.json`. Eight consecutive turns without a successful Store action constitute a stall; exhausting a smaller step budget is separately reported as `budget_exhausted`.

README/spec/task-board changes belong to the orchestrator and were not edited within this worker scope.

`steps` counts simulated scheduled turns (including waits and rejected purchases); `counts` counts successful Store operations by action type. A `wait` trace entry is a scheduler observation with an unchanged world, not a Store/API action. These are simulated operation counts, not human latency or play-duration estimates. Test elapsed seconds describe verification runtime only.
