# T-014 — M2 shared self-service and governance domain

ROLE: Orchestrator-owned implementation task
AGENT: Codex orchestrator using local repository tools
ID: T-014

## Goal

Implement the shared M2 domain/API foundation required by AC-09–12 and AC-21–23 before feature UI is connected.

## Why

RD, Ops and Admin must operate on one persisted state machine with the same IDs, capacity projection, policy evaluator and audit history. Page-local fixtures would violate INV-01–03 and INV-06.

- `platform/dim-gate/src/demo/**`

- focused tests under the same paths
- generated `platform/dim-gate/docs/openapi.json`
- this task/report and the dim-gate PLAN/STATUS records

## Out of scope (must not touch)

- RD/Ops/Admin feature pages and route rendering
- real cloud APIs, credentials, deployment or paid services
- M3 pipeline/release and M4 observability behavior
- sibling components or direct writes to `main`

## Definition of done

- [ ] M2 seed and explicit M1 snapshot recovery are versioned and tested.
- [ ] Catalog/request/job reads and commands enforce scope, state, version and idempotency.
- [ ] Approval reservation is atomic; cancel/reject/failure release capacity; success creates one environment/CI/placement.
- [ ] Provision failure and retry reuse environment/CI identity and increment job attempt.
- [ ] Admin access/navigation/catalog/model commands enforce AC-21–23 refusal cases and policy invalidation.
- [ ] OpenAPI marks implemented M2 operations executable without changing M3/M4 planned operations.
- [ ] M1 regression plus focused M2 tests pass.
