# T-016 — M2 Admin governance UI

ROLE: Orchestrator-owned implementation task
AGENT: Codex orchestrator using local repository tools
ID: T-016

## Goal

Connect the accepted T-014 governance APIs to usable Admin access, navigation, catalog, CMDB model and audit routes required by AC-21–23.

## Inputs read first

- `platform/dim-gate/docs/sdd/01-product-ux.md`
- `platform/dim-gate/docs/sdd/04-permissions-admin.md`
- `platform/dim-gate/docs/sdd/05-frontend-architecture.md`
- `platform/dim-gate/docs/sdd/06-api-mock.md`
- `platform/dim-gate/docs/sdd/07-delivery-validation.md`
- `platform/dim-gate/docs/M2-INTEGRATION-CONTRACT.md`

## Scope

- typed Admin/governance client and query families
- `src/features/admin/**`
- Admin route registry/composition and dynamic navigation label/order/enabled projection
- focused client/component tests and production browser journeys
- T-016 report plus PLAN/STATUS checkpoint metadata

## Out of scope

- arbitrary permission codes, URLs, scripts, required custom fields or identity-field mutation
- M3/M4 UI and behavior, real integrations, deployment, paid services or direct `main` writes

## Definition of done

- [ ] Admin can inspect users/assignments, grant/revoke valid scoped roles, and enable/disable another user.
- [ ] Self-modification and last-enabled-Admin operations surface explicit refusal without stale-policy leakage.
- [ ] Navigation edits affect only registered label/group/order/enabled metadata; recovery entries cannot be disabled and permission guards remain fixed.
- [ ] Catalog draft revision, edit, publish and disable flows preserve immutable submitted snapshots.
- [ ] CMDB custom fields are optional-only, core keys/type mutation are refused, and metadata can be hidden/renamed.
- [ ] Admin audit shows safe mutation history with filters and no raw payload/credential content.
- [ ] Focused tests, full native gates and production Chromium governance journeys pass.

## Budget

One orchestrator implementation/evaluation cycle before integrated M2 review.
