# Captured fixture raw-field readback

This is read-only source/schema verification following root's actual capture attempt2, not a new PG runtime test.

- V2__identity.sql restricts cms_principal.status to lowercase active/disabled/locked. JdbcIdentityStore insert/update writes principal.status().wire(), and PrincipalStatus.wire lowercases the enum. RecoveryInventory does not uppercase or normalize it. Therefore exact raw active is required. Annex uppercase ACTIVE names the semantic state, not the serialized row value.
- cms_principal.id is UUID; username is VARCHAR32 constrained to lowercase ASCII username syntax. PrincipalAdminService normalizes to lowercase, and the captured username is compared to the actual API login identity supplied in memory.
- failed_login_count is INT NOT NULL; Inventory casts every scalar column to text, so zero is exactly string '0'. locked_until and deleted_at are nullable TIMESTAMPTZ; JDBC getString preserves SQL NULL as null, rather than literal 'null'.
- cms_session.id/principal_id are UUID. token_hash is BYTEA UNIQUE, generated by SessionTokens SHA256 of UTF8 token bytes. Inventory sets bytea_output=hex, so exact backslash-x followed by64lowercasehex matches Node's UTF8 SHA256. No live DB query or token-hash file channel was added.
- created_at/expires_at are TIMESTAMPTZ and revoked_at nullable TIMESTAMPTZ. Inventory sets timezone UTC and DateStyle ISO,YMD before selecting column::text. The existing parser accepts PG space separator, optional up-to6fractional digits and +00 offset; the new positive regression includes microseconds. Creation must not be future; expiry must remain future at derivation; revoked_at must be null.
- cms_entry.id, cms_entry_revision.entry_id and cms_media.id are UUID. V3 revision_no is INT with unique(entry_id,revision_no); Inventory's text representation of revision1 is exactly '1'. Existing fixed entry/media IDs and revision lookup match those names/types. Inventory uses table names cms_principal/cms_session/cms_entry/cms_entry_revision/cms_media unchanged.

No further concrete field/type mismatch was found. The prior T144 report's statement that raw principal status was uppercase was incorrect; this schema-backed correction supersedes it. HTTP and raw stored status are both lowercase active, while the Java enum constant is ACTIVE. No broader input normalization or relaxed inactive-state acceptance was added.
