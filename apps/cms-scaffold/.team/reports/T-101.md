## Summary

Implemented P0-DATA within the amended T-101 scope. All nine EntryService database mutations execute through the JDBC store transaction, which shares the DataSource-bound connection with JDBC media and identity stores. Updates atomically check the previous version and advance it by one; purge atomically checks the read version before cascading content deletion, clearing attachments, and inserting audit. Publish claims the version before inserting its revision, and unchanged publish remains idempotent. PATCH still accepts omitted version and rejects explicitly stale versions. Revert validates and rebuilds working refs and attachments while preserving the published payload.

Published attachment indexes contain the deduplicated union of working and published media. Publish, unpublish, archive, restore, patch, and revert synchronize it within the entry transaction. Public media access requires an enabled content type, an enabled public media field, and that exact field's media UUID in publishedPayload. Added shared memory/JDBC CAS and stale-delete regressions; real PostgreSQL rollback/race/state/media tests; extended the existing media HTTP journey through draft changes, publication, and revision restoration.

The initial broad development run had six fixture failures (invalid hyphenated type key, null required media owner, and expected timestamps with more precision than PostgreSQL stores). Corrected the fixtures without weakening persisted-field comparisons; final complete gates have zero failures and zero skips.
