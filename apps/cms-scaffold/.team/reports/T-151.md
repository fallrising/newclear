### Java, Ready/Permit/Result and provenance

`RecoveryInventoryMain.java:128` and `RestoreSessionRevoker.java:107` validate only releaseId digest syntax. Both parse canonical request bytes, hash the complete request, emit Ready.requestSha256, and require Permit.operationId/requestSha256/backendSha256/action to match before reading/mutating. The host `runJdbcHandshake` at helper289 onward likewise binds Ready and Permit to the complete request. This protects byte binding but cannot make an image-valued releaseId compliant; both ends consistently hash the wrong request.

Wave217–220 defines Ready and inventory/revoke Result schemas without direct releaseId. **Do not add releaseId fields to Ready, Permit or Result.** Correct host request generation and independent private-authority verification; the existing canonical request hash then carries the correct release transitively. Java currently has no independently supplied inspected JAR identity in this protocol, so the observed format-only check does not authorize a new Java schema/JAR-probe requirement. Preserve exact helper image, JAR label/source/base image and side immutable-inspection checks: image identity and JAR release identity are complementary.
