# PP1 owner 環境操作清單

2026-10-09。配合[PP1施工圖](../waves/PP1.md)；目前 DRAFT，不是部署 runbook，也不代表正式環境可用。本頁公開版本只有變數與示意域名；實際資產識別與回覆保留私有操作紀錄。

## 本地先行（2026-10-09追加）

Owner已授權先在本地跑並按建議處理。Codex先在新的隔離Compose project與DB／media資料中完成實作及本地驗證；既有資料不搬移或覆寫。目前不需要owner提供正式主機才能繼續。本地以四個 `.cms.test` HTTPS origin、容器範圍CA信任與私有DB網路驗證；不修改主機信任庫。第二個本機加密目錄只算受保護本地副本，不算離機；通知capture也不算外部送達。下面盤點移至正式環境準備時執行，不是本地施工的前置。

## 已批准，不需再選

- 單站、個人／內部少量內容；允許維護停機。
- 使用新的正式 DB／媒體卷，不帶 demo 帳號與內容；保留全部既有試用庫／worktree。
- 正式管理員處理治理；日常操作使用獨立限類型帳號。尚未指定公開類型時不預授anonymous通配權限。
- Front、Back、Admin、API 四個不同 origin，均為 HTTPS 且同 site。API仍是唯一session cookie host。
- 每日停寫一致性備份；目標最多24小時資料損失（RPO）、4小時恢復（RTO）；每日7份＋每週4份。這些是批准的目標，並非已達成測量。
- 先加密後送離機，金鑰需可在正式主機故障時取得；正式主機上的第二個目錄不算離機。

## 之後準備正式主機時：唯讀環境盤點

若已有預定 Linux 主機，請在**那台主機**執行下列唯讀指令。沒有主機就回覆「主機未準備」；不要在本開發工作區執行後把結果當正式主機資料。不需安裝工具或使用sudo，不貼環境變數／secret檔／完整設定。

```sh
uname -srm
if [ -r /etc/os-release ]; then
  sed -n '/^ID=/p; /^VERSION_ID=/p; /^PRETTY_NAME=/p' /etc/os-release
fi
df -h .
if command -v docker >/dev/null 2>&1; then
  docker --version
  docker compose version
fi
for tool in nginx caddy openssl ssh scp rsync systemctl crontab; do
  command -v "$tool" || true
done
```

這些輸出只表示作業系統／可執行檔與版本是否可見。不能證明Docker daemon可用、TLS已簽發、備份目的地可寫或通知可達。若permission denied或command not found，保留原訊息，不變更主機權限。

請另外填寫下表；不知道填「未準備」，不要填假值，不貼密碼、token、私鑰。

| 欄位 | owner提供的非秘密資料 |
| --- | --- |
| 主機 | 預定主機是否存在、上方盤點結果；可用磁碟及是否有獨立資料卷 |
| 入口 | 既有HTTPS代理／靜態服務名稱與版本、是否由你管理；公開或VPN／內網 |
| 網址 | 可用基礎網域及四個URL；可採 `https://front.<domain>`、`https://back.<domain>`、`https://admin.<domain>`、`https://api.<domain>` 命名，實際值不入公開Git |
| DNS／憑證 | 誰能改DNS、既有憑證簽發／自動更新方式；不需要私鑰內容 |
| 離機 | 不同主機／裝置或既有備份服務的種類、可用空間、既有傳輸／加密工具名稱版本；不假定S3，S3不在本波 |
| 金鑰 | 保管者及離線恢復途徑是否就緒；不需要提供金鑰本身 |
| 通知 | 既有email／通知管道的種類與你可管理與否；不提供登入憑證，本階段不發送訊息 |
| 停機 | 每日可停寫起始時間、時區、最長容許停機分鐘數；4小時RTO不等於每日停機窗口 |
| 類型 | 第一批要用的内容類型，以及哪些需要匿名公開；診所預約本批不啟用 |

## 確認環境後的分工

| 動作 | Codex可交付 | owner需操作／提供的證據 |
| --- | --- | --- |
| 正式入口與靜態服務 | 對既有工具產出版本固定的設定／三面建置契約與隔離測試 | 主機若尚無入口軟體，先選定具名工具與版本；新增runtime dependency需另明示批准，不能以本頁當安裝授權 |
| DNS／TLS | 精確記錄四origin與驗收命令，測試CORS／cookie／surface | 在DNS或憑證管理系統執行設定，回報非秘密結果；本階段不執行，也不宣稱TLS已驗收 |
| DB／媒體秘密 | 檔案位置、權限、缺值拒絕與不記錄秘密的設計 | 在正式主機建立秘密／資料目錄，權限與隔離配置等部署前置須待runbook封板；不把值傳給聊天或Git |
| 備份離機／金鑰／通知 | 已有工具的adapter及故障驗收、取回／解密流程 | 準備獨立目的地與金鑰保管；授權實際連線後執行端到端驗證。沒有可驗回執，不標成功 |
| 施工與隔離演練 | 文件通過審查／必要CI／合併後，依DOC_READY實作與測試 | 環境事實未齊前不要求owner自行猜命令／部署 |
| 正式部署與驗收 | 程式完成後交付精確命令和驗收表 | 原指示不部署仍有效；正式主機由owner之後操作或另明示授權，未有其證據不稱正式可用 |

## 決策與能力邊界

「按建議執行」已批准上列政策，沒有提供或證明實際主機、網域、憑證、離機位置與通知管道存在。這些是需補的環境事實，不是重問Git授權。沒有既有工具時，Codex會先給具體方案／依賴／操作步驟，等待必要選定後才生成可執行設定；不虛構可用服務。

保留策略本波先定義可刪候選集合及拒絕刪除最後可恢复集合的規則；本次不對真實備份執行刪除。排程安裝、DNS變更與正式主機服務啟動均屬尚未執行的操作。本頁唯讀盤點不能替代施工、隔離演練或正式設定驗收。
