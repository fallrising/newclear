## 4. 契約

### 4.1 指令契約

根 `package.json` 固定新增：

```json
{
  "scripts": {
    "measure:bundle": "node --test scripts/measure-bundles.test.mjs && node scripts/measure-bundles.mjs",
    "record:frontend": "node scripts/record-frontend.mjs",
    "measure:vitals": "npm run build && playwright test --config playwright.vitals.config.ts vitals-w5.spec.ts",
    "test:a11y": "playwright test --config playwright.quality.config.ts axe-w5.spec.ts",
    "test:visual": "playwright test --config playwright.quality.config.ts visual-w5.spec.ts",
    "test:hardening": "playwright test --config playwright.quality.config.ts hardening-w5.spec.ts"
  }
}
```

Playwright 的 positional argument 一律是各 config `testDir` 內的檔名，不得傳 `e2e-quality/...` 給 `playwright.mock.config.ts`。`measure:bundle` 必須確認三個 `dist/.vite/manifest.json` 存在且比各 app `src` 中最新檔案新；否則 exit 2。其他失敗 exit 1，成功 exit 0。

### 4.2 輸出契約

所有產物放在已 gitignore 的 `test-results/frontend/`：

| 指令 | 必須產生 |
| --- | --- |
| `measure:bundle` | `bundle.json`、stdout 三列 |
| `measure:vitals` | `vitals.json`、Playwright HTML／trace（失敗時） |
| `test:a11y` | `axe.json`，每頁 violation 數 |
| `test:visual` | Playwright diff；baseline 本身在 §3 的 snapshots |
| `e2e:mock` | Playwright report；總數 92 |
| `npm run e2e` | `real-e2e.json`，不得含密碼、cookie、CSRF |

共同 JSON envelope：

```ts
interface FrontendMeasurement {
  schemaVersion: 1;
  measuredAt: string; // UTC ISO-8601
  gitCommit: string;
  dirty: boolean;
  node: string;
  chromium: string | null;
  command: "measure:bundle" | "measure:vitals" | "e2e:mock" | "test:visual" | "e2e";
  artifact: string; // test-results/frontend/ 下的相對路徑
  result: "passed" | "failed";
}

type BundleMeasurement = FrontendMeasurement & {
  command: "measure:bundle";
  apps: Array<{recordId:string; app:"front"|"back"|"admin"; roots:string[]; closureKeys:string[];
    files:Array<{file:string;gzipBytes:number}>; total:number; limit:number; delta:number; notes:string}>;
};
type VitalsMeasurement = FrontendMeasurement & {
  command: "measure:vitals";
  samples: VitalSample[]; // 五個 target 各 5 筆，正好 25 筆
  summaries: Array<{recordId:string; surface:"front"|"back"|"admin"; url:string;
    viewport:"1280x800"; networkCpu:"150ms/1.6Mbps/750Kbps/4x"; runs:5;
    medianLcpMs:number|null; maxLcpMs:number|null; medianCls:number; maxCls:number;
    limits:string; routeLog:string; notes:string}>;
};
type MockMeasurement = FrontendMeasurement & {
  command:"e2e:mock"; recordId:string; repetition:1|2|3; playwright:string;
  passed:number; total:92; axePassed:number|null; axeTotal:60|null;
  critical:number|null; serious:number|null; notes:string;
};
type VisualMeasurement = FrontendMeasurement & {
  command:"test:visual"; recordId:string; os:string; desktopCases:52; mobileCases:15;
  stateCases:3; threshold:0.2; maxDiffPixelRatio:0.001;
  hashManifest:string; authorization:string; notes:string;
};
type RealMeasurement = FrontendMeasurement & {
  command:"e2e"; recordId:string; attempt:number; os:string; jdk:string;
  dockerCompose:string; stack:string; passed:number; total:14;
  durationSeconds:number; exitCode:number; failureClass:string; notes:string;
};
type FrontendRecordInput =
  | BundleMeasurement | VitalsMeasurement | MockMeasurement | VisualMeasurement | RealMeasurement;
```

每個專用檔必須符合上列唯一 union member；數值保存原始 bytes／milliseconds／score，不只保存格式化文字。`recordId` 必須符合 `W5-<kind>-YYYYMMDD-NN`，日期取 `measuredAt` UTC 日，`NN` 由該表既有最大序號加一；同一輸入內依 row 順序遞增且不可重複。首次空表從 `01` 開始；recorder 不讀或改 Markdown，因此執行者在產生 JSON 前先讀對應表尾決定起始序號。`record-frontend.mjs <file>` 只讀 JSON、驗 discriminated schema、固定數量與門檻、按陣列順序印 Markdown row；人員將 stdout 逐字追加到正確表格。

`scripts/record-frontend.mjs` 的 API 固定：

```ts
export function validateEnvelope(value:unknown): FrontendMeasurement;
export function rowsFor(value:FrontendRecordInput): string[];
export function formatCell(value:unknown): string;
export async function main(argv:string[]): Promise<void>;
```

`main` 只接受一個 JSON path；0 或 2 個參數 exit 2。`formatCell` 把 `|` escape 成 `\|`、換行改空格；`rowsFor` 依 `command` 判別上列五種 schema，不認得、欄位缺少、數量錯誤、record id 不連續或數值不符固定值就 throw。Bundle 輸出 3 rows、Vitals 5、其餘各 1；函式不得開啟或修改 Markdown。`record-frontend.test.mjs` 固定測 missing arg、invalid envelope、五種 valid schema、每種各一個 missing-field 反例、錯誤 row count、重複 record id、pipe/newline escaping。

三個 quality spec 的檔內 helper 固定：

```ts
// axe-w5.spec.ts
async function scan(page:Page,id:string):Promise<AxeRow>;
async function writeAxe(rows:AxeRow[]):Promise<void>;
// visual-w5.spec.ts
function assertUpdateAuthorized(argv:readonly string[],env:NodeJS.ProcessEnv):void;
function snapshotName(id:string,viewport:string):string;
// hardening-w5.spec.ts
function forbiddenEngineeringText(text:string):string[];
```

三檔只能 import `pages`、`states`、`openCase`、`prepares`、`settle`；不得複製另一份 route 清單。

### 5.1 bundle 腳本

三個 `vite.config.ts` 都加入精確設定 `build: { manifest: true }`，不得自訂 manifest 名稱；輸入固定是 `<app>/dist/.vite/manifest.json`。

`scripts/measure-bundles.mjs` 匯出並只用下列 API：

```ts
export interface ManifestChunk {
  file: string;
  isEntry?: boolean;
  imports?: string[];
  dynamicImports?: string[];
}
export function staticClosure(manifest: Record<string, ManifestChunk>): string[];
export function gzipFile(path: string): number;
export function measureApp(app: { name:string; root:string; limit:number }): AppBundleResult;
export function measureAll(): FrontendMeasurement & { apps: AppBundleResult[] };
export async function main(): Promise<void>;
```

`staticClosure` 的算法固定：

1. roots 是 manifest 中所有 `isEntry === true` 的 key；沒有 root 就 throw。
2. 對每個 root 做 depth-first traversal；把該 key 的 `file` 加入 `Set`。
3. 只遞迴 `imports ?? []`；每個 import 值必須是 manifest key，不存在就 throw。
4. 完全忽略 `dynamicImports`、`css`、圖片與字型。
5. cycle 由 visited key 截斷；相同 `file` 只計一次。
6. 回傳 `file` 以字典順序排序。這是 Vite entry 的完整 static import closure；Rollup manual chunk 仍會出現在 `imports`，不能逃避預算。

`gzipFile` 對每個 closure JS 檔各自 `gzipSync(readFileSync(path), {level:9})`，`measureApp` 加總各 HTTP asset 的 gzip bytes；不得把檔案串接後只 gzip 一次。1 KB = 1024 bytes；Front limit `92160`，Back／Admin `163840`。等於通過，多一 byte 失敗。JSON 每 app 保存 roots、closure keys、每檔 `{file,gzipBytes}`、total、limit、delta。

`measure-bundles.test.mjs` 用 `node:test` 固定六例：single entry、transitive imports、shared import dedupe、cycle、`dynamicImports` excluded、manual vendor chunk included；另測 missing import throw、exact limit pass、one byte over fail、manifest missing／stale exit 2。`npm run measure:bundle` 先跑 `node --test scripts/measure-bundles.test.mjs`，再 `main()`。

### 5.6 real API e2e

real API 只使用這三個 spec：`e2e/front.spec.ts`、`e2e/back.spec.ts`、`e2e/admin.spec.ts`；不得新增第四個 real spec。

`playwright.config.ts` 固定 `testDir:"./e2e"`、`testMatch:["front.spec.ts","back.spec.ts","admin.spec.ts"]`、`globalSetup:"./e2e/global-setup.ts"`、workers 1、retries 0、locale `zh-TW`、timezone `Asia/Taipei`，reporter 同時是 `list` 與 `json`（output `test-results/frontend/real-results.json`）。

`e2e/helpers.ts` 保留 URL 常數，exports 精確為：

```ts
export function seedPassword(username:string):string;
export async function login(page:Page,origin:string,username:string):Promise<void>;
export async function expectHeading(page:Page,name:string|RegExp):Promise<void>;
export async function waitForHttp(url:string):Promise<void>;
export function redact(text:string,secrets:readonly string[]):string;
```

`seedPassword` 只接受 `CMS_E2E_PASSWORD`，未設才讀 `CMS_E2E_PASSWORD_FILE ?? "local/seed-passwords.txt"`；刪除 `CMS_SEED_PASSWORD` fallback。`waitForHttp` 每 500ms GET，60 秒後 throw。`redact` 依序替換密碼、`cms_session` cookie value、`X-CSRF-Token` value、`Authorization` value 為 `[REDACTED]`。

`global-setup.ts` 依序 `waitForHttp(API+"/actuator/health")`、`waitForHttp(FRONT)`、`waitForHttp(BACK)`、`waitForHttp(ADMIN)`；任何失敗阻止 spec。

`e2e/run.sh` 固定順序：

1. `set -euo pipefail`；建立 `test-results/frontend/real-e2e-logs`。
2. 若 `CMS_E2E_PASSWORD` 未設且 `local/seed-passwords.txt` 不存在，exit 2，不啟動 Compose。
3. `docker compose -f compose.yaml down -v --remove-orphans`，再 `up -d --wait --build`。
4. 用 host Chromium；缺 browser／library 時沿用既有 `mcr.microsoft.com/playwright:v1.63.0-noble` fallback，傳入的 secret 只有 `CMS_E2E_PASSWORD` 與 password file path。
5. 執行 `npx playwright test --config playwright.config.ts front.spec.ts back.spec.ts admin.spec.ts`，保存 exit code。
6. trap 中執行 `docker compose logs --no-color`，以 `helpers.ts` 同一組 regex 的 shell 等價式 redact 後寫 `compose.log`；再 `docker compose down -v --remove-orphans`。
7. 從 JSON reporter 寫 `real-e2e.json` envelope、passed、failed、duration、exitCode；不得含 stdout body、cookie 或 header。以原 Playwright exit code 結束。

三個 spec 的測試與順序固定：

| spec | 順序與 title |
| --- | --- |
| `front.spec.ts` | 1 `W5 real Front selector and three public sites`；2 `W5 real Front album wall uses web image and dimensions`；3 `W5 real Front draft is NotFoundPublic without engineering copy`；4 `W5 real Front clinic vets hide draft`；5 `W5 real Front projects hide private and expose milestones`；6 `W5 real Front member login opens owned dashboard` |

每個檔 `test.describe.configure({mode:"serial"})`；每個 test 自己登入，不依賴前一 test 寫入。定位只能用 W1～W4／W3b 已定 role＋name 或 `data-testid`；若現有畫面沒有表中需要的 locator，停止本波請 owner 修訂，不能自行選替代 locator。

```bash

```

## 7. 測試規格

### 7.1 bundle

| 測試名 | 前置 | 斷言 |
| --- | --- | --- |
| `W5 bundle follows transitive static imports` | entry→shared→vendor | 三檔都計入 |
| `W5 bundle deduplicates shared imports and cycles` | 兩 entry 共用 shared，shared 回指 | 每 file 一次 |
| `W5 bundle excludes dynamicImports` | entry 同時有 imports／dynamicImports | 只計 imports |
| `W5 bundle includes manual chunks` | entry imports `vendor` manifest key | vendor 計入 |
| `W5 bundle rejects missing import key` | imports 指向不存在 key | throw，exit 1 |
| `W5 bundle accepts exact limits` | 產生剛好 90／160 KiB gzip fixture | exit 0 |
| `W5 bundle rejects one byte over` | 超過一 byte | exit 1，仍寫 JSON |
| `W5 bundle rejects missing or stale build` | 無 dist／mtime 舊 | exit 2 |
