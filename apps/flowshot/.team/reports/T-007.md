**P1 decisions before the affected slices**

1. **PathGuard race mechanism and OS support.** SPEC §8 already requires component containment, no symlinks, no-follow handles, post-open identity/size/mtime checks and at most two retries. A canonicalize/check followed by path-based open, even with final-component `O_NOFOLLOW`, cannot protect an intermediate-directory swap. Select a safe handle-relative traversal/read/listing mechanism for Linux/macOS/Windows, with deterministic race hooks and explicit unsupported-platform failure. Workspace Rust forbids unsafe code; a vetted safe OS wrapper may need a pinned dependency. Define root-handle lifetime/revalidation and selected-root symlink-alias policy. Limits must be enforced while reading, not only from initial stat. Initial attempt plus two retries is the natural §8 reading, not an unresolved reason to lower the oracle.

2. **Directory pagination versus scanning.** N02 prohibits reading/rendering every entry at once while requiring global directory-first/name sorting. OS iteration order cannot directly supply that ordered first page without enumeration/indexing. Specify bounded per-directory snapshot construction, or explicitly distinguish bounded-memory enumeration from prohibited eager loading; do not silently weaken the node. Freeze cursor identity, mutation/staleness behavior, expiry/cache bounds and query binding. Define Unicode name ordering/tie-breaks, filesystem case behavior and non-UTF-8 filename handling without lossy identity collisions. SPEC already fixes default/max limits (500/1000), >2000-entry hint and lazy child access. Also define the root `rel_dir` sentinel separately from prohibited empty interior path components.

3. **Ignore/filter authority.** Gitignore syntax alone does not say whether to load root/nested `.gitignore` files or only configured `ignore_rules`, their precedence against built-ins, negation/pruning behavior, or whether global Git configuration is consulted. Freeze these and extension case handling. N02 BDD explicitly forbids bypass through direct opening: document-ID, link and asset paths must reapply current admission policy, not merely omit tree entries. Ignored/detached records and saved tabs must remain preserved with defined unavailable behavior. SPEC already distinguishes forbidden direct `..` from permitted normalized parent-relative hrefs; traversal tests must not reject that valid href case. One decode, encoded-separator/double-decode rejection and same-root confinement are settled.

4. **Canonical bytes and render semantics.** Freeze SHA-256 lowercase/encoding behavior: `sourceHash` covers original UTF-8 bytes before CRLF/NFC/front-matter processing, while `canonicalHash` covers final canonical UTF-8. Preserve raw source through IPC, including a BOM policy. `buildDocumentModel(source): DocumentModel` is synchronous; WebCrypto digest is asynchronous. Choose pinned synchronous pure hashing or explicitly revise/freeze that signature. Define the remaining canonicalization table: nested block/list/table-cell separators, leading/trailing whitespace, image/alt/placeholder text and synthetic separators. Asset loading must not change the canonical model for identical source. `TocItem` fields and exact heading slug/duplicate behavior also need freezing.

5. **DOM/security mapping order.** SPEC answers NFC, prose/code whitespace, UTF-8 half-open offsets, deterministic AST-based IDs, optional source hints and no second Rust Markdown parser. It does not define sanitizer/highlighter/segment ordering or DOM metadata for UTF-16 offsets, collapsed whitespace, NFC composition and split syntax leaves. Freeze leaf granularity and canonical offset attributes after transformations; source hints cannot substitute for this mapping. Raw HTML needs an explicit tag/attribute/URL policy, including hidden text/style behavior and trusted generated metadata versus user-injected attributes. Local/remote images, raw HTML URL attributes and code highlighting must not bypass controlled React adapters. Current `tauri.conf.json` permits `img-src 'self' data:` and lacks `blob:`; M1 must align it with §11.2, revoke Blob URLs and avoid adding remote origins.

6. **Tab state transaction/version contract.** N04 has `entries` but only one optional `expected_updated_at`; N01 CAS tokens are per key. Choose per-entry expected/returned tokens with atomic batch behavior, or one versioned session envelope. Existing values require CAS; missing values use explicit creation semantics. Specify scope/key layout, schema/backward migration and newer-version errors retaining original JSON. Reject duplicate keys/invalid IDs/nonfinite scroll values; define conflict/retry behavior without silently overwriting another writer. Pick a JS-safe token representation rather than accidentally rounding allowed SQLite i64 extremes. Consistent multi-key loads must not assemble different saved generations.

7. **Close/restore semantics.** Specify window-close versus application-exit flush, cancellation/barrier and write-failure behavior; asynchronous `beforeunload` alone is not a persistence guarantee. Serialize debounce/in-flight saves and return authoritative timestamps. Define per-workspace tab membership, active-tab fallback after close, empty state, missing/detached tabs and delayed render/fragment versus saved-scroll precedence. A failed save must retain current UI state, and a newer unknown schema must not be overwritten. SPEC already fixes document UUID identity, post-model scroll clamping, active-first lazy restoration and nonblocking error feedback.
