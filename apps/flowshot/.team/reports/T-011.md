**P1 — failed root admission can leave committed active state.** `src-tauri/src/workspace/service.rs:338–381` creates or reactivates the root inside a DB transaction, commits it, then calls `guard.revalidate()` outside that transaction. If the selected directory is replaced between initial capability acquisition and final validation, the request fails but the new/reactivated active root remains committed. This defeats atomic admission and can leave an unchecked replacement path active for later operations. Validate the captured capability inside the writer transaction before returning successfully, so detected instability rolls back all admission/reactivation state. Add a deterministic root-admission swap hook and assert error plus unchanged roots/documents. Filesystem mutation after a successful completed operation is a separate grant-lifetime question; this finding concerns the existing detected-error path.

**P2 — cursor validation and enumeration use different directory snapshots.** `service.rs:401–423` captures/validates an initial stamp, but `429` discards the stamp returned by `Guard::entries`; `475` encodes the earlier one. Mutation between initial validation and enumeration can therefore produce a successful page from a different snapshot and immediately stale continuation. Existing cursors can skip/duplicate relative to the previous snapshot without the required conflict. Compare the scan's returned stamp to the initially validated stamp before DB identity updates/response; a deterministic between-check-and-scan mutation must return retryable conflict, not a successful page. Mutation during enumeration is already checked by `path_guard/unix.rs:214–216`.

**Authority decision — picker grant is not enforced by this command.** ADR-003 says the native picker grants the selected root. In the inspected code, `nativeApi.ts:5` asks the plugin for a path, then `add_workspace_root` accepts an arbitrary caller `selected_path`; service `294` canonicalizes it without validating any native selection record/token. A direct invoke can create a workspace, register any readable directory and then read its Markdown without a picker choice. If picker selection is intended as a security boundary, enforce it natively (or validate a native grant) and add a negative direct-invoke test. If the trusted frontend is intentionally allowed to grant arbitrary paths, state that trust model explicitly rather than claiming picker-enforced access. No exploit or dialog execution was performed here; this is a source-proven absence of grant checking, with severity dependent on the intended authority claim.

**Other correctness/contract follow-ups:**

- Reattachment (`service.rs:349–352,374–375`) matches detached roots only by canonical-path string and ignores newly supplied extension/ignore policy. Preserve identity on case-insensitive filesystem aliases using actual directory identity where required; explicitly define whether reattachment retains old policy, applies explicit new policy, or rejects changes. Do not silently accept a stricter policy request and activate old rules. Test detach/reattach through a case alias on a case-insensitive filesystem; Linux-only case-sensitive results cannot prove that behavior.
- Context acquisition rechecks current admission at operation start; final open/link/asset checks only active status (`557`, `589`, `611`), while listing also compares policy. No public policy-update API currently exists, so a mid-operation policy-change exploit was not demonstrated. If root editing/reattachment can change rules, include policy generation/equality in final admission checks before returning bytes.
- N02 `nativeApi.loadWorkspaceAsset` returns an owned Blob URL/revoker, whereas ADR-002 Reader expects an abortable Blob loader and owns URL lifecycle. Root must reconcile this composition explicitly, preferably passing admitted bytes as Blob to Reader; avoid duplicate URL ownership or a fetch-back workaround. This is an integration risk, not evidence of a current file/network escape.

**Positive security findings:** `path_guard/unix.rs` opens `/` then canonical-root components as no-follow directory handles, traverses child components with no-follow handles, and opens final files read-only/no-follow/nonblocking. Reads reject nonregular handles, check stat size, use limit+1, compare handle metadata before/after and current entry identity/type plus parent/root identity, retrying only retryable instability for at most three total attempts. There is no path-string ambient reopen after validation. Root aliases are canonicalized only during admission; child symlinks are unavailable. FIFO rejection uses nonblocking open before regular-file verification.

Pure direct paths reject absolute/parent/empty/NUL/backslash components. Hrefs have a separate one-decode path, reject encoded separators/double decoding/schemes and normalize legal parent-relative paths within the same root. Document-ID/link/asset service paths go through active-root and ancestor/target ignore admission. Image reads enforce 10MiB and four magic signatures, then return raw Tauri response bytes; source opens enforce strict UTF-8/20MiB and return original source plus observed hash separately from committed model hashes/revision. Optional mtime is checked into a nonnegative value or None. Additive `ensure_document`/observation do not rewrite committed hashes/revisions; immutable migration SQL is unchanged in the inspected diff.

Root overlap checks run in the writer transaction and compare component paths plus actual ancestor identities, without unconditional lowercasing. A static process admission mutex also serializes service admissions. Directory enumeration streams one level with a limit+1 heap, directory-first Unicode name/path ordering, no child recursion/body reads, skipped invalid-UTF8 count and query/policy/identity/timestamp-bound cursors. Recent/workspace queries are bounded and numeric persistence values become decimal strings in DTOs. These are source observations, not proof of the operation-level races noted above being fixed.

The latest configured `/**` extension inserts its companion directory rule at the original rule position and checks every ancestor; built-ins are unnegatable. Source tests distinguish descendant-only versus explicit parent negation and escaped patterns.
