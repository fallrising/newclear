# ADR-003 — Workspace read boundaries and bounded directory pages

Status: accepted for implementation, 2026-10-23. Authority: N02 revision 2, SPEC §§7/8/10/11. T-007 exposed decisions required before filesystem access. Preserve read-only source handling and all original security/performance oracles.

## Paths and stable reads

Use safe `rustix` handle-relative filesystem APIs on Linux/macOS. Open the canonical root as a directory capability, then each relative component with no-follow directory handles, and final regular files with read-only/no-follow flags. A final-file `O_NOFOLLOW` on a path string is insufficient. No unsafe Rust or ambient fallback after validation. Unsupported platforms compile to an explicit safe unavailable error until a native equivalent is implemented; Windows remains architecturally portable, not a v1 acceptance target.

The native picker grants a selected root; canonicalization may resolve its selected absolute alias before freezing the canonical root. Child symlinks are always displayed as unavailable and never followed. Reject direct absolute/parent/NUL/empty-interior components; the empty `rel_dir` alone denotes root. Markdown hrefs use the distinct SPEC one-decode/source-relative normalization rule, rejecting encoded separators, double encoding and schemes. Revalidate active-root state/current ignore policy for document-ID, link and asset access.

For each operation, acquire/revalidate the root capability, walk from it with no-follow handles and compare the final handle identity/size/mtime before and after a bounded read; also check the current relative entry resolves to that same identity. If a component/entry is swapped, fail or retry from root, never fall back to ambient path reads. Initial attempt plus at most two retries; only retryable instability is retried. Test deterministic intermediate-directory and final-file swaps, not only static symlinks. Enforce file size during reading with limit+1, not just stat; reject nonregular targets so FIFOs/devices cannot block or leak data. Store unknown/pre-epoch mtime as absent via an additive typed observation API; native stable-read comparisons retain actual filesystem timestamps.

## Directory order and cursors

Global directory-first/name ordering requires enumerating the current directory's names. Clarify the memory/laziness requirement: stream only this single level, retaining at most limit+1 matching keys in a bounded selection structure; do not materialize all entries, recurse, read bodies or cache an unbounded snapshot. Ordered pages are directory first, then other entry kinds, Unicode scalar/codepoint name order with full relative-name tie-break. Invalid UTF-8 names are not coerced into colliding identities; skip them with an explicit unsupported-name count. Each page is limited to default500/max1000, and >2000 visible entries yields the required UI hint.

Use stateless versioned keyset cursors bound to root/directory/filter/ignore query, directory identity and modification/change timestamp, plus the last ordering key. Validate all fields and reject stale/mismatched cursors with a retryable conflict; clients restart the page. Check directory identity/timestamps around enumeration so a detected mid-scan mutation is not presented as a stable page. No server cache or arbitrary cursor-directed path reads. The 5000-file first-page <500ms oracle remains unchanged, with traces proving unexpanded children/body files were untouched.

## Ignore and root identity

Interpret configured `ignore_rules` with gitignore pattern/negation semantics using the pinned ignore library, relative to each root. Built-in excluded components (`.git`, node_modules, target, dist, .DS_Store) are always excluded; user negation cannot re-enable these. Do not implicitly read global Git configuration or on-disk .gitignore files: those are outside the current explicit configuration contract. Extension filters use ASCII-insensitive suffix comparison, default md/markdown/mdx. Ignore checks apply to every ancestor and the target; excluded parents remain pruned. Assets use the same ignore/root admission policy but their own MIME whitelist instead of the Markdown extension filter.

Canonical equal/ancestor/descendant roots in one workspace are rejected atomically. On case-insensitive filesystems use actual filesystem identity and ancestor identities in addition to component paths, never lowercase every path unconditionally. Detached roots retain all metadata and may be reattached through the same identity-preserving admission checks. Add typed deterministic bounded workspace/root/recent queries and idempotent document identity ensure; repeated tree/link access must not overwrite committed document hashes/revision. No immutable schema/trigger migration changes.

## Contracts and integration ownership

All commands retain one request object, Rust-authoritative DTOs, existing AppError shape and redacted correlation/duration/result logging. IDs remain UUID strings; i64/u64 persistence tokens returned to JavaScript are decimal strings to prevent precision loss. Directory entries contain stable document UUID only for admitted Markdown files. Open returns unchanged original UTF-8 source plus observed hash and committed snapshot/revision; reading never commits a new model version.

`read_workspace_asset` success is raw binary `tauri::ipc::Response`, received as `ArrayBuffer`, never JSON number arrays or filesystem URLs. Bytes are unmodified admitted PNG/JPEG/GIF/WebP data after magic validation and the 10MiB limit. The typed client explicitly marks binary transport; its adapter infers the Blob MIME from the same four fixed magic signatures (presentation validation, not a second filesystem authority). Errors remain AppErrorDto. Test real raw transport framing separately from JSON command goldens. No custom asset protocol or second metadata round trip is required.

Extend the existing generator with explicit multi-command declarations/wrappers and node-specific lock ownership. Existing get_build_info DTO/wrapper behavior remains stable; N00's lock checks its own command set, not every downstream registered command. Update registry-source fingerprints and N01 additive API fingerprints with retained old evidence; do not disable lock checks. Root owns App composition; N02 supplies a standalone workspace/tree component with injected directory-picker/open callbacks. Native dialog plugin is registered with only open-directory permission; frontend receives no filesystem capability. CSP changes from data images to `img-src 'self' blob:`. External URL opening is integrated later through an allowlisted OS opener only on user action.

Exact dependency candidates verified from official crates.io metadata: rustix1.1.5 (`fs`), ignore0.4.33, tauri-plugin-dialog2.7.3 (`tauri ^2.10`, compatible with pinned2.11.5). Reuse existing pinned sha2/uuid/serde/serde_json/percent-encoding/base64 where needed. Current dialog2.8.3 and opener2.7.2 require Tauri2.12 and are deliberately not selected; later opener2.5.5 supports ^2.10. Cargo alone resolves/generates the lock. Sources: [rustix openat](https://docs.rs/rustix/latest/rustix/fs/fn.openat.html), [Dir](https://docs.rs/rustix/latest/rustix/fs/struct.Dir.html), [Tauri dialog](https://v2.tauri.app/plugin/dialog/), [binary IPC](https://docs.rs/tauri/latest/src/tauri/ipc/channel.rs.html). Inspect pinned local source before relying on version-specific APIs.

`list_workspaces` accepts optional cursor/limit and returns bounded joined rows `{workspace, root|null}`. Empty workspaces receive a null-root row; clients group by workspace UUID across page boundaries. Sort/cursor uses workspace ID then root ID (explicit null sentinel). This exposes existing roots without a new command or unbounded nested arrays; tests cover empty workspaces and roots split across pages.

### Explicit directory-pruning rule

Pinned `ignore` 0.4.33 confirms that `drafts/**` alone matches descendants but not the directory entry, whereas N02's BDD requires the `drafts` directory to disappear. The configured workspace policy therefore explicitly adds a directory-pruning interpretation for positive patterns ending in `/**`: apply the corresponding directory rule at the same rule position as the original descendant rule. This is a documented workspace policy extension, not a claim about Git's default semantics. Preserve ordered negation; a later explicit parent-directory negation can reopen traversal, but a descendant-only negation cannot reopen an already pruned parent. Built-ins remain unnegatable. Test `drafts/**`, sibling names, nested paths, escaped/literal patterns and ordered parent/child negations through both listing and direct access. Do not read any implicit .gitignore file.

### Native picker grants

The picker is a native admission boundary, not merely a UI convention. A caller-provided `selected_path` is insufficient authorization. Pinned dialog2.7.3 writes native filesystem scope grants when its optional fs-plugin state exists (inspected upstream crate `src/commands.rs`, directory branch). Register pinned `tauri-plugin-fs=2.5.2`, already in the resolved dependency graph, solely to maintain/check that native scope; grant no frontend fs permissions. Before `add_workspace_root` admits a path, native command code must reject an absent scope or a path outside the picker-populated scope. Normal restart access uses persisted admitted roots; new admission still requires a current picker grant. Direct invocation cannot create a fresh arbitrary root without that grant. Test denial/success at the command boundary and inspect the actual capability permissions. Keep PathGuard's independent canonical/no-follow/race validation after grant checking; a scope pattern is not a replacement for secure file traversal. The system dialog may grant a selected directory and its descendants; it cannot grant ancestors or siblings.

### Reattachment policy

Reattaching a detached root preserves its UUID and existing extension/ignore policy when optional policy fields are omitted. If a caller explicitly supplies a different policy, reject the request without reactivating it; v1 has no root-policy editing command. Explicit identical values are allowed. Match an existing detached root by canonical component path or actual directory identity where the stored path remains available, so case aliases on case-insensitive filesystems preserve identity. Do not lowercase names or guess moved/missing-directory identity. This decision avoids silently accepting stricter requested filters while activating older, broader rules.
