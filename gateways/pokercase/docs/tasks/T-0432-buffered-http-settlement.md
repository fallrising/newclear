## Observation design

- Reuse existing generated request/attempt IDs, store reservation/conditional finalization and startup recovery. Reserve immediately before every existing inference send, after request preparation/refresh. Do not add a parent-request usage row or log a second legacy row for the same dispatch.
- Preserve original upstream HTTP status independently from local conversion errors. Use existing fixed error classifications; never retain raw body, stderr, headers, prompts, output or credentials. A failed finalization makes one write attempt and reports its fixed failure; no retry of inference or silent replacement row.
- Observe original Chat JSON `usage.prompt_tokens/completion_tokens` or Responses `usage.input_tokens/output_tokens`. Null/missing remain absent; nonnegative i64 zero is known; negative/noninteger/overflow/nonobject usage is invalid while independently valid fields survive. Complete usage requires both valid fields; outcome is independently determined.
- Chat uses supported explicit finish reasons for all requested choices (`stop`/`tool_calls`/`function_call`: succeeded; `length`/`content_filter`: incomplete; missing/unknown/ambiguous evidence: unknown; explicit error: failed). Do not change permissive passthrough bytes just to obtain accounting evidence.
- Direct Responses uses original status/error before validation. Completed/incomplete/failed are distinct; explicitly accepted native `background:true` queued/in_progress remains unknown, with no added polling/replay. Conversion/validation failure overrides an unaccepted success observation with failed, retaining valid original counters.
- Forced-SSE observation follows existing `reassemble_sse` data-line and first-terminal rules, not a newly stricter native framing contract. Observe meaningful text/tool deltas as chunks arrive; role/ping/empty delta is not output. Observe original terminal usage even when the collector returns failure. No post-EOF parse timestamp is presented as first output. Observation is bounded by the existing collection limit, keeps no complete transcript beyond the collector's existing buffer and never changes collection or waits for extra upstream bytes.
- Forced-SSE usage snapshots stay coherent: preterminal lifecycle counters may survive an interrupted collection only as partial observations, without a complete configured estimate. The first terminal replaces both token fields and usage validity from its own original envelope, including clearing omitted fields. Never borrow one missing terminal counter from an earlier lifecycle snapshot to manufacture completeness. Match the collector's existing lossy UTF-8 and data-line rules; single-choice missing index follows the existing Chat observer's index0 convention, while multiple-choice ambiguity remains unknown.
- Direct JSON `first_output_ms=null`: there was no observable delta. `headers_ms` measures dispatch→headers, `total_observed_ms` dispatch→accepted terminal/local stop; legacy latency is not substituted for either. Forced-SSE delta/terminal timestamps use actual observation only; transport failure before buffered delivery cannot be overwritten as a client success. CLI timing remains null for HTTP.
- Preserve existing configured-rate buffered estimates only with complete valid counters and both valid prices. This is an explicit configured estimate, not a subscription bill or verified price revision. Named streaming cost remains null as previously delivered. No historic recomputation/backfill or new cost grouping.
- Keep native Responses passthrough separate from Chat conversion even when an attempt exists; preserve unknown fields, tools, background and byte layout. Settling must not force Responses→Chat→Responses.
