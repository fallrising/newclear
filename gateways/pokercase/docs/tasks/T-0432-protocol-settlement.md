## Design and ownership

Reuse StreamAttempt and the additive SQLite schema. Both converted client handlers reserve using the converted Chat request before HTTP dispatch, share a generated parent request ID across fallback and avoid legacy duplicate rows. The current generic API-key selection remains explicit; unsupported executors stay untouched. Apply the same fixed forwarding-failure/cooldown behavior as the delivered Chat path.

The existing passthrough observer scans a received transport chunk and may settle immediately at [DONE]. Blindly reusing that order before conversion could record success from bytes beyond a converter rejection. For converted streams, observe only the source prefix consumed by conversion and defer settlement until the converter's terminal disposition. Expose a small internal converter failure indicator; a local conversion failure records failed with a fixed code and preserves partial/invalid observed counters. Observe complete data lines at the same LF boundary already consumed by the converters, and flush a pending final line at EOF/termination. This retains known content finish and partial usage if a read error, stall or cancellation occurs before the blank delimiter; it does not change wire framing. Settle before yielding final output; do not retain input beyond existing bounds or poll/drain after termination. EOF/error/stall keep existing wire outcomes and known content-finish semantics. Output protocol expansion is not part of this change.
