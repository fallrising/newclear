## Design and data ownership

`usage_events` receives additive nullable attempt identity, observation time and terminal provenance fields. Existing columns/IDs remain. Reservation occurs before forwarding; one owned guard follows the selected attempt from handler into the stream and exists before its first poll. Store finalization conditionally updates an unfinalized attempt. Only server startup, while holding an exclusive file lock beside the database for the server lifetime, recovers leftover reservations without dispatch; ordinary `Store::open` never recovers live work. A second server for that data directory is rejected with `usage_store_in_use`. Historical rows are never relabelled successful from HTTP200.

Observe original upstream bytes before any output or conversion; this slice uses passthrough only. Retain at most one bounded SSE event, parse CR/LF/CRLF and arbitrary byte splits, and retain only counters/booleans/timestamps between events. A bound/invalid observer record does not change the original wire contract or cause inference retry. No queue, full-response buffer or new drain task. `[DONE]` freezes the observation; forwarding continues under the existing passthrough contract. A valid finish permits success at EOF, while EOF without finish does not. Explicit error before the content terminal is failure. Content completion and usage completion are separate: retain legitimate tail usage until transport terminal/EOF; repeated cumulative values replace, never add. Cancellation after content completion retains that known output outcome with partial/missing usage.

Reserve and finalize failures use fixed safe codes. No request/session identifiers from the client or provider become relation IDs. Generated IDs serve only gateway request/attempt relation; no request/tool content is saved. Existing fallback/cooldown and HTTP error body behavior remain; observer adds no dispatch, stream_options mutation or provider retry.
