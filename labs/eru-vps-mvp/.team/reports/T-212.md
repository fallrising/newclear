## Summary

Implemented the bounded, isolated simulation `RecordStore` and `record_digest` API. Records are strict JSON objects with a 1 MiB size limit and bounded nesting; duplicate keys, non-finite numbers, unsupported Python values, unsafe filenames, symlinks, hardlinks, nonregular files and nonprivate modes are rejected. Every operation traverses using no-follow directory descriptors and verifies the pinned root device/inode. Unknown directory entries fail audit closed.

Publication writes and syncs an exclusive temporary file, links the final name without replacement, removes the temporary link and syncs the directory before returning. Errors propagate; a complete record published before a directory-sync failure remains reserved. New root entries, including a retry after interrupted creation, require parent-directory fsync. Errors do not include raw record content.

## Risks and Follow-ups

This is a synthetic local journal primitive, not a production executor or live acceptance. The root parent must already exist; existing roots must be owner-private. Active temporary files can cause concurrent audit to fail closed; abandoned temporary files are never silently ignored or automatically removed. The store cannot prevent an actor with equivalent operating-system privileges from editing files outside this API.
