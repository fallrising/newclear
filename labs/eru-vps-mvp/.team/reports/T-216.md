## Summary

Implemented a persistent controller-local admission barrier in `scripts/pending_generation.py` and `ClusterLock`. Any `private/pending-generation` path blocks a new lock context, including inherited descriptors, malformed records and interrupted empty directories. The `reserve(project, bindings)` infrastructure API acquires the ordinary controller lock, reserves one fixed directory, persists strict generation and digest bindings with no-clobber publication, and never clears or expires a reservation. `inspect(project)` only classifies absent, pending or invalid state. Trusted private-root symlinks remain supported; lock and publication operations pin and recheck the backing directory and reject symlink descendants.

Historical RED: before implementation, `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests python3 -m unittest -v test_pending_generation` ran two tests; the new empty-directory admission regression failed with `AssertionError: RuntimeError not raised`, while the no-reservation compatibility test passed. This demonstrated the intended missing behavior and was resolved by the guard.

## Risks and Follow-ups

The barrier covers cooperating callers on one controller checkout. It does not revoke a lock already held, stop external writers, establish live fence evidence, prevent a privileged operator replacing the private backing store between processes, or authorize remote operations. Quiescence before reservation remains a required executor precondition. Read-only inspection does not replace lock-based mutation admission. Partial publication deliberately remains blocking; no automatic cleanup or generation skip exists. Accepted-run sealing, generation commit and barrier completion remain future work. All evidence here uses synthetic temporary fixtures; no production private data or VPS was accessed. Full-suite acceptance and independent review are orchestrator-owned.
