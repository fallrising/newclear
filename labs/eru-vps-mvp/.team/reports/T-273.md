### Workload、Name、opaque ID

`types/workload.go:34–49` 的 stored JSON 精確 13 fields：resources、engine_params、id、name、podname、nodename、hook、privileged、user、env、image、labels、create_time。StatusMeta 與 Engine 有 json:"-"，不在 stored record。create_time 為 int64 Unix seconds；privileged bool；env 為 string array 或 nil→null；labels 為 map[string]string 或 nil→null；resources/engine_params 是 plugin-name→RawParams maps。Hook 可 null；非 null 時其 Go fields 沒 json tags，所以是 AfterStart、BeforeStop、AfterResume、BeforeSuspend、Force（types/specs.go:7），不能捏造 snake_case。

### Static Node、CPUMEM 與 CLI 投影

`types/node.go:15–40` stored Node 必有 name/endpoint/podname/labels，bypass/test 為 omitempty bool。available、NodeInfo、ResourceInfo、Engine 均 json:"-"。因此 node 的 static raw bytes 在 workload replay 中應保持 baseline 不變；resource_usage/resource_capacity 不應塞進 `/eru/node/*`，更不存在 source 支持的 `/eru/nodes/*` key。

CPUMEM ledger 外層固定 capacity/usage；兩者各固定 cpu(float64)、cpu_map(map[string]int)、memory(int64)、numa_memory(map[string]int64)、numa(map[string]string)，見 resource/plugins/cpumem/types/node.go:16–22、62–65。Validate 在 :128–139 將 nil maps 轉 objects，stored ledger maps 不應 null。capacity.cpu 初始為 len(cpu_map)，cpu_map 的值是 share pieces，不能將 pieces sum 當 cpu quota。usage.cpu 為 workload CPU requests 加總；usage.memory 為 memory requests 加總；cpu_map 與 numa_memory 逐 key 累加；usage.numa 保存 node NUMA mapping。初始化會保留 capacity key 對應的 zero usage entries，所以比較時須保留完整合法 baseline keyset，不能用稀疏 sum 刪除 zero entries，也不能接受新增陌生 CPU/NUMA key。
