The existing entry shape remains `python3 scripts/labctl.py fresh-run next --run <run> --sha256 <execution-sha> --input <private-step-request> --input-sha256 <raw-request-sha>`. A step request binds the original execution and pending SHA, its exact operation/parameters, and the current private renewal reference. Values below are private reviewed inputs; this document is a contract, not a live authorization.

| Step | Exact parameters | Result or next boundary |
| --- | --- | --- |
| `prepare_replay` | `run_id`, `bootstrap_sha`, `bootstrap_receipt_sha` | Immutable replay plan derived solely from original desired manifest and full bootstrap evidence |
| `execute_replay` | `run_id`, `replay_sha`, `step_index`, `authorization_file`, `authorization_sha` | One fixed journal step; V02/V03/V04/residue are derived from raw captures/results |

| `finalize_generation` | `run_id`, `generation_sha` | Complete only missing exact local prefix/seals; no remote dispatch |

Each replay authorization binds the original plan/execution/pending, exact replay digest and integer step index, scope `fresh-replay-one-step-only`, owner confirmation and at most15-minute current interval. Generation timing input binds the exact acceptance lineage and raw observation references; total/installation monotonic durations, queue intervals and an explicit observed no-queue state are required. Missing or unknown values block preparation rather than becoming zero.

The timing input has one raw observation proof with `source=manual-console-owner-review`, `owner_confirmed=true` and `reviewed_at`. Its ordered `console_queues` contains four raw queue records, each bound to its actual original console action/receipt in the acceptance closure, exact host alias/node, provider console action reference and requested/started timestamps. Its `clock_intervals` contains separate total and installation raw records with the same observer/clock identity, wall endpoints and monotonic tick origins. The index retains all six source records, their transitive action/receipt references, and the original prepare step's owner renewal/admission/fence closure. That original approval must cover index preparation; an expired original window cannot be replaced retrospectively by a newer approval. Finalization independently requires a fresh current renewal.

This is the approved manual owner-review trust boundary: these records document owner-confirmed measurements, not independent provider or machine attestation. Four explicit zero-duration queue records may establish observed no-queue; missing, unknown or merely matching JSON cannot. The fixed1800-second total/installation candidate comparisons are reported truthfully and do not turn synthetic timing into live RTO acceptance.

`fresh-run status` and default `recover` verify local historical integrity, including a partial generation prefix or retained completion, without a probe, dispatch, state write or current readiness claim. Historical output keeps `stage_accepted`, `generation_changed`, `current_authority_verified` and `current_network_ready` false. `generation_committed` and `barrier_completed` describe validated retained state; a retired completion cannot be used by `next` to change a current generation.
