## Durable host lifecycle

Reuse a pinned staging support session with a staging-shaped action (remove firewall additions and restore staging operation). Every observe/activate validates actual staged bytes, safe path/attributes, original staging intent and host machine/boot/key identity. File observation must reference action.staging_intent_sha256. Keep staging pinned raw evidence and descriptors through final operation boundaries. Helper response adds table to the existing exact staging observation.

Dedicated remote slot `/etc/eru/.fresh-network-firewall`, root-owned0700. Before any nft mutation: reject existing slot/table, claim new slot with inode and empty checks, fsync parent, publish canonical immutable intent containing exact firewall action and activation intent hash, verify journal/staging/identity again. Only then invoke one create batch. No replay or repair of an existing claim. After successful batch, independently list and strictly validate the table, then publish canonical complete record binding action/intent plus exact object handles and normalized ruleset digest. Require valid output handles on every object; strip only permitted leading metainfo for stable digest, preserve all semantic fields and handles. Complete provenance must detect table recreation; trusted-root assertion is not protection against root compromise.

Observe is readonly: if slot and table are both absent return table:{kind:absent}; matching complete journal and exact current table return table:{kind:present,ruleset:<strictJSON>,intent_sha256:<activation>}. Incomplete/foreign/poisoned journal or changed table/handles reject, including uncertain kernel success before complete publication. A valid prior slot with no table cannot trigger activation. No automatically reconstructed completion, cleanup, chmod or adoption. Exception after owned claim retains a failure marker in the pinned original slot; unowned replacement/loser is never poisoned. Recheck staged and journal raw bytes, slot/target identity and final table before returning. The final current observation timestamp follows IO; owner injection only supports synthetic fixtures.
