## 1. 要回答的問題

一般程式明確寫下輸入如何變成輸出。
可微數值程式還能計算：參數改一點，結果或誤差會改多少？
這個變化率稱為梯度；它可用來調參，但不保證任意問題都能求解。

本 lab 面向懂基本變數與函式、尚未學過 autodiff 的開發者。
目標是在一頁對照中看懂固定公式、數值圖與係數學習的不同。
完成定義是能解釋結果與限制，不是成功執行一段不懂的範例。

## 2. Handwired 在這裡是什麼

JavaScript builder 用一般 JavaScript 組裝固定形狀的 FP32 數值運算圖。
建圖時的 JavaScript 與執行時的圖內運算是兩個階段。
它不是把任意 JavaScript、DOM、檔案 I/O 或網路程式編譯成可微模型。
固定大小的圖也不表示任意長度輸入或無界迴圈都能直接表示。

FP32 代表單精度浮點數，與一般 JavaScript Number 的精度不同。
相同數學式不保證每個最後位元相同；誤差要有事先界定的容許值。
比較、取整和分段選擇可能在邊界不可微，不能把所有操作當作平滑函式。

上游包含 CPU 執行路徑；文件中的 WebGPU 搜尋能力不表示所有圖都在 GPU 執行。
尤其不能把 JSON 搜尋的 WebGPU 路徑宣稱為任意 JS 的 GPU 編譯器。
第一片只研究明確數值圖，實際 API 與支援操作仍須在實作前逐項核對固定版本。

## 3. 使用情境

使用者看到一個便宜感測器，想把它的讀值換成較可信的溫度估計。
先手動指定校正係數，再觀察係數對輸出的影響。
最後可選擇讓簡單數值最佳化從合成樣本找回係數。

畫面左側輸入讀值與係數，中間顯示公式及運算節點，右側顯示兩條路徑結果。
移動滑桿時，同時顯示普通 JS、FP32 圖、絕對誤差與是否通過容許值。
按下單步調參可看見損失、梯度與參數如何變化。

此例不處理真實醫療、工業警報或安全控制；所有資料是合成教學資料。

## 4. 固定範例與精確領域

令輸入 `x` 為攝氏感測讀值，公式為 `y = a × x + b`。
固定示範取 `a = 1.25`、`b = -2`。
合法輸入為有限實數 `-20 ≤ x ≤ 60`。
可編輯係數領域為 `0.5 ≤ a ≤ 2`、`-10 ≤ b ≤ 10`。
所有超界、NaN、Infinity、缺值及非數字輸入在執行圖前拒絕。

普通 JavaScript Number 公式是數學參考路徑。
另設以 `Math.fround` 明確模擬每次乘加捨入的參考路徑，協助理解 FP32。
Handwired 圖只包含輸入、常數／參數、乘法與加法。
不從使用者字串生成或執行任意 JavaScript。

輸出比較規則為 `abs(graph-reference) ≤ 1e-5 + 1e-5 × abs(reference)`。
容許值先固定；若不通過，保留案例並查明原因，不事後放寬到通過。
每個結果標示比較的是 Number 還是逐步 FP32 參考。
實作須確認上游是否融合乘加；不可假設逐步 FP32 結果與每種 backend 位元相等。

## 5. 不可被學習改掉的條件

輸入領域、有限值驗證、容許值與資料切分是外部固定契約。
學習只能改係數，不能修改這些條件或評分公式。
圖產生 NaN／Infinity 時立即標記失敗並停止該次步進。
不能將非有限值替換成零、忽略錯誤樣本或偷偷改用另一條路徑。

這些規則示範「固定的程式保證」與「可調的數值參數」的區別。
降低損失不等於所有輸入都正確，更不等於學會一般程式設計。

## 6. 可選係數學習

學習階段與固定公式對照分開，預設先完成固定範例。
合成目標仍是 `target(x) = 1.25 × x - 2`，不加噪聲以利理解。
初始係數固定為 `a = 1`、`b = 0`，不讀既有訓練狀態。

為改善尺度，內部使用 `z = x / 40`、`prediction = alpha × z + b`。
對應 `alpha = 40 × a`；畫面仍顯示原本的 a、b 與單位。
學習損失是訓練樣本平均平方誤差。
可學係數範圍為 `20 ≤ alpha ≤ 80`、`-10 ≤ b ≤ 10`。
每步越界則拒絕該候選步並停止，不隱藏投影或截斷行為。

訓練樣本：區間內 32 個固定 seed 的均勻生成讀值。
保留樣本：另一固定 seed 的 16 個讀值，加上兩個端點。
固定 seed 記為 train=1729、holdout=1730；實作前固定 PRNG 演算法和樣本清單。
樣本建立後不可為改善結果重抽，保留集不得參與梯度更新。

第一候選是固定學習率 0.05、最多 500 步的梯度下降。
若損失非有限、係數越界或預先定義的停止條件觸發，留下完整失敗紀錄。
這些超參數尚未試跑，不宣稱一定收斂。
學習成功門檻候選為保留集最大絕對誤差不超過 0.05 攝氏度。
是否達標只影響學習示範，不改變固定公式的正確性判準。

## 7. 梯度如何驗證

先用單點公式解析導數：`dy/da = x`、`dy/db = 1`。
再比對上游提供的梯度能力；若固定版本不支援所需接口，列為阻塞而非捏造 API。
對學習損失另比較解析梯度、圖梯度與中央有限差分。

中央有限差分以 `(L(p+h)-L(p-h))/(2h)` 估計變化率。
在內部 alpha、b 座標先選 `h = 0.01`，再以 `0.005` 檢查尺度敏感性。
只選離係數界限至少 0.1 的測點，且兩側擾動仍在合法領域。
不在 clamp、比較、取整或其他不連續點驗證平滑導數。

有限差分與圖梯度容許值候選為 `0.02 + 0.02 × abs(reference_gradient)`。
解析與圖梯度用較嚴格的 `1e-4 + 1e-4 × abs(reference_gradient)`。
容許值是待測契約；失敗須解釋 FP32 消去誤差、步長或公式缺陷。
有限差分只是交叉檢查，不是所有圖與所有輸入正確的證明。

## 8. 提議模組與資料

| 模組 | 責任 |
| --- | --- |
| input-contract | 型別、領域、有限值檢查 |
| reference | 普通 JS 與逐步 FP32 公式、解析梯度 |
| graph-adapter | 固定上游版本建圖與 CPU 執行，不暴露任意程式 |
| experiment | 固定資料、步進、停止條件、保留集評估 |
| comparison-ui | 結果、誤差、梯度、來源及失敗原因 |
| evidence-export | 匯出有界 JSON 結果與版本 metadata |

圖版本、上游 SHA、資料集 digest、seed／PRNG、參數與容許值一同記錄。
每個樣本保存輸入、參考輸出、圖輸出、差值與判定。
每次訓練保存步數、前後係數、損失、停止原因及保留集指標。
失敗與不支援也是合法結果，不能省略成「沒有資料」。

初版瀏覽器本機運作，不需要後端、登入或外部資料上傳。
是否採上游建置工具待接口核對；本次沒有新增 package manifest 或依賴。

## 9. 畫面與狀態

狀態為未建圖、就緒、執行中、通過、超差、拒絕輸入或執行失敗。
改輸入後舊結果顯示為過期，不能保留綠色通過標記。
訓練另有未開始、步進中、達標、步數耗盡及停止失敗。
固定範例與學習範例各自顯示狀態，不共用一個成功徽章。

輸出至少能回答：輸入是什麼？公式是什麼？比較哪個參考？誤差多少？
學習畫面另外回答：改了哪個參數？梯度指向哪裡？保留集有沒有變好？
提供重設到同一初始狀態；不得以重設抹掉已匯出的失敗證據。

## 11. 正反驗收

- HW-A01：x=-20、0、60 與固定種子樣本均按既定輸出容許值比較。
- HW-A02：超界、NaN、Infinity、字串與缺值在圖執行前被拒絕。
- HW-A03：相同版本、資料和參數重跑結果可比較；backend 差異有標記。
- HW-A04：解析／圖／差分梯度的測點與誤差完整輸出，失敗不省略。
- HW-A05：篡改保留集、改容許值或換圖版本後，舊結果不可當作當前證據。
- HW-A06：學習只更改 alpha、b；輸入檢查與評分器維持固定。
- HW-A07：故意使用過大步長造成失敗時，UI 顯示停止原因而非假裝收斂。
- HW-A08：不支援 WebGPU 的裝置仍可完成 CPU 路徑；不顯示未量測加速倍數。
- HW-A09：初學者能解釋 builder 與 runtime 的差別，並辨認降低 loss 不等於一般智能。

## 12. 何時適合、何時不適合

適合探索小型數值校正、可微公式、參數敏感度與有界最佳化。
不適合取代字串處理、資料庫交易、存取控制或任意 JavaScript 程式。
遊戲貨幣、庫存守恆及權限判定應使用明確離散規則，不交給近似浮點學習。
也不把它接進其他 lab 的核心規則作為第一個示範。

CPU 先建立正確性與基準。只有實際工作量足夠、量測含資料傳輸成本、支援範圍明確時才研究 WebGPU。
微小線性範例預期以可理解性為主，不用它宣稱 GPU 有價值。
