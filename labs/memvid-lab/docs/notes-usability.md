## 實驗設計

採真實固定 `memvid-sdk==2.0.160`；沿用寫入後顯式 doctor 重建及 runtime seccomp 斷網。
比較原生 lexical 與明示的應用層 CJK 二字組預處理：二字組只由文件／query 本身產生，不使用標準答案、人工同義詞或問題文字擴充文件。
原文與穩定 URI 保留；二字組是可見的 lab adapter，不宣稱原生中文語意模型。
此階段不使用既有英語 BGE 模型冒充繁中語意檢索。

先固定並雜湊至少 24 則合成繁中筆記、24 條查詢（至少 6 條無答案），含完整詞、局部詞、自然問句／改述、繁中英數混寫與容易混淆的來源。
每條 query 預先列出相關 URI，至少包含一條多來源問題；資料明示合成、不代表 owner 的私人筆記或真實流量。
品質查詢只在固定小語料上評估；規模語料以同一小語料加確定性干擾筆記擴充至 100／1000 則。干擾資料不是自然資料分布，不能由此推論 production 容量。

報告列出每條前五名結果、相關來源命中、排名及來源內容核對，並分查詢類別彙總：
Recall@5、MRR@5、返回來源精確率、無答案錯誤返回率、來源完整性。沒有命中不可當作來源完整性滿分證據。
來源完整性以 SDK 返回 URI、frame、實得內容對照獨立原文 manifest；不以已知答案替換 native 搜尋結果。

固定計算口徑：先按原生排名保留每個 URI 的第一次命中，再截前五名；原始 hits 與去重後 hits 都保存。
Recall@5 為每條有答案 query 的 `命中相關 URI 數 / 全部相關 URI 數` 後取 macro 平均；MRR@5 為第一個相關 URI 的排名倒數後取同一組 query 的 macro 平均，未命中為 0。
返回來源精確率採 micro：全部 query（含無答案）的相關返回 URI 數總和，除以全部去重後返回 URI 數總和；總返回數為 0 時記 null，採用門檻不通過。
無答案錯誤返回率為「至少返回一個 URI 的無答案 query 數 / 全部無答案 query 數」。
來源完整性為「URI、frame 與內容均符合 manifest 的原始返回 hit 數 / 全部原始返回 hit 數」；沒有 hits 時記 null、不能通過採用門檻。
全體指標與各類別分開計算；某類沒有適用 query／hit 時記 null，不能補零或當成滿分。

更新實驗使用同 URI 追加修訂，記錄原生 current frame、歷史版本與檢索結果；顯式比較只保留 current frame 的應用層 view，另測刪除與新程序重開。
若原生結果會混入舊版，保留觀察，不把過濾後成功寫成原生 overwrite 已通過。
量測 100／1000 筆建檔／寫入／重建、查詢首次延遲與暖機後 p50／p95、檔案 bytes；保存平台與版本、次數及來源雜湊。
計時為單機實測，不設易受 CI 負載影響的延遲 pass 門檻。規模跑每次最多 180 秒，逾時留明確失敗，不縮小資料量冒充通過。

## 固定驗收條件

| ID | Given／When／Then |
| --- | --- |
| NU-01 | Given 已合併 #709／#733 與相同 runtime bytes，When 核對入口和索引，Then 文件準確標示原實驗 complete、未發布 tag／未部署，歷史證據與限制保留。 |
| NU-02 | Given 固定筆記／查詢／相關 URI，When 離線執行兩種策略，Then 每條實得結果及上述五類品質指標可回算，低分如實列出且資料／來源 hash 可核對。 |
| NU-03 | Given 同 URI 新舊版本與待刪筆記，When 更新、刪除並以新程序重開，Then 記錄 current／歷史／原生搜尋差異，current view 不返回舊版、已刪資料或錯誤引用。 |
| NU-04 | Given 100／1000 筆確定性資料，When 有界執行，Then 報告實際筆數、建置及查詢計時、檔案大小、版本與量測條件，不將合成資料結果外推。 |
| NU-05 | Given 報告、既有輸出目錄及無答案案例，When 執行 CLI／回歸測試／審查，Then 拒絕覆寫、錯誤非零、真 SDK 路徑與完整報告有證據，README 記錄重現步驟與採用結論。 |

M2 完成是取得可核對答案，不要求 Memvid 達到產品品質。預先固定的探索性採用門檻：Recall@5 ≥ 0.90、MRR@5 ≥ 0.80、返回來源精確率 ≥ 0.80、無答案錯誤返回率 = 0、來源完整性 = 1（須有實際 hits），更新／刪除 current view 全通過。
只要任一不達標即不建議直接採用此策略；這些是本次小語料的篩選門檻，不是 owner 承諾的產品 SLA。
不得看過結果再改資料、答案或門檻追求通過；資料錯誤須保留原結果與具體修訂理由。
