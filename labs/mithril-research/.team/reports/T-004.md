separate `write_bundle(bundle, new_private_output)` boundary. Generation and
validation perform no subprocess/runtime calls. Transport consumes only a
strict nonsecret bundle manifest and exact ownership manifest; it does not
need credential contents or a dependency on the builder module.

`runtime_spec` must explicitly bind the runtime UID/GID, opaque secret revision,
template revision, and Mithril image/provenance reference. The existing
`builder_image` is a Rust builder, not a Mithril runtime image. A verified
immutable linux/amd64 Mithril image mapping to the pinned binary/source has not
been supplied here. Allow explicit unresolved artifact drafts; never fabricate
a digest or infer verification from a reference token. A draft may render
reviewable configuration but must not produce a runnable Compose image field or
admit mutation. This missing runtime image does not block offline development.

Use a separate schema/lane, source-plan digest and `bundle_sha256`, with
`live_ready=false` and live runtime `UNEXECUTED`. Define the bundle digest over
the normalized nonsecret specification and template revision *before* inserting
that digest into rendered ownership labels; avoid a self-referential file hash.
On load, reconstruct the fixed topology, paths, labels, image pins and caps from
validated bound inputs. A recomputed unkeyed hash is not semantic validation or
approval. Do not hash secret contents into public config/bundle hashes: use only
nonsecret templates and an opaque secret revision. Private output includes
rendered credential-bearing files; CLI stdout is a sanitized count/classification
summary, not serialized bundle contents.

Emit four Compose JSON documents, six independent Redis config/ACL sets and

**D3: Freeze the SSH protocol, not an arbitrary-command API.** Recommended
operations are `observe`, `stop` and `remove`; a local `down` coordinator performs
the fixed order A, replicas, masters, stopping and checking each exact container
before removal. No names/prefix matching, label-wide deletion, compose-down,
forced removal, volumes or directory deletion. Existing approved client activity
must have stopped before down; this tool does not discover or kill unrelated
clients. It only handles containers listed by an independently bound ownership
manifest from an approved prior run, never adopts objects by name.

Request fields bind schema, operation ID, operation, run ID, source-plan digest,
bundle digest, H-role, expected machine identity and exact target IDs/roles.
Responses echo those bindings and state their evidence origin (`ssh` or
`mock-ssh`). Enforce duplicate/unknown-field/type rejection, strict IDs, request
and output limits and deadlines. Mock output must never become live evidence.
Raw request/response/Docker diagnostics stay private; public output omits host
mapping, paths, credentials and untrusted diagnostic text.

Use one immutable trusted remote command and bounded canonical JSON on stdin.
An installed fixed helper is acceptable only if its deployment/provenance is
explicitly an unmet prerequisite. Alternatively a literal, trusted helper
program passed with fixed `python3 -c` plus correctly quoted *static* source can
consume JSON stdin without installing anything. No inventory/request value may
enter remote shell command text. Local `shell=False` alone does not remove
SSH's remote shell parsing. Do not expose caller-supplied command, script,
Docker flags, executable or arbitrary helper path. A test-only dependency
injection seam must not become a public remote arbitrary-command CLI option.

Require BatchMode, StrictHostKeyChecking=yes, no agent/X11/port forwarding,
no TTY, no connection multiplexing and explicit connection/deadline bounds.
Document how the existing private SSH mapping is consumed; strict host-key
checking does not verify machine identity or neutralize inherited SSH config
forwarding settings by itself. The helper compares the expected machine hash
in the same process/session before runtime observation/effects; define the
exact machine-ID normalization/hash convention and reject missing/malformed
identity. A separately completed SSH preflight is insufficient. Select the
approved host-local Docker endpoint explicitly rather than inheriting a remote
DOCKER_HOST/context. Runtime absence, insufficient privilege or helper absence
is a bounded refusal, not a request to install runtime or use sudo.

**D4: Make down fail closed with durable uncertainty.** Match full immutable
container IDs plus run, source-plan, bundle and role labels and expected host
identity. Inspect again inside the helper immediately before each effect.
Inspect errors/nonzero exit, malformed/truncated/overlarge output, identity
drift and ambiguous absence are UNKNOWN, never an empty resource list. Only a
successful bounded authoritative enumeration/inspection can prove absence.
For `remove`, first require a matching stopped object; do not use `rm -f` or
volume-removal flags. Preserve data, nodes.conf, credentials/config, ownership
manifest, journal and evidence.

Require a separate private exact action-admission record for mutations, binding
hosts/run/source-plan/bundle/target IDs/actions and an independent approval
reference. Comparing a plan hash, a boolean or a self-generated approval token
is insufficient. A supplied operator declaration records admission; it does
not authenticate the owner or grant permission outside the session's actual
authorization. Approval of down never covers purge or other operations.

Under one private cooperating-writer lock, persist intent with operation ID,
exact target and action before SSH dispatch; persist the validated outcome
afterward. If timeout, interruption, lost reply or nonzero/malformed output
occurs after possible dispatch, keep the outcome UNCERTAIN and block further
mutations. Killing local SSH does not establish remote cancellation. Bound
stream reads while the process runs: checking length after unrestricted
capture is not a memory/output limit, and a timeout must cover pipes held open
by children. Keep the journal bounded without deleting history.

Reconcile only observes exact IDs/bindings. A stopped matching target may
conclusively resolve a stop; a proved absent target may resolve removal. A
foreign target or incomplete observation leaves uncertainty fenced. If a stop
is observed not to have happened, abandon that intent and require a newly
identified, explicitly admitted action rather than replaying the old request.
Repeated reconciliation must not mutate containers. A local state lock covers
cooperating controllers using that state scope; it is not remote/distributed
exclusivity and cannot prevent outside Docker operators from racing the tool.
