## Documentation

Only the three assigned implementation/test files and this report were written
by this worker. Root owns public documentation, PLAN, full checks and delivery.
The sole bundle authority is `bundle.validate_manifest(manifest,
expected_bundle_digest)`; transport does not implement an alternative manifest
validator. Integration APIs:

- `control(manifest, expected_bundle_digest, ownership, state_root, action, transport, *, admission=None, execute_approved=False)`; actions `observe`, `down`, `reconcile`.
- `Transport(config, *, _runner=None)`: fixed SSH argv; private Python-only mock seam, no CLI runner/command/executable/helper-path option.
- `purge_preview(manifest, expected_bundle_digest, ownership)`: returns the full private review document, its `preview_sha256`, exact Redis-only `data/<role>` candidates, empty `eligible`, explicit unmet fresh-live checks and `apply_supported=false`.
- `validate_purge_approval(preview, expected_preview_digest, approval)`: separately shaped exact-preview declaration; records neither authenticated authority nor eligibility. There is no purge apply API.

Ownership exact keys: `schema_version=1`, `run_id`, `plan_sha256`,
`bundle_sha256`, `targets`. Each of 1-7 targets has exactly `host`, `role`,
`container_id`; roles and 64-character lowercase-hex IDs are unique, and each
role must match its fixed H-host. Source-plan and bundle digests bind the full
machine mapping. Partial approved prior-run ownership is supported; names and
prefixes never establish ownership.

Request exact keys: `schema_version=1`, `operation_id` (32 lowercase hex),
`operation` (`observe|stop|remove`), `run_id`, `plan_sha256`, `bundle_sha256`,
`host`, `machine_identity_sha256`, `target={role,container_id}`. Responses echo
all fields exactly and add only `origin` (`ssh|mock-ssh`) and `observation`
(`running|stopped|absent|foreign|unknown`). Protocol payload and each subprocess
output stream are limited to 64 KiB while running; the helper operation deadline
is 20 seconds, and transport deadlines are explicit integers 1-60 seconds.
Killing local SSH does not establish remote cancellation.

Down admission exact keys: `schema_version=1`, `purpose="down"`,
`admission_id` (32 lowercase hex), `approval_reference` (nonempty bounded reference,
not UNRESOLVED), `ownership` (the exact full ownership document),
`actions=["stop","remove"]`, `clients_stopped=true`. It is supplied independently;
there is no approval generator. A declaration cannot authenticate the owner,
replace actual session authorization or authorize purge.

Transport config exact keys: `schema_version=1`, `ssh_config`, `known_hosts`,
`deadline_seconds`. Both mapping files must be owner-only mode 0600 regular
single-link files reached without symlinks. Their absolute literal paths allow
only letters, digits, slash, underscore, period and hyphen; SSH `%` expansion,
whitespace and ambiguous path lists are refused. The private SSH config is a
reduced mapping, at most 64 KiB: only Host, HostName, User, Port, IdentityFile,
CertificateFile, IdentitiesOnly, HostKeyAlias, HostKeyAlgorithms,
PubkeyAcceptedAlgorithms, RequiredRSASize and PreferredAuthentications are
accepted. Includes, Match, executable hooks and providers are refused before
launch. Fixed argv additionally overrides forwarding, agent/X11/TTY,
multiplexing, hooks, proxy commands/jumps, host-key policy and connection bounds.
Approved mapping and runtime privileges remain operator prerequisites.

CLI: positional `observe|down|reconcile|purge-preview` plus `--manifest FILE`,
`--expected-bundle-digest SHA256`, `--ownership FILE`. Remote actions require
`--state-root DIR`, `--transport-config FILE`, `--execute-approved`; down also
requires `--admission FILE`. All CLI JSON input files are bounded private
no-follow inputs. Help/errors/success emit sanitized aggregate JSON with
`live_ready=false`, `live_runtime="UNEXECUTED"`; errors exit 2 without rejected
input or raw SSH/Docker diagnostics. Purge-preview CLI emits candidate count,
unmet checks and digest only. Exact candidate review uses the private Python
API result; the CLI does not persist a preview file. Purge approval has exactly
`schema_version=1`, `purpose="purge-preview"`, `approval_reference`,
`preview_sha256`; a down admission fails that schema. This validator checks only the supplied preview digest and separate approval-record shape; it does not semantically rederive candidate provenance or fresh live observations. Its return always has empty eligibility and no apply support.
