## Summary

Independent design decision: accept the following bounded **offline** contract
for root to freeze before implementation. This is design review completion,
not acceptance of unwritten code, runtime approval, freshness, readiness or
replication health. Baseline is
`6492e4f92916837c519dbeb98764b4fdf5921885`; research pin remains unchanged.
Only a new bootstrap module, its offline tests and root-owned documentation
are needed. Do not extend the SSH helper or existing lifecycle APIs.

**D1 — Exact private observation inputs and identity binding.** Reuse
`bundle.validate_manifest(manifest, expected_bundle_digest)` and
`ssh_executor.validate_ownership(manifest, ownership)`, additionally requiring
ownership to contain exactly the six Redis targets, with no proxy or partial
set. Require the existing resolved runtime declaration for a proposal; a draft
bundle cannot become a runnable startup plan. Keep its original evidence lane.
Every ownership host, role and full container ID must match the fixed mapping.

Supply `expected_node_ids` separately from observations: an exact dictionary
whose six keys are M1/M2/M3/R1/R2/R3 and whose values are distinct 40-character
lowercase hexadecimal Redis node IDs. There is no discovery or trust-on-first-use
CLI. The operator must independently retain this identity map, normally with
the original reviewed bootstrap document and its independent digest. Subsequent
validation uses that retained map, never a newly inferred map from replacement
snapshots. Replacing every node ID consistently in all six views still refuses
against the retained map. A supplied map is an assertion, not authenticated
proof; arbitrary same-UID edits or choosing a new expected digest remain outside
that guarantee.

Observation envelope exact keys:
`schema_version`, `lane`, `origin`, `snapshot_id`, `run_id`, `plan_sha256`,
`bundle_sha256`, `nodes`.
Values: integer version 1; lane `offline-snapshot`; origin exactly `synthetic`
or `operator-supplied`; snapshot_id exactly 32 lowercase hex; exact run/source
plan/bundle bindings; nodes exactly six records, one per expected role.
Snapshot IDs identify declarations only and prove neither collection time nor
freshness. Do not accept origin `ssh` or a caller-provided live/fresh flag.

Each node record has exactly `host`, `role`, `container_id`,
`machine_identity_sha256`, `labels`, `container_state`, `cluster_nodes`,
`cluster_info`, `info_keyspace`. The first three match its ownership target;
machine SHA matches that host's bound inventory; labels equal the four exact
`bundle.labels(manifest, role)` values; container_state is exactly `running`.
All three raw response fields are strings containing complete successful direct
backend command payloads, respectively CLUSTER NODES, CLUSTER INFO and INFO
keyspace. Errors, absent responses and partial collection refuse. These remain
operator/synthetic assertions; this module does not collect or authenticate them.
Derive the expected data/bus endpoint from the manifest and compare it against
every occurrence in every NODES view. Do not accept a caller-supplied endpoint
as an independent source of truth or query Mithril's virtual CLUSTER surface.

Bounds: private JSON inputs and serialized output at most 1 MiB each;
cluster_nodes at most 64 KiB per node; cluster_info at most 16 KiB;
info_keyspace at most 4 KiB. Reject invalid UTF-8, non-ASCII response payloads,
NUL/control characters except line endings, duplicate JSON keys, unknown fields,
nonfinite numbers, booleans as integers, recursion failures and overlimits.
Accept LF or CRLF complete lines with an ending newline, rejecting bare CR and
internal blank NODES/CLUSTER INFO lines. At most six NODES rows, 16,384 slot
tokens per row, and 64 CLUSTER INFO fields. Size limits are conservative profile
limits: an otherwise valid unusually large response may be refused, never
silently truncated or partially interpreted.

**D2 — Parsers, normalization and admitted states.** Recommended pure APIs:
`parse_cluster_nodes(raw)`, `parse_cluster_info(raw)`,
`parse_info_keyspace(raw)`, then
`validate_observations(manifest, expected_bundle_digest, ownership,
expected_node_ids, observations)` and
`build_bootstrap_plan(manifest, expected_bundle_digest, ownership,
expected_node_ids, observations)`.
All public APIs should raise bounded `labctl.LabError` codes for malformed
inputs rather than leak raw values or Python tracebacks.

NODES grammar is eight required fields followed by zero or more slot tokens:
40-lowercase-hex ID; canonical IPv4:data-port@bus-port; comma-separated flags;
master ID or `-`; ping and pong nonnegative decimal counters; nonnegative config
epoch; link state; slots. Restrict integers to unsigned 64-bit, ports 1..65535,
slots 0..16383, with bounded digit strings before integer conversion. This
bundle does not configure announce hostnames; the minimal profile accepts the
endpoint without a hostname suffix or with an empty suffix, and refuses a
nonempty hostname or nodes.conf auxiliary fields. Document that profile limit.
Known flags can be parsed, but only master/slave plus the one appropriate
myself flag are admitted. Reject duplicate/unknown flags, both master and slave,
fail/fail?/handshake/noaddr/nofailover/noflags, and disconnected links. Exactly
one myself row per direct snapshot must have the independently expected ID for
that snapshot's role. Migration/import tokens in either direction always
refuse, even when every ordinary slot is also present.

Normalize row/flag/slot-token order and equivalent adjacent/split ranges before
comparing views. Detect repeated or overlapping slots **before** set union or
range coalescing, including repeated single-slot tokens and cross-node overlaps.
No regex-only full-coverage shortcut. Ignore observer-local ping/pong differences
when comparing topology, while still validating and retaining their raw input.

CLUSTER INFO requires exactly once each: cluster_state, cluster_slots_assigned,
cluster_slots_ok, cluster_slots_pfail, cluster_slots_fail, cluster_known_nodes,
cluster_size, cluster_current_epoch, cluster_my_epoch. State is ok/fail;
all other values are unsigned bounded decimal integers. Allow the pinned
version's optional numeric counters: cluster_stats_messages_sent/received,
total_cluster_links_buffer_limit_exceeded, and
cluster_stats_messages_<type>_sent/received for type ping, pong, meet, fail,
publish, auth-req, auth-ack, update, mfstart, module, publishshard. Reject other
keys, duplicates, malformed lines and Redis errors. Optional counters have no
readiness meaning; never infer freshness from their values.

INFO keyspace is required rather than DBSIZE because the current generated
backend_operator allows INFO but does not allow DBSIZE. Require the literal
Keyspace section header and a complete response; an empty string or missing
section is unknown, not zero. Accept no database line for empty keyspace, or
one db0 line with exactly keys/expires/avg_ttl and optional subexpiry, all bounded
nonnegative integers; expires cannot exceed keys. Reject duplicate fields/DBs,
other sections, other DBs and unknown fields. Preserve support for the pinned
7.4.11 subexpiry field. Pristine requires every reported count zero; a nonempty
converged keyspace is allowed because this is topology verification, not reset.
An empty response cannot prove empty on-disk storage, historical newness,
client quiescence, completed loading, or emptiness at a later mutation instant.

Only these two whole-set classifications produce a proposal:

| Classification | Required observations | Proposed actions |
| --- | --- | --- |
| pristine | All six independently bound nodes each know only self, myself/master, master `-`, connected, no slots, zero keys; INFO state fail, known_nodes 1, size 0, all four slot counters 0; self config epoch, current_epoch and my_epoch all 0 | Four conditional phases below |
| already-converged | Every direct view contains exactly the same six expected IDs/endpoints, three expected masters and three expected replicas, exact slot ownership and replica relationships; INFO ok/6/3/16384 assigned/16384 ok/0 pfail/0 fail | Empty phases; topology snapshot only |

Final placement is M1/H1:17001@27001 slots 0..5460;
M2/H2:17001@27001 slots 5461..10922;
M3/H3:17001@27001 slots 10923..16383;
R1/H2:17002@27002 follows M1; R2/H3:17002@27002 follows M2;
R3/H1:17002@27002 follows M3. Addresses come from each host's inventory.
Masters have master pointer `-`; replicas own no slots. Every direct view must
prove precisely that placement and each slot exactly once. Require positive,
distinct master config epochs, matching per-node epochs across views and
matching my_epoch to the self row's published epoch, with a consistent
current_epoch at least the maximum published epoch. Replica published epochs
track their master's epoch; do not compare them with initial assigned 4/5/6.
Do not require equal ping/pong counters.

Everything else refuses without actions: missing/extra views or IDs, wrong
endpoints/container/host/labels, mixed pristine and formed state, partial slot
coverage, fully slotted wrong ownership, role failover or wrong replica parent,
cross-host anti-affinity violation, unreachable/failed/migrating nodes,
inconsistent INFO/NODES counts or mutually inconsistent views, retained
nonzero epochs on an otherwise empty isolated node. Never reset, adopt, repair,
reshard or resume partial bootstrap. Connected cluster-bus links and slave flags
do not establish replication link/synchronization health; that needs later
direct INFO replication/ROLE evidence, bounded lag and actual runtime admission.

**D3 — Minimum deterministic typed phases and barriers.** A pristine proposal
contains these phases in this order. There is no argv, shell string, credential,
dispatcher, executor, phase-advance API or automatic retry.

1. `set-config-epochs`: six set-config-epoch actions, M1=1/M2=2/M3=3/
   R1=4/R2=5/R3=6. Before each action the target must still be isolated, empty,
   master and epoch zero. After the phase, reobserve all six: still isolated
   and empty, each self/current/my epoch equals its assigned value.
2. `meet`: five meet actions on M1, targeting M2/M3/R1/R2/R3 in that order,
   using exact derived IPv4/data/bus ports and expected IDs. Afterward reobserve
   all six until every view contains precisely all six connected expected nodes,
   still all masters with no slots, empty keyspace, INFO fail/6/0/zero slots,
   unique configured epochs and current_epoch 6. No timeout-driven reinitialize.
3. `assign-slots`: three addslotsrange actions on M1/M2/M3 with the exact ranges
   above. Afterward reobserve all six for consistent exact full slot ownership,
   no failed slots, INFO ok/6/3/16384/16384/0/0, while prospective replicas are
   still empty masters with no slots. Require emptiness/client quiescence before
   replica conversion; future executors must recheck before each actual effect.
4. `replicate`: three replicate actions on R1/R2/R3 referring to the actual
   independently bound M1/M2/M3 IDs. Afterward reobserve all six for the exact
   already-converged topology. Replication health, persistence and proxy startup
   remain separate unmet runtime gates.

Each phase object has exactly `phase_id`, `actions`, `requires_before`,
`requires_after`; use fixed barrier identifiers and reconstruct them on reload.
Action keys are exactly `kind`, `target` plus `epoch` for set-config-epoch,
`peer` for meet, `slots` for addslotsrange, or `master_node_id` for replicate.
Target keys: host/role/container_id/node_id. Peer keys:
host/role/node_id/ipv4/port/bus_port, all derived from bound inputs. Action kinds
are exactly set-config-epoch, meet, addslotsrange, replicate. Ordered action
counts are 6/5/3/3; no caller extension or opaque command field is accepted.

All later phases are conditional descriptions, not presently admitted actions.
The module admits only pristine or final snapshots and deliberately cannot
consume the intermediate states above to resume work. A future executor needs
a separately reviewed phase-aware collector/validator, fresh same-session
machine/container/labels/node-ID checks, complete bounded successful observations,
actual approved exact phase/actions/targets/plan and durable intent/uncertainty
fencing. Neither current_snapshot timestamps nor operator booleans can satisfy
those requirements. Reobserve after each phase and before each next effect;
mutation errors/timeouts stop progress. A lost reply may still act later, as
the existing down-tool review established. Never blindly replay these phases.

Classification is pristine or already-converged. Unmet requirements are a
fixed ordered list covering authenticated live collection/freshness, exact

runtime artifacts/config/filesystem/network, replication health, persistence

`validate_bootstrap_plan(plan, expected_bootstrap_digest)` requires the
independent expected digest and reconstructs the entire proposal using the
validated embedded inputs; compare exact canonical content, including constants,
classification, phases, action identities and barriers. Rehashing arbitrary
commands, changed topology, live flags or omitted barriers cannot validate.
Valid alternative declarations can yield another digest; a hash does not
authenticate those declarations or establish authority. Preserve original
inputs, detach mutable objects and bound output before creating a destination.

`write_bootstrap_plan(plan, expected_bootstrap_digest, output_path)` writes only
an exclusively new private directory and fixed bootstrap.json through no-follow
directory handles, using existing private-output primitives where appropriate.
Use owned 0700 parent/directories and 0600 single-link regular files; reject
existing destinations, links, traversal, source destinations and remote-intent
ancestry before writing. Retain partial output on I/O failure. No overwrite,
cleanup or credentials input exists.
CLI form: `bootstrap.py plan --manifest FILE --expected-bundle-digest SHA256
--ownership FILE --node-ids FILE --observations FILE --output NEW_PRIVATE_DIR`;

addresses, aliases, paths, labels, node IDs or untrusted parser diagnostics in
