**D4 — RESP framing, size and deadline contract.** Implement minimal RESP2
arrays of bulk-string requests and strictly expected replies, not redis-cli raw
output. Send sequential AUTH backend_operator PASSWORD, CLUSTER NODES,
CLUSTER INFO, INFO keyspace. No HELLO 3, arbitrary command, QUIT or added ACL.
AUTH must reply exactly +OK CRLF. Each observation must be one non-null RESP2
bulk string: bounded decimal length, exact CRLF, precisely that many payload
bytes and trailing CRLF. Refuse error replies, nulls, arrays, integers, RESP3,
negative/oversized/overlong lengths, invalid delimiters and premature EOF.
Bound decimal header to at most 16 bytes before conversion; permit only canonical
nonnegative decimal lengths, no signs/leading zeroes except zero. Payload zero
then fails the required raw parser. Fragmented reads/writes must work. Do not
assume recv returns a complete frame or send writes the whole request.

After the third response, half-close the write side with shutdown(SHUT_WR),
then require EOF with no trailing bytes before the SAME deadline. This is an
explicit conservative completion profile; a peer holding open or sending extra
frames yields unknown. QUIT is intentionally omitted because the current
operator ACL does not explicitly allow it; no bundle/ACL widening is needed.
Half-close behavior remains a later real-runtime acceptance gate. A complete
length-framed header-only Keyspace payload proves only acquired response
completion and its supplied zero count, never empty disk/loading/quiescence.

Raw limits stay CLUSTER NODES=65536, CLUSTER INFO=16384,
INFO keyspace=4096 bytes. Every raw byte must be printable ASCII or CR/LF and
then satisfy the existing complete-line grammar. New helper request cap=65536,
response JSON cap=524288 bytes, Docker stdout/stderr cap=65536 each while
running. New SSH stdout/stderr cap=524288 each while running, not after
unbounded capture. Collection serialized cap=2097152 bytes; unchanged P1c
limits remain 1 MiB and must not be monkeypatched. Worst-case JSON escaping is
bounded by these independent serialized caps; overlimits refuse, never truncate.
A normal six-node response can exceed the old 64 KiB transport cap, so directly
reusing that runner's fixed maximum would be incorrect. A new parameter-bounded
stdlib runner may adapt the existing concurrent-pipe/process-group pattern.

Helper has one 20-second monotonic deadline covering pre/post inspect, connect,
auth, all sends/reads and EOF; each blocking operation uses remaining time,
not a reset timeout per byte/command. SSH config retains its strict integer
1..60-second per-node deadline. Six attempts therefore have at most six transport
deadlines; there is no unbounded polling. Read both child pipes concurrently,
include descendant-held pipes and process exit, refuse nonzero exit, and kill
only the local process group on timeout. This never proves remote cancellation.
Runner environment is fixed PATH/LANG/LC_ALL as before; never secrets in env.
