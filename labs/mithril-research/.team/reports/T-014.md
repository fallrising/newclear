## Summary

Recommend the bounded P1e slice below as p1e-v1: one new pure offline validator
in scripts/phase_validation.py and tests/test_phase_validation.py. Root freezes
this design before behavior writes. All existing implementation, tests, locks
and contracts remain byte-identical. The original redis-collection envelope is
the only snapshot input; it is never relabeled as an offline-snapshot, collected
again, or admitted to P1c. Five exact predicates describe supplied assertions,
with no execution, progression, freshness or authority implication.

**D1 — Exact public API and input contract.**

```python
validate_phase_snapshot(manifest, expected_bundle_digest, ownership,
                        expected_node_ids, collection, barrier_id)
main(argv=None)
```

The first five arguments retain their exact P1d meaning and schemas. In
particular, expected_bundle_digest and the independently retained six-role
expected_node_ids are separate inputs, not derived from collection contents.
Use the unchanged collector.validate_collection on the original collection and
original bindings. Require its returned status to be complete and every one of
the six ordered entries complete with a non-null record. Partial/all-unknown
collections, malformed originals and any binding drift refuse before predicates.
Do not accept P1c offline-snapshot, bootstrap proposals, phase results, normalized
caller-supplied views, executor tokens, credentials or alternate input lanes.

barrier_id must be a plain string equal to one of these exact values, in the
same order as bootstrap.BARRIERS:

1. pristine-isolated-empty-zero-epochs
2. isolated-empty-assigned-epochs
3. six-connected-empty-masters-epoch-six
4. exact-slots-with-empty-prospective-replicas
5. exact-converged-topology-snapshot

The API validates bounded original data, derives fresh internal views with the
unchanged bootstrap raw parsers, checks the selected predicate and returns the
exact success assertion in D4. Invalid inputs or a mismatched predicate raise
labctl.LabError with a constant non-sensitive code. No success-shaped false
result, partial acceptance, fallback barrier, catch-and-continue, normalization
of original raw fields or origin upgrade is allowed. Refuse malformed JSON-like
types consistently as LabError rather than exposing KeyError/AttributeError or
tracebacks. KeyboardInterrupt may propagate at the API boundary; CLI sanitizes
it. Existing parser/binding behavior is preserved, not expanded.

Implementation may reuse bootstrap._expected to derive the manifest's exact
slot/replication assignments after original validation. It may reuse
bootstrap._info_matches and _classify for the rules below. Derived views are
internal only. No call to collect, Transport, socket, subprocess, journal,
build_bootstrap_plan or validate_observations is needed or authorized. In
particular, do not manufacture a P1c-shaped envelope to reuse its public API.
The validator itself performs no file/network/runtime I/O after module imports;
existing collector import-time trusted helper source loading is not a claim of
zero-I/O import behavior. File reads belong only to the private CLI boundary.

**D2 — Common parsed profile and cross-view rules.**

All six records retain original full container/machine/ownership/process
bindings, exact direct self ID and published ID/endpoint checks from P1d. Raw
limits and grammar remain 64 KiB CLUSTER NODES, 16 KiB CLUSTER INFO and 4 KiB
INFO keyspace. This includes connected links, exactly one local myself marker,
no duplicate IDs/endpoints/slots, no unsafe flags or migration tokens and complete
ASCII lines. Do not reinterpret parser errors as an unmet-but-acceptable state.

Let roles be M1,M2,M3,R1,R2,R3 and assigned epochs E be respectively 1,2,3,4,5,6.
Let self(role) be its independently retained node ID. For barriers 3 and 4 every
view must contain exactly all six expected IDs. Its normalized topology maps
each ID to IPv4/port/bus_port, master-or-slave role, master_node_id, epoch and
expanded sorted slot set. These normalized maps must agree across all views.
Ignore only row/flag/slot-token presentation order, local myself placement and
ping/pong counters when comparing topology. The unchanged parsers already
normalize row/flag/slot order. All six views independently retain their exact
local myself binding. Do not compare complete raw response strings or allow
cross-view role/parent/epoch/slot differences.

For isolated barriers 1 and 2, each view instead contains exactly its own node;
requiring the six singleton maps to be equal would be wrong. Per-node process
incarnations are independent and must not be compared for equality across roles.
There is no prior collection/history argument and no cross-snapshot process or
temporal progression inference.

The phrase empty below means every parsed keyspace counter is zero: keys,
expires, avg_ttl and subexpiry. Header-only Keyspace and the parser's explicit
zero-counter representation are equivalent. Empty parsed keyspace is not proof
of empty disk, finished loading, quiescent clients or retained-data eligibility.

INFO equality refers only to the required fields shown in D3. Optional message
statistics retain the unchanged strict parser's keys/unsigned bounds and need
not agree across nodes or equal zero. Local ping/pong/statistics differences are
not topology disagreement. Missing/duplicate/unknown INFO fields still refuse
under the existing grammar.

**D3 — Five exact predicates.**

Barrier 1, pristine-isolated-empty-zero-epochs: reuse the unchanged
bootstrap._classify(views, expected) and require the result to equal pristine.
This preserves P1c's exact singleton self-master/no-parent/no-slots, epoch zero,
all-empty and fail/known1/size0/zero-slot/current0/my0 semantics. Do not broaden
pristine based on a new classifier or weaken existing final/initial admission.

Barrier 2, isolated-empty-assigned-epochs: in each role's view, exactly one row
equals self(role), with flags master+myself, master_node_id "-", no slots and
epoch E(role). Every keyspace counter is zero. INFO required values are:

| Field | Exact value |
| --- | --- |
| cluster_state | fail |
| cluster_known_nodes | 1 |
| cluster_size | 0 |
| cluster_slots_assigned / cluster_slots_ok | 0 / 0 |
| cluster_slots_pfail / cluster_slots_fail | 0 / 0 |
| cluster_current_epoch / cluster_my_epoch | E(role) / E(role) |

Barrier 3, six-connected-empty-masters-epoch-six: every view has the six-ID
normalized agreement from D2. Every row is a master, has parent "-", has no
slots and has epoch E(its role). Every keyspace counter on all six nodes is
zero. INFO required values are fail, known6, size0, assigned0, ok0, pfail0,
fail0, current6 and my=E(observing role). No replica, early slot, extra peer,
missing peer, alternative positive epochs or mixed gossip views may pass.

Barrier 4, exact-slots-with-empty-prospective-replicas: every view has the
six-ID normalized agreement from D2. All six rows are still masters with parent
"-" and epochs E(role). M1/M2/M3 each own exactly their manifest-assigned slot
range; these ranges are disjoint and cover all 16384 slots. R1/R2/R3 own no
slots. Require all six parsed keyspaces empty for this initial bootstrap
profile, including the slot-owning masters. INFO required values are ok,
known6, size3, assigned16384, ok16384, pfail0, fail0, current6 and
my=E(observing role). Premature replication and nonempty masters refuse here.

Barrier 5, exact-converged-topology-snapshot: reuse unchanged
bootstrap._classify(views, expected) and require already-converged. Its exact
rules remain authoritative: six-view normalized agreement, three expected
masters owning exact non-overlapping full coverage, three correct cross-host
replicas with no slots and each replica's published epoch equal to its master's;
master epochs are distinct and positive; INFO is ok/known6/size3/full assigned
and ok/zero failure counters, my=self's published epoch, and one common current
epoch at least the largest published epoch. Do not impose the initial 1..6
epoch assignment or current6 on this final barrier. Retained, nonempty legal
keyspaces and differing legal key counts/statistics across nodes remain valid,
exactly as in P1c. It does not prove replication links, lag, contents or health.

All predicates are exact single-barrier tests. A snapshot matching another
barrier refuses the requested one. No searching for the furthest phase, next
action, idempotent adoption, retry recommendation or executor precondition is
returned. Barrier 5 retains existing final semantics rather than an imagined
proof that barriers 1 through 4 happened previously.

**D4 — Exact detached API success schema.**

Return a fresh dict with exactly these keys and values; all flags use actual
booleans, schema_version is strict int 1 and all copied identities are strings:

```json
{
  "schema_version": 1,
  "lane": "offline-phase-validation",
  "result": "predicate-matched",
  "barrier_id": "the exact requested barrier",
  "origin": "the unchanged collection origin",
  "collection_id": "the original collection ID",
  "collection_sha256": "canonical validated original collection SHA256",
  "run_id": "the original run ID",
  "plan_sha256": "the original bound plan digest",
  "bundle_sha256": "the original bound bundle digest",
  "execution_supported": false,
  "phase_execution_supported": false,
  "live_ready": false,
  "live_runtime": "UNEXECUTED",
  "freshness_verified": false,
  "authenticated_authority": false
}
```

The placeholder descriptions above denote the already validated source values,
not accepted new literals. origin stays exactly ssh or mock-ssh from the original
collection; imported ssh is still an assertion, never an authenticated receipt.
collection_sha256 is labctl.digest of the detached validated original collection,
including its original raw strings, retained map, process and bindings. It is
an unkeyed source fingerprint only. Equivalent normalized topology with changed
raw presentation can match the same barrier but has a different fingerprint.
Do not hash normalized views or drop original provenance. No raw data, credentials,
expected map, actions, eligibility, admission or next phase is returned.

No result importer, persisted result format, output writer or second validator
API is required. Caller-edited result dicts confer no authority and cannot be
supplied back as collection inputs. No argument is mutated or retained by
reference; repeated calls with unchanged inputs produce equal results. No new
UUID, timestamp, clock read or temporal assertion is needed.

**D5 — Minimal private CLI and exact bounds.**

```text
python3 scripts/phase_validation.py validate
  --manifest PRIVATE_FILE --expected-bundle-digest INDEPENDENT_DIGEST
  --ownership PRIVATE_FILE --node-ids PRIVATE_FILE
  --collection PRIVATE_FILE --barrier EXACT_BARRIER_ID
```

No collection, plan, execute-approved, credentials, output, transport, remote,
mock, arbitrary command or mutation options. Disable option abbreviation. Help
and parse failures must sanitize untrusted option/argument/path values, as the
existing labctl.Parser pattern does. Do not print argparse usage/errors with raw
values or program-path echoes.

Private JSON files use absolute normalized paths, no traversal, no source-tree
paths, no symlink components and private owned 0700 immediate parents. Files
must be regular, same-UID owned, exactly 0600 and singly linked; reject FIFO,
device, socket, directory and symlink inputs without blocking. Use descriptor
and no-follow traversal consistent with existing helpers. No directories/files
are created and no existing file is changed.

Byte limits, including CLI whitespace and JSON escapes, are exactly:

| Input | Maximum file bytes and API canonical bytes |
| --- | --- |
| manifest / ownership / expected_node_ids | 1048576 each |
| collection | 2097152 |

Read at most limit+1 and refuse overflow even if fstat was smaller. Check file
metadata with the corresponding limit before reads; do not use old
labctl.file_stat/read_at on collections because they enforce the old 1 MiB cap.
Use a small new bounded private reader in the new module, reusing safe directory
walking/private-parent checks. Do not modify any old constant or helper. Reuse
collector_helper.decode with its explicit limit argument or an equivalent
strict decoder: duplicate keys, invalid UTF-8, nonfinite values, excessive
nesting and trailing non-whitespace refuse. A whitespace-padded valid collection
file larger than 1 MiB and no larger than 2 MiB is supported; its canonical
object must also satisfy the existing 2 MiB collection cap. The raw response
caps are unchanged and cannot be evaded by escaping or JSON envelope padding.

Success exits 0 and emits only the D4 fields lane/result/barrier_id/origin plus
execution_supported, phase_execution_supported, live_ready, live_runtime,
freshness_verified and authenticated_authority. No schema/bound IDs/digests,
paths, private node IDs/endpoints, raw responses or exception diagnostics appear
on stdout/stderr. Help emits these fixed flags with result=help and
actions=["validate"], without a barrier/origin echo. Any refusal or interrupt
exits 2 with the fixed flags, result=error and error=phase-validation-refused;
do not echo the requested barrier or distinguish private failure details. No
runtime outcome is reported as passed by this CLI.
