# SDD M7: foreground manual retained lab lifecycle

Status: proposed implementation contract; SDD-only baseline must be reviewed and committed before implementation. Execution results belong in STATUS. Scope is lab/CI operator tooling only. No host installation, machine account, service manager, detach, boot startup, resource limits, soak or provider changes.

## Outcome and authority

Retain one synthetic original-runtime application across distinct manual CLI invocations and foreground owner sessions. Reuse original pinned v0.2.4 artifact, source and SHA256 unchanged. Use existing fixtures/worker.js unchanged and lab.py constants INSTANCE/WORKER/FLOW, schema and deployment metadata. Trusted synthetic inputs only; no arbitrary code or outbound application workload. Linux x64, real non-root passwd home, matching readable PID namespace, Python3.11 standard library, loopback transport only.

M1–M6 remain disposable and unchanged. Add an explicit narrow component AGENTS exception: only M7 commands may resume an exact scope they previously initialized, using their matching private manifest and verified clean shutdown receipt; never adopt arbitrary scopes. M7 never automatically deletes state, including on failure. Scope remains passwd-home/.open-compute, not HOME relocation. Operator provides a new absolute --state directory outside scope/cache/output with owned no-symlink parents (immediate parent current UID, all ancestors current UID or root and not group/world writable; root-owned safe system ancestors allowed); directory mode0700, regular files0600/nlink1/currentUID. AF_UNIX path must fit <=100 encoded bytes, refuse before runtime starts otherwise.

## Files and fixed module interfaces

`trial_state.py` owns local manifest/lock/protocol boundaries only; never spawns/signals runtime or calls HTTP.

- `StateError(reason)` exposes fixed reason from schema/ownership/busy/dirty/protocol/io/deadline.
- `StateDirectory(path, *, create=False)` context manager: create=True exclusively mkdir0700; otherwise open existing root O_DIRECTORY|O_NOFOLLOW, validate UID/mode/device/inode. Both open fixed `owner.lock` nofollow regular0600/nlink1 and acquire LOCK_EX|LOCK_NB. Lock creation only on initial creation; later missing/changed lock fails. Lock held for full init/serve/destroy lifecycle. Contenders fail busy; never wait or replace lock inode. Constructor/context APIs may perform validation in __enter__, but must be used through with.
- `.load() -> dict`, `.save(manifest) -> None`: strict validate schema; read <=65536 bytes; atomic private same-directory exclusive temp write, fsync, replace and directory fsync while owner lock held; validate existing destination before replace, no symlink following. Failure leaves old or new complete record and fails the operation. A clean record may only be constructed after independently verified graceful exit; a directory-fsync failure after replace may leave those valid clean bytes, but cannot grant a passing command/report. No claim of power-loss transactional acknowledgement is made. Preserve interrupted temporary artifacts rather than treating them as authority. Init first save may exclusively create manifest. `.check() -> None` revalidates held root/lock identity before operations.
- `validate_manifest(value) -> dict`: return new canonical strict dictionary, reject extras, wrong types including bool-as-int, nonfinite/oversized numbers/strings and over-limit nesting. JSON parser rejects duplicates/nonfinite values. `validate_scope(manifest) -> OwnedScope`: reconstruct bounded OwnedScope from fixed passwd-home scope, recorded device/inode/marker/port and run check_owner. No create or remove call here.
- `encode_message(value) -> bytes`, `decode_message(data) -> dict`: one JSON object terminated by LF, <=16384 bytes including LF; reject extra frames/trailing bytes, invalid UTF8/duplicates/nonfinite/extras/types. Request/response schema below. No arbitrary Python object serialization.

`trial.py` owns CLI, foreground runtime, safe credential reads, finite local HTTP and Unix control owner/client. `main(argv=None) -> int`; `run_init(args) -> dict`, `run_serve(args) -> dict`, `run_destroy(args) -> dict`, `run_client(args) -> dict`; CLI prints one strict response object for finite commands; serve prints one ready response then one final response, no raw runtime logs. Functions raise bounded fixed errors internally. `trial_integration.py main(argv=None) -> int` owns original-runtime CI scenario using real separate subprocess CLI and a tracked foreground serve child. It alone emits aggregate acceptance evidence.

### Private manifest schema v1

Exact top keys: `schema_version`=1, `uid`, `trial_id` (32 lowercase hex), `scope`={device,inode,marker}, `port`, `binary`={path,sha256}, `fixture_sha256`, `identity`, `clean` (bool), `workflow` (null or object). `scope.marker` is 64 lowercase hex and private, never projected. Numeric IDs nonnegative integers; port1024..65535. Binary path absolute, nofollow owned regular safe-mode/nlink1 and locked artifact SHA verified before execution; compare artifact to checked-in lock, not merely manifest hash. `identity` is null during incomplete init, otherwise {instance_id,account_id,database_id,deployment}, where deployment is exact validated projection of lab.deployment_observation(...,with_r2=False), including bindings/runtime. Deployment exact keys deployment_id/version_id/script_etag/runtime/bindings; IDs bounded as below, script_etag64hex, bindings exactly [{type:d1,name:DB,database_id:<identitydatabase>},{type:workflow,name:FLOW,workflow_name:m1-flow,class_name:LabFlow}]. Runtime is deliberately opaque private JSON object (depth<=4, <=32keys perobject, keys<=64characters, strings<=256characters, arrays<=32items, total<=4096bytes, finite scalar values), preserved for exact equality only and never exposed publicly; no generic config execution. Resource IDs restricted [A-Za-z0-9_-]{1,100}; projection <=16KiB. Binary path <=4096UTF8 bytes; manifest total <=64KiB. Identity null or clean=false forbids later serve/destroy. No repair/reseed/recreation fallback.

`workflow` is null or exact {id,job_id,created_at,boot_id,created_monotonic,phase,nonce_sha256,completed}. IDs follow fixture bounds; created_at finite positive UTC epoch seconds; boot_id canonical lowercase UUID from bounded /proc/sys/kernel/random/boot_id read; created_monotonic finite nonnegative seconds. phase reserved/waiting/complete; reserved has nonce_sha256=null/completed=false, waiting has digest64hex/completed=false, complete has digest64hex/completed=true. Only one Workflow record per trial; any nonnull value refuses another workflow creation.

Before POST, require original job row callback_count0/completed0, save a durable reserved record with both clocks and boot identity. Do not POST unless save succeeds. After waiting/public committed callback and exact row/counter1/nonce checks, replace reserved with waiting. Any failure after reservation until confirmed waiting save permanently poisons this owner session: stop bounded, leave clean=false even after actual graceful stop. Later serve/destroy refuse reserved or dirty manifest; no rediscovery/reseed or second creation. Before approval similarly mark owner mutation in-flight; request/validation/save uncertainty poisons owner until explicit success is durably saved as complete. Lost client response after successful save is not re-executed; read-only status is the reconciliation path. Client never retries writes.

Approval uses original five-minute wait, never reset. Before resuming or approving a pending Workflow require same boot_id, monotonic_now>=created_monotonic, wall_now>=created_at, and absolute disagreement between wall elapsed and monotonic elapsed <=2 seconds. Require max(elapsed_wall,elapsed_monotonic)<270 (30-second completion margin); clamp approval/terminal polling to original remaining300s. Reboot/clock uncertainty refuses pending approval, not permission to reset the deadline. Complete workflows need no pending-clock validity. This is same-boot manual lab operation, not host reboot recovery.

Manifest `clean=false` is durably saved before ANY runtime spawn (including init); only verified exit0/no force/no observation error/all owned generations exited/observer drainage and scope validation, complete initialized identity, no reserved Workflow and no sticky mutation/save uncertainty permits saving clean=true. Record initial manifest with identity=null before init runtime. Abrupt owner crash leaves dirty and refuses future runtime/deletion; no automatic stale-PID adoption, orphan reclamation or recovery. Same-UID hostile mutation is not a security boundary. Destroy does not clear dirty to manufacture proof.

## Commands and protocol

All commands require --state PATH. Init additionally accepts --port (default8787), --cache PATH. Serve accepts --seconds (integer1..86400, default3600). Finite clients: status; submit --id ID --payload TEXT; read --id ID; workflow --id ID --job-id ID; approve; stop. Destroy is separate cold command. No command takes token/key/URL/SQL/code arguments.

Init acquires new state lock then existing lab.preflight(port), verifies pin/download/version, creates fresh bounded OwnedScope, saves dirty incomplete manifest, starts owned Process, uses same lab instance setup, creates one D1 schema, deploys original fixture, verifies Worker health and exact deployment identities. Gracefully stops runtime, verifies cold exit and scope marker, saves complete clean manifest. Failure retains scope/state; never finally-rmtree. Repeated init refuses without changing old state. Cache/state paths cannot overlap scope/each other or unsafe output.

Serve acquires owner lock, validates clean complete manifest/currentUID/pin/fixture/scope and cold runtime locks (ocd.lock, platform.lock, objects/backend.lock; release before spawn), saves dirty then spawns original foreground daemon using Process. No setup/create/deploy/reseed allowed. GET-only instance/account/database/deployment identity and Worker-health checks precede binding control.sock. Original deployment mismatch fails closed. Existing control.sock (even stale) is never unlinked before validation; a stale socket left by crashed owner is diagnosis, not restart permission. Create AF_UNIX socket inside held state root mode0600; record inode and only unlink exact own socket during owner cleanup. No TCP control server. Check process still alive/ownership each loop and before requests. Accept one client at a time, no work queue beyond listen backlog1; bad client request bounded and returns protocol failure without killing healthy owner. Linux SO_PEERCRED UID must equal owner UID. No peer receives token/marker/private paths. Client validates root/socket type/UID/mode, same UID peer and response schema. No connection retry after writes (lost response may mean committed operation).

Request exact object `{schema_version:1,command:CMD,args:ARGS}`. ARGS: status/read/submit/workflow as above (read {id}; submit {id,payload}; workflow {id,job_id}); status/approve/stop use {}. ID regex matches fixture ^[a-z0-9][a-z0-9-]{0,63}$; payload string<=128 UTF-16 code units (the unchanged JavaScript fixture length contract) and encoded request bound. Response exact object `{schema_version:1,command:CMD,result:passed|failed,error:null|ENUM,data:OBJECT}`. Error enum schema/ownership/busy/dirty/protocol/io/deadline/preflight/pin/bootstrap/deployment/runtime/workload/workflow/shutdown/interrupted/evidence/conflict/not_found. Data strictly projected by command; no exception strings/raw upstream errors/logs. Limit response16KiB, no freeform diagnostics.

Status data {running:true,daemon:{pid,start_ticks},instance_id,account_id,database_id,deployment_id,version_id,worker_healthy:true,workflow}; workflow is null or {id,job_id,status,nonce_sha256,completed}, verified by actual GET when present, terminal status fixed enum waiting/complete/errored/terminated/paused. Read/submit data {job,row_count}; job exact projected fields id,payload,callback_count,nonce_sha256,completed (nonce_sha256 null before callback, otherwise digest of nonempty actual nonce). Never expose raw step_nonce. Owner retains raw nonce only in memory/read response internally, validates hash across restarts. Identity IDs are synthetic and strictly validated; no private paths or credentials. Root may hash IDs in aggregate evidence. GET missing job maps fixed not_found; submit different payload maps conflict, no change. Workflow data {id,job_id,status:"waiting",callback_count:1,nonce_sha256}; approve data {id,job_id,status:"complete",callback_count:1,nonce_sha256,completed:1}; require original nonce/count/job/output. Stop data is Process.stop strict public projection {was_running,signal,forced,exit_code,all_owned_exited}; send final stop response after actual exit verification and clean-manifest save. Init/destroy data {initialized:true} / {destroyed:true}. Serve ready/final use command serve, data {ready:true} / {stopped:true,clean:true}; failure may use {}. Responses on failure use data={}.

Stop request, SIGTERM/SIGINT owner, or serve duration expiry initiates bounded stop; SIGINT/SIGTERM handling must not lose ownership transfer. Process.stop graceful30s and existing finite fallback; any fallback SIGKILL is containment only and fails M7, retains dirty state. Unexpected daemon exit fails; never marks a crashed/previously dead daemon clean. No automatic restart. Owner raw logs remain Process's bounded in-memory ring only (no persistent log sink); never printed/uploaded, no disk growth from runtime stdout. Disconnect can end owner; there is no unattended service promise. Unknown owner exit/dirty receipt needs manual diagnosis.

Destroy only when complete clean manifest, owner lock, no control socket, exact owned scope and nonblocking three cold locks pass. It removes only exact recorded scope under bounded safe-rmtree while locks held; never remove state root, owner lock or evidence. Leave private manifest intact after scope removal: repeated destroy refuses missing scope rather than adopting/recreating it. Partial removal fails and requires manual diagnosis. This is explicit retirement for new lab scope only, never general host cleanup.
