# RE-3 自動化可玩性驗收契約

Owner 於 2026-10-22 接受以自動化取代真人試玩門檻（issue #481）。不變動 RE-0～RE-2 遊戲規則，不新增第三方 runtime，不部署、不建 tag、不關 issue。

## 三層驗收

1. **固定瀏覽器旅程**：保留 `tests/browser_smoke.mjs` 全部既有斷言，兩隔離角色完成首輪、掛單／取消／互買及第二輪；涵蓋輪詢、遺失回覆後重載／重送、真伺服器重啟與貨幣守恆。桌面／手機截圖及結果保存。
2. **UI-only agent 探索**：新 context 的探索者只知道「試玩這個本機遊戲，完成畫面呈現的目標；可以操作兩角色」。不提供遊戲源碼、規則／路線文件、API／資料庫、預製成功腳本。控制器只允許可見文字、截圖、點擊、輸入、選項、捲動與切換角色。提供最長 20 分鐘／200 次互動預算，記錄前五分鐘的目標／下一步、操作與耗時、卡點／求助、每角色結果與截圖；至少完成一名角色首輪，並實際嘗試市場及第二輪。未完成的部分照實記錄，可由固定旅程證明流程存在，不能假報 agent 成功或真人結果。若發現阻斷缺陷，需修復並重驗；探索成功率不外推為真人成功率。
3. **標準庫策略模擬**：直接使用真實 SQLite Store 動作邊界，不另造經濟實作。固定 seeds 7／19／41，互補兩職業各完成三輪並互買補給；記錄步數、採集／製作／交易／塔路消耗、逐角色輪數、等待／拒絕與最終餘額。每動作核對貨幣總額＝建角補助＋首次獎勵，以及四物品來源／轉移／消耗；重開 DB 後狀態一致。另跑同職缺供應、過高價格兩種反例：在明定步數內停滯並列原因，不將策略失敗當作服務錯誤或隱藏。測試必須先觀察新增案例 RED，再實作 GREEN；故意破壞帳目或結果時驗收器須拒絕，防止只印 PASS。
