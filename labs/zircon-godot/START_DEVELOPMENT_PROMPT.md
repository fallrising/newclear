## 本項目優先順序

- 先整理 [SDD](docs/sdd/README.md)、[quickstart](docs/quickstart.md)、[既有證據](docs/evidence.md) 和固定上游來源；目前研究完成不等於遊戲已可執行。
- 從 AC-02 的最小建置／啟動切片開始：核對固定版本 SDK、外置合法資源與實際路徑，讓單機 server、一個 Godot client、一張地圖、一個角色連通。
- 接續 AC-03 登入／移動／戰鬥／掉落拾取，再補 AC-04 正常停啟保存與一項可撤回規則修改；按 P0–P4 依賴逐步驗收。
- VPS 可承載伺服器測試；Godot 客戶端仍需適合的圖形環境證據。不重寫引擎、不做完整 MMORPG／商城／分片，不用 Web 原型替代既定桌面目標；素材授權與來源保持清楚。

## 執行方式

1. 文檔先行：先讀本項目的 [AGENTS.md](AGENTS.md)、[SUCCESS.md](SUCCESS.md)、[README.md](README.md)、相關 SDD、任務板與最近證據；核對目前分支和程式，修正過時或互相矛盾的描述。分清「缺實作」「已有實作但缺驗證」「已知失敗」，不以 README、測試數或檔位推測完成。
2. 重用既有文件，補清主線目標、範圍／非目標、AC、最小依賴順序和驗證入口；在項目任務板記錄本次工作。文件足以指導下一個切片就開始實作，不把文件整理變成無止境規劃，也不另建第二套進度權威。
3. 拒絕過度設計：優先完成主線任務，選最小可用的端到端切片，沿用現有技術棧與責任邊界。沒有當前 AC 需要，不新增抽象層、框架、微服務、通用平台或周邊功能；後續願望另列，不擋住主線。
4. 行為修改先建立失敗案例，再實作到通過並必要重構；執行與變更相稱的原生測試、建置、整合與使用流程驗證。保留歷史失敗和未跑原因，不縮小既有 AC、不放寬門檻來湊完成。
5. 梳理文件後持續完成可執行的主線工作，不停在計畫或一個 health check。若有必需的外部輸入，精確指出缺項並繼續其他獨立工作；不能由等待推導已批准或已驗收。

## VPS 測試授權

需要 VPS 測試時，可自行從 `~/.ssh/config` 查找候選主機，檢查連線、CPU／記憶體／磁碟、現有程序／容器／服務及測試任務，選擇空閒且適合本項目的機器。不要只憑低負載判定空閒，也不要把整份 SSH 設定或憑證貼進報告。

Owner 已授權：必要時可以停掉機器上的測試服務（例如 ERU），騰出本項目測試資源，不需要為這類已授權停測再次詢問。操作前確認精確服務、用途及目前是否承載其他執行中的測試；記錄原狀態、停止／恢復方式並保留資料與設定。優先正常停止；涉及其他正在使用的任務先協調，不能確認用途就換機或釐清。測試後釋放本次資源並依記錄恢復原測試服務，驗證恢復結果；若無法恢復，保留明確接手資訊。

此授權涵蓋必要的隔離測試啟停，不等於刪除 ERU／測試資料、全域 prune、重灌主機、停正式服務、購買資源或正式部署。公開文件只記去識別證據，真實主機名、IP、帳號、私有設定及憑證留在 repo 外。需要 macOS、圖形介面、真人登入或特定外部系統的 AC，不能以 VPS mock 測試代替。
