## Summary

Implemented offline PostgreSQL backup creation, corruption verification, and restore into an explicitly named empty database. Native custom-format dumps hold the migration advisory lock, SHARE table locks and an exported snapshot. Preflight requires fully drained, terminal work and conservative stopped/confirmed/released ownership proofs; source records are never rewritten.

The shipped migration 016 catalog is independently pinned to PostgreSQL 18. The schema audit rejects undeclared types and other schema objects, changed columns/defaults/constraints/indexes/trigger definitions, migration drift and unexpected grants. System namespace exclusions use the exact pg_toast name and anchored numbered temporary-schema names; legal lookalike user schemas are rejected in both source and destination. Restore uses native single-transaction/exit-on-error mode, then validates exact schema and quiescence, leaves all runtime nodes drained and generates a fresh maintenance UUID. Sessions, login limits, model/tool tokens and the original maintenance identity are excluded; archive payloads/tombstones, export uncertainty, commands, audit and GC plans/receipts survive. Failed finalization leaves no usable maintenance identity.

Bundles use pinned descriptors, safe owned ancestors without ACLs, a private 0700 creation parent and bundle, and 0600 regular single-link files. Existing destinations are preserved. Symlinks, hardlinks, unsafe permissions/ACLs, FIFOs, invalid manifests and corrupted/oversized dumps are rejected. Completion failures remove only the new bundle's manifest and retain its dump for diagnosis. Native errors and public summaries contain no connection URL/password; tools use explicit environment connection parameters, bounded output and process timeouts.

## Risks and Follow-ups

Only PostgreSQL 18 with the shipped migration catalog is supported; subsequent migrations/catalog changes require deliberate pristine-fixture re-derivation and independent review. Native tools must match that server major. The operator must stop every writer and trust the backup source: hashes establish corruption detection, not authenticity of executable native database definitions. Native commands have a 300-second timeout; dump files are bounded to 8 GiB and manifests to 64 KiB. Restore does not recover external credential files, connector journals/fences, VM state or roles/tablespaces, start services, reset generations, replay exports or complete all disaster-recovery acceptance. No real database, deployed runtime, paid service, commit, push or publication was used by this worker.
