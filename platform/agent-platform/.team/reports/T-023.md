## Summary

Added a repeatable single-node rehearsal wrapper and seven focused tests. The wrapper always delegates to the existing PostgreSQL fixture runner for a new owned container. It ignores ambient database, provider, connector, model, export and proxy settings, pins Docker to the local Unix socket without changing Docker configuration/credentials, and requires the pinned native image to exist locally.

The rehearsal creates uniquely named source and restore databases after a strict dedicated-loopback database guard; cleanup checks their recorded database OIDs and ownership. Actual unmodified CLI subprocesses migrate, bootstrap, serve the loopback API and static entry/assets, execute a FILE/TEXT mock task in an independent worker, and restart the API and worker. Session/CSRF, exact archive bytes/hash, task/run/event persistence and command replay are verified through real HTTP. The existing local-mock path records one conversation, one local-mock message and one job attempt, with zero provider prompt operations; all counts remain unchanged after restart/replayed admission.

After stopping API/worker processes, the rehearsal changes only runtime drain flags, creates/verifies a real native backup and restores into the separate empty database. Real pg_dump/pg_restore run in an owned PostgreSQL18 client container through the existing test-only native-runner injection. This is not installed-host backup-create/restore CLI acceptance. The unmodified backup-verify CLI is separately exercised without DATABASE_URL. Restored durable tables, archive and history match; the original session is rejected, fresh login works, the maintenance UUID changes and both runtime nodes remain drained. Success evidence is printed only after the test runner and owned PostgreSQL cleanup succeed.

Wrapper interface: `python scripts/single-node-rehearsal.py [--directory PATH] [--web-dist PATH]`. The directory must be new; without it, temporary evidence is removed after printing the bounded JSON summary. `--web-dist` defaults to `AP_REHEARSAL_WEB_DIST`; without either, a minimal static fixture keeps platform discovery independent of a prior frontend build.

## Risks and Follow-ups

This is loopback HTTP with the existing fake/local-mock backend and synthetic data. It does not validate TLS, a service manager, reverse proxy, remote access, real provider/export credentials, a deployed database, VM/KVM lifecycle, or every M3/M4 acceptance item. Processes and HTTP waits are bounded. The wrapper gives its owned runner a SIGINT cleanup grace period; an unresponsive runner requiring SIGKILL reports `rehearsal_cleanup_incomplete`. Uncatchable hard kills cannot guarantee cleanup, and the wrapper does not perform broad-label cleanup or touch unrelated resources. Existing source/restore database ownership checks fail closed if ownership changes. No commit, push, merge, deployment or external provider action was performed by this worker.
