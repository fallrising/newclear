# Manual audit retention — T-089 Phase A contract

Design only, 2026-10-25, at merged event-retention baseline `ce81af8aef6e0faa4ef10d64d17b8d438c5d69a4`. Implementation, migrations and runtime acceptance are not released. This specifies the existing SDD §12 audit90-day requirement as a bounded manual operation. No deployment, scheduler, live data operation, dependency or broader AT-13/M4 completion is included.

## Policy decision and source trace

**Acceptable design without another product-policy decision:** an operator may explicitly approve deletion of any audit row whose created_at is strictly older than a cutoff at least90days before preview. Default/minimum90days, maximum36500days. Equality is retained. The action, actor, target or related run state does not introduce another retention hold. SDD already specifies audit retention; no source dependency requires inventing a terminal/cleanup/export hold here. An operator can choose a longer retention period or decline the preview.

Audit rows are authoritative records of recorded past actions; expiration intentionally removes that readable history. They are not the application's source for authorization, approval application, idempotency, ownership/recovery or dispatch. Do not describe them as a complete security log: for example rejected login attempts are rate-limited without an audit write. Preserving the tables below does not claim every past audit fact can be reconstructed after expiry.

Migration001:162 defines `audit_events(id uuid PRIMARY KEY, actor uuid REFERENCES operators(id), action text NOT NULL, target text, decision text NOT NULL, created_at timestamptz NOT NULL DEFAULT now())`. Actor is nullable; action/target/decision are unrestricted text. The only outgoing FK is actor→operators. No migration001..017 defines an incoming FK to audit_events. `target` is nullable untyped text, holding command/approval/run/service IDs or maintenance digests; it is not a run FK or proof that a particular resource is safe to reclaim.

## Proposed Python/CLI boundary

`audit_retention.preview(db, *, retention_days=90, limit=100)` and `audit_retention.apply(db, plan, *, approval_digest)` return bounded JSON-serializable plan/receipt. CLI `audit-gc-preview --retention-days 90 --limit 100` and `audit-gc-apply --plan PATH --approve DIGEST`, using the existing private DATABASE_URL environment and maintenance dispatcher. No new HTTP mutation/list route or browser feature. Use existing `agent_platform.cli` entrypoint; do not invent a package __main__ to make a test pass.

Reject boolean/float integers. limit1..100 bounds inspected rows, not only emitted candidates. Each operation's selected canonical-record encodings are capped at8MiB; plan/file at65536bytes. No new ingestion length restriction or index on action/target/decision. Existing statement10s/lock5s/connect/pool bounds remain; LIMIT does not claim bounded database scan/sort cost.

Plan exact fields: schema_version=`audit-gc-v1`, maintenance_id, created_at, expires_at, cutoff, retention_days, limit, byte_limit=8388608, candidates, approval_digest. Times are canonical UTC ISO strings with six fractional digits; expiry=created+1hour; cutoff=created-retention_days. Canonical JSON is `json.dumps(value,sort_keys=True,separators=(',',':'),ensure_ascii=True,allow_nan=False).encode('utf-8')`. Approval is SHA256 of this plan without approval_digest. Each ordered candidate has exactly `{id,created_at,encoded_bytes,record_sha256}`. Record hash covers the full canonical object `{id,actor,action,target,decision,created_at}`, with UUIDs canonical strings and nullable actor/target JSON null. Persist hashes/IDs/time/size, not the raw actor/action/target/decision in plans or receipts.

Preview selects a fixed `(created_at,id)`-ordered list with `created_at < cutoff LIMIT limit`, projecting only UUID/time/null flags and DB-computed UTF-8 octet lengths of action, nullable target and decision. Do not refill skipped rows from outside that fixed list. Before text materialization reserve `6*(action_bytes+target_bytes+decision_bytes)+512` bytes per selected record, conservatively including JSON escaping and fixed keys/UUID/time/null metadata. Skip an inspected record whose bound exceeds the remaining shared budget; later smaller records within the fixed list may still fit. An oversized first row does not permit scanning a replacement101st row; limit1 with an oversized row emits an empty plan. Oversized raw records remain unchanged without a new ingestion restriction. Fetch text only through checked-size `substring(convert_to(field,'UTF8') FROM 1 FOR bound)` bytea; require exact prechecked byte lengths/strict UTF-8 and verify actual canonical bytes fit before hashing one record at a time. No character-count substring for byte limits, whole-table materialization or raw-content copy in the plan. SQL sorting/scanning stays timeout-bounded.

Apply validates strict keys/types/UUID/hash/time/count/order/sums and detaches the bounded plan before waiting. Reject duplicate JSON keys, nonfinite numbers, malformed nesting/Unicode and oversized private files. Preserve private-file ancestor/ownership/ACL/no-symlink/hardlink checks:0700 parent,0600 plan. Errors are sanitized `audit_gc_*` codes; retain existing archive/event CLI errors and restore logging filters on exit.

Approvals are canonical digest-bound, not cryptographically signed: there is no signing key. Authority is the exact immutable database-issued plan plus explicit operator review/digest and trusted local CLI access. Content hashes detect changed approved records; they do not authenticate a plan against a malicious same-UID process or database superuser. Private file and trigger checks preserve the existing local trust boundary, not production authentication/authorization against those actors.

## Permanent evidence versus expired raw history

Migration018 adds immutable audit_gc_plans and audit_gc_receipts, following the existing digest/JSON/timestamp shapes. Plans have approval_digest text PK with lowercase64hex check, plan jsonb object NOT NULL, created_at timestamptz NOT NULL DEFAULT clock_timestamp(). Receipts have approval_digest PK/FK to plans, exact plan/receipt jsonb objects, transaction_id bigint NOT NULL DEFAULT txid_current(), created_at timestamptz NOT NULL DEFAULT clock_timestamp().

A minimal `audit_gc_tombstones` table has id uuid PRIMARY KEY, approval_digest text NOT NULL REFERENCES audit_gc_receipts(approval_digest), created_at timestamptz NOT NULL (original row time), record_sha256 text NOT NULL with lowercase64hex check, encoded_bytes bigint NOT NULL CHECK1..8388608, pruned_at timestamptz NOT NULL. It contains no actor UUID, action, target or decision. Tombstones/plans/receipts are permanent operation evidence and intentionally grow; they are not retained raw audit history or a claim of full content erasure/net storage reduction (especially for short audit rows). Hashes can be compared with a separately trusted copy but do not reconstruct or authenticate deleted text.

Receipt exact fields: schema_version, approval_digest, maintenance_id, pruned_at, candidates (exact approved candidate list), count, total_encoded_bytes. Record receipt.created_at=pruned_at explicitly. An empty approved batch may record its receipt and one fresh maintenance audit, reporting count0 honestly.

The same transaction performs: acquire locks; re-read DB time/identity; require created<=now<expires and exact issued plan; re-read only approved IDs and compare immutable fields/full hashes/encoding/cutoff; insert exact receipt; set transaction-local `agent_platform.audit_gc_approval`; insert exact minimal tombstones; delete exactly approved rows; append one fresh `audit_gc.apply` row through existing auth.audit with actor=None and target=approval_digest; commit. Recheck row counts; any failure rolls back receipt, tombstones, deletion and new audit together. No new/older eligible IDs can be added to an approved batch. New maintenance audit time is now, so it cannot be a candidate in the same90-day plan; after90days it can expire normally, while its minimal maintenance receipt persists.

Within validity, repeated apply requires exact issued/saved plan, strict complete receipt equality, every approved ID absent from audit_events and an exact candidate-matching tombstone set (ID/time/hash/size/approval/pruned_at), then returns the saved receipt without another delete/audit. It does not recompute hashes of vanished raw records or claim post-delete raw-content verification. A missing/changed tombstone, surviving/reinserted approved row or malformed receipt fails closed. Expired replay fails even if previously applied. Changed maintenance UUID rejects all pre-restore plans/replays before receipt lookup; preserved tombstones still prevent resurrecting expired IDs.

## Migration018 guards, locks and compatibility

Append `018_audit_retention.sql`; never rewrite001..017. No historical audit deletion or backfill of removed contents occurs on migration. Add an ordinary fixed-size `(created_at,id)` audit selection index, never a B-tree over unrestricted text. All table columns use existing backup-parser-supported uuid/text/bigint/timestamptz/jsonb; all functions have exactly `CREATE FUNCTION name() RETURNS trigger LANGUAGE plpgsql AS $$...$$`, zero arguments, security invoker, no config. No SQL digest helper, extension, view, enum, sequence or parser change.

Zero-argument row triggers reject UPDATE of audit_events; reject UPDATE/DELETE of plans, receipts and tombstones. Audit INSERT rejects an ID present in audit_gc_tombstones by its UUID PK, preserving normal uuid4 writers without scanning JSON receipts on every write. A tombstone INSERT guard requires the current local approval, receipt.transaction_id=txid_current(), exact issued/saved plan and candidate fields, matching current maintenance identity and receipt timestamp within plan/current validity. The audit BEFORE DELETE guard requires the same authority, OLD.id in its exact candidate, OLD.created_at equal candidate time, created_at<cutoff, and an exact same-receipt tombstone. Trigger checks are structural/transactional; the trusted application under locks verifies full content hashes first. Do not pretend triggers authenticate a malicious database owner who can alter schema/disable guards. There is no FK from retained authoritative control state to expired audit rows and no ON DELETE CASCADE to those tables.

Use existing advisory77310401 then77310402, followed by one fixed `LOCK TABLE maintenance_identity,audit_events,audit_gc_plans,audit_gc_receipts,audit_gc_tombstones IN EXCLUSIVE MODE NOWAIT`. Acquire no row locks first; any NOWAIT error aborts the whole transaction and releases partial locks. This excludes pre-existing ROW SHARE/ROW EXCLUSIVE audit writers but permits ordinary ACCESS SHARE readers. Unlike event GC, audit GC needs no run/job/binding locks because its eligibility does not read those relations. A writer already inserting audit makes GC fail safely; GC first lets that writer resume afterward. A command may hold job/run rows and wait to append audit, but GC never waits for job/run rows, avoiding the prior lock cycle. Ordinary auth bootstrap's77310402 and both older GCs'77310401→02 order remain compatible. Backup/migration hold77310401 before table locks, serializing their snapshot with complete pruning state. No implicit retry.

Independently derive/review the pristine PostgreSQL18 migration018 catalog fingerprint after the SQL is frozen and before updating backup.SCHEMA_SHA256. Existing migration017 pin is not valid for018. Keep backup schema parser, quiescence/private-path guards and EXCLUDED unchanged; native dump automatically includes remaining audit rows plus plans/receipts/tombstones. Restore to an empty target preserves them, regenerates maintenance identity and keeps runtime drained. Native restore must prove deleted raw rows stay absent, surviving rows/control state match, tombstones/receipt replay metadata persist and old approvals are refused. Restore017 bundles with matching017 application before explicit migration; current018 exact-version verification must reject old manifests.
