## Source call trace and distinct hazards

Paths below are component-relative, inspected at baseline `2c4abddf4ce69105d1b4ee8c894e8ef1835aa92f` (root must confirm the frozen source before release).

- `store.py:event` locks the run, checks `(run_id,source,source_event_id)` in `run_events`, increments `runs.last_event_seq`, then inserts. Migration001 gives unique source identity and `(run_id,seq)`. Deleting events alone breaks replay dedupe. No source-ID rewriting or new duplicate-payload conflict policy is permitted.
- `worker.py:execute_fake` stores assistant messages with their separate uniqueness, calls `event(...source='fake',source_id=observed['event_id'])`, and advances backend_cursor. Runtime/controls/cancellation/recovery/approvals/model/tool producers also call this helper. Static call search found no production consumer of the helper's returned payload. Preserve all backend cursor, message and command behavior.
- `Store.events` currently reads floor/last sequence and rows in separate statements under the ordinary transaction default. Atomic deletion alone cannot prevent a reader seeing an old floor followed by new rows. Use transaction-local `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ` before its first query, not a session/connection default change; commit/rollback restores the pool's ordinary isolation. Do not lock readers behind a producer's row lock.
- `api.py` event endpoint calls Store.events before starting SSE and for each follow poll. A stale initial cursor returns HTTP410 `events_archived`; expiry during a stream emits `stream_error`. `web/src/events.ts:56` maps that to 410; `App.tsx:923` fetches run snapshot, clears rendered events, sets cursor to floor-1 and shows the existing activity-retention notice.
- `test_control_plane.py:test_events_dedupe_concurrent_producers_and_retention_cursor` deletes rows by fixture SQL and moves floor; it does not exercise a retention product operation. Add meaningful product coverage without presenting that fixture as previous acceptance.
- `archive_retention.py:ELIGIBLE` protects ownership/recovery state AND any export reference to an archive. Event GC uses the ownership proof below, but does not copy the archive-specific payload/reference predicate. Export history reads archives and its own records, not replayable run_events; an export reference therefore does not protect redundant event payloads. Archive bytes and all export records remain untouched.
- `db.py:migrate` uses advisory77310401; archive GC locks77310401 then77310402 and its table list; backup create locks77310401 then all known tables SHARE and exports a snapshot. `backup.py` pins catalog fingerprint for migrations001..016, includes durable histories, excludes maintenance_identity and ephemeral tokens, and restore creates a fresh identity.

## Python and CLI boundary

New `event_retention.preview(db, *, retention_days=30, limit=100, event_limit=1000)` and `event_retention.apply(db, plan, *, approval_digest)` return JSON-serializable plan/receipt. CLI `event-gc-preview --retention-days 30 --limit 100 --event-limit 1000` and `event-gc-apply --plan PATH --approve DIGEST`; DATABASE_URL stays in private environment. No maintenance HTTP mutation endpoint. Existing authenticated run/events APIs and SSE shapes remain stable.

Strict integers (reject booleans/floats): days30..36500, inspected-run limit1..100, emitted-event limit1..1000. byte_limit=8388608 bounds the combined full-record and identity-record canonical encoding inspected by one operation, including unrestricted source/source_event_id/type and JSON escaping. Payload bytes are accounted separately and are necessarily below this cap. Candidate selection is the fixed two-stage algorithm below; limits do not promise bounded database scan/sort cost. Existing statement/lock timeouts still apply. No claim of immediate database-file shrink.

Preview writes only issued-plan metadata. Exact top-level fields: schema_version=`event-gc-v1`, maintenance_id, created_at, expires_at, cutoff, retention_days, limit, event_limit, byte_limit=8388608, candidates, approval_digest. Dates are canonical UTC ISO timestamps with six fractional digits; expiry=created+1h; cutoff=created-days. Every canonical encoding uses `json.dumps(value,sort_keys=True,separators=(',',':'),ensure_ascii=True,allow_nan=False).encode('utf-8')`, with integers as JSON integers and UUID/timestamps as canonical strings. Approval is SHA256 of the whole plan excluding approval_digest. Maximum plan/file bytes65536; reject duplicate keys, extra/missing fields, noncanonical UUID/hash/time, oversized/nested malformed data before work. Reuse private-file ownership,0700 parent/0600 file and sanitized connection diagnostics from existing maintenance CLI; generic file parsing may be parameterized without changing archive error behavior.

Each ordered candidate contains run_id, old_floor, last_event_seq, through_seq, first_created_at, event_count, payload_bytes, encoded_bytes, prefix_sha256 and identity_sha256. prefix_sha256 hashes the canonical seq-ordered array of records `{run_id,seq,event_id,source,source_event_id,type,created_at,payload_text}`. identity_sha256 hashes the canonical seq-ordered array of the exact same records without payload_text. Stream array brackets, commas and each canonical object into SHA256; do not collect the array. `payload_text` is PostgreSQL's exact text at preview/recheck, not client JSON reserialization. Both signed hashes/count/range are retained in the exact receipt; payload hash is used on first apply, identity hash remains checkable after deletion. encoded_bytes is the sum of both array encodings' lengths; payload_bytes sums UTF-8 payload_text only. Candidate order is `(first_created_at,run_id)` and first_created_at must equal the retained identity timestamp at old_floor. Apply checks only approved runs/ranges, never silently adds newly eligible runs. UUID/seq fields, counts and byte sums validate strictly. Refuse an oversized plan rather than emit unusable approval.

Two-stage bounded inspection, shared by preview and first-apply recheck:

1. Preview uses one static SQL query joining `run_events e ON e.run_id=r.id AND e.seq=r.event_floor`, applies the full ownership predicate and `e.created_at < cutoff`, selects only bounded scalar run_id/event_floor/last_event_seq/e.created_at, orders by e.created_at,r.id and uses `LIMIT limit`. The limit bounds inspected runs, not successful/emitted candidates. A missing floor row is not selected or repaired. Freeze that returned run list; no refill if a run is subsequently rejected. First apply instead restricts this static query to exactly the approved run UUIDs and requires the approved scalar values and order; newly eligible runs cannot enter. Database scan/sort work remains timeout-bounded, not O(limit).
2. Visit only that fixed list, sharing a total `event_limit+1` row-inspection budget across all runs. For each run select seq-ordered rows from its floor with `LIMIT remaining_inspections`, initially projecting only UUID/seq/timestamp and `octet_length(convert_to(source,'UTF8'))`, likewise source_event_id/type and payload::text. Each projected row consumes budget even when rejected; never refund or seek replacement runs. Check expected seq and strict cutoff before fetching text. Emit at most event_limit events; the extra inspected row is only lookahead. A gap in an inspected run rejects that run's whole proposed prefix; a recent row ends its prefix. No lookahead or budget permits jumping a gap.
3. Before materializing text, compute conservative canonical bound `6*(payload_utf8_bytes+2*(source_utf8_bytes+source_id_utf8_bytes+type_utf8_bytes))+2048` for both record encodings, plus array bracket/comma overhead. The fixed2048 covers both records' keys, UUIDs, canonical timestamp and signed-bigint sequence fields. Six bytes per UTF-8 byte safely covers JSON escaping including supplementary Unicode. Refuse materialization unless this upper bound fits the remaining shared8MiB inspection budget; do not refund budget after rejecting a run. If its first record cannot fit, skip that run; otherwise end its prefix before that record. This deliberately conservative policy can leave eligible data for a fresh preview.
4. Fetch unrestricted fields only as `substring(convert_to(field,'UTF8') FROM 1 FOR bound)` bytea, with a bound no larger than the prechecked length/remaining budget, never character-count substring. Require the returned byte lengths to equal the prechecked lengths, decode UTF-8 strictly, then canonical-encode one full and one identity record. Check actual encoded lengths including separators before hashing/retaining the candidate. Keep only one bounded record pair and fixed-size candidate metadata in memory. On first apply an exact approved range which no longer fits or matches any bound aborts the entire batch rather than shortening it. Receipt replay applies the same byte/row inspection discipline to identity-only records (bounded by their originally approved encoding).

## Eligibility and contiguous prefix

Only runs in succeeded/failed/cancelled with every associated job status=done qualify. Every active state, interrupted run and unfinished job is protected. Require no binding belonging to this run except its selected sandbox_id, no selected binding belonging to another run, and no other run referencing that sandbox_id. Then require exactly one proof:

1. Never allocated: cleanup_state=not_allocated, sandbox_id/backend_ref NULL, generation0, no binding or adapter operation for the run, and no job with nonzero generation/attempts or non-null lease_owner/lease_until.
2. Confirmed cleanup: run cleanup_state=confirmed; matching binding id/run/generation; binding desired/observed stopped and cleanup confirmed; matching reservation exists and released_at non-null. For openhands require cocoon-local and nonempty/non-pending provider_handle. For fake require fake-local and nonempty/non-pending handle or precisely `pending:<same-run-id>`; the latter is the existing fake lifecycle's confirmed stopped handle, not proof for real allocation. Missing/mismatched reservation, generation, node or handle fails closed.

Begin at event_floor. Select only a contiguous sequence prefix whose every created_at is strictly less than cutoff; equality is retained. Stop at the first recent timestamp, a gap or batch/byte cap; never remove an old row beyond a retained row. An existing gap at floor or within the proposed range rejects that run as inconsistent; do not repair historical data. A limited prefix can end before last_event_seq. All-events expiry sets floor=last_event_seq+1. Never decrease floor or reset last_event_seq; terminal status itself is not an age timestamp.

## Migration017, dedupe and atomic apply

Append `017_event_retention.sql`; never modify applied migrations. `run_event_identities` columns are run_id uuid NOT NULL REFERENCES runs(id), seq bigint NOT NULL CHECK(seq>0), event_id uuid NOT NULL, source text NOT NULL, source_event_id text NOT NULL, type text NOT NULL, created_at timestamptz NOT NULL. Constraints exactly preserve existing key shapes: PRIMARY KEY(run_id,seq), UNIQUE(event_id), UNIQUE(run_id,source,source_event_id). Backfill every tuple exactly from existing run_events under migration lock and offline migration procedure, then validate run_events FOREIGN KEY(run_id,seq) REFERENCES run_event_identities(run_id,seq), with default NO ACTION on update/delete and no cascade. A zero-argument BEFORE INSERT OR UPDATE row-trigger on run_events looks up that identity by its fixed-size primary key, requires a match, and verifies `ROW(NEW.run_id,NEW.seq,NEW.event_id,NEW.source,NEW.source_event_id,NEW.type,NEW.created_at) IS NOT DISTINCT FROM ROW(identity.run_id,identity.seq,identity.event_id,identity.source,identity.source_event_id,identity.type,identity.created_at)`; return NEW only on equality, otherwise raise. A separate zero-argument BEFORE UPDATE OR DELETE row-trigger rejects every identity change; ordinary producer INSERT remains possible.

No index includes type or the complete metadata tuple, and no new metadata/type length restriction is allowed. `store.event` passes kind directly; migration001 defines type as unbounded NOT NULL text and does not index it. A complete metadata UNIQUE/FK would newly subject previously valid long incompressible types to the B-tree tuple-size ceiling. PostgreSQL18 documents that ceiling as roughly a third of an index page after applicable compression ([B-tree documentation](https://www.postgresql.org/docs/18/btree.html)); preserving the old key shapes plus equality trigger avoids that compatibility break. Backfill validation explicitly compares the seven metadata columns by primary-key join before enabling the write trigger; it never builds a type index. The identity table stores no payload. Identities are permanent, immutable, backed up; this slice bounds retained payload history, not all database growth. Already manually deleted historical source IDs cannot be reconstructed: preservation starts with existing retained rows/migration017 and all subsequent events, and must not be claimed retroactively.

Producer uses its existing run FOR UPDATE lock, finds identity first and returns the existing event when present. If the identity's payload row was pruned, return the same event_id/run_id/seq/source/source_event_id/type/created_at with payload=None; never regenerate, reinsert or increment. Current callers ignore the return; add direct helper tests documenting the unavailable-payload return. For a genuinely new source identity increment sequence once, insert identity and event atomically with one explicitly shared created_at, preserving the original source identity and first-write-wins semantics. Do not retain payload in dedupe metadata or change adapter replay behavior. The fixed-size run_id/seq FK and seven-column equality trigger prevent payload rows from disagreeing with permanent identity metadata without indexing unrestricted type text; backfill precedes FK/trigger validation. Ordinary app SQL never mutates identities.

Add `event_gc_plans(approval_digest text PRIMARY KEY CHECK lowercase64hex,plan jsonb NOT NULL CHECK object,created_at timestamptz NOT NULL DEFAULT clock_timestamp())` and `event_gc_receipts(approval_digest text PRIMARY KEY REFERENCES event_gc_plans(approval_digest),plan jsonb NOT NULL CHECK object,receipt jsonb NOT NULL CHECK object,transaction_id bigint NOT NULL DEFAULT txid_current(),created_at timestamptz NOT NULL DEFAULT clock_timestamp())`. Zero-argument BEFORE UPDATE OR DELETE row-triggers reject all plan/receipt mutation. Receipt's exact fields are schema_version, approval_digest, maintenance_id, pruned_at, ranges, total_count, total_bytes; every range contains all signed candidate fields plus new_floor=through_seq+1, retaining both hashes/count/range exactly. JSON structure/strict bounds remain application-validated, not a new SQL digest helper.

The zero-argument BEFORE DELETE row-trigger on run_events returns OLD only if all of these database predicates hold: nonempty transaction-local `current_setting('agent_platform.event_gc_approval',true)` equals the receipt digest; receipt.transaction_id=txid_current(); receipt.plan equals the issued event_gc_plans.plan; receipt/plan/current maintenance_identity.id agree; plan/receipt schema_version is event-gc-v1 and receipt approval_digest agrees; receipt pruned_at equals receipt.created_at (apply inserts that explicit timestamp); created_at<=pruned_at<expires_at and the transaction's current clock is still within plan validity; and the OLD run_id/seq is inside an exact candidate old_floor..through_seq range whose receipt range matches all candidate fields, count=through_seq-old_floor+1 and new_floor=through_seq+1. Also require the permanent identity tuple for OLD to match all seven metadata columns. Otherwise raise an exception. A receipt from another transaction, wrong range, wrong identity or stale time never authorizes deletion. Apply sets the local approval only after inserting its receipt. Preserve ordinary producer INSERT and all existing archive triggers. This guard protects the application maintenance path; database-owner SQL authority is not a new security boundary.

Apply validates and detaches the plan before lock acquisition. In one transaction: lock, re-read database time/maintenance identity, require created<=now<expires, require exact issued plan, revalidate candidate eligibility/floors/last sequence/range, recompute both hashes/count/bytes, write receipt with explicit created_at=pruned_at, set transaction-local approval, delete exactly approved rows, advance each floor to through_seq+1, insert one audit action `event_gc.apply` targeting digest, commit. Check row counts and invariants; any mismatch/error rolls everything back. An identical replay within validity requires exact issued/saved plan equality, strict receipt structure/all expected fields, absent payloads throughout every approved range, floor>=saved new_floor, exactly event_count permanent identities spanning old_floor..through_seq, and recomputed identity_sha256 equality. Do not recompute prefix_sha256 after deletion or require receipt.transaction_id to equal the replay transaction; that requirement authorizes deletion only. A later valid GC can advance the floor while the immutable identity hash remains checkable. Replay never deletes again or adds another audit row. Expired plans fail even after successful apply, as existing archive GC does. Changed identity rejects pre-restore plans including receipt replay.

## Locks and concurrent operations

Use advisory77310401 then77310402, then one explicit `LOCK TABLE maintenance_identity,jobs,runs,sandbox_bindings,resource_reservations,adapter_operations,run_event_identities,run_events,event_gc_plans,event_gc_receipts IN EXCLUSIVE MODE NOWAIT`. All identifiers/order are fixed. EXCLUSIVE conflicts with ROW SHARE from SELECT FOR UPDATE as well as ROW EXCLUSIVE writes, while ordinary ACCESS SHARE readers remain allowed. This specifically prevents a producer holding a run row then waiting on GC's table lock while GC waits to update that row. It also covers the existing jobs-before-runs worker path and changes/insertion into every eligibility relation. No row locks are acquired before this entire table-lock statement succeeds; any candidate row locks are ordered by run UUID afterward. Any NOWAIT error aborts the transaction and releases every partially acquired table lock before returning; never catch it and continue in the transaction. Advisory waits retain existing five-second lock timeout. Report sanitized `event_gc_database_unavailable`; operator reruns preview/apply deliberately, with no hidden retry or partial success.

Producer that already holds a conflicting write lock makes GC fail closed. If GC locks first, producer waits; after commit duplicate replay finds durable identity, while new events allocate last_event_seq+1 and remain at/above floor. Appending a new event between preview and apply changes last_event_seq and rejects the approved candidate; there is no arbitrary prefix reinterpretation. Concurrent GC operations serialize through advisories. Backup holds77310401 before SHARE locks, hence cannot capture deletion without its corresponding floor/identity/receipt/audit. REPEATABLE READ event requests see one complete old window or the committed new floor/410; each follow poll is a new consistent transaction. A stale snapshot can return old committed events already read, which is safe; it cannot return a newly committed gap.

## Backup and compatibility impact

Do not learn the accepted fingerprint from a backup source. Keep all new tables in parser-supported simple CREATE TABLE forms with the explicit uuid/text/bigint/timestamptz/jsonb columns above; all public functions must use exactly `CREATE FUNCTION name() RETURNS trigger LANGUAGE plpgsql AS $$ ... $$`, zero arguments, security invoker, no function configuration. Use row triggers and ordinary UNIQUE/FK/CHECK constraints only. Add no public SQL digest helper, extension, view, sequence, enum or other parser-unsupported object, and do not change the backup parser in this slice. New constraints/triggers still change the independently reviewed catalog fingerprint. Native dump includes identities, plans and receipts by default; EXCLUDED stays unchanged. Restore keeps event_floor/last_event_seq, remaining payloads, dedupe and receipts, regenerates maintenance identity and keeps nodes drained. Native restore must prove both approved identity hash and receipt/floor persist, payload range stays absent, duplicate-source replay consumes no seq and the fresh UUID rejects old plans. Old001..016 backups must be restored using matching old application then explicitly migrated; current exact-version verification must reject their manifests, not silently accept them. No backward-compatible restore claim or real restore operation is made here.
