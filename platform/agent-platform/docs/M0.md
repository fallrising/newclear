# M0：OpenHands 契約驗證

本切片提供可以執行的相容性測試工具，不是平台 API／Web UI。2026-09-21 已在真實 KVM 主機通過固定 OpenHands × Cocoon 的五項 M0 gate，範圍與完整證據見 [KVM 驗收](KVM-VALIDATION.md) 及 [gate report](evidence/m0-gates-2026-09-21.json)。單一 probe 的 `full_m0_complete` 仍固定為 `false`；只有獨立證據匯總代表 M0 狀態。

本機 `make check` 為 45 tests，原始映像及 guest 各 14 項 Docker checks。早期 `kvm_permission_denied` 已由 operator 安裝／權限設定解除，[初期紀錄](evidence/new-host-2026-09-21.md) 保留歷史；[ready report](evidence/kvm-ready-2026-09-21.json) 為安裝後的實際 KVM API 12 結果。

## 執行

需要 Python 3.12+、本機 Linux Docker Engine、amd64 執行環境。Docker Desktop、遠端 Docker daemon 與 rootless Docker 尚未驗證。Docker 網路的容器 IP 必須可由測試程序所在主機連線。工具不需要 provider key、GitHub token 或主機目錄掛載。

```bash
cd platform/agent-platform
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
make check
agent-platform-m0 preflight
```

`preflight` 只回報本機先決條件；無可讀寫 `/dev/kvm` 時退出碼為 2。這不阻止下面的 Docker 契約測試，也不是遠端 sandbox 主機可用性的判定。

```bash
docker pull ghcr.io/openhands/agent-server@sha256:8d015443e480ce5fa0f6f0b21b8031d5b2115840805e28eac89f5d82799ea51b
make docker-smoke OUTPUT=.artifacts/my-first-run
```

每次使用新的輸出目錄。工具不自行拉取／更新映像；digest 不存在於本機時失敗。測試約 30 秒，首次映像下載另外計算。主機需有至少 2 GiB 可供容器使用的 RAM；實際啟動還有主機端程序開銷。

輸出目錄權限 0700，含 0600 的 `report.json` 和 `events.sqlite3`。SQLite 只保存事件 ID、順序和 payload hash，不保存對話文字、工具輸出或 API key。報告不包含 session token、完整上游回應或容器日誌。程式退出碼 0 表示 **Docker 契約通過且清理成功**，不表示 M0 全數通過。退出碼 1 表示執行失敗；清理失敗時報告列出此次建立的資源名稱供人工核對。

## 實際檢查範圍

1. `/ready`、必要 OpenAPI routes、映像 build SHA 與版本一致。
2. 未認證 REST 請求被拒絕；認證請求可以建立對話。
3. `run=false` 的訊息不會啟動 agent；明確 `/run` 後取得假模型結果並結束。
4. REST history 與 WebSocket 事件內容一致；兩次 reconnect replay 不重複寫入 journal 或再次啟動 agent。
5. 執行中的 `/interrupt` 轉成 `paused`；`/run` 可接續到 `finished`。
6. 重啟同一容器後保留歷史，並能接續新的使用者訊息。這不等於換一台 VM、VM checkpoint restore，或在任意工具中途恢復。
7. 刪除對話後讀取回傳 404；無論成功或例外，都嘗試刪除自己建立的容器、匿名 volume 與 network。

固定映像內執行原有 Agent Server；假模型以 Python 標準函式庫在容器 loopback 提供 chat-completions。測試限制 4 iterations、停用 autotitle、沒有註冊工作區工具。模型在一則測試訊息第一次呼叫時延遲，讓 interrupt 路徑可被測試；此切片不測付費模型、真實工具副作用或取消 billing 的時序。

容器使用非 root 映像預設使用者、`cap-drop=ALL`、`no-new-privileges`、2 GiB／2 CPU／256 PID 上限。Docker `--internal` network 限制對外連線；主機上的短期 loopback TCP relay 只轉送至該容器的 8000 port。沒有暴露 host port、掛載 Docker socket 或掛載使用者工作區。這些 Docker 設定不是 MicroVM 隔離驗收證據。

## 本次實測發現

**訂閱快照必須與持久化事件分開。** 此版本在每次訂閱時先送一個 `ConversationStateUpdateEvent`，`key=full_state`，並為它產生新的 ID；這個快照不在 REST history。probe 只將這一個首幀快照排除於 journal，其他事件照 ID 去重並核對內容 hash；同 ID、不同內容會失敗。未來平台 adapter 必須保留這個區別。

**interrupt 不是取消任務或釋放環境。** 上游只能證實 `paused`。平台的 `cancelled` 仍需由 sandbox 停止／資源釋放核實，不能使用此測試結果代替。

**不要讓重新導向轉送 session key。** REST 禁止 redirect 和環境 proxy；WebSocket 使用預先建立的 socket，因此 library 在 redirect 時會拒絕重新連線。session key 僅送在第一個 WebSocket auth frame，不放 query string。回歸測試覆蓋 REST／WebSocket redirect、環境 proxy、JSON 錯誤、事件衝突、分頁循環與失敗清理。
