# M2：真實 Cocoon／OpenHands 任務

本文件記錄 M2 合併時的行為。最新 worker 恢復與升級要求見 [M3 recovery](M3-RECOVERY.md)。

M2 完成 AT-02／AT-03／AT-10：Web 建立固定輸入的任務，獨立 worker 經 connector 配置 Cocoon VM，在 guest 內 checkout repository、啟動固定版 OpenHands、執行 terminal 工具，保存來源事件與 diff，確認 VM 停止後歸還容量。下一個切片為 M3。

**模型仍是固定 fixture。** 它只透過 OpenHands terminal 在工作區建立 `m2-result.txt`，內容為該 run 的 UUID。目標文字會保存，但不由真實模型推理；沒有真實 provider 呼叫、費用或通用程式任務能力。驗證通過只表示固定檔案修改的 assertion 通過，UI 另外標示專案測試未設定。

## 已實作

- `002_runtime.sql` 擴充 immutable profile 與 runtime catalog；不改寫 M1 migration。Profile 固定 OCI digest、`openhands` backend 與 `fixture:m2` model reference。
- API／worker 不持有 sandboxd root token、guest session key 或 host paths。私有 loopback connector 提供固定配置、準備、prompt、讀事件、收集結果與 release 操作；不接受任意 host shell、guest image 或 repository 路徑。
- Connector 使用 0700 state directory、0600 journal、fsync／atomic rename、單 process flock 與每 run lock。每項 mutation 先保存 intent；相同 payload 的完成操作可重送，未完成的操作拒絕重做。Generation 不符拒絕，release 開始後拒絕其他 mutation。這是保守的不重送契約，**尚不是完整 crash recovery**。
- 獨立 worker 最多四個並行工作；多 worker／fake 與 real 混用也共用四個 reservation 上限。每節點另外檢查 CPU／RAM reservation。每 VM 固定 4 vCPU／4 GiB，connector 檢查主機可用記憶體仍有至少 4 GiB 或總 RAM 20% 的保留，以及 12 GiB 可用磁碟。CPU 可在 runtime service 的 quota 內共享。
- 上游 HTTP／VM 操作在 DB transaction 外執行；worker 每 5 秒續 30 秒 lease，phase mutation 重新核對 ownership。結果不明時保留容量與 `interrupted`，不自動另建 VM、不重送 prompt。
- Sandbox TTL 一次申請 run deadline + 120 秒；不宣告支援 lease renewal。固定 none lane、zero-warm node，不新增 guest NIC 或 egress。
- REST history 是來源事件依據，平台 seq 與 backend cursor 分開。來源 ID 去重、丟失 cursor 回明確錯誤；不把 WS ephemeral full-state 當持久事件。公開內容每事件最多 16,000 字元，截斷有標示，私有 runtime state／認證值不送到 UI。
- Agent Server 對話與 bash state 放在 `.openhands-state`，與 repository workspace 分開。Diff 以純文字顯示、上限 256 KiB、含 SHA-256；結果 transaction commit 後才終態。完整 artifact store／download 屬 M4。
- Cleanup 同時要求原始 VMM PID＋start ticks 消失、VM record 消失、runtime/COW directory 消失、CPU scope 消失及 claim-list 無該 claim。只有 ACK 或 claim-list 消失不會釋放容量。
- UI 呈現執行方式、真實 tool events、結果與 diff。pause／resume／cancel／approval 控制禁用，actions API 驗證 session／CSRF／版本後回 `409 unsupported_capability:*`。M0 的 primitive 通過不代表平台已完成 M3 的安全控制流程。

## 設定與啟動

沿用 [M1](M1.md) 的 PostgreSQL、operator bootstrap、API 與前端。Python 使用 `requirements.lock`；Node 24.18.0 與 npm lockfile。先完成 [KVM 主機準備](KVM-HOST.md) 的 runtime 安裝。Connector 需要同一台主機讀取 sandboxd usage journal、固定 Cocoon config、`/proc` 與 cgroup，並使用已準備好的**專用 zero-warm node**；目前不支援把 connector 任意指向遠端 node。

管理員建立 repo 外的 0700 工作目錄與兩個獨立 0600 token files：sandboxd operator token 與 worker→connector token。不要把值放進 browser、CLI 參數、Git 或 PR。Connector 本身不需要 database 或模型 API key。

Repository 目前使用**管理員登錄的唯讀 Git bundle**，避免在無網路 guest 內引入額外 clone 憑證／網路政策。先在可信的 repository checkout 中產生包含指定 commit 的 bundle：

```bash
git bundle create /private/path/source.bundle HEAD
git rev-parse HEAD
sha256sum /private/path/source.bundle
```

Bundle 上限 8 MiB，每次使用重新驗證 SHA-256；guest 以非 root 的 `agentprobe` 使用者 fetch bundle 並 detached checkout 完整 SHA。Canonical URL 與 base SHA 必須精確匹配 catalog，UI 不能指定 host path。它不是直接從 GitHub 網路 clone，也不支援任意新 commit 自動取得。

私有 `connector.json`（0600）結構如下；替換實際 paths、完整 SHA 與已匯入的 OCI manifest digest：

```json
{
  "origin": "http://127.0.0.1:7788",
  "template": "registry.example/agent-guest@sha256:REPLACE_WITH_PINNED_DIGEST",
  "state_dir": "/private/path/connector-state",
  "terminal_launcher_file": "/private/path/terminal",
  "terminal_launcher_sha256": "REPLACE_WITH_LAUNCHER_SHA256",
  "connector_token_file": "/private/path/connector-token",
  "sandbox_token_file": "/private/path/sandbox-token",
  "cocoon_config": "/private/path/cocoon.json",
  "sandbox_data_dir": "/private/path/sandboxd",
  "repositories": [{
    "canonical_repo": "https://github.com/owner/repository",
    "base_sha": "REPLACE_WITH_FULL_COMMIT_SHA",
    "bundle": "/private/path/source.bundle",
    "sha256": "REPLACE_WITH_BUNDLE_SHA256"
  }]
}
```

目前版本須先依 [guest isolation 升級步驟](M3-GUEST-ISOLATION.md) 建立固定 launcher 並 pin digest。

啟動 connector，再於已載入 `DATABASE_URL` 的 worker terminal 登錄與執行：

```bash
agent-platform connector --config /private/path/connector.json --port 17888
# 另一個 terminal；只給 worker／管理 CLI，不需要給 Web/API：
export CONNECTOR_ORIGIN=http://127.0.0.1:17888
export CONNECTOR_TOKEN_FILE=/private/path/connector-token
agent-platform migrate
agent-platform register-runtime
agent-platform worker
```

`register-runtime` 透過已認證 connector 讀取 metadata 後寫入 catalog；若仍有 real reservation，拒絕修改。註冊後可在 UI 建立 OpenHands profile，選擇已登錄 repository 與 SHA。`CONNECTOR_ORIGIN` 空值時 worker 只處理 fake 任務；沒有登錄時 UI 不提供真實 profile。

執行中不要切換 connector state directory 或清除 journal。不確定操作會停止自動進度，完整 operator reconciliation／TTL 後容量回收工具仍屬 M3。直接重啟 worker 不會消除未知 reservation；不要靠手動刪 DB row 重新派送。

## 已執行驗收

- [真實 KVM report](evidence/m2-kvm-2026-09-22.json)：四個 live VM、第五個 queued、同名檔案不同內容隔離、五次 OpenHands tool edit、diff/assertion 保存、停止證據與容量歸還、replay 不增加操作。開始／結束均為零 live VM／claim。
- [彙整 evidence](evidence/m2-2026-09-22.json)：來源 hashes、測試版本、範圍與限制。
- AT-03：Chromium + 真實 PostgreSQL／HTTP，fake source 逐筆產生 100 events；瀏覽器離線後按 cursor 接續，畫面 seq 無缺口／重複，reload 後仍為 100 筆；prompt 與 allocation 各一次。測試使用 1 秒 stream lifetime，確保 offline 期間發生新連線失敗。
- AT-10：API 的 unsupported／版本／不產生操作驗收；瀏覽器確認四個控制禁用；component test 確認不可信 diff／HTML 僅顯示文字。
- 另測 journal 重啟、相同操作去重／不同 payload 拒絕、未知 allocation 不重送、RAM 上限、mixed adapters 四 slot 上限、清理 ACK 不足時保留容量、認證／Origin／大小限制與錯誤遮蔽。

```bash
make platform-check
make web-check
web/node_modules/.bin/playwright install --with-deps chromium
make browser-test
```

`browser-test` 使用專用 `agent_platform_test` database；若未提供 `TEST_DATABASE_URL`，runner 建立並清理 task-owned PostgreSQL 容器。測試會清空該測試 DB，拒絕其他 database 名稱。Browser fixture 不提供產品 API 測試後門；seed／producer 是獨立測試程式。

真實 KVM 驗收為明確 opt-in，不放在一般 CI：

```bash
python scripts/test-postgres.py python scripts/m2-kvm.py \
  --config /private/path/connector.json \
  --origin http://127.0.0.1:17888 \
  --output .artifacts/m2-kvm-new
```

需先啟動 connector，node 起始沒有陌生 VM／claims。測試 driver 在四個 guest 完成準備後同步放行 prompt，方便量測並行；每個 run 的實際配置、checkout、事件、result、release 都使用產品 adapter。它只清理自己建立的 run，不刪陌生資源。

2026-09-22 本機使用 M0 已固定的 OCI digest 與 Cocoon cache，沒有重建 guest 或啟動 registry；`localhost:15000` 不是常駐服務。Sandboxd user service 保留 24 GiB／8 CPU 限制，主機約 61 GiB RAM。測試結束後 connector／sandboxd 及測試 DB／HTTP server 均停止；私密 journal 與 cache 留作追查，不代表產品已部署。
