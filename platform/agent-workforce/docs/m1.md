# M1 離線控制核心

本切片使用 Python 3.11 標準庫、SQLite、單一可信 controller 和 FakeBackend。選定 FAKE 案例以持久資料觀察及受控 backend 呼叫計數驗證；完整設計的 AC 仍依 [verification](verification.md) 分層驗收。

## API 與邊界

| 模組 | 職責 |
| --- | --- |
| domain | Registry defensive snapshots；owner/revision/reference、canonical relative paths、可信 session/workspace 與 workflow assignments |
| admission | 純 grant、route evidence、scope、caller/origin、entitlement、deadline 和 message/turn/hop 准入 |
| storage_base | SQLite schema、單一資料庫 inode instance lock、RLock、巢狀 savepoint、JSON 64 KiB/depth40 限制及 audit rollback |
| store | 版本化 records、durable receipts、inbox/outbox、命令 identity 與用量觀察 |
| runtime_store | durable attempt intent、五層 reservations、lease/epoch/fence、停止證據及普通重啟恢復 |
| controller | 可信 records/grants 安裝、accept/dispatch、投影、reconcile/stop；I/O 留在 Store/backend 邊界 |
| fake | 合成 running/complete/accepted-with-lost-receipt、inspect/stop/finish 及呼叫歷史 |

`Controller(store, backend, *, clock, trusted_issuers)` 提供 `register`、`put_grant`、`accept`、`dispatch`、`receive`、`recover`、`reconcile` 和 `stop`。可信 operator/caller 由本機邊界傳入；訊息 body 的自報 caller、grant 或執行文字無法自行啟動工作。M1 不提供身分驗證服務。

單筆命令固定一個可信 SessionBinding 和 workspace。資源 key／capacity 由 registry 取得；其他 resource scopes 拒絕。API-origin hop 必須符合可信 job.step_hops；個人帳號的 agent-origin 和 replay 無法准入新執行。

## 持久性與執行規則

收件 receipt 先提交，再返回。穩定 identity 是 sender/message_id/recipient，完整 canonical JSON digest 不同即衝突；字典順序不影響 digest，recipient-list 順序有影響。到期訊息保留供觀察及去重。

命令 identity 是 job/step 和完整 normalized request、target／固定 route policy；renewable grant identity 不改變命令。相同命令重送不增加 message/turn，改動 input/AC、caller/origin/hop、operation、scope、session 或 route constraints 會衝突。Outbox 對 job/step 各自編碼，ACK 不產生新 message ID。

Dispatch 在交易內重查准入，保留 job/account/quota_pool/session/workspace 五層資源並提交 attempt/operation intent，然後才呼叫 backend。Shared pool 使用可信 entitlement capacities 的最小值； held snapshots 也採最小值。Session/workspace 各一個 slot；整個 workspace 採保守排他。

`dispatch`、`reconcile`、`stop` 必須在呼叫者的外層 Store transaction 提交後執行；外層交易仍開啟時會先拋出 StoreError，backend 呼叫計數為零，也不隱式提交呼叫者的交易。Store 的一般資料操作仍可使用巢狀 savepoint。

送出前再重查 current grant/route/binding/budget，以及 prepared attempt 的 lease、epoch、fence 和 operation identity。即使 grant 仍有效，profile 所限制的 prepared lease 到期也拒絕啟動，並以確定 never-started 證據取消原 attempt／釋放 reservations。已有 prepared attempt 的最後一次檢查只排除該 attempt 已计入的一次 turn；其它 attempts 保留在計數。確定尚未送出才可記錄 never-started proof／取消。Backend 可能已接受時，例外或 receipt 缺失保持原 operation 與 Unknown；再次 dispatch 不會重做。

Lease 到期、epoch 改變或 stale fence 拒絕 publication，並保留資源。已觀察的 expiry 有持久旗標，clock 回退不能恢復舊 lease；明確 reclaim 使用單调持久 fence，保持同一 attempt／operation。完整停止證據要求 exact operation、實際 boolean stopped/effects_resolved；部分或錯誤證據保留 slots。邏輯完成、撤權及 timeout 本身不提供停止證據。

普通 reopen/recover 保留 receipts、snapshots、原 IDs、結果及 reservation history。Unresolved prepared/running/stopping 轉 Unknown；已有 review/terminal 結果保留。Reconcile 僅 inspect 原 operation；constructor、idle、projection 和 replay 的 backend start 計數為零。Fake 完成停在 awaiting_review，外部 Done 不由 exit0 或結果文字推導。

## 驗證範圍

| 選定案例 | M1 部分與 oracle |
| --- | --- |
| FAKE-01 | 独立 worker/account/route/resource，跨帳號 shared pool minimum；DB reservations 與 start count |
| FAKE-02 | current route/evidence/revision/profile gates；拒絕時零 start |
| FAKE-03 | durable inbox/outbox/ACK、immutable command 去重及 transactional faults/reopen |
| FAKE-04 | trusted sender/grant/scope 與 session/workflow binding；拒絕時無命令或 start |
| FAKE-05 | accepted-with-lost-receipt 保留原 operation；重送零 replacement |
| FAKE-07 | all-layer capacity、expired lease/old epoch/stale fence、strict proof；未知 slots 不釋放 |
| FAKE-08 | canonical workspace aliases／排他，reviewer write/path guards；合成 scope 部分 |
| FAKE-10 | queue/pre-start grant expiry/revocation 及 audit failure；zero unauthorized start |
| FAKE-12 | durable replay/projection、personal origin gates、idle zero start；Kith live 未接線 |
| FAKE-13 | finite message/turn/hop/deadline、unknown usage 保持 null；API billing-class 合成准入 |
| FAKE-16 | ordinary reopen/epoch recovery，保留 data/result/ID/resources；無自動重新送出 |

這些是具名案例的離線部分。Full native resume／causal ContextPack、candidate hash/artifact ACL／review／publisher、backup restore 和 FAKE-06/09/11/14/15／FAKE-16其餘部分維持延期；全部 NATIVE/API/LIVE/SOAK NotRun。沒有 production authentication、OS/filesystem isolation、多 controller、worker daemon、真實模型或外部副作用的完成聲稱。
