# M2：有界原生 adapter 切片

這版以 Python 3.11 標準庫實作 Codex writer、Claude Code reviewer 的固定 profile、原生 JSONL 解析、私有 operation/session journal、有限程序執行與 M1 backend bridge。它是可獨立檢查的 M2 切片；完整 M2 尚未通過。

## 實際 API 與權威

| Port | 實際行為 |
| --- | --- |
| `NativeProfile` | 固定 provider／role、絕對 binary 與 hash、精確 model／版本、account reference、route/profile revision、workspace／physical binding、設定 digest 與 timeout；模型訊息不能傳 argv 或擴權 |
| `configuration_digest` | 觀察已知管理／project policy、Codex execpolicy 及 API/routing override presence；重查不匹配即拒絕。這不是完整 plugin audit、登入或 entitlement 證據 |
| `NativeRunner.run/inspect/stop` | intent 與 session claim 先 fsync，再使用同一 operation；重送、reopen、receipt gap 不重啟。stdout/stderr 合計最多 2 MiB，prompt 最多 3000 UTF-8 bytes，其他 JSON 最多 64 KiB |
| `ProcessSupervisor.execute/inspect/stop` | argv 無 shell，Linux boot identity/PID/start ticks/PGID/SID、pidfd exact signal、觀測的後代、有限 deadline 與輸出；缺 ownership 不按裸 PID 發 signal |
| `normalize_events` | Codex／Claude 各自 dialect；UTF-8、每行 64 KiB、總量 2 MiB、4096 events、JSON depth40，拒絕 duplicate keys／非有限數；缺原生終態／session／內容不算成功 |
| `NativeBackend` | `prepare/start/observe/resume/cancel/reconcile` 與 capability description；從 M1 已提交 command/attempt 讀可信綁定；以同一可信 clock 將執行 timeout 收窄到剩餘 lease/profile 上限。Native resume 回報未合格，不使用 latest／continue |
| `attest_effects` | 僅可信 operator 的 operation-bound 證據入口；模型的成功文字不構成授權或 proof |

CLI 原生終態、主程序退出、完整後代停止、遠端副作用與費用是不同事實。可信 `failed` receipt 可讓 Controller 記錄明確 native/tool 失敗；失敗本身不釋放五層 reservations。正常 terminal 也只到 `awaiting_review`，沒有外部 Done。

## 停止與恢復限制

實際故障測試證明：子程序可在首次 `/proc` 掃描前 setsid、關閉 stdio 並重新掛父程序。輪詢無法排除它。因此 generic supervisor 對任何已 spawn 的 operation 都保留 `stopped=False`；`leader_stopped` 僅表示主程序已退出。Timeout/cancel 會對可核對的 ownership 作有限停止，但不能因此宣稱所有後代或遠端工作已停止。

原生終態仍可被解析並封存，但所有 capacity holds 留下。缺完整停止 proof 時，`attest_effects`、native resume 及 fresh-session reconstruct 都被阻擋。新 session ID 不是解決未知工作的方式。Synthetic injected proof 只測 gate 邏輯，不提升原生 resume 能力。原 polling port 保持此 gate；另有下述明確選用的本機停止 port。沒有新增 daemon、全域 subreaper、持久主機設定或隔離承諾。

Reopen／inspect／projection 不呼叫模型。Operation intent gap 保留同一 ID；session 的 account、worker、job、role、workspace、route/profile/version 不匹配時不能接續。原生 session ID 和 raw events 只保存在受控資料。

Session claim 先於 operation intent 持久化；中斷的 claim 會阻擋新 operation，包括跳過待對帳 operation 而 resume 舊 parent 的情況。缺 claim 時最多檢查 4096 個 journal directory entries，發現舊 orphan operation 或超出界限就拒絕啟動，交由 operator 對帳。接收結果、採用 native session、停止程序與確認 effects 前，runner 都要求 process receipt 的完整 binding/signature 與 durable intent 相同；不匹配保留 unknown，也不授權發 signal。

## 原生 profile

Codex 使用明確 `never`、`workspace-write`、精確 model、JSONL 和持久 session；不使用 ephemeral、latest 或 bypass。命令局部排除 user routing configuration，保留 execpolicy 與 managed controls。Claude reviewer 使用 `dontAsk`、Read/Glob/Grep、必要 Write/Edit/Bash/delegation/MCP deny、strict MCP、管理政策與 project/local settings，保留持久 session。這些是原生限制與已觀察政策，不是每檔 OS ACL，也不保證完整 credential isolation。

真實 qualification 使用獨立 synthetic writer workspace／固定 reviewer 副本與明確 operator 範圍，直接測產品 runner。這是 production promotion 前的受控測試入口；M1→NativeBackend 的 grant／五層 holds／intent-before-start 另以合成事件和真實本機子程序測試。完整跨 writer/reviewer 協作仍屬 M3，沒有用開發 Grok/Cursor 成功替代產品 route 證據。

## 證據與未通過項

逐 route 觀測、實際版本／model、測試數與不確定值保存於 [M2 evidence](m2-evidence.json)。Raw native events、session/account mapping、invocation、ownership、失敗與原始檔案保存在受控交付 evidence；公開摘要僅含必要版本、方法、status 與 hash。

- WF-T-NATIVE-01／02：兩個新 fixture 都取得最終來源的必要工具／session 證據。Claude 的第二個 Read 有 matching tool result 和 permission_denials；Codex 的拒絕由相同 native session 持久紀錄的實際 call/output 證明，不能以 final text 代替。
- Codex stdout 串流省略巢狀 exec 失敗，所以產品 stdout-only receipt 仍顯示 complete；這不是完整 task 成功。補充 session 證據目前由驗收端核對，產品未自動匯入，不提升 route。Claude 受控拒絕則被產品正確記為 failed，沒有被 CLI exit0 掩蓋。
- WF-T-NATIVE-03：新 subreaper port 對兩次原生呼叫取得本機完整後代 closure；兩條固定原生 profile 另各通過獨立 cancel／timeout 本機 closure 與重開對帳；本機 helper 的 receipt gap／crash 有測試。中斷時遠端 acceptance／effects 保持 unknown，原生 parent-crash／lease 故障矩陣尚未完整通過；原 polling operation 仍 unknown。
- WF-T-NATIVE-04：兩條新 route 的重開／inspect／stop 回讀一致；實際 replacement／resume 請求在 unresolved effects 前被 gate 拒絕，沒有啟動模型。真正 native resume／reconstruct 仍 NotRun，不能自行 attest effects 解除前置。
- WF-T-NATIVE-05：Claude synthetic-secret 的拒絕讀取有實際事件，token 未進入原生輸出；Codex 此固定 workspace-write profile 沒有已驗收的逐檔讀取隔離。兩條 route 的 controlled auth-expiry 仍 NotRun：固定 native-login profile 沒有獨立受控 auth fixture，未改既存 credential／登入或偷偷換 API。
- API、LIVE、SOAK、完整 artifacts/review/publisher/ContextPack/backup、M3–M5、release/deploy 未在此切片完成。

模型 request/token、quota 和 actual billing 沒有來源時保持 unknown；CLI 啟動數不當作 provider request 數。所有意外拒絕、Failed、Blocked、NotRun、Unknown 必須留在驗收摘要。

Qualification 的 invocation source digests 固定當時觀測版本。歷史觀測不能提升後續版本。新 qualification 的 source/test digest 綁定本次最終來源，與歷史記錄分開；本機停止前置解除後仍須逐項通過其餘 route gate，不能盲目重跑原 operation。

## 明確選用的本機停止 port

`ReapingProcessSupervisor`（`native_reaping.py`）與原 supervisor 使用相同 execute／inspect／stop 介面，可由可信呼叫端注入 `NativeRunner(..., supervisor=...)`。預設 polling port 與既有 journals 不變；不能替舊未知 operation 補造新 proof。

每個新 operation 先持久保存 intent、helper request、nonce 與程式／interpreter digest，再啟動獨立的 Python helper。Helper 建立並核對程序專屬 Linux subreaper，發布 READY；parent 持久保存匹配的 boot/PID/start ticks 後才寫一次性 go。Payload 不繼承 journal/control descriptors。Helper 是唯一 waiter，使用 `waitpid(-1, WNOHANG | __WALL)`；立即 double-fork、setsid、非 SIGCHLD clone 與巢狀 subreaper 不靠輪詢猜測完整性。

正常 leader 結束、timeout 或 nonce-bound stop 都進入有界清理。`/proc` 只用於發現待停止的直接子程序，pidfd 核對 incarnation 後發 signal。只有關閉 fork 入口、已觀測 leader 結果且核心回覆 ECHILD，helper 才寫出完整 closure receipt。Parent 另核對 protocol、operation、request digest、nonce、helper identity、go 與 proof，並同步 receipt；payload stdout 的 JSON 不構成 proof。

Helper crash、缺失／不匹配 receipt、無法完成清理或不支援 Linux primitives 都保留 unknown。Reopen／inspect／stop 不重新執行 payload。任何 local closure 仍回 `effects_resolved=False`；可信 operation-bound effects 證據、M1 grants、五層 reservations、lease/fence 及 native continuity 前置均維持。這是合作式 same-UID journal 的本機子孫停止證明，**不是對惡意同 UID 程式的 sandbox**，也不涵蓋提交給既有外部 daemon／服務的工作或實際帳單。

本機合成程序測試不能取代 Codex／Claude 最終來源的原生資格驗證；兩條歷史 qualification 的 stopped/effects unknown 狀態保持不變。逐項結果以 [M2 evidence](m2-evidence.json) 為準。
