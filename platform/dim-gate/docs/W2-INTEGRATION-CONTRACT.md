| Transition | Authoritative rule |
| --- | --- |
| draft → submitted | Current requester scope, complete typed spec, catalog and target versions; no active allocation yet. |
| submitted → approved/rejected | Different actor, qualified Ops pool and all affected project/stage grants, mandatory reason. Approval atomically reserves quota; rejection creates no execution. |
| draft/submitted/approved → cancelled | Current requester, before execution; release reservation atomically. |
| approved → executing | Qualified Ops, current policy/catalog/target versions/quota/target lock, one new attempt and scheduler task. |
| executing → succeeded/failed | Shared logical clock; atomic success creates/updates canonical object/binding/Placement or failure retains previous active version, releases lock/reservation and preserves diagnostic history. |
| failed → submitted | Requester explicit retry, unchanged valid snapshot/targets and new independent decision; previous attempts preserved. Changed content becomes a new draft. |

ChangeExecution records changeId/attempt/state queued-running-succeeded-failed/targetRefs/plannedObjectIds/plannedBindingIds/stepResults/failureCode/start/completion/correlation. Stable planned IDs belong to the original change across retries. Five bounded steps validate/reserve/configure/register/verify join existing clock (one tick, no new independent timer). Resource failure scenario targets eligible authorized execution and fails at configure; no partial fake binding. Scheduler/integrity validate no ghost, duplicate, missing task or conflicting target.
