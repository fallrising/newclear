# Public API and Compatibility Review

`CloudTaskOrchestrator`, `CloudLifecycle`, `UnknownSubmitDecision`,
`DuplicateRiskAcknowledgement`, and typed lifecycle errors match SPEC-T004B. Public methods carry
CU-AGT-P0-02 rustdoc. The lower observation/resolution bridge remains crate-private, and no
generic `AgentBackend`, arbitrary executable/argv/path, retry callback, provider-cancel claim, or
diff authority was added.

The T004A public runner API remains compatible. Its T004A1 bridge is now consumed through one
private provider-specific port, and the temporary dead-code allowances were removed.

# Atomicity, Concurrency, and Recovery Review

The version-1 `cloud-lifecycle.json` record is bounded to 64 KiB, 32 validated phases, and 100
validated candidate IDs. It uses mode `0600`, effective-UID ownership, a regular single-link file,
no-follow reads, create-new temporary replacement, file sync, atomic rename, and directory sync.
Malformed, oversized, unsafe, linked, unknown-version, over-history, over-candidate, and impossible
records fail closed.

Every start observes lower readiness before committing `Submitting`, delegates exactly one submit
without holding the lifecycle mutex, then commits before returning. A different lower operation
restores the exact prior terminal bytes or removes and directory-syncs a prior-Idle file; injected
restore failure leaves fail-closed `Submitting` and returns `RecoveryRequired`.

Cancel clones the exact in-memory signal and waits without holding the mutex. Every post-submit
exit clears the signal and wakes waiters, including persistence failure. Pre-authorization cancel
is local-only, ambiguity after authorization is unknown, and cancellation of a known task records
`provider_may_continue: true`. The real CLI test proves process-group termination and reap.

Resolution requires the exact operation, durable reconciliation, a complete latest candidate set
for adoption, successful status inspection, or an operation-bound named acknowledgement for
abandonment. The lower ledger terminal commits before the upper projection. Exact adoption and
abandonment replay are byte-stable and issue no further lower read or resolution.

# Fresh Review Findings

The first fresh Cursor Agent implementation review returned `IMPLEMENTATION ACCEPTED` with no
blocker. Its observations led to added disconnect-during-submit, fake post-authorization cancel,
and complete restart-conflict partitions.

The final fresh document-driven review returned `ACCEPTED` with no blocker. Subsequent evidence
hardening added exact adopted/abandoned resolution replay, lower operation-ID mismatch, unchanged
unknown byte stability, no-op terminal cancel, and explicit history/candidate bounds.

# Non-blocking Observations

- The monotonic property test exercises the durable ledger transition boundary; the remaining
  orchestrator transition/concurrency paths are covered by focused example tests.
- Write failures after a lower/provider effect intentionally collapse to `RecoveryRequired`;
  load-time invalid/unavailable categories remain distinct.
- Repairing `Submitting` from a durable lower abandonment records the conservative intermediate
  `OutcomeUnknown` before `AbandonedUnknown`.
