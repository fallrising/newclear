# Scope

CU-CLOUD-P0-02 only: one E0 read of an accepted provider-managed task diff through the pinned
trusted process boundary. The reader returns bounded untrusted `CloudDiff` display data. It does
not parse or apply a patch, check out a repository, publish an artifact, execute repository code,
expose arbitrary executable/argv/path authority, or retry internally.

# Public API and Compatibility Review

`CloudDiffReader`, `DiffEligibleCloudTask`, `CloudDiffReadError`,
`CloudDiffReadErrorCategory`, and `CloudTaskOrchestrator::{diff_reader,diff_eligible_task}` are the
only new public surface. The authority has no public constructor, deserializer, raw-task-ID
conversion, or mutable field. The reader has no public constructor from runner configuration,
credential scope, executable, path, environment, or a raw task ID.

T004A's public `CloudTaskRunner` API remains unchanged. T004C reuses its private runner handle,
scope lease, process policy, sentinel validation, and supervisor. The existing submit/status/list
capture limits remain 64 KiB per stream; only the private diff invocation selects 2 MiB stdout and
64 KiB stderr.

# Security, Atomicity, and Process Review

Minting succeeds only from T004B's current durable `Ready` or `Applied` projection. Retrieval
acquires the same trusted scope lease, reloads both lifecycle and submit ledgers without recovery
or mutation, requires exact operation/task identity plus the configured environment and branch,
and accepts only lower `TaskRecorded` or `TaskAdopted`. The lease remains held until the diff child
is reaped, so an accepted runner operation cannot replace eligibility between validation and spawn.

The invocation is exactly `cloud diff --attempt=1 <TASK_ID>`. The shared launcher still uses null
stdin, non-TTY pipes, `env_clear`, only `CODEX_HOME`, the private non-repository cwd, a new process
group, parent-death binding, a 60-second deadline, two-second termination grace, and direct-child
reap. Both pipes continue draining after their retained limits.

T004C validates an already existing owned mode-`0700` no-follow `error.log/` directory immediately
before spawn. It never creates, repairs, chmods, replaces, or removes the sentinel. A real fake-CLI
test attempts the exact pinned append and proves it remains a no-op. E0 snapshots cover the submit
and lifecycle ledgers, lease file, configuration files, working directory, and sentinel while
excluding provider-owned `CODEX_HOME` bytes and host access timestamps under ADR-0003.

# Fresh Review Findings

The first fresh design review returned `DESIGN REJECTED`. It found that the original specification
did not define the authority mint API, wrong-scope/stale binding, reader construction, or
diff-specific shared-supervisor limits. The specification was repaired before test generation.
It also gained a validate-only sentinel rule because creating a missing sentinel would violate E0.
A second fresh design review returned `DESIGN ACCEPTED`.

The final fresh implementation review returned `IMPLEMENTATION ACCEPTED` with no blocker. Its
non-blocking observations led to added same-path environment mismatch, additional noneligible
terminal lifecycle partitions, and a durable-state snapshot around the real cancellation/reap
test. A real 60-second timeout test was not added: timeout and cancellation share the exact
`terminate_group` implementation, real cancellation proves that path, and the injected timeout
matrix proves its typed E0 projection.
