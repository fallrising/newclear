# Scope

CU-SES-P0-01 only: one process-lifetime, single-writer session lifecycle over the accepted
provider-specific T004 orchestrator. The runtime owns one active turn, one worker, bounded ordered
event history/fanout, explicit cancellation/recovery, and bounded status monitoring. It does not
own HTTP, WebSocket framing, browser authentication, P1 persistence, repository execution, or
generic backend conformance.

# Public API and Compatibility Review

The public surface is limited to the session runtime/config, typed snapshots/events/errors,
subscriptions, and their strong-ID projections. `P0CloudTaskId` is privately constructed from an
accepted T004 lifecycle display projection; it cannot be converted into lower task authority.
Invalid configuration identifies only a fixed `P0SessionConfigField` enum and never echoes a
rejected value.

T004's accepted public API was not changed. The concrete integration constructs the accepted
orchestrator and proves start through Ready, eligible diff read, and session shutdown through the
real public composition without network access.

# Concurrency, Atomicity, and Recovery Review

One mutex is the sole writer for session state, event sequence/history, queued work, and
subscriber registry. Blocking lower calls occur outside it. Intent/event commit precedes worker
admission, and a private claim-to-admit handshake rechecks cancel/shutdown before entering T004.
Explicit cancellation clears scheduled monitoring; terminal projections reject backward changes,
so a stale in-flight monitor result cannot overwrite a winning cancellation.

Startup inspects at most once and fails closed when provider-read state cannot reconstruct the
deliberately redacted durable task ID. Pending startup resumes monitoring. Checked provider-read
failures retain the exact last pending lifecycle, publish a safe category, and use bounded backoff;
nonprojectable lower failures stop without retry. Unknown submit is never automatically resolved or
resubmitted.

Subscriptions validate retained cursors and capture replay, snapshot/high-water, and the later-live
sender under the same lock. Full subscriber queues are removed by nonblocking publication and do
not delay or mutate the turn.

# Fresh Review Findings

The complete T005 decomposition received `DESIGN ACCEPTED` only after three rejected drafts repaired
durability/authentication, state-transition, cancel/shutdown, startup-observation, and subscription
handoff gaps.

The first implementation review rejected four concrete blockers: a stale monitor could overwrite a
terminal cancel; claimed-but-not-entered starts were not suppressed by shutdown; concrete T004
composition was missing; and `InvalidConfig` lacked a safe field enum. All four were repaired and
covered directly. The final fresh review returned `IMPLEMENTATION ACCEPTED`.

The reviewer noted two nonblocking points. The property model covers local start/cancel while the
broader deterministic suite owns lower-result/subscriber interleavings. Also, a lower-conflicting
cancel result can leave an internal cancel flag on an already-terminal turn; terminal state is
unchanged, no event is published, and the next accepted start replaces that turn record.

# Decision

recovery/cancellation, bounded nonblocking fanout, lower-before-upper durability, no automatic
retry, and no new filesystem/process/repository/artifact authority. T005B is now the sole Ready
production task.
