# Implementation and Boundary Review

The route authenticates the accepted application cookie, acquires the existing application-session
and process-lifecycle RAII admissions, validates exact Origin, rejects every non-HTTP/1.1 request,
and only then delegates version-13 upgrade validation to pinned Axum 0.8.9. All extractor failures
normalize to the exact safe 426 response; successful 101 responses retain no-store/nosniff.

The private socket runner accepts only one deny-unknown-fields subscribe object. It consumes the
accepted T005A subscription into prevalidated bounded replay frames, then polls the one lower live
receiver directly. It creates no production event queue and never assigns an `EventSeq`.

Application-session validity is checked before every application frame and at bounded idle
intervals. The subscription admission join is selected against peer control, monotonic
logout/expiry, and lifecycle shutdown. If a blocking admission completes late, its result is
discarded and its live receiver drops; the connection admission does not wait for it. A current
network write retains its ten-second deadline, server shutdown uses 1012, and terminal error
selection rechecks authentication/lifecycle immediately before serialization/send.

Every text frame is serialized completely before send and bounded to 64 KiB. Error types contain
only fixed codes/messages and safe optional sequence/version values. Binary/oversize/protocol
input, lower errors, cookies, Origin, prompts, diffs, device codes, provider output, and paths are
never echoed.

# Fresh Review Findings

The initial fresh acceptance review rejected the implementation for four material issues:

1. a blocking subscription admission could delay revocation and shutdown;
2. terminal error sends did not recheck the application-session/lifecycle;
3. HTTP/1.0 could reach the pinned extractor; and
4. fragmented bounds, gated shutdown/write/grace, subscriber-cap/unavailable mappings, repeated
   concurrency, and meaningful partition evidence were incomplete.

Commit `e965add` repaired all four findings and added direct deterministic coverage. Cursor and Grok
then produced no final verdict within the project owner's 80-second windows. Under the owner's
explicit fallback authorization, a new fresh-context Codex subagent reviewed the repaired HEAD
read-only and returned `IMPLEMENTATION ACCEPTED`.
