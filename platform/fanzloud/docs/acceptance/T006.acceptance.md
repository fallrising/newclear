over the accepted T005 HTTP and WebSocket contracts. T006 adds no provider, repository, execution,

# Spec-First and Test-First Evidence

The initial design review found atomicity, browser bearer, resynchronization, CSP/WSS, redirect,

Commit `63ae330` added all 12 exact SPEC-T006 test skeletons and made their Rust/Node compilation

# Implementation and Repair Evidence

The final controller:

- sends the opaque bootstrap bearer through an exact browser-compatible UTF-8-byte-to-ByteString
  conversion and never persists, logs, or places it in a URL;
- uses only fixed same-origin T005 routes with no-store, same-origin credentials, no-referrer, and
  fail-closed redirect behavior;
- validates exact success statuses, response/frame schemas, T005 error-code/status pairs, T005A
  state/projection combinations, Cloud task IDs, and both legal subscriber-lag shapes;
- incrementally bounds JSON, diff, and WebSocket bytes, rejects invalid UTF-8 and media types, and
  renders untrusted values only as text;
- adopts snapshot high-water state on required resynchronization, never retries a mutation, and
  fences late requests, automatic refresh continuations, disposed generations, and failed stream
  generations;
- publishes verification-code and diff clearing before relevant requests can complete; and
- provides no browser-selected execution, provider, repository, path, environment, branch,
  recovery, apply, artifact, push, or arbitrary network authority.

Fresh implementation reviews identified and drove narrow repairs for exact response compatibility,
automatic-refresh disposal, impossible snapshot combinations, volatile-display timing,
unsynthesizable `Submitting`, Cloud task-ID grammar, reconnect delay/UTF-8 coverage, and queued
callbacks after a terminal protocol failure. The final reviewed commit `d66d79d` latches a failed
socket generation before close and ignores its later open/message/error callbacks.
