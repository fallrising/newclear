# Scope

T030B's `CU-EVT-02` boundary: bounded, ordered, immutable SQLite event replay after one caller
sequence. Append, snapshots, reducer application, projection construction, live fanout, upcasting,
repair, and web framing remain outside this acceptance.

# Fresh Reviews

The initial fresh, read-only Grok design review blocked three overclaims or evidence gaps:

- statement-snapshot visibility had been confused with a `LIMIT`-truncated whole-batch page;
- bounded corrupt-row allocation lacked exact per-column gates; and
- Busy, Storage, worker failure, and page/chunk invariance lacked exact evidence.

The specification and test plan were repaired. A fresh rerun returned `T030B DESIGN ACCEPTED`.

A separate fresh, read-only Cursor Agent implementation review inspected the final public API,
query, decoder, errors, async boundary, and tests. It returned `T030B IMPLEMENTATION ACCEPTED` with
no blocker.

The implementation review recorded two non-blocking notes: hosted CI and this acceptance report
were still pending at review time, and the `StreamId` corrupt-row stage is enforced through exact
SQL filtering plus post-decode identity checks rather than a directly injectable integration case.
Both acceptance prerequisites are now satisfied or covered by inspection evidence.

# Security, Atomicity, and Recovery

Replay accepts typed stream/sequence/count values only, opens SQLite read-only, uses fixed bound
parameters, conditionally projects bounded bodies, and fails closed on malformed persisted input.
It executes no DDL, DML, journal-mode change, snapshot write, repair, or logging. Cancellation may
allow the bounded worker read to finish, but the result is discarded and Codebox application state
remains identical. Busy and transient storage reads may be retried because the boundary is E0.

# Decision

Accepted. Every T030B clause maps to executable or inspection evidence, the test-first history is
recorded, local gates and hosted CI pass, and independent fresh design and implementation reviews
found no remaining blocker. Snapshot work remains separate; T030D is still blocked until its
save-conflict, retry, and crash semantics are resolved through the TD/ADR process.
