# Outcome

A reproducible Rust workspace builds the four application boundaries named by TD §3.1 and enforces
the initial formatting, lint, test, build, and dependency-policy gates in CI.

# Inputs

- TD §3.1 repository boundaries
- TD §12 minimum CI and policy gates
- TD §15.2 T000 seed
- ADR-0001 infrastructure-only task contract exception

# Deliverables

- A workspace manifest with four explicitly listed binary members.
- A pinned Rust toolchain with `rustfmt` and `clippy`.
- Minimal warning-free binary entry points for `control-plane`, `node-agent`, `boxd`, and
  `codebox-cli`.
- A dependency-source, advisory, ban, and license-policy baseline.
- A GitHub Actions workflow that runs the machine acceptance commands.
- A committed application-workspace lockfile.

# Versioned Developer and CI Interfaces

- Rust toolchain: `1.97.1`, edition `2024`, with `rustfmt` and `clippy`.
- Dependency policy tool: `cargo-deny 0.19.4`.
- Workspace package names:
  - `codebox-control-plane`
  - `codebox-node-agent`
  - `codebox-boxd`
  - `codebox-cli`
- Machine acceptance commands listed below are the authoritative local and CI interface for T000.

# Non-scope

- Production behavior, library APIs, protocols, persisted formats, trust boundaries, and runtime
  integration.
- The future `crates/*` modules.
- The React/TypeScript application, which is owned by T220.
- Docker, node-agent RPC, `boxd` framing, providers, agents, storage, and deployment.

T000 introduces no production public boundary and qualifies for ADR-0001.

# Invariants

- No application receives runtime privileges or external dependencies during bootstrap.
- Adding a future workspace member is explicit; workspace membership does not use broad wildcards.
- CI and documented local acceptance run the same commands.

# Dependency Evidence

T000 has no dependencies. The repository began with only the Technical Design and its documentation
baseline.

# Decomposition

T000 is intentionally limited to repository infrastructure and four inert binary boundaries. Domain
types begin in T010; frontend work begins in T220.

# Machine Acceptance

Run from the repository root:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --all-features
cargo build --workspace --bins --all-features
cargo deny check
```

Acceptance requires every command to exit successfully from a clean checkout using the pinned
toolchain and `cargo-deny` version.

# Risks and Gaps

- The implementation environment initially lacks Rust and `cargo-deny`; validation requires their
  installation.
- CI service execution is external evidence and cannot be claimed until GitHub runs the workflow.
  Local execution of the identical commands is required before acceptance.
