# Outcome

Coordinate the independently accepted credential-scope and device-login child tasks into the P0
Codex login broker boundary.

# Inputs

- TD §§1.6–1.7, 2.2, 2.3, 8.2–8.10, 11.3 P14, and 15.0
- ADR-0002 §§Credential boundary and First execution interface
- T002A credential scope lease and isolation
- T002B Codex device-login lifecycle
- Current Codex manual: Configuration, Authentication, and Models; Authentication and sessions;
  Login on headless devices

# Deliverables

- Accepted T002A and T002B tasks and acceptance reports.
- Combined workspace and P14 security gates.

# Non-scope

- API-key or browser-supplied access-token login.
- Repository checkout, prompts, `codex exec`, `codex app-server`, Codex Cloud task submission, or
  repository-controlled process execution.
- Multi-user tenancy, credential sharing, token export, or persistent browser sessions.

# Invariants

- The broker runs only the administrator-configured Codex executable with fixed login arguments.
- `CODEX_HOME` is outside repositories and permission-restricted to the operator runner.
- Credentials never enter prompts, argv, general environment, logs, events, artifacts, responses, or
  downloads.
- At most one login operation owns an operator scope at a time.
- An interrupted login is reconciled through `codex login status` before any retry.
- The browser receives status or provider verification instructions, never credential material.

# Dependency Evidence

T001 and T010 are Accepted. T002 is decomposed because CU-AUTH-P0-02 is E1 while CU-AUTH-P0-01 is
E2; TD §9.3 forbids one implementation task from mixing those atomicity models.
