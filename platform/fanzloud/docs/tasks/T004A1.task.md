# Outcome

Add the narrow trusted composition bridge that lets T004B observe a caller-identified submit after
restart and durably terminalize an explicitly adopted or abandoned unknown operation without
executing another Cloud command.

# Inputs

- TD §§2.3 INV-006, 8.2–8.10, 9.2–9.3, 11.3 P15, 14, and 15.0
- ADR-0002 and ADR-0003
- Accepted T004A
- T004B design-gap review

# Deliverables

- Prompt-free, crate-private observation of one caller-created submit operation ID.
- Trusted, crate-private unknown resolution for a previously recorded candidate or an explicit
  abandonment decision.
- Durable adopted-task and explicitly-abandoned terminal phases that permit a later independent
  operation.
- Crash, replay, mismatch, candidate-validation, no-extra-exec, and ledger fault tests.

# Non-scope

Public recovery authority, authentication, acknowledgement creation, candidate selection, provider
status policy, lifecycle projection, HTTP, browser commands, provider-side cancellation, diff
retrieval, and general retry.

# Invariants

- Observation never requires or reconstructs a prompt and never executes a Cloud command.
- Resolution is unavailable until bounded reconciliation evidence is durable.
- Adoption accepts only a task ID in the exact latest durable candidate set.
- Abandonment records risk acknowledgement only at T004B; the T004A ledger records a redacted
  terminal disposition.
- Resolution is replay-idempotent for the same operation/decision and fail-closed for conflicts.
- No resolution path executes Cloud exec or authorizes an automatic retry.

# Risks and Gaps

This amendment is necessary because the accepted T004A public submit API intentionally does not
persist prompts, and its unknown ledger intentionally blocks new operations. The bridge remains
crate-private so only the reviewed T004B policy can decide adoption or abandonment.

# Design Review

The initial T004B preparation review rejected the accepted lower boundary for prompt-free recovery,
unknown terminalization, stale-decision binding, lifecycle durability, and cancel concurrency.
Two revised reviews found and closed the remaining lower-readiness and rollback-test gaps. The
final fresh, read-only review returned `DESIGN ACCEPTED` with no blocker and authorized T004A1 as
the sole Ready task.
