# Outcome

Retrieve one provider-managed task diff through the pinned trusted runner and return only the
bounded untrusted `CloudDiff` projection without applying it locally.

# Inputs

- TD §§2.3 INV-007 and INV-011, 8.2–8.10, 11, 14, and 15.0
- ADR-0002 and ADR-0003
- Accepted T003, T004A/T004A1, and T004B

# Deliverables

- Fixed diff execution over an accepted, scope-bound task reference.
- E0 success/failure snapshot tests and bounded draining.
- Redaction, no-apply, no-checkout, and no-artifact-publication tests.
- Proof that T004A's validated diagnostic sentinel prevents the pinned upstream write.

# Non-scope

Patch parsing, application, semantic path validation, repository checkout, artifacts, status
polling, backend conformance, and browser rendering.

# Invariants

- Diff text is untrusted display data and is never executed or applied.
- No local repository, workspace, credential, prompt, or raw diagnostic is returned.
- The child cannot claim E0 while a failure can mutate observable local state.

# Risks and Gaps

The first fresh Cursor Agent design review found that the original specification did not define the
task-authority mint, bind a reader to the minting orchestrator's trusted scope, require retrieval-time
lifecycle revalidation, or project the diff-specific capture limits onto the shared supervisor.
SPEC-T004C now closes those blockers before test-skeleton generation: only the orchestrator creates
the reader and opaque task authority, and retrieval validates the exact lifecycle and lower submit
records under the same held scope lease before spawn.

The pinned upstream Cloud client attempts to append `error.log` during backend initialization.
Ready/Applied provenance guarantees that T004A previously installed the private `error.log/`
directory sentinel. T004C must validate that existing sentinel without creating or repairing it;
otherwise the E0 read would mutate managed state. ADR-0003 defines the E0 snapshot over
provider-task and Codebox-managed state without reading provider-owned credential bytes. A version
change reopens the write assumptions for review. No `[TD-GAP]` remains.

[`ACCEPT-T004C`](../acceptance/T004C.acceptance.md) records all named tests, repeated
process-sensitive evidence, combined local gates, and the final fresh Cursor Agent
`IMPLEMENTATION ACCEPTED` decision.
