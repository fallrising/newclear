# Outcome

Serve one dependency-free, same-origin private operator page that performs the accepted P0 login,
prompt, replay/live status, explicit cancel, and final-diff flow without creating new execution,
provider, credential, or persistence authority.

# Inputs

TD §§1.7, 2.3, 7, 8–10, 14, and 15.0; ADR-0002; ADR-0004; accepted T005 HTTP/WebSocket
composition; and SPEC-T006.

# Deliverables

- Compile-time embedded same-origin HTML, JavaScript modules, and CSS with strict response security
  headers and no runtime filesystem/template/configuration input.
- A bounded browser controller for bootstrap exchange, login status/device flow, explicit prompt
  submission/cancel, replay/live reconnect, snapshot refresh, and text-only diff display.
- Dependency-free browser-controller tests using Node's built-in test runner plus Rust route/security
  tests, all integrated into hosted CI.

# Non-scope

Public or multi-user deployment, browser-selected environment/branch/repository/executable/argv/path,
provider credentials, local checkout/execution, `cloud apply`, automatic mutation retry, recovery
decision UI, crash-durable browser state, offline/service-worker behavior, editor, artifact, push,
approval, or generic P1 UI.

# Invariants

- Page load, refresh, WebSocket disconnect/reconnect, and error handling invoke no mutation.
- Only a direct operator action invokes bootstrap, device-login start/cancel, turn start/cancel, or
  logout; every cookie-authenticated mutation uses the current instance and a fresh UUID key.
- The bootstrap token, prompt, verification code, diff, cookie, provider secrets, and error sources
  are never persisted, placed in a URL, logged, or interpreted as HTML/script.
- The browser cannot choose provider/repository execution configuration or call an undeclared route.
- A client timeout, abort, redirect, or lost response never implies that an admitted T005 mutation
  rolled back. The controller never retries it and re-reads accepted state before another direct
  action.

# Dependency Evidence

T005 is Accepted in `ACCEPT-T005`; it is the complete API/stream authority consumed by this page.
T006 adds no server mutation and cannot bypass T005 authentication, Origin, instance, idempotency,
schema, lifecycle, or provider boundaries.

# Decomposition

One Contract Unit, CU-WEB-P0-01. Static transport/header behavior and the browser controller are
test partitions of the same UI trust boundary, not independent production authorities. Read-only
actions are E0; explicitly delegated mutations retain the accepted T005 per-endpoint atomicity.

# Machine Acceptance

The 12 exact SPEC-T006 tests cover static routes/MIME/CSP, ephemeral browser-compatible bootstrap
handling, login, explicit mutations and ambiguous responses, replay/reconnect/high-water
resynchronization, cancel/disconnect, streaming-bounded text-only diff rendering, refresh/restart,
exact HTTP status/code and optional WebSocket-lag shapes, redirect/error safety, forbidden
authority, semantic T005A snapshot/event consistency, pre-dispatch volatile-state publication, and
a generation-aware schedule model over every explicit mutation and automatic-refresh continuation.
Node tests use an explicit ESM
package boundary and Node's built-in runner without third-party packages; hosted CI runs the
literal command from SPEC-T006 before the Rust workspace gates.

# Required Documentation Updates

Update SPEC-T006, this task, traceability, HANDOFF, and `ACCEPT-T006`.

# Risks and Gaps

The first fresh read-only design review rejected blanket E0 atomicity, zero-cursor history-gap
loops, undefined browser bearer encoding, missing static MIME/WSS CSP mechanics, redirect/body
bounds, non-mechanical error handling, and unpinned Node/ESM acceptance. SPEC-T006 and TD §14 now
repair those blockers. A second review found five residual precision gaps; the final fresh-context
read-only review confirmed their atomicity, resynchronization, success-status, test-partition, and
production-module-import repairs and returned `DESIGN ACCEPTED`.

Implementation reviews then found exact response/status drift, stale automatic-refresh
continuations, impossible T005A state combinations, delayed volatile-display clearing, incomplete
Cloud task-ID and reconnect/UTF-8 partitions, and a post-protocol-failure callback race. Each
finding was reproduced or confirmed against accepted T005 behavior and repaired. The final
fresh-context read-only review at `d66d79d` returned `T006 ACCEPTED`; hosted CI run
30423184446 passed.
