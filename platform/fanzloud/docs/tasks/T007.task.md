# Outcome

Accept the complete private personal-BYOS P0 subscription slice with one deterministic,
network-free fake-Codex test across the concrete accepted T002–T006 composition, plus an explicitly
gated operator-authenticated live-smoke record that never claims success when credentials or the
private deployment environment are unavailable.

# Inputs

TD §§1.6–1.7 and 15.0; ADR-0002, ADR-0003, and ADR-0004; every accepted T001–T006 task,
specification, implementation, test suite, and acceptance report; and SPEC-T007.

# Deliverables

- One Linux CI integration test using the concrete credential scope, login broker, Cloud
  orchestrator, session runtime, HTTP control plane, static page route, and real loopback
  WebSocket against a deterministic private fake Codex executable.
- Exact end-to-end evidence for bootstrap, logged-in subscription status, initial replay, one
  explicit prompt, contiguous live lifecycle, terminal snapshot, bounded provider-managed diff,
  explicit logout, invocation policy, and secret/non-authority boundaries.
- A live-smoke procedure and acceptance record whose status is either genuinely passed with
  operator-supplied evidence or explicitly unavailable because its credential/environment gate was
  not satisfied.

# Non-scope

New production APIs, state transitions, provider adapters, browser controls, persistence,
credentials, public/multi-user deployment, local repository checkout/execution, private Git
credentials, `cloud apply`, automatic push, approval UI, recovery decision UI, synthetic live
credentials, or a claim that fake-Codex evidence proves live provider availability.

# Invariants

- The deterministic test executes no network request outside an ephemeral loopback listener and
  starts no executable except its exact private fake Codex fixture.
- The browser-side contract remains the accepted T006 exact request/frame contract. T007 proves
  its wire-equivalent sequence against the concrete accepted server/lower stack and does not add a
  second client or production route.
- The fake fixture matches the prompt only as the final exact `cloud exec` argv item required by
  T003 while production stdin remains null. Its invocation ledger records only bounded command
  classifications, never argv values, and proves exactly one Cloud submit, at least one status
  read, exactly one diff read, and zero `cloud apply` or arbitrary/repository command.
- Bootstrap, cookie, credential, prompt, provider output, diff, and private-path canaries appear
  only at their explicitly authorized boundary and never in snapshots, events, diagnostics, logs,
  URLs, or invocation records.
- The live smoke is manual, explicit, and side-effecting. It may run only in a private
  operator-controlled deployment after all required administrator configuration and live Codex
  authentication are present.

# Machine Acceptance

The exact test
`p0_subscription_e2e_fake_codex_reaches_final_diff` must be added as a compiling skeleton before
its assertions/fixture are implemented. It must pass alone, in ten consecutive runs, in the
control-plane package, and in every workspace gate. SPEC-T007 defines the exact partitions.

# Required Documentation Updates

Create `ACCEPT-T007`, update this task, SPEC-T007, traceability, and HANDOFF, and record the live
smoke as either passed with bounded nonsecret evidence or gated/unavailable.

# Risks and Gaps

The accepted P0 components have not yet been exercised in one deterministic path from static page
delivery and private HTTP/WebSocket authentication through a concrete fake CLI submit/status/diff
lifecycle. Live provider behavior also depends on operator credentials, provider availability,
private HTTPS deployment, and an administrator-selected environment; those are deliberately not
fabricated by CI.

The first fresh design review rejected an incorrect stdin prompt assumption. The accepted T003
contract passes the prompt as one final `cloud exec` argv item and T004A attaches null stdin.
Commit `58d644f` repaired the fixture and ledger rules; a second fresh-context read-only review
returned `DESIGN ACCEPTED`.

Commit `adf5d19` established the compiling, fixed-failure skeleton before implementation. The
deterministic test then passed alone, in ten consecutive runs, in the 37-test control-plane
package, and in the 179-test workspace. All repository gates and hosted CI run 30425447197 passed.
A fresh-context read-only final review returned `T007 ACCEPTED` at `2e54567`.

The operator live smoke was `not run — credential/environment gate unavailable`: all nine required
administrator variables were absent. No live-success claim or synthetic credential was created.
