# Outcome

Provide the first reusable domain crate with non-interchangeable entity identifiers, validated
workspace-relative paths, event sequence values, and typed value-construction errors. Downstream
tasks consume these types instead of passing interchangeable strings or unclassified failures.

# Inputs

- TD §4.1 cross-module identifiers and §4.3 state-machine values
- TD §8.2–§8.3 typed error and precondition rules
- TD §9.2–§9.6 task and specification protocol
- TD §16.1 CU-FS-00 seed specification
- ADR-0001

# Deliverables

- `crates/codebox-domain`, explicitly added to the workspace.
- Strong UUID newtypes for the entity identifiers named by TD §4.1.
- A validated, portable `WorkspacePath` value with deterministic normalization.
- `EventSeq` with checked successor behavior.
- Typed domain errors for invalid IDs, paths, and sequence overflow.
- Serde round-trip support that cannot deserialize a nil ID or invalid workspace path.
- Rustdoc contract projections and executable unit, serialization, and compile-fail tests.

# Non-scope

- Event persistence, database schemas, HTTP protocols, provider adapters, filesystem access, and
  symlink inspection.
- Authentication, authorization, secret handling, and runtime policy enforcement.
- Arbitrary path canonicalization against a filesystem.

# Invariants

- Different entity ID types are not interchangeable at compile time.
- A constructed entity ID is never nil.
- A constructed workspace path is non-empty, relative, portable, and bounded.
- Value validation is deterministic and has no external side effects.
- Invalid external values return typed errors; constructors do not panic.

# Risks and Gaps

The portable path maximum of 4096 UTF-8 bytes is a local specification choice recorded as
`[NEW-SPEC]`; it does not claim a filesystem-specific maximum. Symlink safety remains explicitly
outside this task and belongs to the filesystem execution tasks.
