# Outcome

Define the first versioned durable session-event schema and a pure deterministic reducer that
reconstructs the required session projection while rejecting stream, sequence, schema, transition,
turn, and approval inconsistencies. Separately classify high-frequency runtime deltas as ephemeral
so downstream persistence cannot mistake them for durable domain events.

# Inputs

- TD §§4.1–4.5 command/event separation, session state machine, and projections
- TD §§8.2–8.10 typed errors, archetype questions, E0 atomicity, and trace rules
- TD §§11.1–11.4 test generation and required regression P7
- TD §14 `CU-PROTO-01` and `CU-PROTO-03`
- TD §§15.1–15.2 T020 task graph and seed outcome
- Accepted T010 domain values and errors

# Deliverables

- Version-1 `DomainEvent`, `NewDomainEvent`, and `DomainEventEnvelope` value types in
  `codebox-domain`.
- A session-event schema covering the exact TD §4.2 state transitions without provider, tool,
  storage, web, or sandbox adapter behavior.
- `SessionReducer`, `SessionProjection`, `SessionStatus`, and typed `SessionReducerError`.
- Pure, immutable `SessionReducer::apply` with contiguous-sequence, same-stream, supported-version,
  legal-transition, active-turn, and pending-approval enforcement.
- A pure runtime-event persistence classifier that marks semantic domain events durable and text,
  reasoning-summary, terminal, and tool-output deltas ephemeral.
- Serde fixtures, table-driven transition/error tests, property replay determinism, E0 failure
  snapshots, and named regression `regression_ephemeral_not_persisted`.
- Rustdoc contract projections, task/spec/acceptance records, handoff, and traceability updates.

# Non-scope

- `CU-EVT-01` append, `CU-EVT-02` replay, SQLite, transactions, snapshots, conflict resolution,
  event-ID uniqueness enforcement, persistence across restart, or any other T030 storage behavior.
- Command dispatch, actor leases, fencing, idempotency receipts, or T040 session-actor behavior.
- Conversation, web, provider, tool-ledger, approval-policy, sandbox, artifact, or usage
  projections.
- Delta buffering, coalescing, transport, backpressure, or artifact storage.
- Upcasting an older persisted schema or accepting an unknown future schema.

# Invariants

- An accepted event belongs to exactly the reducer's session stream.
- Accepted event sequences start at one and are unique, contiguous, and gap-free.
- The first accepted event is `SessionCreated`.
- The projection follows only the legal TD §4.2 state transitions.
- At most one turn is active; turn-bound events must name that exact turn.
- At most one approval is pending; resolution must name that exact approval.
- Unsupported schema versions never mutate or advance the projection.
- Replaying the same valid sequence from the same empty reducer produces an equal projection.
- High-frequency deltas are classified ephemeral and are never represented as `DomainEvent`.

# Risks and Gaps

The exact first-event rule, version-1 state-transition payloads, immutable reducer shape, error
precedence, and highest-sequence `occurred_at` projection are `[NEW-SPEC]` local derivations needed
to make the TD state machine executable. They do not add persistence, side effects, security
authority, retry, or recovery behavior.

No unresolved `[TD-GAP]` blocks T020. Event-store conflict, transaction, restart, and replay paging
semantics remain owned by T030.
