# Outcome

Create the P1 SQLite event-store crate and implement an E1 append boundary that assigns globally
unique event IDs and contiguous per-session sequence numbers under one expected-sequence
transaction.

# Inputs

- TD §§2.3 INV-003/INV-004, 3.2, 4.4–4.6, 7.4, 8.1–8.10, 11.1–11.4, 14, 15.1–15.2, and 16.2
- Accepted T010 IDs/sequences and T020 version-1 event schema

# Deliverables

- `codebox-event-store` workspace crate.
- Version-1 SQLite initialization with a fixed application/schema identity.
- Exact `SqliteEventStore::append` projection of `CU-EVT-01`.
- Typed bounded errors and rustdoc contract projection.
- Contract, concurrency, transaction-fault, duplicate-ID, restart, limit, and path-security tests.

# Non-scope

Public replay (`T030B`), snapshot load/save (`T030C`/`T030D`), reducer validation, session actors,
command idempotency, migrations from a prior event-store schema, backup, encryption, or network
storage.

# Invariants

- Empty or oversized batches never begin a database transaction.
- Successful batches assign exactly `expected_seq + 1..=expected_seq + N`.
- Event IDs are non-nil and globally unique; `(stream_id, seq)` is unique.
- A sequence conflict returns the committed actual sequence and makes no change.
- Serialization, constraints, busy failure, cancellation, timeout, and crash cannot expose a
  partial batch.
- A committed batch survives store drop/reopen and is encoded for T030B replay.

# Dependency Evidence

T020 is Accepted at merge commit `c4b0b73`; `DomainEventEnvelope`, `NewDomainEvent`, `EventSeq`, and
the exact version-1 serde schema are available from `codebox-domain`.

# Decomposition

T030A owns only the E1 append transition plus inseparable adapter initialization. Replay and
snapshot public methods remain separate child tasks because their atomicity and test partitions
differ.
