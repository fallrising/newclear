# Outcome

Implement bounded, ordered E0 replay of committed durable events after a caller-supplied sequence.

# Inputs

TD §§4.4–4.6, 7.2, 8.1–8.10, 11.1–11.4, 14, and accepted T030A.

# Deliverables

`load_after` with typed limit/corruption/storage errors and empty, one, many, limit, order,
cross-stream, restart, cancellation, and no-mutation tests.

# Non-scope

Append, snapshots, live fanout, web frames, upcasting, or reducer application.

# Invariants

Replay returns only the named stream, only sequences greater than `after`, in strict ascending
order, without mutating the database.

# Dependency Evidence

T030A is Accepted at implementation commit `16b468b` with accepted-tree commit `0ddba62`.
`ACCEPT-T030A` freezes the version-1 SQLite event-row codec used by this read boundary.

# Decomposition

One E0 `CU-EVT-02` boundary.

# Machine Acceptance

Focused event-store replay tests plus all workspace gates.

# Required Documentation Updates

Normative contract: [`SPEC-T030B`](../specs/SPEC-T030B-sqlite-replay.md). Traceability, rustdoc,
handoff, hosted CI, and [`ACCEPT-T030B`](../acceptance/T030B.acceptance.md) record the accepted
boundary.

# Risks and Gaps

The 1–256 page limit, bounded corrupt-row decoder, statement-snapshot semantics, and read-only
connection are reversible `[NEW-SPEC]` details. No unresolved security, atomicity, retry, or
recovery decision blocks implementation.
