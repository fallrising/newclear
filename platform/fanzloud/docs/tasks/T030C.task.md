# Outcome

Load an absent or present versioned session snapshot cache through an E0 bounded-resource boundary.

# Inputs

TD §4.6, accepted T030A/T030D schema and snapshot type.

# Deliverables

`load_snapshot` with absent, present, stale, corrupt, restart, bound, and no-mutation evidence.

# Non-scope

Snapshot production, saving, public reducer restore/import, history repair/deletion, or cache cleanup.
Internal prefix replay for persisted provenance is required by the accepted T030D design;
it is not a replacement for public A/B replay or caller-owned suffix reduction.

# Invariants

Load never mutates durable history, and a snapshot is never represented as source of truth.

# Dependency Evidence

The [ADR-0005](../adr/ADR-0005-snapshot-cache-contract.md)/
[SPEC-T030D](../specs/SPEC-T030D-sqlite-snapshot-save.md) codec/trust/schema design is accepted.
T030D runtime is Accepted. This child remains blocked pending its own complete SPEC-T030C
and independent design review.
The shared matrix assigns public load/C assertions here; they do not block D acceptance. T030C has no implementation or acceptance.

# Decomposition

One E0 `CU-EVT-03` boundary.

# Machine Acceptance

Focused snapshot-load tests plus all workspace gates.

# Required Documentation Updates

Create `SPEC-T030C`, traceability, rustdoc, handoff, and `ACCEPT-T030C`.

# Risks and Gaps

Accepted design S09/S10 defines absent/corrupt/unsupported cache **values** as miss (structural lookup-key/schema/index/physical
damage remains store error), corrupt observed history as
error, pinned read transaction, verified replayed projection, and cache-sequence budget S<=4096
even behind larger H. No direct import into private reducer/projection is permitted.
T030C still needs its own complete E0 SPEC-T030C and review; it is not Ready.
