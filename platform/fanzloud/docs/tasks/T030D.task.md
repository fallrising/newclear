# Outcome

Implement the accepted versioned, discardable session snapshot cache save contract with
verified concurrency, failure and recovery evidence.

# Inputs

TD §4.6; accepted T020/T030A/T030B; accepted [ADR-0005](../adr/ADR-0005-snapshot-cache-contract.md)
and ready [SPEC-T030D](../specs/SPEC-T030D-sqlite-snapshot-save.md).

# Deliverables

Design S01–S16 is independently accepted. Implement snapshot
value/codec, verified E1 save and narrow v1→v2 open transition, substantive contract/concurrency/
fault/restart/security tests, rustdoc, traceability and runtime acceptance. No runtime code exists.

# Non-scope

Durable event replacement, history deletion, reducer bypass, or treating snapshots as truth.

# Invariants

Durable events remain the source of truth and a failed snapshot operation cannot corrupt them.

# Dependency Evidence

T020 and recovered T030A/B are Accepted; recovery merged as PR #242 at `1f555f61`.
The fresh-context design review accepted ADR-0005/SPEC-T030D after R1 repair.
This task is Ready for implementation, not Accepted; no snapshot runtime exists.

# Decomposition

One verified E1 cache-save state transition with inseparable narrow schema extension. Dependent
E0 load remains T030C; its trust/codec requirements are specified here for composition.

# Machine Acceptance

Exact future names and concrete oracles are in SPEC-T030D S01–S16. They are planned,
unimplemented and unrun. Fixed-failure skeletons must precede production code; focused event-store,
domain, workspace, Node P0, formatting, Clippy, build, dependency policy and diff gates follow.
Apply the matrix ownership column: D owns save/codec/schema and raw-SQL observer assertions;
public load/C assertions are deferred to T030C and are not prerequisites for D acceptance.

# Required Documentation Updates

[T030D-design.acceptance.md](../acceptance/T030D-design.acceptance.md).

# Risks and Gaps

The earlier concurrency/failure gap has an accepted resolution in ADR-0005/SPEC-T030D:
current durable-head save, full-prefix persisted provenance, explicit same-seq byte arbitration,
monotonic cache, E1 old/complete-row crash visibility, no automatic unknown-completion retry,
bounded codec/errors and narrow exact-schema evolution. The bounded R1 design repair uses
nullable ANY only for disposable seq/version/body values, retains full CHECK-enabled event/store
integrity, and distinguishes malformed values from damaged structural keys/indexes. Fresh-context independent recheck accepted this repair.

The correctness-first 4096-prefix limit does not accelerate initial reducer replay and can hold
the writer lock during verification. Large streams keep A/B replay; cache cleanup and optimized
provenance require separate accepted designs. T030D is Ready; T030C and the parent remain
blocked. Snapshot runtime remains unimplemented. Any new security, atomicity, retry or trust
gap discovered during implementation must be recorded and resolved before continuing.
