### Changes since the first hand-off

`tests/test_hardening.py` (RED first, five new regressions in
`ReworkRegressionTests`, plus tightened existing cases):

- `test_evaluate_egress_revalidates_a_directly_constructed_policy` — a
  default-allow/direct policy that lists only `evil.invalid` is rejected both
  at construction and by `evaluate_egress`; a policy forged with
  `__new__` + `object.__setattr__` is rejected at evaluation; a list
  allowlist, a plain `dict`, and an http entry are rejected; instances accept
  no new attributes.
- `test_drills_require_exact_tuple_steps_and_charges` — `list(COMPROMISE_STEPS)`,
  `[1]`, and `range(1)` are rejected; the existing compromise/cost tests now
  list those inputs as rejections instead of acceptances.
- `test_restore_race_keeps_existing_destination_and_cleans_only_staging` —
  patches the module's `_rename_noreplace` to create the destination (with a
  sentinel file) immediately before publication; expects `ContractError`, the
  sentinel intact, and no staging residue.
- `test_restore_fails_closed_without_atomic_noreplace_rename` — with
  `_RENAMEAT2` patched to `None`, nothing is published and staging is cleaned.
- `test_restore_reads_backup_through_pinned_no_follow_descriptors` — a
  symlinked backup root, a symlinked ancestor inside the backup, and a config
  path that traverses a symlinked directory are all rejected.
- Rotation test now constructs each bad `CredentialMetadata` inside the
  assertion (validation moved to construction), and adds forged-instance and
  float/bool field cases.

`src/ice_maker/hardening.py`:

- Every open goes through `_open_pinned`, which walks each path component with
  `O_DIRECTORY|O_NOFOLLOW` descriptors and opens the final component with
  `O_NOFOLLOW`; the old `Path.is_file`/`read_bytes` pre-check pattern is gone.
  Contents are read from the descriptor with `fstat` regular-file and size
  checks, and a length mismatch after read is rejected.
- Backup entries are opened component by component under one pinned backup
  root descriptor, so a swapped root or ancestor cannot mix snapshots.
- Staging is created and populated relative to one pinned destination-parent
  descriptor; files are created `O_CREAT|O_EXCL|O_NOFOLLOW`, written, then
  re-read through the same descriptor and re-hashed.
- Publication uses glibc `renameat2(..., RENAME_NOREPLACE)` bound via the
  stdlib `ctypes` module (no new dependency). If the symbol or platform is
  unavailable the restore fails closed before publishing.
- Cleanup (`_discard_staging`) unlinks/rmdirs only the exact entries this call
  created, by descriptor, in reverse order; there is no `shutil.rmtree` or any
  path-based recursion, so a swapped directory can never be deleted.
- Every public contract/result validates in `__post_init__`; `evaluate_egress`
  and `rotate_credential` revalidate input fields again (including forged
  instances with missing slots). All dataclasses are `frozen=True, slots=True`.
- `respond_to_compromise` requires `type(steps) is tuple` equal to
  `COMPROMISE_STEPS`; `enforce_cost_ceiling` requires `type(charges) is tuple`.
  `_bounded_int`/`_label` use exact type checks (bool never passes as int).

The three `ops/hardening/*.json` files are tracked, strict local contracts.
