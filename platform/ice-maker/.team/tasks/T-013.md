## REWORK 1 — orchestrator evidence

The four focused tests pass, but the first pass is rejected at the pipeline
trust boundary:

- `gate_argv` accepts any non-shell executable, including mutating/network
  commands such as `git push` or `curl`; the pipeline therefore contains an
  ungoverned command execution surface.
- Builder/reviewer inputs are merely arbitrary callables, and reviewer output
  is a raw string rather than bounded `CommandEvidence`. Failed, timed-out,
  truncated, or redacted reviewer execution cannot be distinguished or audited.
- A caller-supplied ledger is checked only for equal budget. It can carry an
  unrelated configuration/history, so usage and repeat decisions are not bound
  to this immutable pipeline request.
- Stage aliases/providers are free-form rather than bound to the accepted Phase
  3 routes. The report also lost the mandatory `STATUS:` line when the CLI
  output file replaced the worker-written report.

Required rework:

- [ ] Replace the raw gate argv surface with explicit immutable builder, gate,
  and reviewer boundary values. Each boundary may expose only its typed invoke
  callback; gate execution happens inside that injected bounded boundary, not
  from an arbitrary command string accepted by `run_pipeline`.
- [ ] Require every boundary invocation to return valid `CommandEvidence` and
  parse reviewer JSON only from that validated evidence. Cover failed,
  timed-out, truncated, empty, redacted, exception, and malformed evidence.
- [ ] Bind exact provider/alias roles to the accepted Phase 3 configuration:
  Codex/DeepSeek builders, local zero-cost deterministic gate, Claude/Grok
  reviewer, and a provider different from the selected builder. Reject forged
  or write-capable identities before any callback runs.
- [ ] Make the pipeline own and bind its ledger. If prior normalized failures
  are needed to prove the repeated-failure stop, accept only a bounded immutable
  request field and validate it; do not accept an arbitrary ledger object.
- [ ] Prove callback order and that the reviewer receives only immutable
  builder/gate evidence. No raw shell/argv, workspace, publisher, merge, deploy,
  network, or `main` capability may enter the pipeline API.
- [ ] Keep all failure paths non-publishable with truthful reached-stage usage;
  rerun focused and full gates and restore a `STATUS: DONE | PARTIAL | BLOCKED`
  report with exact REWORK evidence.
