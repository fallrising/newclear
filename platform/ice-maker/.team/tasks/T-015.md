## REWORK 1 — orchestrator evidence

The pixel OCR path works and four tests pass, but cache trust is incomplete:

- Cache paths reject only a leaf symlink and may create/follow a directory
  through symlinked ancestors.
- A cache attacker can recompute `canonical_digest` for negative/bool pages,
  arbitrary regions/methods, NaN confidence, unsafe text, duplicate pages, or
  structurally inconsistent page/chunk lists; dataclass construction does not
  validate these fields.
- A cache file that wins the no-replace race is silently accepted for the
  current call without verifying that it equals the computed canonical result.
- Duplicate JSON keys are accepted and exact cache schema/cardinality/order are
  not checked.

Required rework:

- [ ] Validate every existing component of the cache path before creation and
  reject intermediate symlinks, non-directories, unsafe names, and symlinked
  cache entries without reading their targets.
- [ ] Parse duplicate-free JSON and require exact schema keys/types. Validate
  source SHA, extractor/OCR versions, ordered 1-based unique pages, bounded
  region grammar/dimensions, exact method/confidence pairing, finite confidence,
  safe normalized text, chunk/page one-to-one identity, and recomputed chunk
  IDs before returning a cache hit.
- [ ] On a publication collision, validate the winning file is the exact safe
  canonical cache for this result; otherwise fail closed in the same call.
- [ ] Add regressions for version/digest/schema/type/NaN/page/region/method/text/
  chunk forgery, duplicate keys, intermediate symlinks, entry symlinks, and
  mismatched collision. Prove no OCR invocation occurs for one valid cache hit.
- [ ] Preserve the honest synthetic-only scope and standard-library constraint;
  replace the report and rerun focused plus full tests.
