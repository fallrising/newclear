## REWORK 1 — orchestrator findings

The first pass reported 147 green tests, but independent probes found that a
directly constructed `AssembledBook` rendered an invalid `not-a-sha` commit and
that the same chunk ID bound to different source SHA values across two chapters
was accepted. The manifest also embeds `source_commit`, which creates an
impossible self-reference for a tracked manifest intended to describe its own
build commit. Correct all of the following within the original scope:

- Remove `source_commit` from the tracked manifest schema. Accept the exact
  lowercase 40-hex commit as a separate `assemble_book`/compiler argument and
  store it on the canonical assembled value for both renderers.
- Add complete `__post_init__` validation for every public frozen/slotted value,
  including `Manifest`, `Chapter`, and `AssembledBook`. Direct construction must
  not bypass field, citation, commit, ordering, bibliography, reference, or
  synthetic-only invariants.
- Accept only exact `bytes` or `str` JSON at parsing boundaries. Require an exact
  bounded immutable tuple of canonical chapters at assembly; reject mappings,
  lists, generators, subclasses, and unbounded iterables.
- Reject citation drift across the whole book: one chunk ID cannot resolve to
  more than one source SHA across chapters. Build the bibliography in a simple
  bounded deterministic pass.
- Add RED regressions for the exact probes, commit self-reference removal,
  mutable/unbounded inputs, direct-value forgery, cross-record citation drift,
  and malformed nested values. Keep the renderer output byte-stable and rerun
  the original verification.
