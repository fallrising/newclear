## REWORK 1 — orchestrator review

The first implementation is not accepted. Preserve the useful pure-renderer
work, but correct the following observable defects before reporting again:

- Add the missing service/API tests required by the task: completed listing and
  Markdown/browser success, unfinished batch 409, unknown/cross-batch source
  404, corrupt state/FTS 409, oversize 413, deterministic replay, hostile HTML
  escaping, and absence of filenames/paths/text from listings. Tests must
  exercise real `run_batch` durable index/progress state rather than a runner
  that only fabricates `result.json`.
- Preserve progress isolation across multiple completed batches. The current
  implementation scans the global `batch-progress` directory and rejects every
  progress record whose manifest belongs to another batch, so a second batch
  makes the first unreadable. Validate records safely, but select bindings by
  the requested manifest/source/item path without rejecting valid records for
  other manifests.
- Verify the progress `index_sha256` using the original durable insertion order
  (`chunks.rowid`), because `run_batch` hashes the extractor's chunk order. Do
  not hash chunks ordered by random `chunk_id`; keep rendering order independent
  inside the pure renderer.
- Enforce the 10,000 source-chunk ceiling before materializing an unbounded
  source query (for example, query with `LIMIT 10001`). Keep full schema/row/FTS
  validation and validate every returned chunk.
- Map all malformed result/progress/index/provenance state to the stable
  `readable_state_invalid` response. Do not allow `BatchContractError`,
  filesystem exceptions, or malformed progress values to escape as HTTP 500.
  Map `ReadableResultTooLarge` to 413 even when encountered while preparing a
  listing.
- Metadata `utf8_bytes` is the sum of extracted text UTF-8 bytes, not the size
  of a rendered Markdown envelope; listings must not render every body or fail
  merely because an individual Markdown response would exceed 256 KiB.
- Add no source dependency on a private `_validate_chunk` helper. Expose a
  supported validation boundary from `knowledge_index.py` or validate through
  the public bounded source-read path. Remove unused imports and keep changes
  reviewable.
- The browser page's 256 KiB limit includes its fixed HTML envelope. Test the
  limit and the full-document HTML escaping. Ensure the download response is
  UTF-8 Markdown with a safe deterministic filename/content disposition.
