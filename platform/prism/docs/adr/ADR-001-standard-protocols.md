# ADR-001：以既有標準協定作為唯一外部契約

## 狀態

Accepted

## 決策

Prism 的外部契約只採用既有生態系協定：寫入使用 OTLP；查詢與告警介面使用 Prometheus、Loki、Jaeger 與 Alertmanager 相容 API。Prism 不建立專有遙測傳輸協定，也不建立專有查詢語言。

## 背景

可觀測性平台的主要整合成本通常不在資料接收本身，而在收集器、儀表板、告警、查詢工具及既有操作流程的相容性。若 Prism 自訂外部契約，使用者必須維護額外的 SDK、轉接器與前端整合，遷移和退出成本也會增加。

## 理由

- 協定與 API 相容屬於合法且可獨立實作的互通邊界。
- 可直接重用 OpenTelemetry Collector、Grafana 與現有告警工具鏈。
- 使用者能以既有工具遷入或遷出，降低供應商鎖定。
- 此決策具可逆性：內部實作與儲存後端可以演進，而外部工具不必同步重寫。

## 後果

- Prism 必須承擔各相容協定的歷史包袱，例如不同時間單位、標籤語意與回應格式。
- 非標準功能不得偷偷擴張標準 API；需要時應放在明確區隔的控制平面 API。
- Prometheus 相容端點必須回報 Grafana 可辨識的相容版本，細節見 ADR-005。
- 相容性必須透過契約測試及真實客戶端驗證，而不能只依賴相似的 JSON 結構。

## 替代方案

### 自有 gRPC API 與專用前端

否決。此方案可讓內部模型更單純，但會迫使使用者採用 Prism 專用 SDK、查詢工具與視覺化介面，造成不必要的生態系重建與鎖定。
