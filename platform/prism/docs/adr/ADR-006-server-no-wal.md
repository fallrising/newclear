# ADR-006：Server 不提供 WAL，可靠性由收集端承擔

## 狀態

Accepted

## 決策

Prism server 不實作 write-ahead log（WAL）。寫入重試、磁碟佇列與背壓期間的資料保留由 OpenTelemetry Collector 等收集端 agent 負責；Prism 僅在後端確認寫入成功後回覆成功。

## 背景

Prism v1 的目標是資源可控的單節點服務。OTLP 收集端已能在資料抵達 server 前提供 retry 與 persistent queue；若 server 再加入 WAL，就會在相鄰層重複保存同一批資料，並引入回放、去重、排序、磁碟管理及損毀復原語意。

## 理由

- 把可靠性放在最接近資料來源的收集端，可在 server 不可達時持續排隊。
- 避免 agent queue 與 server WAL 的雙重緩衝及容量規劃。
- server 可維持無本地持久狀態，部署、升級及故障復原更簡單。
- 寫入是否持久化仍由儲存驅動的成功語意明確決定。

## 後果

- 正式部署必須設定收集端的持久佇列、重試與容量上限；未設定時可能在 Prism 或後端不可用期間遺失資料。
- Prism 必須在後端寫入失敗時回傳可重試的失敗，不得先行確認成功。
- 必須監控收集端 queue 深度、丟棄量及重試狀態。
- 此架構不提供 server 接收後、後端確認前的額外本地副本。

## 替代方案

### 在 Prism server 實作 WAL

否決。它會新增回放、去重、順序、磁碟耗盡、資料損毀與升級相容等狀態機，超出 v1 的單節點資源預算，且與收集端 persistent queue 重複。

### 收集端與 server 同時啟用持久 WAL

否決。雙重持久化提高延遲與磁碟成本，卻仍需定義兩層確認與重試的互動，無法合理化新增複雜度。
