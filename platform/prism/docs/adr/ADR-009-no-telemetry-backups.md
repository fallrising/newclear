# ADR-009：Prism 不備份遙測資料

## 狀態

Accepted

## 決策

Prism 的內建備份範圍只涵蓋必要的設定與控制平面資料，不備份 metrics、logs、traces 等遙測資料。遙測資料的冗餘、快照與災難復原由所選儲存後端及部署者負責。

## 背景

遙測資料量遠大於設定資料，並依 retention policy 持續淘汰。Prism 同時支援多種儲存後端；若平台自行提供統一遙測備份，便必須處理各後端的一致性快照、增量備份、還原順序、容量與版本相容性，超出 v1 單節點目標。

## 理由

- 儲存後端最了解其一致性、快照與複寫機制，Prism 不應再建立一層不完整的抽象。
- 避免備份資料量倍增，維持可預測的磁碟與運算成本。
- 遙測資料已有 retention 與可丟棄性假設，和必須保護的設定資料風險不同。
- 明確劃分責任比提供無法保證一致還原的「通用備份」更安全。

## 後果

- 使用者若需要遙測災難復原，必須選擇並設定具備快照、複寫或外部備份能力的儲存後端。
- Prism 文件與 UI 必須明確說明內建備份不包含遙測資料。
- 還原 Prism 設定不會還原先前的 metrics、logs 或 traces。
- 驅動可揭露後端原生備份能力，但不得讓它看起來是 Prism 的跨後端保證。

## 替代方案

### Prism 統一備份所有儲存後端的遙測資料

否決。後端能力與一致性模型差異過大，統一介面容易產生虛假的安全保證，且成本超出 v1 範圍。

### 強制所有部署採用特定複寫或 RAID 配置

否決。部署者可自行採用這些措施，但它們依賴基礎設施與故障模型，不能成為 Prism 的可攜預設。
