# P1-09 — ClickHouse migrations and writes

Go 1.27.1. P1-08 is complete.

## Scope and boundaries

Implement SDD12 P1-09 and SDD17 sections 1–3, 10: registered native ClickHouse factory, bounded lifecycle/options, eight embedded migrations and metrics/logs/traces writes. Official clickhouse-go/v2 v2.48.0 and necessary selected transitive changes are authorized; inspect actual licences/provenance and existing regressions. Public SPI and other drivers remain unchanged. Root workflows, production query implementations (P1-10), background dependency reconciliation (Phase 3), releases and deployments are outside this milestone.

Read APIs return classified Unsupported; optional query/metadata/delete interfaces are absent. Capabilities report only implemented signals, unlimited out-of-order, and configured retention options. Retention.Enforced remains false: metric_series metadata has no automatic expiry, although samples/logs/spans/aggregates have TTL. This is not a claim that every stored tenant/label expires. No claim of full driver conformance or runnable daemon ClickHouse integration until the later query/wiring milestone.

## Contract adaptations (ADR-018)

The executable MetricPoint SPI contains Name, Labels and TS but no precomputed fingerprint. Use the existing utm.Fingerprint on validated complete sorted labels with UTF-8 names and values (including __tenant__ and __name__), once per point identity; no new SPI field/hash algorithm. Require a nonempty trusted tenant and matching metric name; reject contradictory identities before any I/O. Logs/spans take tenant from nonnil Resource; conflicting reserved tenant labels are rejected, never used to override Resource.

The 100,000-entry metric cache is bounded by logical bytes as well as entries, keyed with tenant and full identity. Admit cache updates only after both metadata/sample sends succeed; extending first/last seen emits new metadata even for a cached series. Cache eviction permits redundant metadata. Writes are not multi-table transactions: partial server success or lost acknowledgements can leave duplicates; no driver retry. Async default acknowledgements do not guarantee durable storage; verification uses synchronous settings and explicitly checks async acknowledgement separately.

The initial log/span schema preserves full Resource fields, and the span schema preserves TraceState and link attributes in additional columns/Nested arrays, along with SDD fields. Original span nanoseconds and event nanoseconds are preserved using utm conversion functions. Driver never rewrites business data or telemetry labels. Required span/link IDs and nonempty log/parent IDs must pass existing utm.ValidTraceID/ValidSpanID, including rejection of all-zero IDs; optional log/parent IDs may be empty. Missing/nil maps are empty maps. Unsupported histogram/exemplar structures return Unsupported before writes; classic expanded floats remain supported.

## Lifecycle, settings and bounds

Parse native clickhouse:// DSN without exposing credentials. Validate known numeric/time/retention options, reject unknown options and invalid/duplicate DSN query values. Support DSN credential-file variants within the existing SPI option map, with bounded regular-file-only reads (reject FIFO/device) and sanitized errors; no new exported credential type or internal import. Context cancellation/deadlines retain errors.Is and ErrTimeout; operation completion checks the monotonic deadline as well as ctx.Err so a native socket timeout cannot race the context timer into an Unavailable result after the deadline; server codes follow SDD17 section9, raw server/client/SQL/credential errors never escape.

Each operation has a finite default client timeout (max_execution_time plus 5 seconds, 60 seconds by default). Controlled migration scans and telemetry/receipt INSERTs explicitly set the validated server max_execution_time in SQL, because the pinned client derives a larger protocol setting from context deadlines. Native batches retain SQL SETTINGS by preparing the fixed table without an explicit column list and must verify the returned column count and names against the original fixed list before any Append; schema mismatch closes the batch and fails closed. DDL keeps the caller deadline and client cancellation; its protocol server limit is derived by the upstream client and is not promised to equal the configured scan/INSERT cap. Every operation has a bounded concurrency admission tied to max_open_conns, and backend Close cancels/drains admitted operations before closing the native client exactly once. Migrations and writes share lifecycle protection; no active use after Close. Rows and batches always close, including all error paths. No backend-owned long-lived goroutine.

Fixed writer limits: at most 10,000 records/call, 16 MiB logical input/call, 256 nested events or links/record, 128 entries per individual map or label collection. Individual strings are charged into the byte limit. Validate all rows before preparing any batch. No automatic chunk retries. Cache max 100,000 entries and 32 MiB logical identities. These are storage-safety bounds, distinct from ingest limits and RSS guarantees; excess returns TooLarge.

## Migrations and schema

Eight SQL templates follow SDD04/17, split multi-statement files safely from our controlled source. Migration 008 materializes the SDD17 canonical labels_str from sorted key/NUL/value entries separated by SOH; it is not the display representation of a Map. This establishes the storage format without adding production reads. SHA256 is of unrendered template. Validate every stored version/name/checksum, duplicates and unknown future versions with bounded rows; mismatch blocks Migrate/startup with a fixed sanitized drift error. Apply missing versions ascending, commit migration receipt synchronously only after every DDL succeeds. IF NOT EXISTS enables retry after partial DDL. Retention changes reconcile MODIFY TTL idempotently without changing template checksums, for metric samples/logs/spans/trace index/RED/service-deps/service-ops; pending links expire after one day.

Series first_seen/last_seen use DateTime64(3), preserving exact millisecond extents. metric_series has no TTL as in SDD04: metadata lifetime covers samples and cannot expire behind a cached identity. All persisted timestamps, including log observed timestamps/span ends/events, must be within [1970-01-01T00:00:00Z, 2106-02-07T06:28:16Z), the weakest DateTime aggregate/index range; invalid dates and end before start are rejected before I/O. TTL expiry uses UTC DateTime arithmetic. On the pinned server, TTL expressions require DateTime, so writers additionally reject a TTL source whose UTC timestamp plus its effective retention reaches 2106-02-07T06:28:16Z. Logs and metrics use their own retention; span starts use the maximum of trace retention, RED retention and the one-day pending-link retention. Span ends/events and log observed timestamps retain the raw range check. Rejection is BadRequest before any batch preparation; retention is never silently shortened. Before any MODIFY TTL, Migrate checks the existing maximum source timestamp in all eight TTL tables under the operation deadline and rejects unsafe data without changing any TTL. Drain other backend/process writers before changing retention and running Migrate; independent writers with older options cannot be atomically guarded by a separate migrator. Migrate calls on one backend are context-aware serialized; concurrent independent process migrations are not a supported deployment workflow and strict history checks fail closed if duplicates appear.

Only single-node cluster-empty mode is supported in this milestone; nonempty cluster returns Unsupported rather than silently creating local tables. Replicated/ON CLUSTER deployments require later independently verified infrastructure work. The database must already exist; no automatic database creation outside configured target. All identifiers/TTL template values are validated and no user telemetry enters generated SQL.

Span writes perform bounded local dependency joins keyed by tenant+trace+span, with pending-link persistence for unresolved parents (SDD17 section3.4/8). No cross-trace join or background job. Declare Dependencies false; queries and reconciliation remain later scope. Do not claim a dependency ratio metric unless registry and actual implementation are supplied; retain approximate-graph limitation.
