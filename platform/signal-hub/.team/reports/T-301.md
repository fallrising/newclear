## Documentation

The orchestrator owns `docs/m3-design.md`, runtime/quickstart documentation and integration. Communicated these implemented operational decisions:

- At most 1,000,000 buckets per evaluation/backfill. Larger ranges return `ErrUnavailable` before rollup writes, without silent truncation. A narrow manual backfill can recover from an ancient hot event.
- Evaluation resumes from the earlier of the normal late-event window and the prior computation's bucket after downtime.
- Cardinality uses the union of current and previous retained groups. Threshold replay interprets omitted/evicted rows as missing (predicate false for every comparison), distinct from present empty count/sum rows with value zero. Historical groups still recover after eviction without increasing the rollup cap.
- Threshold events always include `data.group_key_sha256`; full `data.group_key` is included only up to 1,024 UTF-8 bytes. Full canonical keys remain in rollups and deterministic event-ID hashing.
- Metric cursors use a SHA-256 selector so a valid large key does not produce an oversized pagination URI. The orchestrator separately handles the bounded HTTP header allowance for explicit full group filters.
- `BackfillRule(ctx, id, from string, now time.Time)` accepts RFC3339; the CLI normalizes date-only input.
