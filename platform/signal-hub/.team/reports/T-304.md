Four P2 correctness findings were independently reproduced and subsequently resolved. The original failures remain visible in the named initial logs:

1. **Restart catch-up:** original `internal/store/evaluate.go:66-97` ignored persisted last computation when choosing the normal window. Evaluating at 10:30, closing/reopening, then evaluating at 14:00 left the 10:00 bucket permanently partial and the 11:00 bucket missing. Proposed fix: include the last successful computation bucket in bounded catch-up.
2. **Threshold payload expansion:** original `internal/store/evaluate.go:380` embedded the complete canonical group key in internal event data. A valid event containing 8,100 quote characters in `data.group` passed ingest but failed threshold evaluation with `data exceeds 16384 canonical UTF-8 bytes`, rolling back all rule projections. Proposed fix: bounded event metadata plus a full-key digest while retaining full canonical keys in rollups and stable event identity.
3. **Oversized pagination cursor:** original `internal/store/metrics.go:43,173` encoded the full group key in every metric cursor. The same valid group generated a 43,368-byte cursor; a real HTTP listener configured with the then-production 16 KiB header limit returned 431 on page two. Proposed fix: compact logical cursor selector; account separately for exact group-filter request size.
4. **Evicted group recovery:** original `internal/store/evaluate.go:325-390` replayed only explicit group rows. With 200 groups crossed at 10:00 and one new lexicographically earlier group at 11:00, evaluation at 12:00 recovered only 198 original groups; the two evicted groups remained crossed. Proposed fix: replay implicit empty buckets through gaps and tails for previously observed groups, without enlarging the 200-rollup cap, and preserve deterministic transition identity.

The orchestrator explicitly chose a cap over the union of current and previous retained groups, including zero/null groups. Under that policy new group contributions may enter `__other__` because retained groups occupy slots. This was treated as a documented product decision rather than a defect. Finding 4 concerns threshold recovery under that selected policy.


Resolved implementation and independent closure:

1. Restart catch-up now uses persisted `last_computed_at` before applying the range guard (`internal/store/evaluate.go:59,68-77`). The original close/reopen probe now passes.
2. `thresholdData` always supplies a full-key SHA-256 digest and includes the raw key only at or below 1024 UTF-8 bytes (`internal/store/evaluate.go:480-485`). Stable event IDs and rollups still use the full canonical key. The original 8,100-quote input now evaluates successfully.
3. Metric cursors use a group digest and resolve the logical bucket/version/key position against at most 200 retained rows (`internal/store/metrics.go:125-173`). The original real-HTTP probe now paginates successfully even with its original 16 KiB server limit. The runtime's separately documented 128 KiB request/header bound accommodates exact group-filter URLs.
4. `thresholdReplay` consumes missing complete-bucket runs arithmetically, including gaps, reentry, and tails (`internal/store/evaluate.go:334-439`). Missing values are nil/false for every comparator; explicitly materialized empty count/sum rows remain numeric zero. The original cap-eviction probe now observes all 200 recoveries. Native regressions additionally establish multi-bucket continuity, restart idempotency, missing `<= 0` behavior, and stable null-valued recovery events across a century-scale gap.
