## Summary

Implemented the bounded M5 backup, restore and maintenance leaf. `Backup` uses SQLite `VACUUM INTO`, read-only integrity/application-schema validation, file fsync, SHA-256, versioned `<snapshot>.manifest.json`, and no-replace hard-link publication. `VerifyBackup` checks strict bounded manifest JSON, filename, size, snapshot byte hash, regular files, sidecars and SQLite integrity. `RestoreBackup` verifies before copying, verifies the copied bytes and integrity again, records `backup.restore` as owner with the original snapshot hash and required reason, and exclusively publishes a new isolated database. It never starts networking or resets queue state. `OpenExisting` rejects missing, empty, unrelated and symlinked databases before migrations.

CLI adapters provide `backup`, `restore`, `archive run`, `archive verify`, and `archive import`. Archive JSON results use `{parts,events}`, `{parts}`, and `{imported,duplicates}`. Backup/restore results use the approved manifest fields `version`, `file`, `size_bytes`, `sha256`, `created_at`; the existing CLI output stream remains unchanged. CLI parse/runtime failures do not echo paths or reasons. Audit reasons require nonblank UTF-8 of at most 4096 bytes.

Optional `-archive-dir` and `-backup-dir` run at startup and every 24 hours with a shared cancellation context. One operation's failure does not suppress the other. Empty flags leave maintenance disabled. Backup filenames use UTC time plus random bytes; created backup directory entries and their parents are fsynced. Output serialization prevents concurrent worker logs racing on non-thread-safe writers.

The source worker checkout intentionally lacks T-501 archive store APIs. No production stub or out-of-scope store copy was introduced. The final archive adapters and newly added archive round-trip/directory tests await root integration and rerun. Root owns repository-wide gates and independent acceptance.
