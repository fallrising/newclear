## Independent external liveness design

Run outside both hub process and host failure domain, using approved tailnet connectivity to `/healthz` and `/readyz`. Liveness proves process response; readiness proves SQLite access, neither proves all production capacity. Proposed fixed start-to-start cadence60s, combined probe cycle deadline10s, two consecutive failed/missing cycles and bounded independent send/retry budget60s. Use an independent notification path/account, never a hub subscription. Overlapping or missing observations count as failures, with clock/scheduler delays recorded. Running only an on-host probe cannot satisfy host outage detection. Monitoring the monitor is outside the personal-use scope.

Worst nominal stop just after a successful observation: next failed cycle completes by70s, second by130s, bounded send finishes by190s. This leaves110s margin inside300s; network/scheduling/provider delay can consume it. Record stop, scheduled and actual probe times, deadlines/errors, send attempts/provider acknowledgement and actual phone arrival. Provider acknowledgement alone is insufficient. A real authorized outage and observed receipt are required; the worksheet checks timestamp relationships only. No monitor, account or schedule is installed here.

## Source and delivery recovery

1. Save immutable producer envelopes before send. Retry original bytes/id/time on ambiguous timeouts/transient429/503/transport errors; on200 inspect every Alertmanager member status and original seq. Unexpected409 is a failed integration gate: retain source/id/content hash and sanitized mapping evidence; investigate changed episode labels/annotations/time rather than minting another ID. Stop on auth/scope/400/413 errors and review config. Authenticated configured-name receipt freshness is distinct from event time, new timeline events and duplicates. Never-seen/missing intervals cannot establish healthy continued source operation. Irregular release/Alertmanager needs separately reviewed heartbeat/watchdog policy.
2. Before receiver re-enable, verify HMAC signature and freshness window, then durable delivery-ID dedup in the accepting transaction before2xx. Delivery remains at-least-once. A timeout after successful receiver commit can repeat; dedup must survive receiver restarts.
3. Record subscription IDs/safe definitions, cursors, pending/inflight/DLQ counts, attempts/lease fences and replay audit. Restart retains these; wait for the two-minute inflight lease expiry rather than clearing rows or attempts. Missing subscription pauses queues. Re-add the same stable ID/safe definition to resume; URL and credential references come from current accepted runtime config. Never reset cursors to manufacture replay. Materialized queue body/header/ID bytes remain fixed even when event detail is archived.
4. Inspect counts/age/recent attempts after restart and before enabling producers. DLQ replay uses owner-authenticated `POST /v1/deliveries/{id}:replay`, JSON nonblank `reason`, active same-ID subscription, retained ID/body/history and audit; it starts a new bounded retry round. Capture duplicate receiver receipts and successful drain. Do not blanket-delete queues or hide failed episodes.

## Archive, previous-day restore and rollback

Use current runtime maintenance CLI from the pinned compatible binary. Below are argument shapes, not commands against a real host; all uppercase operands must refer to approved private locations.

```text
signalhub archive verify --db DB --archive-dir ARCHIVES --day YYYY-MM-DD
signalhub archive import --db DB --archive-dir ARCHIVES --day YYYY-MM-DD --reason REASON --retention-days 7
signalhub rules backfill --config CONFIG --db DB --rule RULE --from UTC_DATE_OR_TIMESTAMP
signalhub backup --db DB --output NEW_SNAPSHOT.sqlite
signalhub restore --backup SNAPSHOT.sqlite --db NEW_ISOLATED.sqlite --reason REASON
```

Verify gzip bytes/hash/count/order and DB manifest exact membership before import or accepting a purge. Keep immutable parts and orphans after interruptions; retry under a new part/name. Import only manifests associated with the DB or its consistent restored copy, and complete missing archived intervals before rules backfill. Repeated import preserves original seq/identity, freshness, subscription cursors/materialized queue bytes and attempts; it does not extend restore retention. Historical query cursors can invalidate: restart queries, never subscription state. New subscriptions do not redeliver restored history; existing materialized delivery remains.

For this optional expanded drill, use the previous UTC day's real snapshot and its `.manifest.json`, verify SHA-256/size/date/schema and SQLite integrity. A DB file copied while WAL is live is not a backup; use the native consistent backup command. Incomplete pairs are unusable; preserve/report them and choose a new output. The restore destination and sidecars must be absent, with an existing safe parent; preserve original snapshot/manifest/source. Record original checksum before and after. Copy required immutable archive parts to separate isolated storage.

Before starting the restored copy, establish independent egress isolation and substitute synthetic receiver URLs/credential file references in the current config while retaining stable subscription IDs and safe definitions. Persisted safe definitions omit URLs/credential refs, but the snapshot retains materialized body/header/IDs and pending/inflight/DLQ state: dispatch uses current configuration. Removing subscriptions merely pauses jobs and cannot prove resumed delivery. Start with isolated credentials, loopback and compatible binary/schema; verify queries/original seq, health/ready, archive verification, queue state/leases, receiver dedup/replay and a new synthetic ingest. Keep original files unchanged. Read-only API evidence alone cannot prove full queue recovery.

Rollback stops only the authorized workload through OneFleet, then preserves failed-state DB/WAL/SHM/logs. Select a previously tested compatible binary/config and verified snapshot into a new path; an older binary can reject newer schema, and no downgrade is implied. Verify before switching the approved lifecycle pointer. Reconcile events after snapshot using saved immutable producer payloads and durable receiver dedup; lost post-snapshot data is an explicit recovery-point risk. Abort on digest/schema/integrity mismatch, missing archive dependencies, incorrect isolation, unintended recipient, failed health/ready or unreconciled identity conflict. Never overwrite a live DB, purge failure evidence, or use a host-wide stop.
