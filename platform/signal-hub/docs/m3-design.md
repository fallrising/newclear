# M3 implementation contract

M3 adds versioned event projections, retained rollups, threshold events and a read-only metric board. M0 schemas and OpenAPI remain authoritative; this document resolves runtime details before implementation. No runtime dependencies are added: the board uses React and SVG.

## Evaluation and state

- UTC 5m/1h/1d buckets; event time determines membership. Evaluate at startup and every minute. Refresh current partial bucket plus completed buckets starting at max(current minus two buckets, current minus 24h). After downtime, also catch up from the bucket of the last successful computation so no old partial bucket remains stranded. Newly loaded versions backfill from earliest hot event through now. Manual backfill uses `signalhub rules backfill --config ... --db ... --rule <id> --from <RFC3339 or YYYY-MM-DD>` and never runs a listener.
- Filters follow M0, including typed scalar equality and mandatory explicit types excluding the reserved rule prefix. Missing aggregation fields are ignored; numeric aggregates ignore non-numeric values. Empty count/count_distinct/sum is 0; empty min/max/avg is null. sample_count counts contributing values (all matching events for count).
- Group keys use canonical JSON arrays in group_by order; no grouping is `[]`. Missing group values become null. Each bucket considers the union of current-event keys and the previous bucket's retained keys, including zero/null series. Sort canonical keys deterministically, retain first 199 distinct keys and combine the remainder into reserved `__other__` when there are more than 200 keys (maximum 200 rows per bucket). Up to 200 distinct keys need no overflow row. Retained zero/null series also occupy slots: a new key may fall into `__other__` even when it is the only key with current events. Contributions are conserved; genuine values cannot collide with the reserved overflow string. Threshold replay treats missing complete buckets for evicted groups as false, so cardinality eviction cannot strand crossed state.
- Evaluation/backfill rejects ranges exceeding 1,000,000 buckets before writes (503/unavailable); it never silently truncates history. Narrow the manual backfill range when needed. Context cancellation remains effective.
- Rule definitions use canonical JSON hashes, persisted per id/version. Reusing any known version with different content rejects the entire configuration. Reactivating an identical historical version is allowed. Changed versions replace older-version rollups over the recomputable interval only; older history remains. Rules removed from config stop evaluating while retained data remains queryable.
- Evaluation for each rule is transactional: rollups, durable threshold state and internally validated events commit together through the existing ingest transaction helper. One rule's failure does not cancel other rules. Three consecutive failures emit one deduplicated failure event per failure episode; success resets the episode.
- Thresholds use only complete buckets, contiguous per group. Null/missing values do not satisfy predicates. Crossed/recovered require for_buckets consecutive true/false results. Replay recomputes deterministic transitions; stable event IDs and persistence prevent repeated transitions on tick/restart/backfill. Threshold event data always contains group_key_sha256 and includes the raw group_key only when it is at most1024 UTF-8 bytes; full group keys still determine stable IDs and remain in rollups. Existing emitted events remain immutable if late arrivals change past values. Persist state and do not mutate original event payloads on a duplicate ID.

## API and reload

- Existing `GET /v1/metrics/{rule_id}` contract is implemented with strict parameters, [from,to), exact group key, query-bound compact opaque cursor (group SHA-256 selector) and 100/200 default/maximum page sizes. Rows sorted by bucket_start, version, group_key. Missing rules return 404; historical retained rules remain available.
- Add `GET /v1/rules` for safe active rule definitions (id, version, title, filter, aggregation, bucket, optional group_by and threshold), in `{items,next_cursor}` with id order, cursor/limit, owner/readonly roles. It contains no credential references. The UI follows pagination and fetches metric pages without silently truncating results.
- `POST /v1/config:reload` is owner-only and accepts no body/query. Prepare and validate the whole config and credentials first; atomically persist source/rule changes and audit/event, then publish credentials under the same server lock. Failure keeps prior effective configuration. Rejection emits a sanitized internal event. Subscriptions remain unsupported and nonempty subscriptions are rejected.
- Board shows a chart per active rule, time and group selection, gaps for null values, dashed partial buckets, version boundaries, threshold line, earliest recomputable event and last computation. Tokens remain in memory and use existing error handling. Keyboard-accessible data tables accompany SVG charts.

## Acceptance

AC-20–26 and AC-44/45, all six aggregates, typed filtering, deterministic cardinality, failed reload atomicity, historical version guards, restart/backfill idempotency, query authorization/cursors, 90K-event backfill measurement, real Go HTTP/SQLite and Chromium baseline and final acceptance. Go race/vet/build, web format/types/unit/build/dist consistency, contract checker and independent review are required. Production producers, delivery, archive and deployment remain future milestones.
