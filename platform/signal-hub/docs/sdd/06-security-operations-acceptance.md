# 06 安全、維運與驗收

## 1. 信任邊界

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| 生產者 token | 寫入自己 `source_prefix` 與 `allowed_types` 的事件 | 讀取事件、寫入其他來源、使用 `signalhub.*` 類型 |
| 唯讀 token（AI agent、決策系統查詢用） | 查詢 API | 寫入、重放、重載設定 |
| Owner | 看板、重放、重載設定 | — |
| 中樞 process | 讀寫自己的資料庫與封存目錄；對允許清單內的目標發送 HTTP | 執行任何命令、存取其他主機、以 root 執行 |

## 2. 威脅與對策

| 威脅 | 對策 |
| --- | --- |
| 公網掃描與暴力嘗試 | 只綁定 tailnet 介面；沒有公網入口 |
| token 外洩後冒充來源 | 每個來源獨立 token，只能寫自己的前綴；資料庫只存雜湊；可單獨撤銷 |
| 偽造事件觸發決策系統 | 同上；決策系統只訂閱特定類型，並依 `source` 判斷可信度 |
| 事件中夾帶 secret 或個資 | 生產者負責；業務日誌只送衍生事件；中樞不宣稱能攔截 |
| webhook SSRF | 目標必須在允許清單內 |
| 偽造或重放 webhook | HMAC 簽章、時間戳檢查、delivery ID 去重（接收端） |
| 訂閱或規則迴圈 | 規則不能匹配 `signalhub.rule.*`；訂閱不能匹配自己的投遞失敗事件 |
| 磁碟寫滿 | 交易失敗不得回成功；自我觀測與主動低空間拒絕是補強目標，實際能力以 [runtime](../runtime.md) 為準，首次使用不承諾容量預警 |
| 設定錯誤導致服務失效 | 設定整份驗證，失敗則保留舊設定 |

Secret（token、webhook secret、ntfy token）只以 `*_ref` 指向執行期檔案，不寫入設定 repo、資料庫或日誌。本 public repository 的範例一律使用 `example.invalid` 與合成 ID。

## 3. 部署邊界

- 部署是 M6，需要 owner 另行授權；本 SDD 不授權任何部署或主機變更。
- 可用單一非 root Docker 實例，或已具備非 root／設定與 secret／資料掛載 admission 的 OneFleet workload；只開放必要資料目錄與唯讀設定／secret。OneFleet generic adapter 的缺口不再是 Docker 個人使用的前置工作。
- 兩條路徑都維持 loopback／tailnet-only、無公網入口；Docker 本身不等於已驗證網路、持久化或備份。實際部署仍須核對所選實例。
- 實際的主機、tailnet 名稱、設定 repo 位置屬於私人資訊，放在 kernel 或私人設定 repo，不寫進本目錄。

## 4. 里程碑與驗收

| 里程碑 | 完成條件 | 對應驗收 |
| --- | --- | --- |
| M0 契約 | 事件 JSON Schema、設定 schema、OpenAPI、正反 fixtures 進 repo；參考 webhook 接收端的簽章 test vectors | schema 驗證所有 fixtures |
| M1 Ingest | ingest 與查詢 API、來源 token、去重、衝突紀錄 | AC-01–AC-06 |
| M2 看板 | 時間線、事件詳情、關聯鏈、來源新鮮度 | AC-40–AC-43 |
| M3 指標 | 規則評估、回填、門檻事件、圖表 | AC-20–AC-26、AC-44 |
| M4 投遞 | webhook、ntfy、摘要、重試、DLQ、重放 | AC-30–AC-37 |
| M5 封存 | 封存、備份、還原演練 | AC-10–AC-14 |
| M6 個人使用 | 一個有用來源、單一實例、資料可保存與還原 | 見下；通知與擴展運維另行記錄 |

**M6 個人使用驗收（2026-10-17 縮減後的目前契約）：**

1. **沿用已完成的功能證據。** 認證與來源隔離、202 新增／200 同身分去重／409 異內容衝突、查詢、重啟持久化、HTTPS/HMAC 投遞與隔離還原可由既有 Docker／Python／原生測試證明；不因縮減而重做整套。這不代表真實來源或正式部署已驗收。
2. **先接一個有用途的來源。** 實際腳本、管線或服務的事件能在時間線找到，原文重送保留原 seq；接入時核對該來源的錯誤處理。Docker／Python 是執行方式，不決定事件是否真實。其他來源需要時各自接入與驗證；Alertmanager 啟用時仍須核對真實重送內容及 HTTP200 內逐筆結果。
3. **單一實例安全且資料持久。** 非 root、私人網路、來源與角色憑證分離、secret 檔案引用、明確的資料掛載／目錄。對所選實例確認重啟後既有事件可查，不把容器可啟動當作持久化證據。
4. **備份可用。** 對實際資料啟用適合自己的備份方式，確認完整 snapshot／manifest 能還原到新位置且資料可查；不限定必須前一個日曆日。保留原檔、校驗與啟動前的出口／憑證隔離。合成還原證明機制，實例備份的可用性另記。備份頻率依資料價值選定，不默認可遺失一天資料。
5. **只為有週期的來源設定沉默檢查。** 沿用既有 silent／recovered 功能證據，接入時核對 expected_interval；不為非週期 release／Alertmanager 強造 heartbeat。手機通知暫緩，不是首次使用條件。

不新增專屬驗收表單；在 [STATUS](../STATUS.md) 及私人接入紀錄分別記錄功能證據、來源接入、部署與備份結果。既有 auth、不可變身分、持久化去重、TLS／HMAC、目的地限制及安全還原契約保持不變。原有 `/v1/self` 等自我觀測設計不是首次使用的硬門檻；其實作差距必須如實列於 STATUS，不從設計文字推定已提供。

**選用的擴展運維驗收（原 M6 條件，未因此視為通過）：**

- 三個實際來源連續觀察七天且沒有非預期 `409`；區分新事件、重複、觀察及自然空窗。
- 停止週期來源後看板標示 `silent`，並實際收到手機通知。
- 停止中樞後由不同主機故障域的獨立通知路徑，在五分鐘內實際通知。
- 前一天真實快照的完整隔離還原與佇列恢復演練。

只有選擇相應運維目標時才執行以上項目；通知暫緩期間不承諾主動發現停機。若未來要求主機故障仍通知，獨立故障域是必要條件，不以同主機 Python／Docker 模擬冒充。備份與停機容忍度不由未回覆推定。

**狀態要分開記錄：** 設計接受、PR 合併、功能驗收、來源接入、部署與持續運作是不同狀態。歷史失敗／跳過仍保留，不能把選用項目改標 passed。

[M6 設計](../m6-design.md)說明接入與復原不變條件；[擴展部署驗收包](../deployment-acceptance.md)及 worksheet v1／`check_deployment.py --acceptance` 保留原嚴格語義，只用於上述擴展運維範圍，不再是個人使用的必填通道。範例或 checker 通過均不授權主機、生產者、secret 或通知帳號操作。
