ROLE: WORKER

AGENT: reviewer-contract-author

ID: T-012

Goal: Define the forward-only reviewer-report compatibility contract without rewriting any existing
report bytes or invalidating the accepted evidence hash chain.

Why: The current `teamctl.py validate-report` grammar accepts worker-style single-line verification
entries but rejects several historically correct reviewer reports whose evidence is split across
multiple lines. Future review evidence needs one deterministic, machine-valid shape.

Inputs to read first: codex-team-superpowers:codex-task-worker; `.team/PLAN.md`;
`products/hai-taskboard/AGENTS.md`; ADR-006; the complete initial plugin report contract;
all `.team/tasks/T-*.md` and `.team/reports/T-*.md`; and the current `teamctl.py validate-report`
implementation/help.

Scope (may touch): `.team/REVIEWER_REPORT_CONTRACT.md`; `.team/reports/T-012.md`.

Out of scope (must not touch): Existing task/report bytes; `.team/PLAN.md`; product specifications,
source, dependencies or tests; validator/plugin code; Git refs; credentials; providers/external state.

Definition of done:

- [ ] Record the validator version/source identity and the exact current pass/fail compatibility
      inventory for every existing report, including each report's SHA-256 and visible outcome.
- [ ] State that historical reports and accepted hash references are immutable evidence; validator
      incompatibility is metadata/process debt and does not relabel a PASS or FAIL.
- [ ] Define a future reviewer report grammar that passes the existing worker validator: every
      required Verification item is one physical line ending exactly in ` — passed`,
      ` — failed`, or ` — skipped`; details belong elsewhere or on the same line.
- [ ] Require reviewers to use report-only scope, run validator before handoff, preserve required
      failed/skipped evidence, and let only the orchestrator record acceptance.
- [ ] Define how a future validator migration may add a reviewer mode without rewriting legacy bytes:
      immutable compatibility manifest plus new-version validation results.
- [ ] Produce a validator-compatible T-012 report with exact commands, outputs, hashes and scope audit.

Verify with: current `teamctl.py validate-report` across all historical reports and T-012; SHA-256
inventory; `git diff --check`; exact scope audit.

Budget: One bounded documentation task; no delegation, commit, Git ref or external mutation.
