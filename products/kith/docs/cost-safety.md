# Cost safety contract

This contract supplements INV-05, INV-10 and the existing wake budget. Code controls do not prove deployment state or billed usage. No cloud deployment is part of this change.

## Paid execution

- Hosted and ambient defaults are off. A paid attempt requires `ff_hosted_agent=on`, `KITH_PAID_ENABLED=on`, and valid positive integer limits for global daily attempts, per-agent daily attempts and global concurrency. Missing, zero, malformed or excessive values refuse work. Provider configuration alone does not enable inference.
- The existing ROOM namespace hosts one instance-wide accounting object named `cost:global`. Its storage transaction reserves each `(generation, attempt)` once, counts all retries against UTC daily global/per-agent quotas, and limits active generation leases. Reservations are never refunded after a call or an unknown result. This is an attempt limit, not a currency guarantee. Model prices and input/output token limits still matter.
- Room admission applies to every hosted wake, including mention: at most one active hosted generation per room and six admissions per rolling minute. Admission is idempotent by generation ID and has a bounded lease. All async entry points recheck opt-in before external work.
- Each generation persists a phase before any network operation. Only `pending` or an explicitly scheduled `retry_wait` may atomically become `running`. The original deadline watchdog must remain scheduled before the running claim becomes durable; pre-deadline replay of an initializing/running phase restores cleanup without replaying inference. A crash after claiming work has an unknown outcome and fails closed. A compact terminal tombstone preserves identity while transcript/fake payloads are removed.
- V1/V2 paid attempts share an original 300-second admission/inference deadline, with bounded input, response bytes and output tokens. Deadline guards stop local waiting and prevent queued drafts/final sends from starting after expiry. Already-started platform RPC or provider work may remain pending or billed; this is not an absolute DO duration or invoice cap. Only an explicit retriable HTTP response may schedule at most one delayed retry; network failures/timeouts do not prove the provider did no work and are not replayed. A retry rechecks every gate and consumes another attempt.

## Background and transport bounds

- Ambient pending work expires within five minutes, with at most eight debounce re-arms and at least one second between re-arms. Terminal/drop paths clear pending state and alarms; platform Alarm retries do not reset these persisted bounds.
- Live-tail waiters are event driven, at most sixteen per Inbox, and expire within thirty seconds. No 25-ms storage polling. SSE streams have finite lifetimes, cancellation cleanup and a room concurrency limit; reconnect resumes through persisted seq/replay semantics. Live sidecars reconnect after response-body read errors as well as EOF, retain the cursor and active-generation identity, and honor explicit cancellation. Stream rotation must not exit a healthy live sidecar or replay inference. Room WebSockets use the Hibernation API and enforce the existing 32-connection cap. WebSocket send/status frames also require atomic per-member (120/minute) and per-room (1,000/minute) admission before D1, storage or fan-out work; frames larger than 16 KiB or over quota are refused. The minute counter retains at most the existing 32 room-member identities. These fixed limits preserve ordinary chat but do not replace edge connection/request abuse protection.
- Cron trace GC handles at most eight rooms and 2,048 trace rows per room per run with a persisted cursor. The count subquery reads at most the 50,000-row retention threshold plus this batch size through a room index. It does not claim that a SQL LIMIT alone bounds arbitrary scanned rows; query indexes are part of verification. At 64 active rooms a cycle takes up to nine daily runs, so cleanup throughput and backlog require monitoring, especially for summary-only trace traffic. User messages are not deleted to save costs.
- Full trace uploads reserve at most 128 per room and 32 per agent per UTC day. A D1 receipt is claimed before R2 work; duplicate or unknown-outcome uploads do not repeat writes. GC first atomically marks eligible receipts `deleting`, then deletes R2 text before its D1 reference. This prevents a concurrent late upload from creating an orphan. Failed cleanup keeps a retryable `deleting` receipt; unknown `claimed` uploads are quarantined and excluded from indexed automatic GC until operator reconciliation. Existing text is preserved on duplicate upload. Retrying with the same message ID cannot assume the first write was unbilled. Trace reads and authenticated core traffic still require account-level usage monitoring.
- API bodies are limited before parsing. API/MCP admission uses the existing accounting object to enforce an instance ceiling of 5,000 requests/minute and a per-IP default of 120/minute; login has a separate per-IP default of 10/minute. Counters expire each UTC minute and hold at most 512 clients. Operators may explicitly raise `KITH_MAX_API_REQUESTS_PER_MINUTE` or `KITH_MAX_LOGIN_ATTEMPTS_PER_MINUTE` to at most 1,000; malformed values deny access. Missing client IP shares an `unknown` bucket. These are application backpressure controls; requests to the Worker/accounting DO still incur platform usage, so edge abuse protection remains an owner action.

## Operator opt-in and rollback

Keep the default configuration for chat without hosted inference. To enable paid hosted behavior deliberately, set `ff_hosted_agent=on`, `KITH_PAID_ENABLED=on`, `KITH_MAX_PAID_ATTEMPTS_PER_DAY` (1–1000), `KITH_MAX_AGENT_ATTEMPTS_PER_DAY` (1–global limit), and `KITH_MAX_PAID_CONCURRENCY` (1–8). Start with small limits, e.g. 20 / 5 / 1. Enable `ff_providers` only to use configured V2 providers; enable `ff_ambient` separately only after checking its policy. Test fixtures opt in explicitly with fake providers.

Set `KITH_PAID_ENABLED=off` to stop subsequent attempts, including queued Alarm retries. Existing requests cannot be assumed unbilled or cancelled at the provider. Configuration changes require the operator's normal deployment process; this patch does not apply them to a running instance. Restoring flags alone cannot bypass mandatory limits. Do not restore the vulnerable execution code as a way to re-enable features.

Account Budget Alerts are informational and do not cap usage. The owner must independently check deployed bindings/flags, Workers/DO/D1/KV/R2 usage, account alerts, provider budgets and current invoices. Rate limiting does not prevent Workers request charges, and application controls cannot guarantee a maximum invoice.

## Offline verification

E2E history fixtures that need more than 1,000 missed messages must seed bounded local D1 data with the existing isolated test persistence directory; production HTTP quotas remain enforced. Reconnect assertions wait for the selected room's initial catch-up, and hosted reply assertions distinguish the human trigger from the actual agent reply. Tests retain all pagination, gap-fill and placeholder assertions, use fake providers only, and never bypass admission controls or access remote D1.
