# Reading capture phase 2 contract

This fixes the open implementation choices in cloudflare-reading-capture.md §8 for #463. The existing security invariants and RC-01–07 acceptance obligations remain unchanged. CI builds synthetic committed content and local tests publish atomically; no private repository, live publication, credentials or deployment is configured by this milestone.

## Immutable content

`reading/bundle.ts` exports `parseBundle(value: unknown): ReadingBundle | null`, `ReadingBundle = {version:1,commit:string,articles:{id:string,title:string,body:string}[]}`. A commit is exactly 40 lowercase hexadecimal characters. IDs match `[A-Za-z0-9_-]{1,128}`, are unique and explicit, never derived from paths. At most 200 articles, each title 1–200 UTF-8 bytes, body 1–65536 UTF-8 bytes, complete JSON at most 8 MiB. Reject malformed UTF-16, NUL and unknown object keys. The registry is `{version:1,articles:[{id,title,path}]}`; paths are relative POSIX regular Git blobs (no empty/dot/dotdot segments, backslash, colon, symlink or submodule). Its location is an explicit CLI argument. Markdown `/reading/<id>` links must name a registered ID; a missing ID or duplicate is a build failure. Renaming a path preserves its explicit ID.

`reading/build.ts` exports `buildReading({repo,commit,registry,output})`, returning the validated bundle. CLI: `node reading/build.ts --repo PATH --commit SHA --registry PATH --output PATH`. Only reads blobs from that exact full commit using Git plumbing; never executes content code/hooks/filters. Build the whole bundle and atomically rename a sibling temporary file to output. Parse, missing-file and build errors leave the previous output byte-for-byte unchanged. Default committed synthetic registry: `products/kith/content/articles.json`.

The only publication path is `web/dist/_reading/current.json`. Worker-first asset routing denies every direct private asset request, including HEAD; internal ASSETS fetch is available only after operator authentication. `GET /api/reading` returns the complete validated bundle, or 503 without partial data. Private responses/errors use no-store. Browser `/reading` and `/reading/:article_id` poll every 5 seconds and on focus; validate complete bundles before switching commit/catalog/body together. Keep the previous version on failure and preserve unsaved notes. UI shows commit (`reading-commit`), AI body (`reading-body`), divider, then human supplement (`note-body`, `note-save`, `note-status`). Article links carry `reading-link-<id>` test IDs. No editable AI body. Use existing safe React Markdown with headings/lists/internal links; raw HTML and unsafe URLs stay inert.

## Notes and credentials

Operator-session-only GET `/api/notes/:article_id` returns `{note:null|Note}`; PUT accepts exactly `{body,revision}` where revision is the expected current revision, 0 for creation. Note = `{id,article_id,body,revision,updated_at,exported_commit}`. IDs are safe strings; raw body uses the phase-1 exact UTF-8 1–16384-byte validation. Article must be in the valid current bundle. Atomic SQL CAS creates revision 1 or updates expected revision to +1, clears exported_commit, and sets injected UTC time. Exhausted safe integer rejects. A retry at expected+1 with identical raw body returns the existing note, otherwise 409 `note_conflict`; the UI keeps unsaved text and requires explicit reload before retrying a conflict. No automatic last-write-wins. Successful response `{note}` (201 create, 200 update/replay).

Operator-session-only POST `/api/reading-export/tokens` with `{}` returns 201 `{id,token}` once; GET returns `{tokens:[{id,created_at,revoked_at}]}` without secrets; DELETE `/:id` revokes, idempotent 204. Existing CSRF applies. Store only SHA-256, bound to the active operator who issued it. Dedicated `kith_export_` bearer token permits exactly GET `/api/reading-export` and POST `/api/reading-export/ack`; never falls back to a session, bot token or another method. Existing operator sessions also permit these two routes. Revocation is checked on every request. UI exposes create/revoke controls and one-time token without persistent browser storage.

GET export requires `kind=captures|notes`; optional `limit` 1–100 (default100), `cursor` a safe record ID. Returns `{records:[Capture|Note],next_cursor:string|null}` ordered by ID ascending, exclusive cursor. It includes already-exported rows so each bounded complete pass reconciles human Git edits with D1 authority. Capture = `{id,body,source:"web",created_at,exported_commit}`. No client_key/password/token fields. A pass is at most 100 pages per kind; reaching this bound stops with an explicit incomplete result, never silently claims full reconciliation.

POST ACK accepts exactly `{commit,captures:[id],notes:[{id,revision}]}`; total at most100, no duplicate IDs in each list, valid full SHA. Returns `{captures:number,notes:number}` changed-row counts. Capture ACK only changes pending rows; note ACK requires matching ID AND revision AND pending status. Old/repeated ACK changes zero rows. Remote confirmation is the trusted exporter's responsibility, not a claim that Worker can inspect Git.

## Local exporter

`reading/export.ts` exports `runExport({repo,branch,baseUrl,token, ...injected fault hooks})` and CLI `node reading/export.ts --repo PATH --branch BRANCH --url URL --token-file PATH`. One invocation performs one bounded pass; an operator may schedule it periodically. CLI credential file must be a private regular file, owner-only mode. Never log bodies/tokens or pass tokens to Git/URLs. HTTPS except loopback HTTP fixtures; reject redirects, use finite request/subprocess timeouts and response bounds. No provider calls.

Fixed JSON paths are `captures/<safe id>.json` and `notes/<safe id>.json`, no raw unsafe pathname interpolation. Canonical files contain the record fields above except exported_commit (to avoid self-referential commits), plus no changing timestamps beyond D1 fields. Use a process-lifetime singleton lock covering the entire pass; fail closed if lock ownership is uncertain. Persist a journal under Git metadata before file writes; recover that snapshot before fetching new pages. Guard against symlinked export directories/files, unrelated dirty source, unexpected branches/remotes and untrusted journal paths. Git hooks are disabled. Commit only explicitly owned snapshot paths, never force push or discard user work. Hooks for crash injection after write/commit/push are test-only injectable callbacks, not production environment switches.

Each snapshot is compared by full bytes/revision. Identical remote files create no new commit. Reconcile remote via fetch; before ACK verify the commit is contained by the configured remote ref AND that its files equal the snapshot. Push rejection, network failure or unconfirmed push leaves D1 pending and journal recoverable. A lost push response is recovered by remote inspection. A newer D1 revision cannot be ACKed by old snapshot recovery. Manual edits to exported files are overwritten on the next full reconciliation and an event records kind/ID (never body). Journal recovery is serial, so an old snapshot cannot race a newer run. Bounds/errors preserve remaining pending work.

## Evidence boundary

RC-05 uses actual local bare Git remotes, isolated D1 and injected crash/push failures. RC-06–07 use synthetic repositories and local atomic artifact replacement while the browser remains open. Full message-table snapshots and fake-provider counters must remain unchanged. CI builds its exact checked-out commit, runs exporter/builder tests and includes the bundle in the web output; content-path changes trigger that build. Real private-source access and live publication are an operational follow-up, not an implemented deployment claim.
