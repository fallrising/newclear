# 06 — 互動設計（UX）

[回 v2 索引](README.md) · 視覺：[07](07-visual-design.md)

## 1. 設計原則

1. **對話是主角。** 時間線佔最大面積；管理功能不擠進聊天畫面，放到控制台。
2. **人和 agent 一眼分得出，但地位平等。** 同一套訊息樣式，不同的頭像形狀與小徽記；不把 agent 做成系統通知。
3. **誠實的狀態。** 只顯示後端真的告訴我們的事：「正在回覆」來自 hosted 的 status，「已接手」來自 runner 的 `post_status`。不猜、不假裝排隊。
4. **可預期的限制。** 誰叫不醒某個 agent，在 @ 之前就看得到原因。
5. **一次一個主要動作。** 每個表單一個主要按鈕；錯誤在欄位下方。

## 2. 版面

### 2.1 桌面（≥ 1024px）

```text
┌──────────┬──────────────────────────────────────┬───────────────┐
│ Sidebar  │  Room header                         │ Right panel   │
│ 272px    │  ──────────────────────────────────  │ 320–400px     │
│          │  Timeline                            │ （可收合）      │
│ ▸ Kith   │                                      │ Members /     │
│ 搜尋房間  │                                      │ Thread /      │
│ Rooms    │                                      │ Agent detail  │
│  # Lobby │                                      │               │
│  # …     │  ──────────────────────────────────  │               │
│ Console* │  Composer                            │               │
│ 我 ▾     │                                      │               │
└──────────┴──────────────────────────────────────┴───────────────┘
* 只有 operator 看得到
```

### 2.2 平板（768–1023px）

Sidebar 272px ＋時間線；右側面板改為覆蓋式抽屜。

### 2.3 手機（< 768px）

- `/`：房間列表全頁。
- `/r/:slug`：聊天全頁，頂欄左側返回。
- 成員、thread、agent 詳情：底部 sheet（可拖到全高）。
- 輸入列貼底，處理 `visualViewport` 與 safe area。

## 3. Sidebar

- 頂部：Kith 字標；搜尋框（只篩選房名，本機）。
- 房間列：房名、最後一則預覽（`發送者: 內容`，單行省略）、相對時間、未讀數徽章。有未讀時房名加粗。選中房間有底色與左側色條。
- 排序：最後活動時間降冪（B-02 的 `last_message.created_at`）；沒訊息的房間排最後，依建立時間。
- operator 另有「＋ 新房間」與「控制台」入口。
- 底部：自己的頭像與名字，選單內有「設定」「主題：系統／淺色／深色」「語言：繁體中文／English」「登出」。
- 已封存的房間收在列表最下方可展開的「已封存」分組。

## 4. 房間畫面

### 4.1 Header

房名（可點開房間資訊）、成員頭像堆疊（最多 5 個＋「+N」，點開成員面板）、連線狀態點（只在非 live 時顯示文字：「連線中…」「離線，重新連線中…」）、operator 的「邀請」按鈕、右側面板開關。

v1 的 `live` pill 移除（正常狀態不佔空間）；離線改為 header 下方細條，不再同時出現 pill 與 banner。

### 4.2 Timeline

- **分組**：同一發送者、間隔 < 5 分鐘、中間沒有日期分隔 → 合併成一組；組首顯示頭像、名字、時間；組內其他則在 hover 時顯示時間。
- **日期分隔線**：「今天」「昨天」「9月21日 週一」。
- **新訊息分隔線**：進房時依未讀 cursor 插入「新訊息」線，捲動停在該處。
- **自己的訊息**：與他人同一欄靠左，但組首的名字改成「你」，底色極淡的 accent tint（可辨識但不搶眼）。
- **agent 訊息**：頭像為圓角方形＋runtime 徽記；名字旁邊一個小標籤（`AI`，hover 顯示 runtime 與模型名）。
- **提及**：`@handle` 顯示成 inline 高亮；提及到自己的整則左側加 accent 色條。
- **Markdown**：程式碼區塊有複製按鈕、語言標籤；長程式碼區塊可橫向捲動；不做語法高亮（Phase 2 決定是否加輕量高亮）。
- **系統訊息**（沒有 sender 的列）：置中、小字、無頭像。
- **訊息操作**（hover 或長按）：複製文字、在 thread 回覆、複製連結（`/r/:slug?seq=N`）、operator 看得到「查看 seq／generation」。
- **狀態列**：pending（送出中淡色＋小時鐘）、unknown（重送中）、failed（紅字「送出失敗」＋重試）。
- **捲動**：在底部時新訊息自動捲；不在底部時出現「↓ N 則新訊息」浮動按鈕。
- **頂端**：`has_more=false` 時顯示「這是 # 房名 的開頭」＋建立者與建立時間。

### 4.3 回覆中與草稿

- hosted agent 收到 `is replying` → 時間線底部出現該 agent 的**佔位訊息**（頭像＋名字＋三點動畫）。
- 收到 `draft` → 佔位內顯示目前文字，末尾有游標閃爍。
- 正式 event 到達 → 佔位消失，正式訊息出現在正確 seq 位置（通常就在同一處，不跳動）。
- `reply failed` → 佔位換成一行「{名字} 回覆失敗：{原因}」，8 秒後淡出；operator 另有「詳情」連結到 generation 列表。
- 300 秒無後續 → 佔位靜默消失（FM-SYNC-15）。
- runner 的 `post_status`：`accepted` →「{名字} 已接手」；`running` →「{名字} 執行中…」＋經過時間；`blocked` →「{名字} 卡住了」＋body；`idle` → 清除。顯示在同一個佔位位置。
- typing（人類）→ 輸入列上方一行「{名字} 正在輸入…」，多人時「A、B 正在輸入…」「3 人正在輸入…」。

### 4.4 Composer

- 多行輸入，1 行起長高，上限 40% 視窗高。
- Enter 送出、Shift+Enter 換行、IME 組字中 Enter 不送（沿用 v1 規則）；手機上 Enter 換行、按鈕送出。
- `@` 補全：沿用 v1 10 章的 combobox 規則；候選顯示頭像、名字、`@handle`、`AI` 標籤、限制句（例如「只有 operator 能喚醒」「未啟用：runner 離線」）。
- 提示文字只在輸入框空白且聚焦時淡淡顯示（placeholder：「傳訊息到 # 房名」）；鍵盤說明移到 `?` 按鈕的 tooltip，不再常駐。
- 離線時：可以打字，送出按鈕停用並提示「離線中」。
- 輸入框草稿每房保留（FE 狀態表）。

## 5. 右側面板

### 5.1 Members

分兩組：「人」與「AI」。每列：頭像、名字、`@handle`、角色（owner）、限制句、runtime 狀態點（AI）。operator 每列有「⋯」選單：移出房間、調整喚醒方式（attention，開一個小表單）。底部「邀請」按鈕。

### 5.2 Thread

頂部是根訊息，下面是回覆時間線（同樣的訊息元件），底部是 thread 專用的 composer。關閉回到成員面板。URL 同步 `/r/:slug/t/:threadId`。

### 5.3 Agent detail

點 agent 頭像或名字 → 面板顯示：名字、handle、runtime（hosted：連線名＋模型；runner：adapter 種類＋最近上線時間；external）、quota 說明、在本房的喚醒方式。operator 另有「在控制台編輯」連結。

## 6. 控制台（operator）

獨立版面：左側導覽（Agents、Providers、People、Rooms），右側清單＋詳情。

### 6.1 Agents

- 清單欄位：頭像、名字、runtime、狀態（`runtime_status`）、所在房間數、token 數。
- 新增 agent 精靈（3 步）：
  1. 基本：handle、顯示名。
  2. Runtime：選 `hosted`／`runner`／`external`，各有一句說明。
     - hosted：選連線（沒有就「新增連線」）、選模型（連線支援列模型時下拉，否則自由輸入）、進階（system prompt 附加、max tokens、temperature、串流）。
     - runner：選 adapter 種類；quota 選擇（「用 API key」或「用我的個人訂閱登入」＝`operator_personal`）。
     - external：quota 選擇。
  3. 完成：runner／external 顯示一次性 bot token＋可複製的設定片段；明確提示「關閉後無法再看到」。
- Runtime 分頁可改變 runtime 種類（RT-01）：確認對話框說明 in-flight 回覆會被丟棄、需重新選 quota、是否一併撤銷 token。
- 詳情頁分頁：概覽、Runtime、Tokens（列表、簽發、撤銷，撤銷需確認）、Generations（W5：最近 50 次，狀態、耗時、錯誤類別、token 用量）、房間（加入／移出）。

### 6.2 Providers

- 清單：名字、preset、格式、base URL（主機名）、key 末 4 碼、狀態（最近測試結果）、被幾個 agent 使用。
- 新增：選 preset → 自動填格式與 base URL → 貼 key（或選 env secret 名稱）→「這個連線背後是個人訂閱嗎？」（是 → `operator_personal`，BR-54）→「測試連線」→ 儲存。
- 編輯 key：只能覆寫，不能讀回。

### 6.3 People

人類帳號清單；新增人類（handle、顯示名、初始密碼，只顯示一次）；重設密碼；停用。

### 6.4 Rooms

所有房間清單、改名、封存／解除封存（BR-14）、成員數；點進去看成員與 agent 的 attention 設定總表。

## 7. 空狀態、載入、錯誤

| 情境 | 畫面 |
| --- | --- |
| operator 首次登入、沒有房間 | 引導卡片：建房間、建 agent、邀請人（UJ-01） |
| 一般成員沒有房間 | 「還沒有人邀請你加入房間」＋ operator 的名字 |
| 房間沒有訊息 | 房間開頭區塊＋「打個招呼吧」 |
| 載入中 | 骨架屏（時間線 6 列、列表 5 列），不用轉圈 |
| 成員載入失敗 | 面板內錯誤＋重試；已有的名單保留（沿用 v1 10 章） |
| API 5xx | 頁內錯誤區塊＋重試；不整頁白屏 |
| 找不到房間 | 「找不到這個房間，或你不是成員」＋回列表 |
| 403 console | 「這裡只有 operator 能進入」 |

## 8. 鍵盤快捷鍵

| 按鍵 | 動作 |
| --- | --- |
| `Ctrl/⌘ K` | 快速切換房間 |
| `Alt ↑/↓` | 上／下一個房間 |
| `Alt Shift ↑/↓` | 上／下一個有未讀的房間 |
| `Esc` | 關閉面板／清單；在時間線時捲到最新 |
| `Ctrl/⌘ /` | 顯示快捷鍵說明 |
