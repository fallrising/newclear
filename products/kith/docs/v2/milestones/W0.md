## 4. 契約

W0 不新增、不修改任何 HTTP 端點、WS 封包、MCP 欄位或 D1 表。它使用的既有端點與行為如下（已實測，§10）。

### 4.0 使用的既有 API（v1 [04 協定](../../sdd/04-protocol.md)）

| 方法 | 路徑 | 權限 | request | 成功回應 | 錯誤 |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/csrf` | 無 | — | 200 `{"csrf":"<token>"}`，同時 `Set-Cookie: csrf=<token>`（`worker/index.ts:67-71`、`worker/auth.ts:63-70`） | — |
| POST | `/api/auth/login` | CSRF：header `X-CSRF-Token` 必須等於 cookie `csrf` | `{"handle":string,"password":string}`；未知欄位 → 400 | 200 `{"ok":true,"member":Me}`，`Set-Cookie: kith_session=…; HttpOnly`（`worker/index.ts:73-101`） | 400 `invalid_request`（JSON 壞、未知欄位、空欄位）；401 `unauthorized` message `invalid credentials`（帳號不存在、不是 human、停用、密碼錯）；401 `unauthorized` message `CSRF token missing or mismatch`（`worker/index.ts:58-65`） |
| POST | `/api/auth/logout` | CSRF | 無 body | 200 `{"ok":true}` | 401 CSRF 錯誤 |
| GET | `/api/me` | session 或 bearer | — | 200 `Me` | 401 `unauthorized`；bearer 存在時先驗 bearer，未知 token 直接 401，不看 session（`worker/auth.ts:148-158`） |
| GET | `/api/rooms` | session 或 bearer | — | 200 `{"rooms":[{id,slug,name,created_at,role}]}`，依 `rooms.created_at` 升冪（`worker/index.ts:116-129`） | 401 |

失敗範例（已實測）：

```http
POST /api/auth/login
X-CSRF-Token: <與 cookie 相同>
{"handle":"ada","password":"wrong-password"}

HTTP/1.1 401
{"error":{"code":"unauthorized","message":"invalid credentials"}}
```

成功範例：

```json
{"ok":true,"member":{"id":"m-ada","kind":"human","handle":"ada","display_name":"Ada Lin","capabilities_json":"[]","quota_class":"api_key","is_operator":1}}
```

注意：CSRF 不符與帳密錯誤都是 401 `unauthorized`。前端**每次** unsafe request 前都重新 `GET /api/csrf`（§5.2.2），因此不需要分辨兩者。

### 4.1 前端 TypeScript 型別（`web/src/api/types.ts`，完整內容）

```ts
export type QuotaClass = "api_key" | "operator_personal";

/** GET /api/me 與 POST /api/auth/login 的 member（worker/index.ts publicMember）。 */
export type Me = {
  id: string;
  kind: "human" | "agent";
  handle: string;
  display_name: string;
  capabilities_json: string;
  quota_class: QuotaClass;

export type LoginRequest = { handle: string; password: string };
export type LoginResponse = { ok: true; member: Me };
export type LogoutResponse = { ok: true };

```

### 4.2 E2E 證據 manifest（`contracts/v2/e2e-manifest.json`）

Schema：[`contracts/v2/e2e-manifest.json`](../../../contracts/v2/e2e-manifest.json)（JSON Schema 2020-12，`additionalProperties: false`）。由 `e2e/harness/reporter.ts` 在每次執行結束時寫入 `<run_dir>/manifest.json`。

欄位規則（schema 以外的語意）：

| 欄位 | 規則 |
| --- | --- |
| `run_id` | `YYYYMMDD-HHMMSS`（UTC，config 載入時的時間）＋`-`＋7 碼 git short sha＋工作樹有變更時 `-dirty` |
| `command` | `"playwright " + process.argv.slice(2).join(" ")`，在 reporter 中計算 |
| `status` | Playwright 的 `FullResult.status`；reporter 自己的檢查（`errors` 非空或 `hits_after_redaction > 0`）會強制改成 `failed` |
| `results` | 每個 (測試 × project) 一筆；標題沒有驗收 ID 的測試**不**列入，改在 `errors` 加 `missing acceptance id: <title>` |
| `results[].evidence` | `screenshot`／`api-log`／`ws-log`／`trace`／`file` 有 `path`＋`sha256`；`assertion` 只有 `text` |
| `files` | run 資料夾內所有檔案，排除 `manifest.json`、`summary.md`，以及第一層目錄為 `report/`、`test-output/`、`state/`、`nested/` 的檔案；依路徑排序 |
| `redaction.patterns` | 固定為 7 條規則 ID（§5.1.5） |
| `redaction.scanned_files` | 實際掃描的檔案數（§5.1.5 的掃描範圍） |
| `errors` | harness 層級錯誤；非空即 `failed` |

#### 4.4.4 SQL 產生規則

1. 第一行 `-- kith e2e seed base-v1 (generated by e2e/fixtures/seed.ts; test-only credentials)`。
2. 依序 INSERT：members（表格順序）→ rooms（表格順序）→ room_members（房間順序，每房 owner 先，其餘依表格順序）→ messages（`room-lobby`、`room-long`、`room-ada-private`，各依 seq）。
3. 每個 INSERT 一行，以 `;` 結尾，列出完整欄位名。
4. 字串以單引號包住，內部單引號重複成兩個（`'` → `''`）。
5. body 含換行時，以 `char(10)` 串接：`'- 週六：爬山' || char(10) || '- 週日：休息'`。這樣每個 SQL 陳述都在一行內。
6. body 不得含 `;`（`wrangler d1 execute --file` 以分號分句）；`buildSeed()` 發現就丟錯 `seed body must not contain ';': <message id>`。
7. `sha256` = SQL 全文（UTF-8）的 sha256 hex。

#### 5.1.4 `paths.ts`、`git.ts`、`run-env.ts`

`paths.ts`：以 `fileURLToPath(new URL("..", import.meta.url))` 取得 `E2E_DIR`（`harness/` 的上一層），其餘依 §4.5 的註解以 `path.join` 組出。

`git.ts` `readGit()`：以 `execFileSync("git", [...], { cwd: KITH_DIR, encoding: "utf8" })` 依序執行並 `trim()`：

1. `rev-parse HEAD` → `sha`
2. `rev-parse --short=7 HEAD` → `short`
3. `rev-parse --abbrev-ref HEAD` → `branch`
4. `status --porcelain` → `dirty = 輸出非空`

任一指令丟錯 → 丟 `Error("kith e2e requires a git checkout: <原訊息>")`。

`run-env.ts` `ensureRunEnv()`：

1. 若 `process.env.KITH_E2E_RUN_ID` 未設定：
   1. `now = new Date()`；`stamp = now.toISOString()` 取 `YYYY`、`MM`、`DD`、`HH`、`mm`、`ss` 組成 `YYYYMMDD-HHMMSS`。
   2. `git = readGit()`；`runId = stamp + "-" + git.short + (git.dirty ? "-dirty" : "")`。
   3. `process.env.KITH_E2E_RUN_ID = runId`。
2. `runDir = join(artifactsRoot(), process.env.KITH_E2E_RUN_ID)`；`process.env.KITH_E2E_RUN_DIR = runDir`。
3. 若 `process.env.KITH_E2E_RUN_DIR_CHECKED !== "1"`（主程序第一次載入 config）：`existsSync(runDir)` 為真 → 丟 `Error("run dir already exists: " + runDir)`；否則設 `process.env.KITH_E2E_RUN_DIR_CHECKED = "1"`。worker 繼承這個變數，所以不會在 setup 建好資料夾之後誤判。
4. 回傳 `{ runId, runDir }`。

第 3 步必須在 config 載入時做，不能只靠 global setup：setup 失敗時 Playwright 仍會在 `outputDir` 寫 `.last-run.json`、在 html reporter 的資料夾寫 `index.html`；只有 config 載入就丟錯，才完全不碰既有資料夾（已實測，§10）。

config 在主程序與每個 worker 程序都會載入；因為第 1 步只在變數未設定時產生，而 worker 繼承主程序的環境，整次執行只有一個 `run_id`（已實測）。

#### 5.1.5 `redact.ts`：遮罩規則

| 規則 | 作用於 | 行為 |
| --- | --- | --- |
| `R01-cookie-header` | header `cookie`、`set-cookie`（不分大小寫） | 值改為 `[REDACTED]`；改寫前把每個 `kith_session=` 與 `csrf=` 的值傳給 `recordObservedSecret` |
| `R02-authorization-header` | header `authorization` | `Bearer <x>` → `Bearer [REDACTED]`；其他 → `[REDACTED]` |
| `R03-csrf-header` | header `x-csrf-token` | 值改為 `[REDACTED]` |
| `R04-json-secret-keys` | JSON 任何深度的 key：`password`、`old_password`、`new_password`、`csrf`、`token`、`secret`、`api_key`、`bot_token` | 字串值改為 `[REDACTED]` |
| `R05-bot-token` | 所有文字 | 正規式 `/kith_bot_[0-9a-f]{64}/g` → `kith_bot_[REDACTED]` |
| `R06-known-secrets` | 所有文字 | `knownSecrets()`（`accounts.ts`：四個測試密碼、`CANARY`、`canaryBotToken()`）逐一字面取代為 `[REDACTED]` |
| `R07-observed-session` | 所有文字 | `readObservedSecrets()` 的每個值字面取代為 `[REDACTED]` |

函式：

- `redactHeaders(h)`：key 轉小寫後套 R01–R03，再對每個值套 `redactText`。只保留這些 header：`content-type`、`cookie`、`set-cookie`、`authorization`、`x-csrf-token`（其他丟掉，避免 log 過大）。
- `redactJson(v)`：遞迴複製；物件 key 符合 R04 且值為字串 → `[REDACTED]`；其他字串值 → `redactText`。
- `redactText(s)`：依序套 R05、R06、R07（R07 讀 `readObservedSecrets()`）。
- `recordObservedSecret(v)`：`v.length >= 16` 時，把 `v + "\n"` 以 `appendFileSync` 附加到 `process.env.KITH_E2E_SECRET_FILE`（檔案權限 `0o600`）；變數未設定就丟錯。
- `readObservedSecrets()`：讀該檔、以換行切開、去空行、去重；檔案不存在回 `[]`。
- `scanText(s, observed)`：回傳命中的規則（每條至多一次）：`R05`（正規式命中）、`R06`（任一 known secret 出現）、`R07`（任一 observed 值出現）。

掃描範圍（reporter 使用）：run 資料夾下所有副檔名為 `.jsonl`、`.json`、`.log`、`.md`、`.txt` 的檔案，排除 `manifest.json`、`summary.md` 與 `report/`、`test-output/`、`traces/`、`state/`、`nested/` 子目錄。排除理由：`report/`、`test-output/`、`traces/` 由 Playwright 管理（含二進位）；`state/` 在 teardown 刪除；`nested/` 是巢狀執行，有自己的 manifest。`traces/` 與 `report/` 會記錄網路請求，因此含測試密碼與本次 session 值；這些值只屬於一個已銷毀的本機實例，不遮罩也不掃描；V2-INV-01 要求的「伺服器回應、封包、log 不含 key」由 `api/`、`ws/`、`server.log` 覆蓋。

秘密檔位置：`join(os.tmpdir(), "kith-e2e-" + runId + ".secrets")`，**不在** run 資料夾內。

#### 5.1.6 `server.ts`

模組內狀態：`const children: ChildProcess[] = []`。

`getFreePort()`：`net.createServer()` 監聽 `0` 於 `127.0.0.1`，取 `address().port`，關閉後回傳。

`waitForHttp(url, timeoutMs)`：迴圈 `fetch(url)`；`res.status === 200` 就回傳；連線錯誤或其他狀態就等 250 ms 再試；超過 `timeoutMs` 丟 `Error("not ready within <timeoutMs> ms: <url>")`。（這是就緒輪詢，不是正確性證明。）

`startStack(runDir, stateDir)` 步驟：

1. `webMode = process.env.E2E_WEB === "dev" ? "dev" : "build"`。
2. `wranglerEnv = { ...process.env, CLOUDFLARE_CF_FETCH_ENABLED: "false", WRANGLER_SEND_METRICS: "false", FORCE_COLOR: "0" }`。
3. `apiPort = await getFreePort()`、`inspectorPort = await getFreePort()`。
4. `assetsDir`：`build` → `WEB_DIST_DIR`；`dev` → `join(stateDir, "empty-assets")`，建立它並寫入 `index.html`，內容 `<!doctype html><title>assets placeholder</title>`。
5. 寫 `join(stateDir, "wrangler.env")`，內容 `KITH_E2E=1\n`。
6. `spawn(WRANGLER_BIN, args, { cwd: KITH_DIR, env: wranglerEnv, detached: true, stdio: ["ignore", "pipe", "pipe"] })`，`args`：
   `dev --local --ip 127.0.0.1 --port <apiPort> --inspector-port <inspectorPort> --persist-to <stateDir> --assets <assetsDir> --env-file <stateDir>/wrangler.env --show-interactive-dev-session=false --var ff_mcp:on --var ff_hosted_agent:on --var ff_sidecar:off --var ff_ambient:off`
7. 子程序的 stdout 與 stderr 都接到 `lineWriter(join(runDir, "server.log"))`：以 `\n` 切行、去掉 ANSI（`/\x1b\[[0-9;]*m/g`）、`redactText`、`appendFileSync`。
8. `children.push(child)`；把 `{ pid: child.pid }` 附加到 `join(stateDir, "pids.json")`（JSON 陣列）。
9. `await waitForHttp("http://127.0.0.1:<apiPort>/api/csrf", 60_000)`。
10. 若 `dev`：`webPort = await getFreePort()`；`spawn("npm", ["run", "dev", "--", "--port", String(webPort), "--strictPort"], { cwd: WEB_DIR, env: { ...process.env, KITH_API_ORIGIN: apiOrigin }, detached: true, stdio: ["ignore", "pipe", "pipe"] })`，輸出接到 `join(runDir, "web-dev.log")`（同第 7 步的處理），加入 `children` 與 `pids.json`；`await waitForHttp("http://127.0.0.1:<webPort>/login", 60_000)`。
11. 回傳 `{ apiOrigin: "http://127.0.0.1:<apiPort>", baseUrl: build ? apiOrigin : "http://127.0.0.1:<webPort>", webMode }`。

`stopStack()`：

1. 若 `children` 為空，讀 `pids.json`（有的話）當作要停止的 pid 清單。
2. 由後往前，對每個 pid：`process.kill(-pid, "SIGTERM")`（負號＝整個 process group，含 wrangler 啟動的 workerd；已實測）；等該子程序 `exit` 最多 10 s；逾時則 `process.kill(-pid, "SIGKILL")`。`ESRCH`（已結束）視為成功。
3. 清空 `children`。

禁止：`pkill`、`killall`、依名稱殺程序。只停止本次啟動的 process group。

#### 5.1.7 `global-setup.ts`

`export default async function globalSetup(): Promise<void>`，步驟：

1. `const { runId, runDir } = ensureRunEnv()`。
2. `mkdirSync(dirname(runDir), { recursive: true })`，再 `mkdirSync(runDir, { recursive: false })`。若 `runDir` 已存在 → 丟 `Error("run dir already exists: <runDir>")`（第二道防線；第一道在 `ensureRunEnv` 第 3 步，FM-E2E-04）。
   之後的步驟一律使用 `stateDir = join(runDir, "state")`。
3. `process.env.KITH_E2E_RUN_DIR_OWNED = "1"`。
4. `process.env.KITH_E2E_SECRET_FILE = join(os.tmpdir(), "kith-e2e-" + runId + ".secrets")`；以 `writeFileSync(path, "", { mode: 0o600 })` 建立。
5. 建立 `runDir` 下的 `screenshots/`、`api/`、`ws/`、`files/`、`traces/`、`state/`。
6. 以下全部包在 `try { … } catch (e) { await stopStack(); throw e; }` 內（setup 丟錯時 Playwright **不會**呼叫 global teardown，已實測，所以 setup 必須自己收拾）：
   1. 檢查 `WRANGLER_BIN` 存在，否則丟 `Error("missing wrangler: run npm ci in products/kith")`。
   2. web：若 `E2E_WEB !== "dev"`：
      - `KITH_E2E_SKIP_WEB_BUILD === "1"`：檢查 `WEB_DIST_DIR/index.html` 存在，否則丟 `Error("KITH_E2E_SKIP_WEB_BUILD=1 but web/dist/index.html is missing")`。
      - 否則 `spawnSync("npm", ["run", "build"], { cwd: WEB_DIR, encoding: "utf8" })`，把 stdout＋stderr（`redactText` 後）寫到 `runDir/web-build.log`；`status !== 0` → 丟 `Error("web build failed; see web-build.log")`。
   3. migration：`spawnSync(WRANGLER_BIN, ["d1", "migrations", "apply", "kith", "--local", "--persist-to", stateDir], { cwd: KITH_DIR, env: wranglerEnv, encoding: "utf8" })`；輸出附加到 `server.log`；非 0 → 丟 `Error("d1 migrations failed; see server.log")`。（已實測不需互動確認。）
   4. seed：`const seed = await buildSeed()`；寫 `stateDir/seed.sql`；`spawnSync(WRANGLER_BIN, ["d1", "execute", "kith", "--local", "--persist-to", stateDir, "--file", join(stateDir, "seed.sql"), "-y"], …)`；非 0 → 丟 `Error("seed failed; see server.log")`；寫 `runDir/seed.json`（`JSON.stringify(seed.description, null, 2) + "\n"`）。
   5. `const stack = await startStack(runDir, stateDir)`。
   6. 版本：`node = process.versions.node`；`wrangler` = `KITH_DIR/node_modules/wrangler/package.json` 的 `version`；`playwright` = `E2E_DIR/node_modules/@playwright/test/package.json` 的 `version`；`chromium`：`const b = await chromium.launch(); const v = b.version(); await b.close();`。
   7. 寫 `runDir/run-context.json`：`{ run_id, git: readGit(), scope, web_mode, base_url, versions, seed: { id, sha256 }, started_at }`，`scope = process.env.KITH_E2E_SCOPE === "full" ? "full" : "partial"`，`started_at = new Date().toISOString()`。
   8. `process.env.KITH_E2E_BASE_URL = stack.baseUrl`；`process.env.KITH_E2E_SETUP_OK = "1"`。

`wranglerEnv` 與 §5.1.6 第 2 步相同（從 `server.ts` 匯出 `wranglerEnv()` 函式共用）。

`export default async function globalTeardown(): Promise<void>`：

1. `await stopStack()`。

#### 5.1.9 `fixtures/kith.ts`、`recorder.ts`、`evidence.ts`

`kith.ts`：

（`ApiClient`、`ApiResult` 型別在同檔定義，見 §4.5。已實測以 fixture 覆寫 `baseURL` 可行。）

`createApiClient(page, recorder)` 的 `call(method, path, body)`：

1. `headers: Record<string, string> = {}`。
2. 若 `method !== "GET"`：`const c = await page.request.get("/api/csrf")`；`headers["X-CSRF-Token"] = (await c.json()).csrf`。
3. 若 `body !== undefined`：`headers["content-type"] = "application/json"`。
4. `const res = await page.request.fetch(path, { method, headers, data: body === undefined ? undefined : JSON.stringify(body) })`。
5. `json`：`content-type` 含 `application/json` 時 `await res.json()`，否則 `null`。
6. `recorder.logApi({ ts, actor: "api", method, path, status: res.status(), req_headers: redactHeaders(headers), req_body: redactJson(body ?? null), res_headers: redactHeaders(res.headers()), res_body: redactJson(json), error: null })`。
7. 回傳 `{ status: res.status(), json }`。

`page.request` 與 page 共用 cookie，所以登入後可直接呼叫。

`Recorder`：

- `constructor(runDir, id, project)`：`id === null`（標題沒有驗收 ID）時不建立任何檔案，所有方法變成 no-op。否則 `apiPath = join(runDir, "api", id + "." + project + ".jsonl")`、`wsPath = join(runDir, "ws", id + "." + project + ".jsonl")`，兩檔都先以空字串建立（沒有流量也要有檔案）。
- `watch(page, actor)`：
  - `page.on("response", async (res) => …)`：只記錄 `new URL(res.url())` 的 origin 等於 `KITH_E2E_BASE_URL` 且 pathname 以 `/api/` 開頭或等於 `/mcp` 或以 `/mcp/` 開頭者。`req_body`：`res.request().postData()` 可解析成 JSON → `redactJson(parsed)`；不能解析 → `redactText(前 2048 字元)`；沒有 → `null`。`res_body`：`content-type` 含 `application/json` 時 `redactJson(await res.json())`，解析失敗或其他型別為 `null`；原始文字超過 8,192 字元時改記 `{ "truncated": true, "chars": <長度> }`。`res.headers()` 與 `res.request().headers()` 都經 `redactHeaders`（這一步順帶記錄 observed session 值）。
  - `page.on("requestfailed", (req) => …)`：同樣的過濾；`status: null`，`error: req.failure()?.errorText ?? "failed"`。
  - `page.on("websocket", (ws) => …)`：`ws.on("framesent", f => line("out", f.payload))`、`ws.on("framereceived", f => line("in", f.payload))`、`ws.on("close", () => line("close", null))`；`payload` 是字串時嘗試 `JSON.parse` 後 `redactJson`，失敗則 `redactText(前 2048 字元)`；`path` 為 `new URL(ws.url()).pathname`。
- `logApi(line)`：`appendFileSync(apiPath, JSON.stringify(line) + "\n")`。
- `finish(info)`：push 兩筆 annotation：`{ type: "evidence", description: JSON.stringify({ kind: "api-log", path: "api/<id>.<project>.jsonl" }) }` 與對應的 `ws-log`。

`evidence.ts`：

- `acceptanceId(info)`：`/^((?:E2E|PROBE)-W[0-7]-[0-9]{2}) /.exec(info.title)?.[1] ?? null`。
- `shot(page, info, step)`：
  1. `id = acceptanceId(info)`；`null` → 丟 `Error("shot() requires an acceptance id in the test title")`。
  2. `step` 必須符合 `/^[a-z0-9-]+$/`，否則丟錯。
  3. 以 `WeakMap<TestInfo, number>` 為每個測試計數，`n` 從 1 開始，兩位數補零。
  4. `rel = "screenshots/" + id + "/" + nn + "-" + step + "-" + info.project.name + ".png"`。
  5. `await page.screenshot({ path: join(runDir, rel), fullPage: false, animations: "disabled", caret: "hide", mask: [page.locator("[data-mask]")] })`。
  6. push annotation `{ type: "evidence", description: JSON.stringify({ kind: "screenshot", path: rel }) }`；回傳 `rel`。
- `note(info, text)`：push `{ type: "evidence", description: JSON.stringify({ kind: "assertion", text }) }`。`text` ≤ 500 字元。
- `saveFile(info, name, content)`：`rel = "files/" + id + "/" + name`（`name` 符合 `/^[a-z0-9.-]+$/`）；建立目錄、寫檔（**不**做遮罩：呼叫者要自己決定內容）；push `{ kind: "file", path: rel }`；回傳 `rel`。

元件約定（給之後的里程碑）：任何顯示伺服器時間的元素都加 `data-mask="time"`，`shot()` 會遮住它。

#### 5.1.10 `validate.ts` 與 `reporter.ts`

`validateRunDir(runDir)`，回傳 `problems`（空陣列＝通過）：

1. 讀 `manifest.json`；不存在 → `["missing manifest.json"]`。
2. 以 `Ajv2020`（`import { Ajv2020 } from "ajv/dist/2020.js"`，`{ allErrors: true, strict: true }`）編譯 `CONTRACTS_DIR/e2e-manifest.json` 並驗證；每個錯誤加一行 `manifest schema: <instancePath> <message>`。
3. 同樣驗證 `seed.json` 對 `e2e-seed.json`。
4. 對 `manifest.files` 每一筆：檔案存在、`bytes` 相同、sha256 相同；否則 `file mismatch: <path>`。
5. 對每個 evidence 的 `path`：檔案存在且 sha256 相同；否則 `evidence mismatch: <path>`。
6. `summary.md` 存在且包含 `run_id`；否則 `summary missing run_id`。
7. `screenshots/`、`api/`、`ws/` 目錄存在；否則 `missing dir: <name>`。

`reporter.ts`：`export default class KithReporter implements Reporter`。

- `onBegin(config, suite)`：記下 `startedAt`。
- `onError(error)`：把 `error.message`（`redactText` 後、截到 500 字元）加入 `this.globalErrors`。
- `onTestEnd(test, result)`：
  1. `id = /^((?:E2E|PROBE)-W[0-7]-[0-9]{2}) /.exec(test.title)?.[1]`；沒有 → `errors.push("missing acceptance id: " + test.title)`，結束。
  2. `project = test.parent.project()?.name`（`desktop` 或 `mobile`）。
  3. `evidence` = `test.annotations` 中 `type === "evidence"` 的 `JSON.parse(description)`。
  4. `result.attachments` 中 `name === "trace"` 且有 `path` 的，複製到 `traces/<id>.<project>.zip`，加入 `{ kind: "trace", path }`（已實測 Playwright 1.56.1 的 trace 附件名是 `trace`）。
  5. 存成 result：`spec = relative(E2E_DIR, test.location.file)`、`tags = test.tags`、`status = result.status`、`duration_ms = result.duration`、`retry = result.retry`。
- `async onEnd(result)`：
  1. 若 `process.env.KITH_E2E_RUN_DIR_OWNED !== "1"`：印 `[kith-e2e] run dir not owned by this run; nothing written`，回傳 `{ status: "failed" }`（衝突時不覆寫他人的資料夾）。
  2. 若 `process.env.KITH_E2E_SETUP_OK !== "1"`：寫 `summary.md`，內容 `# E2E run <run_id>\n\n- 狀態：setup failed\n` 加上每條 `globalErrors`；刪秘密檔；回傳 `{ status: "failed" }`。
  3. 讀 `run-context.json`。
  4. 每個 evidence path 檢查存在；不存在 → `errors.push("missing evidence file: " + path)`，並把該筆從 evidence 移除（使 manifest 仍符合 schema）。
  5. 掃描（§5.1.5 範圍）：`observed = readObservedSecrets()`；每個檔案 `scanText(內容, observed)`，命中就加 `{ file, rule }` 到 `hits`。
  6. `files`：列出 run 資料夾所有檔案（排除清單見 §4.2 `files` 列），算 sha256 與 bytes，依路徑排序。
  7. `status = result.status`；若 `errors.length > 0` 或 `hits.length > 0` → `"failed"`。
  8. 組 manifest（§4.2），寫 `summary.md`（格式見下），再寫 `manifest.json`（`JSON.stringify(m, null, 2) + "\n"`）。
  9. 自我驗證：`validateRunDir(runDir)`；有 problems → 印出每一條，`status = "failed"`，把 problems 加到 `errors` 後**重寫** `summary.md` 與 `manifest.json`（此時不再驗證，避免迴圈）。
  10. 刪秘密檔（`rmSync(..., { force: true })`）。
  11. 印 `[kith-e2e] run <run_id>: <status>; evidence at <runDir>`。
  12. 回傳 `{ status }`（`status` 為 `failed` 時 Playwright exit code 變成 1，已實測）。

#### 5.1.11 `nested.ts`

`runNested({ root, grep, runId, timeoutMs })`：

1. `const env: NodeJS.ProcessEnv = Object.fromEntries(Object.entries(process.env).filter(([k]) => !dropped(k)))`（以過濾建立，不用 `delete`，避免 `TS2790`）。`dropped(k)` 為真的 key：所有以 `KITH_E2E_` 開頭的 key，以及 `E2E_WEB`、`PLAYWRIGHT_TEST`、`TEST_WORKER_INDEX`、`TEST_PARALLEL_INDEX`、`FORCE_COLOR`、`DEBUG_COLORS`（Playwright worker 設定的變數；保留 `PLAYWRIGHT_BROWSERS_PATH`）。已實測：即使不刪，巢狀執行也能跑；刪除是為了不讓外層狀態影響內層。
2. 加上：`KITH_E2E_PROBE=1`、`KITH_E2E_ARTIFACTS_ROOT=root`、`KITH_E2E_SKIP_WEB_BUILD=1`；`runId` 有值時 `KITH_E2E_RUN_ID=runId`。
3. `spawn(PLAYWRIGHT_BIN, ["test", "--grep", grep], { cwd: E2E_DIR, env, stdio: ["ignore", "pipe", "pipe"] })`，收集 stdout＋stderr 成 `output`。
4. 超過 `timeoutMs` → `child.kill("SIGTERM")` 並丟 `Error("nested run timed out")`。
5. 回傳 `{ exitCode, output: redactText(output.replace(/\x1b\[[0-9;]*[A-Za-z]/g, "")), root }`（去 ANSI 後遮罩）。

`scripts/print-seed.ts`：`const s = await buildSeed(); console.log(s.id, s.sha256, JSON.stringify(s.description.counts));`

`client.ts`：

```ts
import type { ApiErrorBody, CsrfResponse } from "./types";

export class ApiError extends Error {
  readonly status: number;   // 0 = 網路錯誤
  readonly code: string;     // 伺服器 error.code；網路錯誤 "network_error"；無法解析 "http_<status>"
  constructor(status: number, code: string, message: string) { … }
}

export type HttpMethod = "GET" | "POST" | "PATCH" | "PUT" | "DELETE";

export async function apiFetch<T>(
  path: string,
  init: { method?: HttpMethod; body?: unknown; signal?: AbortSignal } = {},
): Promise<T>;
```

`apiFetch` 步驟：

1. `method = init.method ?? "GET"`；`headers = new Headers()`。
2. `method !== "GET"`：`const csrf = await getCsrf(init.signal)`；`headers.set("X-CSRF-Token", csrf)`。（每次都重新取；v1 對 CSRF 不符與未登入都回 401 `unauthorized`，無法區分，所以不快取。）
3. `init.body !== undefined`：`headers.set("Content-Type", "application/json")`，`body = JSON.stringify(init.body)`。
4. `fetch(path, { method, headers, body, credentials: "same-origin", signal: init.signal })`；丟出 `AbortError` → 原樣重拋；其他例外 → `throw new ApiError(0, "network_error", "network error")`。
5. `res.status === 204` → `return undefined as T`。
6. `text = await res.text()`。
7. `!res.ok`：嘗試 `JSON.parse(text)`，符合 `ApiErrorBody` → `new ApiError(res.status, body.error.code, body.error.message)`；否則 `new ApiError(res.status, "http_" + res.status, "HTTP " + res.status)`。丟出。
8. `return (text ? JSON.parse(text) : undefined) as T`。

`getCsrf(signal)`：`fetch("/api/csrf", { credentials: "same-origin", cache: "no-store", signal })`；非 2xx → 同第 7 步丟 `ApiError`；回傳 `(await res.json() as CsrfResponse).csrf`。
