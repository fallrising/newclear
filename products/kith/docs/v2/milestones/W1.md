## 4. 契約

### 4.1 B-01：`GET /api/rooms/:id/messages`

Schema：[`contracts/v2/http-messages-list.json`](../../../contracts/v2/http-messages-list.json)（`$defs.query`、`$defs.response`、`$defs.message`）。

| 項目 | 內容 |
| --- | --- |
| 方法、路徑 | `GET /api/rooms/:id/messages` |
| 權限 | session 或 bearer；必須是房內成員 |
| 既有參數 | `after_seq`（預設 -1）、`before_seq`、`limit`（1–50，預設 50）、`kind`（`message`、`trace`、或兩者以逗號分隔；預設 `message`） |
| 新參數 | `order`：`asc` 或 `desc`。**不帶時行為與 v1 位元級相同**（同一條 SQL、回應只有 `messages`） |
| `order` 存在時 | 查 `limit + 1` 列；`has_more = 列數 > limit`；只回前 `limit` 列；`desc` 時把這 `limit` 列反轉，使**回應陣列永遠 seq 升冪** |
| `has_more` 語意 | `desc`：還有 seq 更小（更早）的列；`asc`：還有 seq 更大（更新）的列。兩者都受 `after_seq`、`before_seq`、`kind` 限制 |
| 回應 | `{ "messages": ServerMessage[] }`（無 `order`）或 `{ "messages": ServerMessage[], "has_more": boolean }` |

錯誤碼（沿用 v1，新增一個 message 文字）：

| HTTP | `code` | 何時 |
| --- | --- | --- |
| 400 | `invalid_request` | `after_seq`、`before_seq`、`limit` 不是有限數字；`kind` 含其他值；**`order` 不是 `asc`／`desc`（message `invalid order`，新增）** |
| 401 | `unauthorized` | 未登入 |
| 403 | `forbidden` | 不是房內成員 |
| 404 | `not_found` | 房間不存在 |

成功範例（seed `base-v1`）：

```http
GET /api/rooms/room-long/messages?order=desc&limit=3&kind=message,trace

200
{"messages":[
  {"id":"msg-long-1197","room_id":"room-long","seq":1197,"kind":"message","thread_id":null,"reply_to":null,"sender_id":"m-ben","body":"長歷史 #1197 — Long history message 1197","mentions_json":"[]","generation_id":null,"client_message_id":"seed-long-1197","origin":"local","created_at":"2026-08-01T19:57:00.000Z"},
  {"id":"msg-long-1198", "…": "…", "seq":1198},
  {"id":"msg-long-1199", "…": "…", "seq":1199}
],"has_more":true}
```

失敗範例：

```http
GET /api/rooms/room-long/messages?order=newest

400
{"error":{"code":"invalid_request","message":"invalid order"}}
```

**實作（逐字取代 `worker/index.ts` 中的 handler）**：

```ts
app.get("/api/rooms/:id/messages", async (c) => {
  const auth = await requireAuth(c);
  if (auth instanceof Response) return auth;
  const roomId = c.req.param("id");
  if (!(await roomExists(c.env, roomId))) return c.json(errorBody("not_found", "room not found"), 404);
  if (!(await isRoomMember(c.env, roomId, auth.member.id))) return forbidden(c);
  const url = new URL(c.req.url);
  const afterRaw = url.searchParams.get("after_seq");
  const beforeRaw = url.searchParams.get("before_seq");
  const limitRaw = url.searchParams.get("limit");
  const kindRaw = url.searchParams.get("kind") ?? "message";
  const orderRaw = url.searchParams.get("order");
  const afterSeq = afterRaw == null || afterRaw === "" ? -1 : Number(afterRaw);
  const beforeSeq = beforeRaw == null || beforeRaw === "" ? null : Number(beforeRaw);
  const limit = Math.min(50, Math.max(1, limitRaw ? Number(limitRaw) : 50));
  if (!Number.isFinite(afterSeq) || (beforeSeq != null && !Number.isFinite(beforeSeq)) || !Number.isFinite(limit)) {
    return invalid(c, "invalid query");
  }
  if (orderRaw !== null && orderRaw !== "asc" && orderRaw !== "desc") return invalid(c, "invalid order");
  const kinds = kindRaw.split(",").map((k) => k.trim()).filter(Boolean);
  if (kinds.some((k) => k !== "message" && k !== "trace")) return invalid(c, "invalid kind");
  const placeholders = kinds.map(() => "?").join(",");
  const params: unknown[] = [roomId, afterSeq];
  let sql = `SELECT id, room_id, seq, kind, thread_id, reply_to, sender_id, body, mentions_json,
                    generation_id, client_message_id, origin, created_at
             FROM messages
             WHERE room_id = ? AND seq > ? AND kind IN (${placeholders})`;
  params.push(...kinds);
  if (beforeSeq != null) {
    sql += ` AND seq < ?`;
    params.push(beforeSeq);
  }
  if (orderRaw === null) {
    sql += ` ORDER BY seq ASC LIMIT ?`;
    params.push(limit);
    const result = await c.env.DB.prepare(sql).bind(...params).all();
    return c.json({ messages: result.results ?? [] });
  }
  sql += orderRaw === "desc" ? ` ORDER BY seq DESC LIMIT ?` : ` ORDER BY seq ASC LIMIT ?`;
  params.push(limit + 1);
  const result = await c.env.DB.prepare(sql).bind(...params).all();
  const rows = result.results ?? [];
  const hasMore = rows.length > limit;
  const page = hasMore ? rows.slice(0, limit) : rows.slice();
  if (orderRaw === "desc") page.reverse();
  return c.json({ messages: page, has_more: hasMore });
});
```

與原 handler 的差異只有：讀 `order`、驗證 `order`、`orderRaw === null` 分支保留原 SQL 與原回應、其餘分支查 `limit + 1`。不動其他路由。

### 4.2 WS（沿用 v1，無變更）

W1 使用 v1 WS 契約（`contracts/ws-client-v1.json`、`contracts/ws-server-v1.json`），以下是實作需要知道、且已對照程式確認的行為：

| 行為 | 依據 |
| --- | --- |
| URL：`ws(s)://<host>/api/rooms/<room id>/ws`，只接受 session cookie（`requireSession`）；非成員 403、房間不存在 404（升級失敗，瀏覽器只看到 `close`，看不到狀態碼） | `worker/index.ts:397-417` |
| client → server 只送 `{"v":1,"type":"send","client_message_id","body","thread_id"?,"generation_id"?}`；W1 不送 `ack` 與 `status` | `worker/room.ts:237-321` |
| 成功：所有連線（含送出者）收到 `{"v":1,"type":"event","event":{id,room_id,seq,kind,body,sender_id,thread_id,generation_id,client_message_id,origin,created_at}}`。WS event **沒有** `mentions_json`、`reply_to` | `worker/room.ts:623-632`、`663-677` |
| 同一 `client_message_id` 重送：只有送出者收到原列的 `event` | `worker/room.ts:285-288` |
| 失敗：只送給送出者 `{"v":1,"type":"error","code":<code>}`，**不帶 `client_message_id`**。code：`payload_too_large`、`invalid_request`、`unauthorized`、`forbidden`、`not_ready`、`generation_dropped` | `worker/room.ts:237-321`、`362-460` |
| 伺服器端 `event` 在 D1 INSERT 成功之後才廣播 | `worker/room.ts:452-459` |

因為 `error` 不帶 `client_message_id`，**RoomSync 同時只讓一則 WS send 在途**（§5.3.6），收到 `error` 就歸屬於在途那一則。

內部狀態：`frames: ChaosFrame[]`、`rules: Map<string, { rule: ChaosRule; held: Array<() => void> }>`、`ruleSeq: number`（rule id = `"r" + (++ruleSeq)`）、`current: { page: WebSocketRoute; server: WebSocketRoute } | null`。

`attach(page)`：

```ts
await page.routeWebSocket(/\/api\/rooms\/[^/]+\/ws$/, (ws) => {
  const server = ws.connectToServer();
  this.current = { page: ws, server };
  ws.onMessage((m) => this.route("out", String(m), () => server.send(m)));
  server.onMessage((m) => this.route("in", String(m), () => ws.send(m)));
  // 不呼叫 onClose：沿用 Playwright 預設，一端關閉時另一端也關閉（官方文件 class-websocketroute.md）
});
```

`route(dir, raw, deliver)`：

1. `json`：`JSON.parse(raw)`，失敗為 `null`；`frames.push({ dir, at: Date.now(), raw, json })`。
2. 依 rule id 的建立順序找**第一條**符合的規則；`matches(match, dir, json, raw)`：`dir` 相等；`type` 有值時 `json?.type === type`；`seq` 有值時 `json?.type === "event" && json.event?.seq === seq`；`bodyIncludes` 有值時 `raw.includes(bodyIncludes)`。
3. 沒有符合 → `deliver()`。
4. `hold` → `held.push(deliver)`；`delay` → `setTimeout(deliver, ms)`；`drop` → 不送；`closeAfter` → `deliver()` 後 `void this.current?.page.close({ code })`。

其他方法：`add(rule)` 回 id；`remove(id)` 刪規則（被 hold 的封包丟棄）；`release(id)`：依序呼叫 `held` 再清空；`inject(raw)`：`this.current?.page.send(raw)`；`closeFromServer(code)`：`void this.current?.page.close({ code })`；`frames()` 回陣列複本；`waitForFrame(match, timeoutMs)`：每 50 ms 檢查 `frames` 中是否有符合 `match` 的封包，逾時丟 `Error("frame not seen: " + JSON.stringify(match))`。

同一個 page 重連時 `routeWebSocket` 的 handler 會再被呼叫一次，`current` 換成新連線；規則保留。

#### 5.3.3 `store/timeline.ts`（Zustand）


- `ensure`：不存在就建立（`rows {}`、`seqs []`、`pending []`、`maxSeq -1`、`contiguousHigh -1`、`oldestLoaded null`、`hasMoreOlder false`、`loadingOlder false`、`olderFailed false`、`phase "loading_latest"`、`jumped false`、`badFrames 0`）；把 `lastOpenedAt` 設為模組內遞增計數 `++openCounter`。之後若房間數 > `ROOM_CACHE_LIMIT`，刪除 `lastOpenedAt` 最小的房間（不刪剛 ensure 的房間）。

- `removePending`：不存在就不 `set`。

#### 5.3.4 `sync/backoff.ts` 與 `sync/clientMessageId.ts`

```ts
export function backoffDelay(attempt: number, random: () => number): number {
  const base = Math.min(BACKOFF_MAX_MS, BACKOFF_BASE_MS * 2 ** attempt);
  return Math.round(base * (0.8 + 0.4 * random()));
}
export function newClientMessageId(random: () => number = Math.random): string {
  let s = "";
  for (let i = 0; i < 20; i++) s += "0123456789abcdefghijklmnopqrstuvwxyz"[Math.floor(random() * 36)];
  return "c-" + s; // 22 字元，符合 8–64
}
```

`attempt` 從 0 起；每次成功進入 `live` 歸零。

#### 5.3.5 `contiguousHigh` 的定義

`contiguousHigh` = 目前確認「從 `oldestLoaded` 到它之間沒有未知缺口」的最大 seq。

- 載入最新頁後：`contiguousHigh = maxSeq`（伺服器回的是連續區間的全部列；區間內缺的 seq 是 trace 被 GC 造成的合法洞，BR-31）。
- 收到 `event.seq === contiguousHigh + 1` → `contiguousHigh = event.seq`，再「前進」：只要 `rows[contiguousHigh + 1]` 存在就加一。
- 補洞（`fetchAfter(contiguousHigh)`）回來 `n` 列：若 `n > 0`，`contiguousHigh = max(contiguousHigh, 最後一列 seq)` 再前進；區間內沒有回的 seq 視為確認的洞。若 `n === 0` 但 `maxSeq > contiguousHigh`（FM-SYNC-04）→ `contiguousHigh = maxSeq`（整段視為確認的洞，不再重試）。
- 以全房 seq 計算（含 trace、thread 回覆，FE-12）；因此所有查詢都帶 `kind=message,trace`。

`useRoomSync.ts` 以真實依賴建立：`openSocket: (u) => new WebSocket(u)`、`setTimer: (f, ms) => window.setTimeout(f, ms)`、`clearTimer: (id) => window.clearTimeout(id)`、`random: Math.random`、`onAuthLost: () => { queryClient.removeQueries({ predicate: (q) => q.queryKey[0] !== "me" }); void queryClient.invalidateQueries({ queryKey: ["me"] }); }`（與 W0 `onAuthLost` 相同，由 `RequireAuth` 導向登入）。

內部狀態（實例欄位）：`stopped = false`、`abort = new AbortController()`、`ws: WebSocket | null`、`wsOpened = false`（本次連線是否曾 open）、`attempt = 0`、`reconnectTimer: number | null`、`gapTimer: number | null`、`gapRunning = false`、`gapRerun = false`、`inFlight: string | null`（在途的 `client_message_id`）、`ackTimer: number | null`、`orderSeq = 0`、`catchingUp = false`。

以下 `S()` = `useTimelineStore.getState()`；`T()` = `S().timelines[roomId]`；「設 phase X」= `S().patch(roomId, { phase: X })`。每個 `await` 之後第一件事：`if (this.stopped) return;`（FM-SYNC-10）。

**`start()`**

1. `S().ensure(roomId)`。
2. `window.addEventListener("offline", this.onOffline)`、`window.addEventListener("online", this.onOnline)`。
3. 若 `navigator.onLine === false` → 設 phase `offline`，結束。
4. 若 `T().seqs.length > 0`（快取中有這房）→ 直接 `this.connect()`（step 2 會補洞）；否則 `void this.loadLatest()`。

**`loadLatest()`**

1. 設 phase `loading_latest`。
2. `page = await api.fetchLatest(roomId, abort.signal)`；失敗處理見下。
3. `S().mergeRows(roomId, page.messages)`；`S().patch(roomId, { oldestLoaded: page.messages[0]?.seq ?? null, hasMoreOlder: page.has_more, contiguousHigh: T().maxSeq })`。
4. `this.connect()`。

失敗：`ApiError.status === 401` → `authLost()`；`403` 或 `404` → 設 phase `not_found`（不重試；畫面見 §5.6）；其他 → 設 phase `load_error`，`scheduleReconnect(() => this.loadLatest())`。

**`connect()`**

1. 設 phase `connecting`；`wsOpened = false`。
2. `url = (location.protocol === "https:" ? "wss://" : "ws://") + location.host + "/api/rooms/" + encodeURIComponent(roomId) + "/ws"`。
3. `ws = openSocket(url)`；綁定 `onopen`、`onmessage`、`onclose`（`onerror` 不處理，交給 `onclose`）。

`onopen`：`wsOpened = true`；`void this.catchUp()`。

**`catchUp()`**

1. `catchingUp = true`；`pages = 0`。
2. 迴圈：`page = await api.fetchAfter(roomId, T().contiguousHigh, abort.signal)`；`mergeRows`；依 §5.3.5 更新 `contiguousHigh`；`resolvePendingFrom(page.messages)`；`pages++`；若 `!page.has_more` → 跳出；若 `pages >= CATCHUP_MAX_PAGES` → `await this.jumpToLatest()` 並跳出。
3. `catchingUp = false`；`attempt = 0`；設 phase `live`；`flushSends()`。
4. 失敗：401 → `authLost()`；其他 → `ws.close(4000)`（交給 `onclose` 重連）。

**`jumpToLatest()`**（FM-SYNC-13）

1. `S().clearRows(roomId)`。
2. `page = await api.fetchLatest(…)`；`mergeRows`；`patch({ oldestLoaded, hasMoreOlder: page.has_more, contiguousHigh: T().maxSeq, jumped: true })`；`resolvePendingFrom(page.messages)`。

**`onmessage(e)`**

1. `typeof e.data !== "string"` 或 `JSON.parse` 失敗、或不是物件、或 `v !== 1` → `patch({ badFrames: T().badFrames + 1 })`，結束（FM-SYNC-16，不斷線）。
2. `type === "event"`：`row = frame.event`；`mergeRows(roomId, [row])`；`resolvePendingFrom([row])`；然後：
   - `row.seq <= T().contiguousHigh` → 結束（重複或舊列）。
   - `row.seq === T().contiguousHigh + 1` → `patch({ contiguousHigh: row.seq })` 並前進（§5.3.5）。
   - 否則（有缺口）：若 `!catchingUp` → `scheduleGap()`。
3. `type === "error"`：`handleSendError(frame.code)`。
4. 其他 `type`（`status`、`draft` 等）→ W1 忽略。

**`scheduleGap()`**：若 `gapTimer === null` → `gapTimer = setTimer(() => { gapTimer = null; void this.fillGap(); }, GAP_GRACE_MS)`。

**`fillGap()`**（同時只有一個，FM-SYNC-03）

1. 若 `T().maxSeq <= T().contiguousHigh`（缺口已消失，FM-SYNC-02）→ 結束。
2. 若 `gapRunning` → `gapRerun = true`，結束。
3. `gapRunning = true`；`page = await api.fetchAfter(roomId, T().contiguousHigh, …)`；`mergeRows`；`resolvePendingFrom`；依 §5.3.5 更新（含 n === 0 的情況）。
4. `gapRunning = false`；若 `gapRerun` 或 `T().maxSeq > T().contiguousHigh` → `gapRerun = false`，`void this.fillGap()`。
5. 失敗：401 → `authLost()`；其他 → `gapRunning = false`，`scheduleGap()`。

**`onclose()`**

1. `ws = null`；清 `ackTimer`；若 `stopped` → 結束。
2. 若 `inFlight !== null` → 該筆 state 改 `unknown`（連線斷了，不知道是否落盤）。
3. 若 `navigator.onLine === false` → 設 phase `offline`，結束（等 `online` 事件）。
4. 若 `!wsOpened`（升級失敗）→ `await api.probeMe(abort.signal)`；401 → `authLost()`，結束（FM-SYNC-09）。其他錯誤忽略。
5. 設 phase `backoff`；`scheduleReconnect(() => this.connect())`。

**`scheduleReconnect(fn)`**：`delay = backoffDelay(attempt, random)`；`attempt++`；`reconnectTimer = setTimer(fn, delay)`。

**`onOffline`**：設 phase `offline`；清 `reconnectTimer`；若 `ws` → `ws.close(4001)`（`setOffline` 不會關閉既有 WS，必須自己關，§10）。**`onOnline`**：若 phase 為 `offline` → `attempt = 0`；若 `T().seqs.length === 0` → `loadLatest()`，否則 `connect()`。

**`authLost()`**：設 phase `auth_lost`；`stop()`；`onAuthLost()`。

**`loadOlder()`**

1. 若 `T().loadingOlder` 或 `!T().hasMoreOlder` 或 `T().oldestLoaded === null` → 結束。
2. `patch({ loadingOlder: true, olderFailed: false })`。
3. `page = await api.fetchOlder(roomId, T().oldestLoaded, …)`；`mergeRows`；`patch({ oldestLoaded: page.messages[0]?.seq ?? T().oldestLoaded, hasMoreOlder: page.has_more, loadingOlder: false })`。
4. 失敗：401 → `authLost()`；其他 → `patch({ loadingOlder: false, olderFailed: true })`（畫面顯示重試）。

**送出**

- `send(body)`：`cmid = newClientMessageId(random)`；`upsertPending({ clientMessageId: cmid, body, order: ++orderSeq, state: "queued", failCode: null })`；`flushSends()`。
- `flushSends()`：若 `inFlight !== null` 或 phase 不是 `live` 或 `ws === null` → 結束。取 `pending` 中第一筆 `state === "queued"` 或 `state === "unknown"` 的：
  - `queued` → state 改 `sending`；`inFlight = cmid`；`ws.send(JSON.stringify({ v: 1, type: "send", client_message_id: cmid, body }))`；`ackTimer = setTimer(() => this.onAckTimeout(), SEND_ACK_TIMEOUT_MS)`。
  - `unknown` → `void this.sendViaRest(cmid)`。
- `onAckTimeout()`：`ackTimer = null`；該筆 state 改 `unknown`；`void this.sendViaRest(inFlight)`。
- `sendViaRest(cmid)`：`inFlight = cmid`；`row = await api.postMessage(roomId, body, cmid, …)`；`mergeRows([row])`；`resolvePendingFrom([row])`。失敗：`ApiError` 且 `status` 為 400、403、404、409 → state `failed`、`failCode = code`、`inFlight = null`、`flushSends()`；401 → `authLost()`；其他（網路、5xx）→ state `failed`、`failCode = "network_error"`、`inFlight = null`。
- `handleSendError(code)`：若 `inFlight === null` → 忽略。清 `ackTimer`。`code === "not_ready"` → state `unknown`，`void this.sendViaRest(inFlight)`；`code === "unauthorized"` → `authLost()`；其他（`payload_too_large`、`invalid_request`、`forbidden`、…）→ state `failed`、`failCode = code`、`inFlight = null`、`flushSends()`（FM-SYNC-08：不重試）。
- `resolvePendingFrom(rows)`：對每列，若 `row.sender_id === meId` 且 pending 有同 `client_message_id` → `removePending`；若它就是 `inFlight` → 清 `ackTimer`、`inFlight = null`。處理完後 `flushSends()`（FE-11、FM-SYNC-06、07）。
- `retry(cmid)`：該筆 state 改 `queued`、`failCode = null`；`flushSends()`（同一個 `client_message_id`，冪等）。
- `discard(cmid)`：若 `cmid === inFlight` → 不做事（按鈕在 `sending`／`unknown` 狀態不顯示）；否則 `removePending`。

**`stop()`**：`stopped = true`；`abort.abort()`；清所有 timer；移除 `online`／`offline` listener；`ws?.close(1000)`；`ws = null`。store 保留（快取）；pending 中 `sending` 的改回 `queued`（下次進房重送，同一 id）。

#### 5.6.3 `features/composer/`

`index.ts`：`export { Composer } from "./Composer";`

`draftStorage.ts`：`loadDraft(roomId): string`、`saveDraft(roomId, text): void`（空字串時刪除 key）、`clearAllDrafts(): void`（刪除所有 `kith.draft.` 開頭的 key）。全部 `try/catch`。

**`Composer`**：`{ roomId: string; roomName: string; phase: SyncPhase; onSend(body: string): void }`。

內部狀態：`value`（初值 `loadDraft(roomId)`）；`coarse = matchMedia("(pointer: coarse)").matches`（mount 時讀一次；已實測 Playwright 手機模擬為 `true`、桌面為 `false`）。

衍生：`bytes = new TextEncoder().encode(value).length`；`tooLong = bytes > 8192`；`offline = phase === "offline"`；`canSend = value.trim().length > 0 && !tooLong && !offline && phase !== "auth_lost" && phase !== "not_found"`。

行為：

1. `onChange`：`setValue`；300 ms debounce 後 `saveDraft(roomId, value)`。
2. 自動長高：每次 `value` 變更後 `el.style.height = "auto"; el.style.height = Math.min(el.scrollHeight, Math.round(window.innerHeight * 0.4)) + "px"`。
3. `onKeyDown(e)`：若 `e.key !== "Enter"` → 不處理。若 `e.nativeEvent.isComposing || e.keyCode === 229` → 不處理（IME 組字中）。若 `e.shiftKey` 或 `coarse` → 不處理（換行）。否則 `e.preventDefault()`；`submit()`。
4. `submit()`：`canSend` 為假 → 不做事；否則 `onSend(value)`（原文，不 trim；伺服器也不 trim）、`setValue("")`、`saveDraft(roomId, "")`、`textarea.focus()`。

畫面：

```text
<form data-testid="composer" class="border-t border-border bg-surface px-3 py-2" onSubmit={(e) => { e.preventDefault(); submit(); }}>
  {offline && <p data-testid="composer-offline" role="status" class="pb-1 text-sm text-warn">{t("composer.offline")}</p>}
  {tooLong && <p data-testid="composer-too-long" role="alert" class="pb-1 text-sm text-danger">{t("composer.tooLong")}</p>}
  <div class="flex items-end gap-2">
    <textarea data-testid="composer-input" aria-label={t("composer.label")} rows={1}
              placeholder={t("composer.placeholder", { room: roomName })}
              class="flex-1 resize-none rounded-md border border-border-strong bg-surface px-3 py-2 text-ink text-md-touch md:text-md focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus" />
    <Button variant="primary" type="submit" data-testid="composer-send" disabled={!canSend}>{t("composer.send")}</Button>
  </div>
</form>
```

手機上 composer 貼底並避開 safe area：外層 `form` 加 `pb-[env(safe-area-inset-bottom)]` **不允許**（任意值）；改在 `index.css` 定義 `.pb-safe { padding-bottom: max(0.5rem, env(safe-area-inset-bottom)); }` 並使用 class `pb-safe`（加入 [07](../07-visual-design.md) §4.1）。
