## 4. 契約

### 4.1 D1 migration `0002_v2_rooms_members.sql`（完整內容）

```sql
-- v2 W2: room archive (B-14, BR-14) and forced first-login password change (B-04, Q-03).
ALTER TABLE rooms ADD COLUMN archived_at TEXT;
ALTER TABLE members ADD COLUMN must_change_password INTEGER NOT NULL DEFAULT 0 CHECK (must_change_password IN (0, 1));
```

| 欄位 | 正例 | 反例 |
| --- | --- | --- |
| `rooms.archived_at` | `NULL`（未封存）；`'2026-09-23T10:00:00.000Z'` | —（任意 TEXT；只由 PATCH 寫入 ISO 字串） |
| `members.must_change_password` | 既有列自動為 `0`；`UPDATE … = 1` | `UPDATE members SET must_change_password = 2` → `CHECK constraint failed: must_change_password IN (0, 1)`（已實測） |

- 遷移：`wrangler d1 migrations apply kith`（本機 `--local`；production 由 operator 手動執行，與 v1 相同）。只加欄位，不改既有列的值。
- Rollback：D1 migration 不支援自動 rollback。兩個欄位都是加法，舊程式讀不到新欄位也不受影響，所以 rollback 程式碼不需要 rollback schema；若真要移除，另寫 migration 以 `ALTER TABLE … DROP COLUMN`（SQLite 3.35+；D1 支援與否在執行前以 `wrangler d1 execute --command "SELECT sqlite_version()"` 確認）。
- 編號：[04](../04-backend.md) §4 原本把全部 v2 DDL 放在一個 `0002_v2.sql`；因為 W2 就需要這兩欄，改為每個里程碑各自一個 migration：本檔 `0002`，W4 的 provider 相關表為 `0003`。
- 已實測：migration 在空 D1 上套用成功；套用後 v1 全套 `npm test` 通過（vitest 讀取整個 `migrations/` 目錄）。

  if (auth instanceof Response) return auth;

app.patch("/api/me", async (c) => {
  const auth = await requireSession(c);
  if (auth instanceof Response) return auth;
  const obj = parseObject(await c.req.text());
  if (!obj) return invalid(c, "invalid json");
  if (extraKeys(obj, ["display_name"]).length > 0) return invalid(c, "unknown field");
  if (typeof obj.display_name !== "string") return invalid(c, "display_name required");
  const displayName = obj.display_name.trim();
  if (displayName.length < 1 || displayName.length > 64) return invalid(c, "display_name must be 1-64 characters");
  await c.env.DB.prepare(`UPDATE members SET display_name = ? WHERE id = ?`).bind(displayName, auth.member.id).run();

| 端點 | 權限 | request | 成功 | 錯誤 |
| --- | --- | --- | --- | --- |
| `GET /api/me` | session 或 bearer | — | 200 `Me`（§4.3） | 401 `unauthorized` |
| `PATCH /api/me` | 只接受 session（bearer 回 401） | `{ "display_name": string }`，trim 後 1–64 字 | 200 `publicMember` | 400 `invalid_request`（JSON 壞、未知欄位、缺欄位、長度）；401 |

`PATCH /api/rooms/:id` 放在 `GET /api/rooms/:id/messages` 之前：

```ts
app.patch("/api/rooms/:id", async (c) => {
  const auth = await requireOperator(c);
  if (auth instanceof Response) return auth;
  const roomId = c.req.param("id");
  if (!(await roomExists(c.env, roomId))) return c.json(errorBody("not_found", "room not found"), 404);
  const obj = parseObject(await c.req.text());
  if (!obj) return invalid(c, "invalid json");
  if (extraKeys(obj, ["name", "archived"]).length > 0) return invalid(c, "unknown field");
  if (obj.name === undefined && obj.archived === undefined) return invalid(c, "name or archived required");
  let name: string | null = null;
  if (obj.name !== undefined) {
    if (typeof obj.name !== "string") return invalid(c, "invalid name");
    name = obj.name.trim();
    if (name.length < 1 || name.length > 80) return invalid(c, "name must be 1-80 characters");
  }
  if (obj.archived !== undefined && typeof obj.archived !== "boolean") return invalid(c, "archived must be boolean");
  if (name !== null) {
    await c.env.DB.prepare(`UPDATE rooms SET name = ? WHERE id = ?`).bind(name, roomId).run();
  }
  if (obj.archived === true) {
    await c.env.DB.prepare(`UPDATE rooms SET archived_at = COALESCE(archived_at, ?) WHERE id = ?`)
      .bind(new Date().toISOString(), roomId)
      .run();
  } else if (obj.archived === false) {
    await c.env.DB.prepare(`UPDATE rooms SET archived_at = NULL WHERE id = ?`).bind(roomId).run();
  }
  const [room] = await roomSummaries(c.env, auth.member.id, { all: true, roomId });
  return c.json(room);
});
```

| 端點 | 權限 | request | 成功 | 錯誤 |
| --- | --- | --- | --- | --- |
| `GET /api/rooms` | session 或 bearer | 選填 `all=1`（只給 operator session） | 200 `{ rooms: RoomSummary[] }`，依 `created_at` 升冪 | 400 `invalid all`（`all` 不是 `1`）；401；403 `operator required`（非 operator 帶 `all=1`） |
| `PATCH /api/rooms/:id` | operator session | `{ "name"?: string（trim 後 1–80）, "archived"?: boolean }`，至少一個 | 200 `RoomSummary`（`role` 是 operator 在該房的角色；operator 不是成員時為 `null`） | 400（JSON 壞、未知欄位、兩者皆無、型別、長度）；401；403 `operator required`；404 `room not found` |

`RoomSummary` 的新欄位（schema：[`contracts/v2/http-rooms.json`](../../../contracts/v2/http-rooms.json)）：`archived_at`、`last_seq`（全房最大 seq，含 trace；空房 `null`）、`member_count`、`last_message`（最後一則 `kind=message`：`{ seq, sender_id, sender_display_name, sender_handle, body_preview（前 140 字，SQLite `substr` 以字元計）, created_at }` 或 `null`）。舊欄位 `id`、`slug`、`name`、`created_at`、`role` 不變（V2-INV-04）。

效能（B-02 待細化項）：單一 SQL；每房兩個相關子查詢（`MAX(seq)` 走 `messages_room_kind_seq` 覆蓋索引，已以 `EXPLAIN QUERY PLAN` 確認）、一個 `COUNT(*)`；實例上限 64 房，一次請求最多 64 × 3 次索引查找。

`archived: true` 重複呼叫保留第一次的時間（`COALESCE`）。

async function roomSummaries(
  env: Env,
  memberId: string,
  options: { all: boolean; roomId?: string },
): Promise<Array<Record<string, unknown>>> {
  const params: unknown[] = [memberId];
  let sql = `SELECT r.id, r.slug, r.name, r.created_at, rm.role, r.archived_at,
                    (SELECT MAX(m.seq) FROM messages m WHERE m.room_id = r.id) AS last_seq,
                    (SELECT COUNT(*) FROM room_members x WHERE x.room_id = r.id) AS member_count,
                    lm.seq AS lm_seq, lm.sender_id AS lm_sender_id,
                    substr(lm.body, 1, 140) AS lm_body_preview, lm.created_at AS lm_created_at,
                    sm.display_name AS lm_sender_display_name, sm.handle AS lm_sender_handle
             FROM rooms r
             ${options.all ? "LEFT JOIN" : "JOIN"} room_members rm ON rm.room_id = r.id AND rm.member_id = ?
             LEFT JOIN messages lm ON lm.room_id = r.id
               AND lm.seq = (SELECT MAX(m2.seq) FROM messages m2 WHERE m2.room_id = r.id AND m2.kind = 'message')
             LEFT JOIN members sm ON sm.id = lm.sender_id`;
  if (options.roomId !== undefined) {
    sql += ` WHERE r.id = ?`;
    params.push(options.roomId);
  }
  sql += ` ORDER BY r.created_at ASC`;
  const result = await env.DB.prepare(sql).bind(...params).all<RoomSummaryRow>();

`localStorage` 讀寫都包 `try/catch`；失敗時只保留 Zustand 內的值。登出時（`useLogout` 的 `onSettled`）刪除所有 `kith.unread.` 開頭的 key 並清空 store。

規則：

1. 第一次看到某房（cursor 不存在）→ 視為全部已讀（cursor = 目前 `last_seq`）。所以未讀只在曾開過 Kith 的同一瀏覽器有效（BR-37）。
2. 在房內且捲到底（`Timeline` 回報 `atBottom === true`）→ `bump(roomId, timeline.maxSeq)`。
3. 離開房間（`RoomView` unmount）→ `bump(roomId, timeline.maxSeq)`。
4. cursor 永遠不送伺服器；只用來組 `after_seq` 查詢參數。

#### 5.4.2 `features/rooms/useUnreadCounts.ts`

```ts
export type Unread = { count: number; more: boolean };
export function useUnreadCounts(rooms: RoomSummary[] | undefined, meId: string, activeRoomId: string | null): Record<string, Unread>;
```

1. `cursors = useUnreadStore((s) => s.cursors)`。
2. `targets` = `rooms` 中 `room.id !== activeRoomId`、`room.archived_at === null`、`room.last_seq !== null`、`cursors[room.id] !== undefined`、`room.last_seq > cursors[room.id]` 的房間。
3. `useQueries({ queries: targets.map((room) => ({ queryKey: ["unread", room.id, cursors[room.id], room.last_seq], staleTime: Infinity, queryFn: ({ signal }) => fetchAfterMessages(room.id, cursors[room.id]!, signal) })) })`；`fetchAfterMessages` = `GET /api/rooms/{id}/messages?order=asc&after_seq={cursor}&limit=50&kind=message`（放在 `api/messages.ts`）。
4. 每個結果：`count = messages.filter((m) => m.sender_id !== meId).length`；`more = has_more`。
5. 回傳 `{ [roomId]: { count, more } }`；沒有查詢或查詢未完成的房間不出現在結果裡。
