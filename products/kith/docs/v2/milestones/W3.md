## 4. 契約

### 4.1 WS server 封包（B-11）

Schema：[`contracts/v2/ws-server.json`](../../../contracts/v2/ws-server.json)。與 v1（`contracts/ws-server-v1.json`）相比只有一個差異：`type=status` 多一個選填欄位 `error_class`。

| body | 誰送 | 何時 | `error_class` |
| --- | --- | --- | --- |
| `is replying` | HostedGeneration | 開始一次 generation（v1） | 無 |
| `reply failed` | HostedGeneration → Room `postReplyFailed` | generation 失敗（**新**） | 只在 operator 的連線；值見下表 |
| `reply ended` | HostedGeneration | 每次 generation 收尾（成功、失敗、丟棄；v1） | 無 |
| `typing` | 人類的 web client（經 WS `status`） | 輸入框有字時，最多每 3 秒一次（**新 client 行為**；伺服器沿用 v1 的 status 路徑） | 無 |
| 其他字串 | 任意（v1 行為） | — | 無 |

失敗時的順序固定為 `reply failed` → `reply ended`：舊前端把 `reply failed` 當一般 status 顯示 4 秒，並靠隨後的 `reply ended` 清掉「回覆中」（V2-INV-04）；新前端收到 `reply ended` 時若該成員已有失敗提示，不另外宣告。

`error_class`（v1 hosted 路徑能分辨的子集；名稱取自 [03](../03-agent-runtime.md) §2.3，W4 補齊其餘類別）：

| 條件 | `error_class` |
| --- | --- |
| 上游 401、403 | `auth` |
| 上游 404 | `not_found` |
| 上游 400、422 | `bad_request` |
| 上游 429 | `rate_limited` |
| 上游 503、529 | `overloaded` |
| 其他上游狀態碼 | `unknown` |
| fetch 丟 `TypeError`（網路） | `network` |
| 200 但沒有文字內容 | `protocol` |
| 回覆落盤失敗（Room 回非 409） | `unknown` |

`NO_REPLY` 與 Room 回 409（`generation_dropped`、`room_archived`）是「丟棄」，不是失敗，不送 `reply failed`（v1 行為不變）。

```ts
/** Test-only directives for the in-worker fake (used only when there is no XAI_API_KEY and FAKE_LLM_TEXT is set). */
export type FakeDirective = { text?: string; delay_ms?: number; status?: number };

export function parseFakeDirective(source: string): FakeDirective {
  const match = /\[\[fake:([^\]]*)\]\]/.exec(source);
  if (!match) return {};
  const out: FakeDirective = {};
  for (const part of match[1]!.split(";")) {
    const eq = part.indexOf("=");
    if (eq <= 0) continue;
    const name = part.slice(0, eq).trim();
    let value: string;
    try {
      value = decodeURIComponent(part.slice(eq + 1).trim());
    } catch {
      continue;
    }
    if (name === "text") {
      out.text = value;
    } else if (name === "delay_ms") {
      const n = Number(value);
      if (Number.isInteger(n) && n >= 0 && n <= 30_000) out.delay_ms = n;
    } else if (name === "status") {
      const n = Number(value);
      if (Number.isInteger(n) && n >= 400 && n <= 599) out.status = n;
    }
  }
  return out;
}
```

指令只在 fake 模式有效（沒有 `XAI_API_KEY` 且設了 `FAKE_LLM_TEXT`，`worker/hosted/generation.ts:232-239` 的既有判斷）；有真實 key 時 `createFakeFetch` 不會被使用。v1 hosted 的 `transcript` 就是觸發訊息的 `body`（`worker/inbox.ts:296`），所以指令只取自觸發的那一則，房間歷史不影響。語法與 [08](../08-testing-e2e.md) §5.3 的 `fake-provider` 相同（本檔只實作 `text`、`delay_ms`、`status`）。

```ts
  private async runJob(): Promise<void> {
    const job = await this.ctx.storage.get<Job>("job");
    if (!job) return;

    let failedClass: HostedErrorClass | null = null;
    try {
      await this.env.DB.prepare(
        `UPDATE generations SET state = 'streaming' WHERE id = ? AND state = 'dispatched'`,
      )
        .bind(job.generation_id)
        .run();

      const text = await this.runModel(job);
      if (isNoReply(text)) {
        await this.markGeneration(job.generation_id, "dropped");
        return;
      }
      if (!text) {
        await this.markGeneration(job.generation_id, "failed");
        failedClass = "protocol";
        return;
      }
      const res = await this.sendToRoom(job, text);
      if (!res.ok) {
        if (res.status === 409) {
          await this.markGeneration(job.generation_id, "dropped");
        } else {
          await this.markGeneration(job.generation_id, "failed");
          failedClass = "unknown";
        }
      }
    } catch (err) {
      await this.markGeneration(job.generation_id, "failed");
      failedClass = classifyHostedError(err);
    } finally {
      if (failedClass !== null) {
        await this.broadcastReplyFailed(job.room_id, job.agent_id, failedClass);
      }
      await this.broadcastReply(job.room_id, job.agent_id, "reply ended");
      // Mention generations never acquired the lock; Room no-ops on generation_id mismatch.
      await this.releaseAmbientLock(job);
    }
  }

  private async broadcastReplyFailed(roomId: string, memberId: string, errorClass: HostedErrorClass): Promise<void> {
    try {
      const stub = this.env.ROOM.get(this.env.ROOM.idFromName(`room:${roomId}`)) as RoomReleaseStub;
      await stub.postReplyFailed(roomId, memberId, errorClass);
    } catch {
      /* a missed status line must not fail the generation */
    }
  }
```

3. 檔尾加入：

```ts
export type HostedErrorClass =
  | "auth"
  | "not_found"
  | "bad_request"
  | "rate_limited"
  | "overloaded"
  | "network"
  | "protocol"
  | "unknown";

/** Map the v1 client's thrown errors to 03 §2.3 LlmErrorClass names (subset available before W4). */
export function classifyHostedError(err: unknown): HostedErrorClass {
  const message = err instanceof Error ? err.message : String(err);
  const status = /failed: (\d{3})$/.exec(message);
  if (status) {
    const code = Number(status[1]);
    if (code === 401 || code === 403) return "auth";
    if (code === 404) return "not_found";
    if (code === 400 || code === 422) return "bad_request";
    if (code === 429) return "rate_limited";
    if (code === 503 || code === 529) return "overloaded";
    return "unknown";
  }
  if (err instanceof TypeError) return "network";
  return "unknown";
}
```

#### 4.2.3 `worker/room.ts`

在 `async activity(roomId: string)` 之前加入：

```ts
  /** B-11: ephemeral `reply failed`. Only the operator's sockets get error_class. No D1 INSERT, no seq. */
  async postReplyFailed(roomId: string, memberId: string, errorClass: string): Promise<{ ok: true } | PersistFail> {
    await this.ctx.storage.put("room_id", roomId);
    if (!(await this.memberInRoom(roomId, memberId))) {
      return { ok: false, status: 403, code: "forbidden", message: "not a room member" };
    }
    const operator = await this.env.DB.prepare(`SELECT id FROM members WHERE is_operator = 1`).first<{ id: string }>();
    const plain = JSON.stringify({ v: 1, type: "status", member_id: memberId, body: "reply failed" });
    const detailed = JSON.stringify({
      v: 1,
      type: "status",
      member_id: memberId,
      body: "reply failed",
      error_class: errorClass,
    });
    for (const ws of this.sockets()) {
      const attachment = (ws.deserializeAttachment?.() ?? {}) as { member_id?: string };
      try {
        ws.send(operator && attachment.member_id === operator.id ? detailed : plain);
      } catch {
        /* drop closed */
      }
    }
    return { ok: true };
  }
```

「operator 的連線」＝ WS attachment 的 `member_id` 等於 `members.is_operator = 1` 那一列的 id（實例恰好一個 operator）。每次失敗多一次 D1 讀取。

## 5. 模組與元件規格

### 5.1 `store/statuses.ts`

```ts
export type ReplyState = { at: number };                               // 收到 is replying 的時間（Date.now()）
export type FailureState = { at: number; errorClass: string | null };  // operator 才有 errorClass
export type RoomStatuses = {
  replies: Record<string, ReplyState>;     // key = member_id
  failures: Record<string, FailureState>;
  typing: Record<string, number>;          // member_id → 過期時間（Date.now() + 4000）
};
export const REPLY_STALE_MS = 300_000;     // FM-SYNC-15
export const FAILURE_SHOW_MS = 8_000;      // BR-45 / B-11
export const TYPING_TTL_MS = 4_000;        // v1 10 章
export const useStatusStore = create<{
  rooms: Record<string, RoomStatuses>;
  apply(roomId: string, frame: { member_id: string; body: string; error_class?: string }, now: number): void;
  onMessage(roomId: string, senderId: string): void;
  clearRoom(roomId: string): void;
}>(…);
```

- `apply`：
  - `body === "is replying"` → `replies[m] = { at: now }`；刪除 `failures[m]`、`typing[m]`。
  - `body === "reply failed"` → 刪除 `replies[m]`；`failures[m] = { at: now, errorClass: frame.error_class ?? null }`。
  - `body === "reply ended"` → 刪除 `replies[m]`（`failures[m]` 保留，直到自己過期）。
  - 其他 body（含 `typing`）→ `typing[m] = now + TYPING_TTL_MS`。
- `onMessage(roomId, senderId)`：刪除 `replies[senderId]`、`typing[senderId]`（v1：訊息事件清掉該成員的回覆中）。
- `clearRoom(roomId)`：三者清空（FM-SYNC-17：斷線、切房、hibernation 後 status 不殘留）。

`useNow(intervalMs: number)`（同檔匯出）：以 `setInterval` 每 `intervalMs` 更新一次 `Date.now()` 的 React state；元件以它過濾過期項目：`replies` 中 `now - at < REPLY_STALE_MS`、`failures` 中 `now - at < FAILURE_SHOW_MS`、`typing` 中 `expires > now`。W3 使用 `useNow(1000)`。

### 5.8 Composer：`@` 補全與 typing

**`mentionQuery.ts`**：

```ts
export type MentionQuery = { start: number; end: number; prefix: string }; // [start, end) = 從 @ 到游標
export function mentionQueryAt(value: string, caret: number): MentionQuery | null;
```

1. 從 `caret - 1` 往回找，途中只允許 `[a-z0-9_]`（不分大小寫），遇到 `@` 或 `＠` 停下，得到位置 `i`；途中遇到其他字元 → `null`。
2. `i === 0` 或 `value[i - 1]` 符合 `/\s/u` → 有效；否則 `null`（v1：`@` 在開頭或前面是空白）。
3. `prefix = value.slice(i + 1, caret)`；長度 > 32 → `null`。
4. 回傳 `{ start: i, end: caret, prefix }`。

**`Composer` 修改**（行為逐條照 v1 10 章）：

- 新 props：`members: RoomMember[] | undefined`、`viewerIsOperator: boolean`、`onTyping(): void`。
- state：`query: MentionQuery | null`、`activeIndex: number`、`dismissedAt: number | null`（按 Escape 時的 `query.start`，同一個 `@` 不再自動開啟）。
- 每次 `onChange` 與 `onSelect`（游標移動）後：`q = mentionQueryAt(value, caret)`；`options = q && members ? members.filter(m => m.handle.toLowerCase().startsWith(q.prefix.toLowerCase())) : []`；清單開啟條件：`q !== null && options.length > 0 && q.start !== dismissedAt && phase !== "offline" && members 已載入`。前綴不再相符（`options` 為空）立即關閉；開啟時 `activeIndex` 夾在範圍內。
- textarea 加 `role="combobox"`、`aria-autocomplete="list"`、`aria-expanded={open}`、`aria-controls={open ? listboxId : undefined}`、`aria-activedescendant={open ? listboxId + "-" + activeIndex : undefined}`。
- `onKeyDown`（在 W1 規則之前處理，清單開啟時）：
  - IME 組字中（`isComposing` 或 `keyCode 229`）→ 不處理（不選、不換行、不送）。
  - `ArrowDown`／`ArrowUp` → `preventDefault`，`activeIndex` 循環加減。
  - `Enter`（無 Shift）→ `preventDefault`；以 `"@" + handle + " "` 取代 `value.slice(q.start, q.end)`；游標移到插入文字之後；關閉清單。**不送出**。
  - `Shift+Enter` → 關閉清單，交給瀏覽器換行（不 `preventDefault`）。
  - `Escape` → `preventDefault`；`dismissedAt = q.start`；本文不變。
- 點按候選＝同 Enter。點清單以外（textarea `onBlur`）→ 關閉清單，本文不變。
