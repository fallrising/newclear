## 來源摘要

以下是對公開條目的短篇改寫，只保留機制本身，不含案例、圖片或原站程式。

來源把「Tune speed to arrange turn order」定義成：讓先手留給鋪墊者，再讓收割者接上。可對上的規則片段是：速度不一定增加行動次數。

來源循環的順序是：觀察當前出手順序 → 調整關鍵單位速度 → 執行鋪墊與後續行動 → 根據敵方先手重新安排。

來源要玩家自行權衡的兩件事，以下僅作繁體轉寫，不是本筆記的結論：「讓治療者搶先保命，還是讓控制者先壓住危險敵人？」「為搶先手犧牲傷害，能否換來少挨一次攻擊？」

## 問題與情境（本地分析）

「先攻順序」要處理的情況是：玩家已經能做「觀察當前出手順序」，但重複這個動作不會自動得到好結果。這類問題的關鍵是單位的順序與目標選擇比單次傷害更早決定勝負。這個條目同時壓在這些設計張力上：必須先承諾，後果才會出現、正確行動若離開窗口就會變成另一種失敗。

適合放進玩家下一步會被「執行鋪墊與後續行動」改寫的系統。若結果在行動前就公布標準答案，這個設計問題會消失。不適用於單位會自己選目標、玩家只負責按下開始的戰鬥。

這裡的判斷是本地設計分析，不是來源作者的意圖，也不是案例遊戲的實驗結果。

## 核心循環（本地分析）

- 玩家行動：承諾「觀察當前出手順序、調整關鍵單位速度」。這一動是玩家主動付出去的部分，不能事後假裝沒有做過。
- 系統回饋：對該行動給出與「執行鋪墊與後續行動」對應、而且能區分成功、部分成功與失敗的結果。只給一個總分不算回饋。
- 下一個決策：玩家依回饋決定要不要進入「根據敵方先手重新安排」，或改走成本不同的另一條路。若回饋不能改變這個選擇，循環就沒有學習價值。

## 解法與取捨（本地分析）

- 在「調整關鍵單位速度」就給出還能不能回頭的資訊，讓玩家不必等到「根據敵方先手重新安排」才知道「讓治療者搶先保命，還是讓控制者先壓住危險敵人」這題選錯了。
- 「速度隨機幅度」用來回答第一個難點；「重排時點」用來回答「為搶先手犧牲傷害，能否換來少挨一次攻擊」。兩個旋鈕如果綁在同一段回饋裡，玩家無法知道自己該改準備還是該改收尾。
- 「觀察當前出手順序」保留一條較穩的走法，「根據敵方先手重新安排」保留一條收益或資訊更高的走法。兩條路的結果必須長得不一樣，否則這個機制沒有選擇。

## 可調參數（本地分析）

- 本地預期：把「速度隨機幅度」調緊時，「觀察當前出手順序」之後更難進入「調整關鍵單位速度」；調鬆時，「調整關鍵單位速度」變容易，前面的準備可能失去重量。先只動這個軸。這不是來源遊戲的實測參數。
- 本地預期：把「重排時點」調緊時，「根據敵方先手重新安排」更常接不上「執行鋪墊與後續行動」；調鬆時，「執行鋪墊與後續行動」幾乎總能銜接，取捨會消失。先只動這個軸。這不是來源遊戲的實測參數。
- 不要把上述旋鈕寫成某一款遊戲的官方數值。來源若提到調整方向，也只是編輯分析，不是實驗報告。

## 失敗模式（本地分析）

- 若玩家看不出「觀察當前出手順序」如何導致「執行鋪墊與後續行動」，就只會記住成敗。以這個條目來說，規則片段「速度不一定增加行動次數」一旦不可觀察，學習就停止。這是本地失敗判斷，不是來源記載的實玩統計。
- 張力是「必須先承諾，後果才會出現」。若介面沒有把這個張力顯示成不同狀態，「根據敵方先手重新安排」會退化成固定手順。
- 不適用於單位會自己選目標、玩家只負責按下開始的戰鬥。在那種結構裡硬加「根據敵方先手重新安排」，只會多一個沒有決策的動畫。

## 最小原型與驗收（本地提案）

此原型尚未實玩驗證。範圍、數量與文字都是本地測試設定，不是來源遊戲參數，也不是原站原型文案。

- 最小範圍：只實作「觀察當前出手順序」「執行鋪墊與後續行動」「根據敵方先手重新安排」三種可區分狀態，不搬原站插圖、案例關卡或程式。
- 驗收：Given 玩家已完成「觀察當前出手順序」且系統處於可觀察的中間態，When 玩家選擇走向「執行鋪墊與後續行動」，Then 回饋必須指出結果屬於哪一類，並給出一個與「根據敵方先手重新安排」不同的下一步。
- 對照：Given 玩家停在中間態不操作，When 超過一個可辨識的等待，Then 結果必須與主動選擇不同，避免不操作也算過關。
