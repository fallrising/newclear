## 來源摘要

以下是對公開條目的短篇改寫，只保留機制本身，不含案例、圖片或原站程式。

來源把「Interrupt an action during preparation」定義成：放棄眼前傷害，換掉敵人即將完成的大動作。可對上的規則片段是：部分行動先準備再生效，期間玩家能用符合條件的攻擊或控制效果把它打斷或延後；玩家還要看準備條、姿勢和冷卻安排時機，太早出手可能被無關動作消耗，太晚則敵人已經完成行動。

來源循環的順序是：辨認敵人的準備動作 → 保留或使用打斷手段 → 確認動作取消或延後 → 等下一次危險準備。

來源要玩家自行權衡的兩件事，以下僅作繁體轉寫，不是本筆記的結論：「現在打斷普通攻擊，還是等更危險的法術？」「打斷者要靠近目標，值不值得承擔途中傷害？」

## 問題與情境（本地分析）

以下各節由模型依本筆記的來源摘要起草，屬本地設計分析，尚未經人工審閱，也不代表來源作者的觀點。

回合制或半即時戰鬥裡，敵人的強力動作若只能等它落地，玩家就只剩補血與硬扛兩種反應。把準備條攤開，再給一個能取消它的手段，玩家才會在傷害與控制之間挪動資源，順便替隊友開出安全的輸出窗口。

這套設計適合節奏偏慢、敵人動作有明顯前搖的戰鬥，尤其是頭目戰與小隊分工明確的場合。若敵人動作幾乎瞬發，或打斷成本高到玩家永遠不敢按，準備條就只是裝飾；以純即時閃避或純數值對抗為核心的遊戲也不合適。

## 核心循環（本地分析）

- 玩家行動：玩家盯著準備條、姿勢與冷卻，決定把打斷手段花在眼前的小招，還是壓住等更危險的法術；需要接近目標時，還得先移動到它身邊。
- 系統回饋：系統讓該次動作取消或延後，準備條熄滅、敵人的架勢被打散，玩家同時看到自己付掉的傷害與進入冷卻的技能。
- 下一個決策：剛斷掉的若是小招，玩家會覺得交牌太早，下一輪更傾向留手；若成功攔下大招，隊友的輸出窗口打開，下一個決定就變成誰去補位、誰繼續保留冷卻。

## 解法與取捨（本地分析）

- 打斷者往往得離開安全位置靠近目標，途中吃的傷害等於用血量換敵人的空檔，距離因此成了第二條資源曲線。
- 若打斷能無條件取消一切，最佳解會變成永遠留一招斷；所以必須加上冷卻、耗材或只對特定前搖生效的限制。
- 準備條要讓玩家讀得到，又不能長到所有敵人都變成待宰；介面揭露多少資訊，直接決定打斷是判斷還是反射動作。

## 可調參數（本地分析）

- 「準備時間」：拉長準備時間，玩家有餘裕看清招式、評估值不值得斷，但節奏變慢，打斷容易變成例行公事；縮短則逼人憑姿勢與經驗預判，誤判和空放明顯增加。
- 「打斷後的處理」：若取消等於完全抹除，玩家只要卡在最後一刻按下即可；改成延後或降階，敵人會以較弱版本回來，玩家得算剩餘冷卻夠不夠再斷一次，取捨才有層次。

## 失敗模式（本地分析）

- 敵人準備動作太快或提示太弱，玩家只能靠背招，打斷從臨場判斷退化成記憶測驗。
- 打斷成本遠高於硬扛傷害時，玩家永遠選擇吃招，準備條與打斷鈕都成了多餘的介面。
- 多個敵人同時準備時，若介面只標示一個目標，玩家無法比較哪個威脅該優先斷，緊迫感被介面本身抹平。

## 最小原型與驗收（本地提案）

此原型尚未實玩驗證。下列通過與否是本地判斷。

- 最小範圍：（本地分析）做一個小場景，讓玩家依序經歷「辨認敵人的準備動作」、「保留或使用打斷手段」、「確認動作取消或延後」、「等下一次危險準備」。來源的原型第一步是「只做一名讀條敵人、一種普通攻擊和一個打斷按鈕」。
- 驗收：（本地分析）對照來源規則「部分行動先準備再生效，期間玩家能用指定攻擊或控制把它打斷或延後」。通過要能滿足「玩家會不會主動停手，把打斷留給危險動作」，並分得出「現在打斷普通攻擊，還是等更危險的法術」。做不到就算失敗。
- 邊界驗收：（本地分析）通過是原型照來源這句做：「打斷成功與目標免疫必須有不同回饋」。

## 相關模式

- [先攻順序](command-initiative-order.md)：（本地分析）先攻順序決定誰先鋪墊、誰後收割；打斷則在回合進行中臨時插入，改掉對手已排好的節奏，兩者都在搶時間主導權。
- [偵察當下視野](command-scout-current-vision.md)：（本地分析）偵察給的是敵人位置與當前狀態，打斷需要的是敵人這一刻正在準備什麼；資訊越新，留手或出手的判斷才越準。
- [連段變化](combat-combo-variation.md)：（本地分析）連段變化用即時評價鼓勵換招；打斷的回報不是分數，而是讓敵人的動作直接消失，換來隊友的輸出窗口。
- [意圖預覽](combat-intent-preview.md)：（本地分析）意圖預覽先把威脅攤在玩家眼前，打斷則是對那份預覽做出的有限回應；少了預覽，打斷只能瞎猜。
