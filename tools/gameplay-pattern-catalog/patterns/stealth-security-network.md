## 來源摘要

以下是對公開條目的短篇改寫，只保留機制本身，不含案例、圖片或原站程式。

來源把「Surveillance control」定義成：攝像頭既能發現你，也能成為你看見敵人的眼睛。可對上的規則片段是：設施監視一片區域，並可能記錄證據或觸發警戒。

來源循環的順序是：確認監控覆蓋 → 尋找裝置或控制點 → 繞開、關閉或接管 → 利用新的安全與情報。

來源要玩家自行權衡的兩件事，以下僅作繁體轉寫，不是本筆記的結論：「為短暫透過直接破壞攝像頭，還是投入更多資源讓它持續偵察？」「已經被錄下時，完成目標就走，還是繞去清除記錄？」

## 問題與情境（本地分析）

「保全網路」要處理的情況是：玩家已經能做「確認監控覆蓋」，但重複這個動作不會自動得到好結果。這類問題的關鍵是被發現的程度，而不只是有沒有被看到。這個條目同時壓在這些設計張力上：看得到的回饋仍要玩家自己解釋、必須先承諾，後果才會出現、存量會改寫下一步還能做什麼。

適合放進玩家下一步會被「繞開、關閉或接管」改寫的系統。若結果在行動前就公布標準答案，這個設計問題會消失。不適用於一被看見就立即結束、中間沒有可反應層級的潛行。

這裡的判斷是本地設計分析，不是來源作者的意圖，也不是案例遊戲的實驗結果。

## 核心循環（本地分析）

- 玩家行動：承諾「確認監控覆蓋、尋找裝置或控制點」。這一動是玩家主動付出去的部分，不能事後假裝沒有做過。
- 系統回饋：對該行動給出與「繞開、關閉或接管」對應、而且能區分成功、部分成功與失敗的結果。只給一個總分不算回饋。
- 下一個決策：玩家依回饋決定要不要進入「利用新的安全與情報」，或改走成本不同的另一條路。若回饋不能改變這個選擇，循環就沒有學習價值。

## 解法與取捨（本地分析）

- 在「尋找裝置或控制點」就給出還能不能回頭的資訊，讓玩家不必等到「利用新的安全與情報」才知道「為短暫透過直接破壞攝像頭，還是投入更多資源讓它持續偵察」這題選錯了。
- 「共享控制範圍」用來回答第一個難點；「接管成本」用來回答「已經被錄下時，完成目標就走，還是繞去清除記錄」。兩個旋鈕如果綁在同一段回饋裡，玩家無法知道自己該改準備還是該改收尾。
- 「確認監控覆蓋」保留一條較穩的走法，「利用新的安全與情報」保留一條收益或資訊更高的走法。兩條路的結果必須長得不一樣，否則這個機制沒有選擇。

## 可調參數（本地分析）

- 本地預期：把「共享控制範圍」調緊時，「確認監控覆蓋」之後更難進入「尋找裝置或控制點」；調鬆時，「尋找裝置或控制點」變容易，前面的準備可能失去重量。先只動這個軸。這不是來源遊戲的實測參數。
- 本地預期：把「接管成本」調緊時，走到「繞開、關閉或接管」的代價變高，玩家會更常保留資源；調鬆時，「繞開、關閉或接管」變便宜，玩家可能不再準備。先只動這個軸。這不是來源遊戲的實測參數。
- 不要把上述旋鈕寫成某一款遊戲的官方數值。來源若提到調整方向，也只是編輯分析，不是實驗報告。

## 失敗模式（本地分析）

- 若玩家看不出「確認監控覆蓋」如何導致「繞開、關閉或接管」，就只會記住成敗。以這個條目來說，規則片段「設施監視一片區域，並可能記錄證據或觸發警戒」一旦不可觀察，學習就停止。這是本地失敗判斷，不是來源記載的實玩統計。
- 張力是「看得到的回饋仍要玩家自己解釋」。若介面沒有把這個張力顯示成不同狀態，「利用新的安全與情報」會退化成固定手順。
- 不適用於一被看見就立即結束、中間沒有可反應層級的潛行。在那種結構裡硬加「利用新的安全與情報」，只會多一個沒有決策的動畫。

## 最小原型與驗收（本地提案）

此原型尚未實玩驗證。範圍、數量與文字都是本地測試設定，不是來源遊戲參數，也不是原站原型文案。

- 最小範圍：只實作「確認監控覆蓋」「繞開、關閉或接管」「利用新的安全與情報」三種可區分狀態，不搬原站插圖、案例關卡或程式。
- 驗收：Given 玩家已完成「確認監控覆蓋」且系統處於可觀察的中間態，When 玩家選擇走向「繞開、關閉或接管」，Then 回饋必須指出結果屬於哪一類，並給出一個與「利用新的安全與情報」不同的下一步。
- 對照：Given 玩家停在中間態不操作，When 超過一個可辨識的等待，Then 結果必須與主動選擇不同，避免不操作也算過關。
